# 4. Процессы

## Описание

Процесс — работающий экземпляр программы. Эта тема объясняет разницу между программой, процессом и потоком. Вы узнаете блок управления процессом, идентификаторы процессов и вызовы Unix `fork`, `exec` и `wait`. Вы также узнаете зомби, сирот, переменные окружения и состояния процессов.

Завершите эту тему после ландшафта загрузки. Завершите эту тему до изучения потоков и планирования. Те темы предполагают процесс.

Используйте один термин для каждого понятия. Программа — файл инструкций и данных. Процесс — объект ОС, который выполняет программу. Поток — контекст исполнения внутри процесса. Зомби — процесс, который завершился и которого родитель ещё не дождался. Не смешивайте `fork` с `exec`. Не смешивайте зомби с сиротой.

## Программа, процесс и поток

Программа — пассивный файл. В Linux файл часто является двоичным ELF или скриптом с интерпретатором. Программа не работает, пока ядро её не загрузит.

Процесс — активный объект ОС. У процесса есть:

- идентификатор процесса
- адресное пространство (виртуальная память)
- список открытых дескрипторов файлов
- полномочия (идентификатор пользователя, идентификатор группы)
- хотя бы один поток

Одна программа может иметь много процессов. Два пользователя могут запустить `/bin/bash` одновременно. Каждая оболочка — другой процесс. Один процесс также может загрузить новую программу поверх себя через `exec`. Идентификатор процесса может остаться тем же после `exec`.

Поток — единица, которую выполняет ЦП. У потока есть стек и набор регистров. Процесс стартует с одним потоком. Процесс может создать больше потоков. Все потоки в одном процессе делят одно адресное пространство и одну таблицу дескрипторов файлов. Тема 5 покрывает потоки.

Программа — сохранённые инструкции. Процесс — работающий экземпляр. Каждый поток — одно исполнение этих инструкций внутри того же процесса. Потоки делят одно адресное пространство.

Ядро отслеживает процессы. Пользовательские инструменты вроде `ps` их перечисляют. Процесс может создавать дочерние процессы. Процесс можно остановить, продолжить или убить.

## Идея блока управления процессом (PCB)

Ядро должно хранить состояние каждого процесса. Учебное имя этих данных — блок управления процессом (PCB). Linux не использует имя PCB в исходниках. Linux использует `task_struct` для потока и связанные структуры для адресного пространства и файлов. Идея та же.

PCB держит как минимум:

- идентификаторы: PID, родительский PID
- состояние: выполняется, готов, заблокирован, зомби
- контекст ЦП: регистры, когда процесс не на ЦП
- описание памяти: таблицы страниц или указатель на них
- таблица файлов: открытые дескрипторы файлов
- полномочия: пользователь, группа, capabilities
- учёт: время ЦП, значение nice
- состояние сигналов

Когда планировщик выбирает процесс, ядро загружает контекст ЦП из PCB. Когда процесс блокируется или когда заканчивается его квант, ядро сохраняет контекст обратно.

Вы не выделяете PCB в своей программе на C. Ядро выделяет его, когда создаёт процесс. Куски PCB вы видите через `/proc/<pid>`.

PCB — причина, по которой `ps` может напечатать список. Ядро обходит свою таблицу структур процессов и копирует безопасные поля в пользовательское пространство.

## PID, родитель, потомок

Ядро назначает идентификатор процесса (PID) каждому процессу. PID — целое число. В Linux PID уникален на время жизни процесса в этом пространстве имён PID. После того как процесс завершился и его собрали, ядро может повторно использовать PID.

Процесс, который создаёт новый процесс, — родитель. Новый процесс — потомок. У потомка родительский PID (PPID) равен PID родителя в момент создания. Дерево можно увидеть через `ps -ejH` или `pstree`.

Идентификатор процесса 1 — `init` (часто `systemd`). `init` — предок пользовательских процессов после загрузки. Если родитель завершается раньше потомка, потомок становится сиротой, и ядро назначает нового родителя. В Linux новый родитель часто `init` или subreaper. Раздел про сирот ниже покрывает этот случай.

Родитель может ждать потомка. Тогда родитель получает код завершения потомка. Это ожидание также убирает зомби. Раздел `wait` покрывает вызовы.

Не предполагайте, что меньший PID — более старый процесс после повторного использования PID. Не предполагайте, что два процесса с похожими командными строками имеют общего родителя.

В Linux также есть идентификаторы потоков (TID). Для однопоточного процесса TID и PID совпадают. Тема 5 покрывает разницу.

## `fork`, `exec`, `wait` (Unix)

Unix создаёт процессы парой идей: скопировать, затем заменить.

`fork` создаёт новый процесс. Потомок — копия родителя. Потомок получает новый PID. Потомок наследует дескрипторы файлов, диспозиции сигналов (с правилами) и адресное пространство как копию (часто копирование при записи; тема 9). `fork` возвращает 0 в потомке. `fork` возвращает PID потомка в родителе. `fork` возвращает `-1` при сбое.

`exec` заменяет текущий образ процесса новой программой. Семейство включает `execve`, `execlp` и другие. После успешного `exec` тот же PID выполняет другой код. Открытые дескрипторы файлов остаются открытыми, если программа не поставила close-on-exec. `exec` не возвращается при успехе.

`wait` и `waitpid` позволяют родителю блокироваться, пока потомок не сменит состояние. Обычное применение — ждать, пока потомок завершится. Тогда родитель получает код завершения, и ядро освобождает зомби.

Типичный путь оболочки:

1. Оболочка читает команду.
2. Оболочка вызывает `fork`.
3. Потомок вызывает `exec`, чтобы выполнить команду.
4. Родитель вызывает `wait` (если команда не в фоне).

В Linux также есть `clone`. `fork` — частный случай `clone`. `posix_spawn` может объединить шаги. Сначала изучите `fork`, `exec` и `wait`.

```c
#include <unistd.h>
#include <sys/wait.h>
#include <stdio.h>

int main(void)
{
	pid_t pid = fork();
	if (pid == 0) {
		execlp("echo", "echo", "from-child", (char *)0);
		return 127;
	}
	if (pid > 0)
		wait(NULL);
	return 0;
}
```

## Зомби и сироты

Зомби — процесс, который завершился, но всё ещё имеет запись в таблице ядра. Запись держит код завершения, пока родитель не подождёт. Зомби не выполняется. Он не использует ЦП. Он использует слот PID и маленький объект ядра.

Зомби видны в `ps` с состоянием `Z` и часто пометкой `<defunct>`. Несколько короткоживущих зомби — нормально. Большое число зомби означает, что родитель не вызывает `wait`. Исправление в родителе: ждать потомков или настроить обработку `SIGCHLD`, чтобы родитель их собирал.

Сирота — процесс, чей родитель завершился. Потомок всё ещё работает. Ядро ставит нового родителя. В Linux новый родитель — PID 1 или процесс, который пометил себя как child subreaper. Новый родитель подождёт сироту, когда сирота позже завершится. Это правило предотвращает вечного зомби без того, кто ждёт.

Не смешивайте два слова.

- Зомби: потомок мёртв, родитель ещё не подождал.
- Сирота: родитель мёртв, потомок ещё жив (или потомок уже умер, и новый родитель должен его собрать).

Двойной fork — шаблон, который делает демон. Потомок завершается, внук усыновляется, и исходному родителю не нужно ждать внука. Вы увидите этот шаблон в служебных программах.

## Переменные окружения

Переменная окружения — строка вида `NAME=value`. Процесс держит список этих строк. Дочерние процессы наследуют копию списка при `fork`. `exec` может сохранить то же окружение или передать новый список (`execve`).

Обычные переменные:

- `PATH`: каталоги, в которых оболочка ищет команды
- `HOME`: домашний каталог пользователя
- `USER` и `LOGNAME`: имя входа
- `LANG` или `LC_*`: локаль
- `PWD`: текущий каталог (оболочка часто его обновляет)

API C использует `getenv`, `setenv` и указатель `environ`. Оболочка использует `export`. Переменная, которая не экспортирована, не идёт в дочерние процессы.

Строки окружения — не секретное хранилище. Любой код в процессе может их читать. Другие пользователи иногда могут читать их через `/proc/<pid>/environ`, когда права это позволяют. Не кладите пароли в окружение на общей машине.

Окружение — состояние процесса. Это не вторая файловая система. Изменение в потомке не меняет родителя.

## Состояния процесса: выполняется, готов, заблокирован, зомби

Процесс (или поток) не всегда на ЦП. Учебники используют небольшой набор состояний.

- Выполняется: процесс сейчас исполняется на ядре ЦП.
- Готов: процесс мог бы работать, но ждёт, пока планировщик даст ему ядро.
- Заблокирован (спит): процесс ждёт события. Примеры: `read`, у которого ещё нет данных, блокировка, `wait` потомка, таймер.
- Зомби: процесс завершился, и родитель его не собрал.

Коды состояния Linux `ps` не используют слово «готов». Выполняемый процесс показывает `R`. Процесс в непрерываемом сне показывает `D`. Прерываемый сон показывает `S`. Остановленный процесс (управление заданиями или отладчик) показывает `T`. Зомби показывает `Z`.

Ядро перемещает процесс между состояниями:

1. Выполняющийся процесс, который израсходовал квант, становится готовым.
2. Выполняющийся процесс, который ждёт ввода-вывода, становится заблокированным.
3. Заблокированный процесс, чьё событие пришло, становится готовым.
4. Процесс, который завершается, становится зомби до `wait`.

Тема 6 объясняет, кто выбирает следующий готовый процесс. Этот раздел только называет состояния.

Процесс может долго оставаться заблокированным. Это нормально. Процесс, который готов, но никогда не выполняется, — проблема планирования или приоритета.

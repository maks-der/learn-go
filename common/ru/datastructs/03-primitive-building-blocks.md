# 3. Примитивные строительные блоки

## Описание

Структура данных строится из битов, слов, примитивных типов и ссылок. Эта тема объясняет эти строительные блоки. Вы изучаете непрерывную память и связные узлы. Вы также изучаете идею выделения на стеке и выделения в куче. Завершите эту тему до реализации массивов и списков.

Используйте один термин для каждого понятия. **Бит** — 0 или 1. **Байт** — 8 бит. **Слово** — естественная единица, которую двигает процессор. **Указатель** или **ссылка** — значение, которое называет адрес. Точные правила зависят от языка.

## Биты, байты, слова

Компьютер хранит информацию как биты. Один бит имеет два значения: 0 и 1.

**Байт** — группа из 8 бит. Адреса памяти обычно называют байты. Один адрес — один байт, если архитектура не говорит иное правило.

**Слово** — группа байтов, которую процессор предпочитает. Обычные размеры слова сегодня — 4 байта (32-бит) и 8 байт (64-бит). Слово может держать целое или адрес на многих машинах.

```text
1 bit    = 0 or 1
1 byte   = 8 bits
1 word   = 4 bytes or 8 bytes on many machines
1 KiB    = 1024 bytes
```

Вы считаете память в байтах, когда говорите о пространстве. Вы считаете биты, когда говорите о флагах и компактных кодах.

Целое из 32 бит может представить 2³² разных шаблонов. Целое из 64 бит может представить 2⁶⁴ разных шаблонов. Большая ширина использует больше памяти и может держать больший диапазон.

Не смешивайте **бит** и **байт** в речи. «32-битное целое» — ширина в битах. «4-байтовое целое» — та же ширина в байтах на обычной машине.

Сетевые данные и файлы тоже используют байты. Структура данных в памяти использует ту же модель байтов.

## Примитивные типы и их размер

**Примитивный тип** — встроенный тип, который даёт язык. Обычные примитивные типы — целые, числа с плавающей точкой, булевы и байты.

У каждого примитивного типа есть размер. Размер — число бит или байт. Размер может быть фиксированным. Размер может зависеть от машины.

```text
typical sizes (many languages, many machines)
  bool           1 byte in a struct, or 1 bit in a packed bitset
  8-bit integer  1 byte
  32-bit integer 4 bytes
  64-bit integer 8 bytes
  32-bit float   4 bytes
  64-bit float   8 bytes
```

В Go есть `int` и `uint`. Размер `int` — 32 бита или 64 бита. Размер совпадает со словом машины в обычных сборках. В Go также есть `int32` и `int64`, когда нужен фиксированный размер.

В Python есть `int`, который растёт. Малое целое Python — объект с заголовком. Заголовок больше 4 байт. Не считайте Python `int` 32-битной ячейкой.

Кодировка символов — не структура данных. Символ всё равно использует байты. UTF-8 использует от 1 до 4 байт на кодовую точку.

Когда вы оцениваете память, умножьте размер элемента на n. Затем добавьте заголовки, указатели и неиспользуемую ёмкость. Размер примитива — только первый член.

## Указатели / ссылки

**Указатель** — значение, которое держит адрес. Адрес называет ячейку или объект в памяти.

**Ссылка** — языковое имя для значения, которое ссылается на объект. Java и Python используют ссылки. Go использует указатели как явные типы (`*T`). Идея одна: программа хранит имя места, а не полную копию большого объекта.

```text
variable p  →  address 0x100
memory 0x100 holds the integer 42
```

У указателя есть размер. На 64-битной машине указатель часто 8 байт. Список из n узлов хранит n указателей, если у каждого узла одна ссылка next. Эти указатели — дополнительная память.

**Нулевой** указатель (или `nil` в Go, `None` в Python) означает «нет объекта». Обход списка останавливается на нуле.

Когда вы копируете указатель, вы не копируете объект. Два указателя могут назвать один и тот же объект. Изменение через один указатель видно через другой указатель. Это разделение полезно. Это разделение также источник ошибок.

**Массив указателей** — не то же самое, что массив значений. Значения могут сидеть далеко друг от друга. Локальность может быть плохой.

Не разыменовывайте нулевой указатель. Программа падает или поднимает ошибку.

## Непрерывная память против связных узлов

**Непрерывная память** — блок ячеек с последовательными адресами. Массив использует непрерывную память. Индекс i находится на фиксированном смещении от начала.

**Связные узлы** — отдельные ячейки. Каждый узел держит значение и один или больше указателей на другие узлы. Односвязный узел держит указатель next. Двусвязный узел держит указатели next и previous.

```text
contiguous:  [ a | b | c | d ]     addresses in a row
linked:      (a)→(b)→(c)→(d)→null  addresses can be anywhere
```

Непрерывная память даёт:

- индекс за константное время
- хорошую локальность
- нужду сдвигать элементы, когда вы вставляете в середину
- фиксированный блок или новый блок, когда вы растёте

Связные узлы дают:

- вставку и удаление у известного узла без сдвига остальных значений
- обход от головы до индекса i
- дополнительную память на указатели
- плохую локальность

Выравнивание может добавить неиспользуемые байты внутри узла. Неиспользуемые байты делают узел больше суммы размеров полей.

Вы реализуете оба расположения. Выбирайте расположение по операциям. Не выбирайте расположение по привычке.

## Выделение на стеке и в куче (зависит от языка, концептуально)

**Выделение** — акт резервирования памяти для значения.

**Стек вызовов** — область, которая держит кадры. Каждый вызов функции кладёт кадр. Кадр держит локальные переменные, которые язык кладёт на стек. Когда функция возвращается, кадр уходит. Выделение на стеке быстрое. Размер кадра стека обычно известен на этапе компиляции. Большой массив в кадре может переполнить стек.

**Куча** — область для значений, которые живут после вызова, или у которых размер вы знаете только во время выполнения. Аллокатор находит свободный блок. Программа позже освобождает блок, или сборщик мусора освобождает блок. Выделение в куче медленнее выделения на стеке. Выделение в куче гибче.

```text
call f()
  stack frame of f: small locals
  heap:             a dynamic array that f creates and returns
return from f
  stack frame of f is gone
  heap array still lives if a caller holds a reference
```

Правила зависят от языка:

- Go: многие значения уходят в кучу. Решает компилятор. Вы не вызываете `malloc`. Сборщик мусора освобождает неиспользуемые объекты кучи.
- Python: почти каждый объект живёт в куче. Имена — ссылки.
- C: вы вызываете `malloc` и `free`. Вы владеете временем жизни.

Этот справочник использует **стек** для кратковременного хранения кадра и **куча** для области аллокатора. Не смешивайте этот стек с ADT стека. ADT стека — более поздняя тема. Стек вызовов — область памяти.

Структура данных из n узлов обычно живёт в куче. Переменная, которая называет голову, может жить в кадре.

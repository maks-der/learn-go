# 17. Строки как данные

## Описание

Строка — последовательность символов. Эта тема объясняет наивный поиск, Кнута–Морриса–Пратта, Рабина–Карпа, боры, суффиксные массивы и суффиксные деревья. Завершите эту тему после массивов и хеш-таблиц. Завершите деревья до раздела про бор.

Используйте один термин для каждого понятия. **Текст** T имеет длину n. **Образец** P имеет длину m. **Совпадение** — индекс i, где T[i .. i+m−1] равно P. **Префикс** — ведущий сегмент. **Суффикс** — хвостовой сегмент.

## Наивный поиск

**Наивный поиск** пробует образец в каждом стартовом индексе i в 0 .. n−m.

В каждом i сравните P[0] с T[i], P[1] с T[i+1], ... до несовпадения или полного совпадения.

```text
T = A B A B A C
P = A B A

i=0: ABA vs ABA  match
i=1: BAB vs ABA  mismatch at first letter
i=2: ABA vs ABA  match
i=3: BAC vs ABA  mismatch
```

```text
naive(T, P):
  n = length(T)
  m = length(P)
  for i = 0 to n - m:
      if T[i .. i+m-1] == P:
          report i
```

Время худшего случая — Θ((n − m + 1) m). Пример: T — n раз A, P — (m−1) раз A плюс один B. Каждый старт почти сравнивает m символов.

Среднее время на случайных буквах ближе к Θ(n). Многие старты падают на первой букве.

Наивный поиск легко написать и легко проверить. Реализуйте его первым. Используйте его как тестовый оракул для KMP и Рабина–Карпа.

Не используйте наивный поиск как единственный метод на огромных текстах и длинных образцах, если можете использовать линейный метод.

Индексы с нуля в этом справочнике. Совпадение в конце начинается в n − m.

Пустой образец — особый случай. Определите его: нет совпадения или совпадение в каждом индексе. Запишите правило в тестах.

## Кнут–Моррис–Пратт (идея + реализация)

**Кнут–Моррис–Пратт (KMP)** ищет за Θ(n + m) времени. Он не перезапускает образец с P[0] после каждого несовпадения. Он использует **таблицу префиксов** (также функция отказа или lps: самый длинный собственный префикс, который также является суффиксом).

**Идея.** Вы сравнили T[i .. i+q−1] с P[0 .. q−1], а затем T[i+q] != P[q]. Некоторый хвост совпавшего куска всё ещё может быть префиксом P. Таблица говорит, насколько вы можете сдвинуть P, чтобы этот префикс остался выровнен. Вы не двигаете i назад по тексту. Вы только уменьшаете совпавшую длину q.

**lps[k]** — самая длинная длина j < k+1 такая, что P[0 .. j−1] равно P[k-j+1 .. k]. lps[0] = 0. (Точные соглашения индексов различаются. Выберите один учебник и оставайтесь с ним.)

```text
P = A B A B A C
lps idea: after a mismatch, slide to the next possible prefix
```

```text
kmp(T, P):
  lps = buildLps(P)
  q = 0
  for i in 0 .. n-1:
      while q > 0 and P[q] != T[i]:
          q = lps[q - 1]
      if P[q] == T[i]:
          q = q + 1
      if q == m:
          report i - m + 1
          q = lps[q - 1]
```

**buildLps** — KMP образца против себя. Время — Θ(m).

Реализуйте KMP после того, как можете нарисовать один сдвиг на бумаге. Сначала реализуйте buildLps. Печатайте lps для ABA, AAAA и ABC.

KMP не хеширует. Он только сравнивает символы и использует целые в lps.

Время худшего случая — Θ(n + m). Дополнительная память — Θ(m) для lps.

Не копируйте таблицу с сайта без проверки против наивного поиска.

## Рабин–Карп (скользящий хеш)

**Рабин–Карп** сравнивает **скользящий хеш** текущего окна длины m с хешем P. Если хеши различаются, окно не совпадение. Если хеши равны, вы сравниваете символы (или принимаете малый риск коллизии в некоторых вариантах).

**Скользящий хеш** обновляет хеш окна за O(1), когда окно двигается на один символ. Вы отбрасываете левый символ и добавляете правый символ. Вы не пересматриваете m символов для хеша.

```text
hash of T[i .. i+m-1]
next = (hash - T[i] * base^{m-1}) * base + T[i+m]
modulo a prime
```

```text
rk(T, P):
  hp = hash(P)
  hw = hash(T[0 .. m-1])
  if hw == hp and T[0 .. m-1] == P: report 0
  for i = 1 to n - m:
      hw = roll(hw, T[i-1], T[i+m-1])
      if hw == hp and T[i .. i+m-1] == P: report i
```

Используйте большой простой модуль. Используйте основание вроде 256 для байтов. Следите за переполнением. Используйте беззнаковые целые или явную модульную арифметику.

Время худшего случая — Θ(n m), если каждое окно сталкивается и вы проверяете каждое. Среднее время — Θ(n + m) с хорошим хешем.

**Двойной хеш** (два модуля) уменьшает риск коллизии.

Рабин–Карп полезен для нескольких образцов одной длины и для идеи скользящего хеша в других задачах.

Не пропускайте проверку символов, если нужен верный список совпадений. Коллизия хеша редка, но реальна.

KMP обычно первый линейный поиск строки, которому вы доверяете. Рабин–Карп — урок хеша.

## Бор / префиксное дерево

**Бор (trie, префиксное дерево)** хранит множество строк. Каждое ребро помечено символом. Путь от корня — префикс. Узел может помечать «конец слова».

```text
words: at, ate, be

      *
     / \
    a   b
    |   |
   t*  e*
    |
    e*
```

**Insert** идёт или создаёт одного ребёнка на символ, затем помечает последний узел как конец.

**Find** идёт по символам. Если ребёнок отсутствует, слова нет. Если вы заканчиваете слово и метка конца установлена, слово присутствует.

**Запрос префикса.** Идите по префиксу. Если обход успешен, некоторое хранимое слово имеет этот префикс. Затем вы можете обойти поддерево для автодополнения.

Время insert или find — Θ(L) для строки длины L. Оно не зависит от числа слов n так же, как линейный просмотр всех слов. Память может быть большой, если у многих узлов мало детей.

Массив из 26 детей подходит строчному английскому. Отображение из символа в ребёнка подходит большему алфавиту.

Бор — не суффиксное дерево. Бор хранит целые слова как пути от корня. Он не хранит все суффиксы одного текста, если вы их не вставите (это потратит память).

Не используйте бор, когда нужен только точный поиск нескольких слов. Хеш-множество проще. Используйте бор, когда важны префиксы.

## Суффиксный массив (на высоком уровне)

**Суффиксный массив** текста T — массив стартовых индексов всех суффиксов T, отсортированных в лексикографическом порядке.

```text
T = banana
suffixes:
  0 banana
  1 anana
  2 nana
  3 ana
  4 na
  5 a

sorted suffixes: a, ana, anana, banana, na, nana
suffix array:    5, 3, 1, 0, 4, 2
```

Суффиксный массив использует Θ(n) целых. Он использует меньше памяти, чем суффиксное дерево. Многие запросы, на которые отвечает суффиксное дерево, могут использовать суффиксный массив плюс дополнительные таблицы (LCP). Эти дополнения — более поздняя тема.

**Найти образец.** Двоичный поиск по суффиксному массиву. Сравните P с суффиксом в среднем индексе. Время — O(m log n) сравнений, если сравниваете с начала каждый раз. Дополнительные данные LCP могут уменьшить эту стоимость.

Вы можете построить суффиксный массив за O(n log n) сортировкой суффиксов и аккуратным ключом или за O(n) сложным линейным построением. Этот справочник требует определение и медленное построение для малого n: отсортируйте n суффиксов языковой сортировкой.

Не стройте суффиксный массив огромного текста полной сортировкой строк, если n велико. Это может стоить Θ(n² log n) работы по символам. Используйте известный алгоритм, когда n велико.

Суффиксный массив — не бор. Это перестановка индексов 0 .. n−1.

## Суффиксное дерево (ознакомление)

**Суффиксное дерево** — сжатый бор всех суффиксов T. Компактное ребро хранит подстроку T (два индекса) вместо одного символа на ребро. После построения за линейное время многие строковые запросы быстры.

Этот раздел — **только ознакомление**. Не реализуйте алгоритм Укконена в этой теме.

Факты, которые нужно запомнить:

- Дерево имеет O(n) узлов, если рёбра сжаты.
- Вы можете найти P за O(m) времени после того, как имеете дерево (вопросы алфавита в стороне).
- Суффиксное дерево может найти самую длинную общую подстроку двух текстов (с объединённым текстом и разделителем).
- Построение за линейное время знаменито и легко сделать неверно.
- Суффиксный массив плюс LCP — обычная замена на практике.

```text
you implement now:  naive search, KMP, rolling hash, trie, slow suffix array
you only name:      suffix tree, Ukkonen
```

Если статья говорит «постройте суффиксное дерево», спросите, достаточно ли суффиксного массива для запроса.

Суффиксное дерево — не B+-дерево. Слово «дерево» — единственная общая идея.

Не путайте суффиксное дерево с бором словаря. Бор словаря хранит выбранные слова. Суффиксное дерево хранит каждый суффикс одного текста.

### Вопросы

#### Теоретические вопросы

1. Опишите путь от наивного сравнения к линейному просмотру (KMP) и к хеш-окну (Рабин–Карп).
2. Как бор и суффиксный массив оба используют префиксы, но хранят разные объекты?
3. Напарник говорит «положи текст в хеш-отображение, чтобы найти образец». Какие факты вы используете, чтобы поправить это предложение?
4. Что должно остаться тем же у наивного, KMP и Рабина–Карпа на верном тесте?
5. Почему этот справочник откладывает суффиксные деревья, но просит реализовать KMP?

#### Простые практические задания

1. Напишите шпаргалку на одну страницу: наивный, lps, скользящий хеш, бор, суффиксный массив, ознакомление с суффиксным деревом.
2. Нарисуйте бор из трёх слов и суффиксный массив одного четырёхбуквенного слова.
3. Составьте таблицу: «Нужда», «Структура». Строки: точное множество слов, дополнение префикса, просмотр одного образца, все суффиксы.
4. Напишите T, P, n и m для одного примера по памяти.

#### Средние практические задания

1. Реализуйте наивный, KMP и Рабина–Карпа. Они должны согласиться на 15 тестах.

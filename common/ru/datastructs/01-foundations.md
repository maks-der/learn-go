# 1. Основы

## Описание

Структура данных — способ хранить и организовывать значения в программе. Эта тема объясняет эту идею. Вы узнаете разницу между абстрактным типом данных и реализацией. Вы также узнаете Big-O на практике, частые классы роста, амортизированную стоимость и локальность памяти.

Завершите эту тему первой. Завершите эту тему до изучения массивов и списков.

Используйте один термин для каждого понятия. **Абстрактный тип данных (ADT)** — список операций. **Реализация** — раскладка и код, которые выполняют эти операции. **n** — число элементов. **Класс роста** — семейство функций, например константное или линейное. **Локальность** — использование соседних ячеек памяти за короткое время.

## Что такое структура данных

Структура данных — организация значений в памяти. Структура решает, как вы храните значения и как вы получаете значения. Структура также решает, как вы добавляете значения и как вы удаляете значения.

Примеры структур данных: массив, связный список, хеш-таблица и дерево. Каждая структура хранит значения. Каждая структура даёт разную стоимость каждой операции.

Вы не выбираете структуру только по имени. Вы выбираете структуру по операциям, которые вам нужны. Если нужен быстрый доступ по индексу, используйте массив. Если нужна быстрая вставка в начало, используйте связный список.

Структура данных — не алгоритм. Алгоритм — последовательность шагов. Структура данных — раскладка значений. Алгоритм использует структуру данных.

Значение в структуре — **элемент**. Некоторые тексты говорят «item». Этот справочник использует **элемент** для хранимого значения. Этот справочник использует **узел** только для связной ячейки, которая держит значение и ссылку.

```text
structure: array of 4 integers
indexes:   0    1    2    3
elements:  10   20   30   40
```

Те же четыре числа могут жить в списке узлов. Значения не меняются. Раскладка в памяти меняется. Это изменение раскладки и есть структура данных.

Программа использует время и память. Время — работа процессора. Память — то, что программа держит. Вы сравниваете структуры по этим стоимостям. Вы измеряете время в шагах, а не в секундах. Шаг — одно простое действие: сравнение, присваивание или индекс. Секунды зависят от машины. Шаги не зависят.

## Абстрактный тип данных и реализация

Абстрактный тип данных (ADT) — контракт. Контракт называет операции. Контракт не называет раскладку в памяти.

Стек — ADT. Операции стека — push, pop и peek. Контракт не говорит «массив» или «список».

Реализация — код, который выполняет контракт. Один стек может использовать массив. Другой стек может использовать связный список. Обе реализации — стеки, если они выполняют одни и те же операции.

ADT скрывает раскладку. Пользователь ADT вызывает операции. Пользователь не читает внутренние поля. Это разделение позволяет позже сменить реализацию.

```text
ADT: Stack
  push(x)  — put x on the top
  pop()    — remove the top and return it
  peek()   — return the top and do not remove it
  empty()  — true when the stack holds no element

Implementation A: array + top index
Implementation B: linked list + head node
```

Тип в языке программирования не всегда ADT. Тип языка — инструмент. ADT — идея проектирования. Можно записать ADT как тип. Можно записать ADT как набор функций.

Используйте один термин для каждой идеи. Говорите **ADT**, когда речь о контракте. Говорите **реализация**, когда речь о коде и раскладке памяти.

Имя ADT не говорит вам стоимость. Стоимость говорит реализация. Всегда спрашивайте, какая у вас реализация.

Один ADT может иметь много реализаций. Операции остаются теми же. Стоимости меняются. Вы выбираете реализацию по операциям, которые делаете часто.

## Big-O на практике: лучший, средний, худший

Сложность описывает, как стоимость операции растёт, когда растёт вход. **Big-O** — обычная запись в повседневной работе. Big-O — верхняя оценка. Если операция O(n), время не растёт быстрее, чем константа, умноженная на n, для больших n.

Big-O может быть свободной оценкой. O(n) также является O(n²). Более полезна тесная верхняя оценка. **Big-Theta** — тесная оценка. Если операция Θ(n), время растёт как n. Многие тексты пишут O(n), когда имеют в виду Θ(n). Читайте текст.

Игнорируйте постоянные множители в записи. 2n и 100n оба Θ(n). Не игнорируйте константы в реальной программе, когда n мало. Запись — про рост. Измерение — про реальную машину.

Отбрасывайте младшие члены. n² + 3n + 10 есть Θ(n²). Член n² доминирует при большом n.

У одной операции может быть больше одной стоимости по времени. Стоимость зависит от входа.

**Лучший случай** — самый дешёвый вход размера n. Пример: найти значение, которое стоит в первой ячейке массива.

**Худший случай** — самый дорогой вход размера n. Пример: найти значение, которого нет в массиве. Вы посещаете каждую ячейку.

**Средний случай** — ожидаемая стоимость для типичного входа. Нужна модель типичного входа. Если каждая позиция равновероятна, средний поиск в неотсортированном массиве посещает около n/2 ячеек.

Пишите случай, когда пишете оценку. «Поиск есть O(n)» — неполное утверждение. «Поиск в неотсортированном массиве есть O(n) в худшем случае» — полное.

```text
binary search in a sorted array of n elements
  best case:    Θ(1)   — the middle cell is the target
  worst case:   Θ(log n)
  average case: Θ(log n)  for a usual model
```

Не смешивайте случаи. Не сравнивайте лучший случай одной структуры с худшим случаем другой структуры.

## Константный, логарифмический, линейный, линеарифмический, квадратичный

Класс роста — имя семейства функций. Вы используете эти имена, когда сравниваете операции.

**Константный** — Θ(1). Стоимость не растёт с n. Пример: чтение индекса i в массиве.

**Логарифмический** — Θ(log n). Стоимость растёт как число раз, которое вы можете делить n на 2. Пример: двоичный поиск в отсортированном массиве. Один шаг отбрасывает примерно половину оставшихся ячеек.

**Линейный** — Θ(n). Стоимость растёт как n. Пример: посетить каждый элемент один раз.

**Линеарифмический** — Θ(n log n). Стоимость — константа, умноженная на n, умноженная на log n. Пример: эффективная сортировка сравнением n элементов.

**Квадратичный** — Θ(n²). Стоимость растёт как n, умноженное на n. Пример: сравнить каждую пару элементов.

```text
n        10     100     1 000    1 000 000
1        1      1       1        1
log n    ~3     ~7      ~10      ~20
n        10     100     1 000    1 000 000
n log n  ~33    ~664    ~10 000  ~20 000 000
n²       100    10 000  1 000 000  10^12
```

Таблица использует логарифм по основанию 2 и округлённые значения. Точное основание не меняет класс.

Операция константного времени не бесплатна. Она всё равно тратит шаги. Слово «константный» значит, что число шагов не растёт с n.

Логарифмический рост остаётся малым при большом n. Квадратичный рост становится большим. Для n = 1 000 000 значение n² — около миллиона миллионов шагов. Эта стоимость часто слишком велика.

Не говорите «быстро» без класса. «Быстро» — не класс роста.

Есть и другие классы: кубический, экспоненциальный, факториальный. Эта тема использует пять имён выше для повседневной работы.

## Амортизированная стоимость

**Амортизированная стоимость** — средняя стоимость одной операции в последовательности. Некоторые операции в последовательности дорогие. Многие операции дешёвые. Среднее всё равно может быть малым.

Обычный пример — append в динамическом массиве. Большинство append пишут одну ячейку. Эта стоимость Θ(1). Когда буфер полон, append копирует все n элементов в больший буфер. Этот один append есть Θ(n).

Если буфер удваивается, копирования происходят при размерах 1, 2, 4, ..., n. Сумма этих копий меньше 2n. Для n append из пустого массива общая стоимость копий есть Θ(n). Амортизированная стоимость одного append есть Θ(1).

```text
n appends from empty, doubling
  cheap appends: write one cell
  grow at:       1, 2, 4, ..., n
  total copies:  < 2n
  amortized:     Θ(1) per append
```

Амортизированная стоимость — не то же самое, что средний случай. Среднему случаю нужна модель случайного входа. Амортизированной стоимости нужна последовательность операций. Последовательность может быть худшей. Удвоение всё равно даёт Θ(1) амортизированный append для любой последовательности из n append из пустого массива.

Амортизированная стоимость — не гарантия для одной операции. Один append всё ещё может занять Θ(n) времени. Если нужна строгая оценка худшего случая для каждого вызова, амортизированного Θ(1) недостаточно.

Простой способ увидеть амортизированную стоимость — **метод агрегации**: сложить полную стоимость n операций, затем разделить на n.

Не используйте рост на +1 для общего динамического массива. Каждый полный append копирует n элементов. Общая стоимость копий около 1 + 2 + ... + n. Эта сумма есть Θ(n²). Амортизированная стоимость тогда Θ(n), а не Θ(1).

## Локальность памяти: массивы против погони за указателями

**Локальность памяти** — использование соседних адресов за короткое время. Процессоры загружают **строку кэша**: небольшой блок соседних байтов. Если следующий элемент в этом блоке, следующий доступ дешёвый.

**Массив** хранит элементы в непрерывных ячейках. Обход от индекса 0 до n−1 использует соседние адреса. У обхода хорошая локальность. Кэш может держать много элементов в одной строке.

**Связный список** хранит элементы в узлах. Каждый узел держит значение и указатель на следующий узел. Следующий узел может лежать далеко в памяти. Обход идёт по указателям. Этот обход — **погоня за указателями**. У погони за указателями плохая локальность. Каждый узел может промахнуться в кэше.

```text
array walk:     [10][20][30][40]   — cells sit in one block
list walk:      [10|•] -----> [20|•] -----> [30|null]
                nodes can sit far apart
```

Хорошая локальность не меняет класс роста. Обход массива и обход списка оба Θ(n), чтобы посетить n элементов. Постоянные множители могут сильно отличаться. На реальной машине обход массива часто быстрее.

Локальность также важна для вставки и удаления. Массив, который сдвигает блок ячеек, всё равно использует непрерывные записи. Список, который меняет два указателя, пишет меньше, но поздний обход может остаться медленным.

Не выбирайте список только потому, что вставка в середину — «смена указателя». Считайте полную стоимость: найти позицию, сменить ссылки, затем позже обходить с плохой локальностью.

Этот справочник использует **непрерывный** для раскладки массива. Этот справочник использует **связный** для раскладки узлов.

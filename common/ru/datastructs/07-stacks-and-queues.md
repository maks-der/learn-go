# 7. Стеки и очереди

## Описание

Стек и очередь — абстрактные типы данных для упорядоченного доступа. Эта тема объясняет LIFO и FIFO. Вы изучаете реализации на массиве и списке, кольцевой буфер, дек, стек вызовов и предварительный взгляд на BFS и DFS. Завершите эту тему после массивов и списков.

Используйте один термин для каждого понятия. **LIFO** означает последним пришёл — первым ушёл. **FIFO** означает первым пришёл — первым ушёл. **Стек** — ADT LIFO. **Очередь** — ADT FIFO. **Дек** — двусторонняя очередь. **Кольцевой буфер** — фиксированный буфер с индексами, которые заворачиваются.

## Стек LIFO: массив против списка

**Стек** поддерживает push, pop и peek (верх). Push кладёт элемент на верх. Pop снимает верх и возвращает его. Peek возвращает верх и не снимает его. Empty сообщает, нет ли в стеке элемента.

**LIFO** означает, что последний push — первый pop.

```text
push 1, push 2, push 3
stack top → 3, 2, 1
pop → 3
```

**Реализация на массиве.** Используйте динамический массив. Push — append. Pop — удаление в конце. Peek — get(length − 1). При геометрическом росте push — амортизированная Θ(1). Pop — Θ(1). Локальность хорошая.

**Реализация на списке.** Используйте вставку в голову как push. Используйте удаление у головы как pop. Каждая операция — Θ(1) в худшем случае. Локальность плохая. Дополнительная память включает указатели.

```go
// array-backed idea
func (s *Stack) Push(x int) { s.data = append(s.data, x) }
func (s *Stack) Pop() int {
	n := len(s.data) - 1
	x := s.data[n]
	s.data = s.data[:n]
	return x
}
```

Не делайте pop пустого стека. Верните ошибку или булево. Определите поведение пустого в ADT.

Стек не даёт get(i) в ADT. Если нужен доступ по индексу, нужен другой ADT.

Используйте стек на массиве по умолчанию. Используйте стек на списке, когда нужна гарантированная Θ(1) push без редкого изменения размера, или когда вы уже используете узлы.

## Очередь FIFO: кольцевой буфер против списка

**Очередь** поддерживает enqueue, dequeue и front. Enqueue кладёт элемент в конец. Dequeue снимает элемент спереди. Front возвращает передний элемент и не снимает его. FIFO означает, что первый enqueue — первый dequeue.

```text
enqueue 1, enqueue 2, enqueue 3
front → 1, then 2, then 3
dequeue → 1
```

**Реализация на списке.** Enqueue в хвост. Dequeue у головы. Вам нужны голова и хвост. Каждая операция — Θ(1). Не делайте enqueue в голову и dequeue у хвоста на односвязном списке. Dequeue у хвоста — Θ(n).

**Реализация кольцевого буфера.** Используйте фиксированный массив плюс два индекса: голова и хвост, или голова и длина. Когда индекс выходит за последнюю ячейку, индекс заворачивается в 0.

```text
capacity 4
cells:  _  10  20  30
head=1  tail=0  (next write at 0)
enqueue 40 → 40  10  20  30
dequeue → 10, head=2
```

Enqueue кольцевого буфера — Θ(1), когда буфер не полон. Когда буфер полон, вы отклоняете enqueue или выделяете больший буфер и копируете по порядку.

Динамический массив, который делает dequeue с индекса 0, — плохая очередь. Каждый dequeue сдвигает n элементов. Эта стоимость — Θ(n). Не реализуйте очередь так.

В Go нет кольцевого буфера в языке. Вы пишете его или используете список. Python `collections.deque` — цепочка блоков, эффективная на обоих концах.

## Дек

**Дек** (двусторонняя очередь) поддерживает вставку и удаление и спереди, и сзади. Обычные операции — push_front, push_back, pop_front и pop_back. Peek на обоих концах необязателен.

Дек может реализовать стек (используйте один конец) и очередь (используйте противоположные концы).

```text
push_back 1, push_back 2, push_front 0
front → 0, 1, 2 ← back
pop_front → 0
pop_back → 2
```

**Реализация на списке.** Двусвязный список с головой и хвостом даёт Θ(1) на обоих концах.

**Реализация блоками или кольцом.** Кольцевой буфер может служить деком, если вы заворачиваете оба индекса. Python `deque` использует связные блоки массивов. Этот дизайн имеет лучшую локальность, чем один узел на элемент.

Компактный динамический массив дёшев сзади и дорог спереди. Не используйте его как общий дек.

Используйте дек, когда нужны оба конца. Если нужен только один конец, используйте стек. Если нужен только FIFO, используйте очередь. Меньший ADT легче проверить.

## Стек вызовов против явного стека

**Стек вызовов** — область памяти для кадров функций. Каждый вызов кладёт кадр. Каждый возврат снимает кадр. Стек вызовов — LIFO. Рекурсия использует стек вызовов.

**Явный стек** — ADT стека, который вы создаёте. Вы кладёте свои значения. Вы снимаете свои значения. Значения могут быть индексами, узлами или кадрами, которые вы проектируете.

```text
function a calls b, b calls c
call stack (top): c frame, b frame, a frame

explicit stack for the same idea:
  push a, push b, push c
  pop c, pop b, pop a
```

Рекурсивный алгоритм использует стек вызовов. Итеративный алгоритм может использовать явный стек и делать тот же обход. Итеративная форма избегает глубокого переполнения стека вызовов. Итеративная форма также позволяет видеть стек в отладчике как ваши данные.

У стека вызовов ограниченный размер. Глубокая рекурсия может упасть. Явный стек живёт в куче. Предел кучи больше. Вы всё равно не должны расти без границы.

Не смешивайте два термина. Говорите **стек вызовов** для кадров. Говорите **стек** или **явный стек** для ADT.

ADT стека не заменяет стек вызовов для адресов возврата. Язык всё равно использует стек вызовов для вызовов. Ваш ADT — дополнительные данные.

## BFS использует очередь; DFS использует стек (предварительный взгляд)

Этот раздел — предварительный взгляд. Вы изучите графы и деревья в более поздних темах. Выучите пару сейчас.

**Поиск в ширину (BFS)** посещает узлы по расстоянию от старта. BFS использует **очередь**. Вы кладёте соседей. Вы снимаете следующий узел. Порядок FIFO посещает уровень 0, затем уровень 1, затем уровень 2.

**Поиск в глубину (DFS)** идёт глубоко по одному пути. DFS использует **стек**. Рекурсия использует стек вызовов. Итеративный DFS использует явный стек. Порядок LIFO продолжает новейший узел первым.

```text
BFS idea
  enqueue start
  while queue not empty:
      v = dequeue
      enqueue unvisited neighbors of v

DFS idea
  push start
  while stack not empty:
      v = pop
      push unvisited neighbors of v
```

Один и тот же граф может использовать BFS или DFS. Порядок посещения разный. ADT разный.

BFS находит кратчайший путь в невзвешенном графе. Этот факт — более поздняя тема. Запомните, что очередь — инструмент.

Лабиринт с «держи одну руку на стене» ближе к DFS. Заливка кольцами ближе к BFS.

Не реализуйте полную библиотеку графов в этой теме. Реализуйте крошечный пример: сетку из четырёх ячеек или дерево из трёх узлов.

# 3. SQL в PostgreSQL

## Описание

Эта тема показывает основной SQL в PostgreSQL 16 и PostgreSQL 17. Вы пишете `SELECT`, `INSERT`, `UPDATE` и `DELETE`. Узнаёте `RETURNING`, `ILIKE` и dollar-quoting. Также узнаёте соединения, `WITH`, рекурсивные запросы, `LEFT JOIN LATERAL` и `DISTINCT ON`.

Сначала завершите темы 1 и 2. Нужно подключение и таблицы с ключами. Завершите эту тему до изучения функций, JSON и индексов.

Используйте один термин для каждого понятия. Оператор — одна SQL-команда. `RETURNING` отдаёт строки результата из записи. Dollar-quoting — способ написать строку без экранирования кавычек. Соединение объединяет строки двух таблиц. CTE — именованный подзапрос в предложении `WITH`. Латеральное соединение позволяет правой стороне использовать столбцы левой. `DISTINCT ON` оставляет первую строку каждой группы в текущем порядке сортировки.

## `SELECT` / `INSERT` / `UPDATE` / `DELETE`

Эти четыре оператора — команды данных. `SELECT` читает строки. `INSERT` добавляет строки. `UPDATE` меняет строки. `DELETE` удаляет строки.

Создайте учебную таблицу:

```sql
CREATE TABLE items (
    id   integer PRIMARY KEY,
    name text NOT NULL,
    qty  integer NOT NULL DEFAULT 0
);
```

Вставка строк:

```sql
INSERT INTO items (id, name, qty) VALUES (1, 'nail', 100);
INSERT INTO items (id, name, qty)
VALUES
    (2, 'screw', 50),
    (3, 'bolt', 25);
```

Выборка строк:

```sql
SELECT id, name, qty
FROM items
WHERE qty > 10
ORDER BY name;
```

Обновление строк:

```sql
UPDATE items
SET qty = qty + 5
WHERE name = 'nail';
```

Удаление строк:

```sql
DELETE FROM items
WHERE id = 3;
```

Правила:

- `WHERE` ограничивает `UPDATE` и `DELETE`. `UPDATE` без `WHERE` меняет каждую строку. `DELETE` без `WHERE` удаляет каждую строку.
- `INSERT` должен удовлетворять ограничениям.
- `SELECT` без `FROM` допустим. Пример: `SELECT 1 + 1;`.
- PostgreSQL в клиентских API использует параметры стиля `$1`. В `psql` пишете литералы. Не склеивайте пользовательский текст в SQL. В программах используйте параметры.

`INSERT ... SELECT` копирует из запроса:

```sql
INSERT INTO items (id, name, qty)
SELECT id + 100, name, qty FROM items WHERE qty < 10;
```

`UPDATE` может использовать `FROM` для соединения с другими таблицами. `DELETE` может использовать `USING`. Эти формы учите после соединений в этой теме.

`LIMIT` и `OFFSET` ограничивают результат. `OFFSET` пропускает строки. Большой `OFFSET` медленный. Тема 13 разбирает keyset-пагинацию.

```sql
SELECT id, name FROM items ORDER BY id LIMIT 10 OFFSET 20;
```

`FETCH FIRST 10 ROWS ONLY` — форма `LIMIT` из стандарта SQL.

PostgreSQL не требует `FROM DUAL`. Для выражений используйте `SELECT` без `FROM`.

## `RETURNING`, `ILIKE`, dollar-quoting

`RETURNING` добавляет набор результата к `INSERT`, `UPDATE` или `DELETE`. Вы получаете строки, которые оператор записал или удалил.

```sql
INSERT INTO items (id, name, qty)
VALUES (4, 'washer', 10)
RETURNING id, name;

UPDATE items
SET qty = qty - 1
WHERE id = 4
RETURNING id, qty;

DELETE FROM items
WHERE id = 4
RETURNING *;
```

Используйте `RETURNING`, когда база заполняет identity, default или значения триггера. Клиенту не нужен второй `SELECT`.

`LIKE` сравнивает с шаблоном. `%` значит любую строку. `_` значит один символ. `LIKE` чувствителен к регистру для типичного текста с collation `C`.

`ILIKE` — форма без учёта регистра. Это расширение PostgreSQL.

```sql
SELECT name FROM items WHERE name LIKE 'n%';
SELECT name FROM items WHERE name ILIKE 'N%';
```

Экранируйте `%` и `_` через `ESCAPE`, когда пользовательский текст может содержать эти символы. Тема 4 разбирает `SIMILAR TO` и регулярные выражения.

Dollar-quoting пишет строку без удвоенных одинарных кавычек:

```sql
SELECT $$it's a nail$$;
SELECT $body$line 1
line 2$body$;
```

Тег между знаками `$` должен совпадать. Используйте dollar-quoting для тел функций (тема 9) и для длинного текста в скриптах. Dollar-quoted строка всё равно строковый литерал. Это не параметр. Не кладите пользовательский ввод в dollar quotes в прикладном SQL.

PostgreSQL также приводит типы во многих контекстах. Пишите явные приведения, когда тип неочевиден: `qty::text` или `CAST(qty AS text)`.

## Соединения

**Внутреннее соединение** возвращает строки, которые удовлетворяют условию соединения.

```sql
SELECT c.email, o.id AS order_id
FROM customers AS c
INNER JOIN orders AS o ON o.customer_id = c.id;
```

`JOIN` без слова — внутреннее соединение. При обучении пишите `INNER JOIN`.

**Левое внешнее соединение** возвращает каждую строку левой таблицы. Когда совпадения нет, правые столбцы — `NULL`.

```sql
SELECT c.email, o.id AS order_id
FROM customers AS c
LEFT JOIN orders AS o ON o.customer_id = c.id;
```

**Правое внешнее соединение** возвращает каждую строку правой таблицы. **Полное внешнее соединение** возвращает каждую строку с обеих сторон.

```sql
SELECT *
FROM customers AS c
FULL JOIN orders AS o ON o.customer_id = c.id;
```

**Декартово соединение** — декартово произведение. Каждая левая строка сочетается с каждой правой. Предложения `ON` нет.

```sql
SELECT *
FROM sizes
CROSS JOIN colors;
```

Используйте декартово соединение только когда нужны все пары (пример: размер × цвет).

`USING (customer_id)` — короткая форма, когда у обоих столбцов одно имя. `NATURAL JOIN` сопоставляет все одноимённые столбцы. Не используйте `NATURAL JOIN`. Новый столбец может изменить соединение.

Фильтр в `ON` против `WHERE` для внешних соединений:

- `ON` решает совпадения
- `WHERE` по правому столбцу после `LEFT JOIN` может убрать несовпавшие левые строки и превратить соединение во внутреннее

```sql
-- оставляет клиентов без заказов
SELECT c.email, o.id
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id AND o.id > 10;

-- убирает клиентов без подходящего заказа
SELECT c.email, o.id
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id
WHERE o.id > 10;
```

Всегда пишите псевдонимы. Всегда пишите условие соединения. Не соединяйте без `ON`, если не имеете в виду `CROSS JOIN`.

`UPDATE ... FROM` и `DELETE ... USING` — соединения для записи. Соединение кладите в `FROM`/`USING`. `WHERE` оставляйте для дополнительного фильтра.

## `WITH` и `WITH RECURSIVE`

CTE именует запрос. Основной запрос читает это имя как таблицу.

```sql
WITH recent AS (
    SELECT id, customer_id, created_at
    FROM orders
    WHERE created_at >= DATE '2026-01-01'
)
SELECT c.email, r.id
FROM recent AS r
JOIN customers AS c ON c.id = r.customer_id;
```

Можно перечислить больше одного CTE. Разделяйте их запятыми.

```sql
WITH a AS (...),
     b AS (SELECT * FROM a WHERE ...)
SELECT * FROM b;
```

По умолчанию CTE в старых ментальных моделях — барьер оптимизации. В PostgreSQL 12 и новее планировщик может встроить многие CTE. Материализацию можно форсировать через `WITH a AS MATERIALIZED (...)`. Встраивание разрешить через `NOT MATERIALIZED`.

Используйте CTE, чтобы назвать шаг. Не вкладывайте десять CTE, когда хватает простого соединения.

`WITH RECURSIVE` строит рабочую таблицу. Первая часть (якорь) выполняется один раз. Вторая часть (рекурсивный член) читает рабочую таблицу, пока не добавит ни одной строки.

```sql
WITH RECURSIVE tree AS (
    SELECT id, parent_id, name, 1 AS depth
    FROM categories
    WHERE parent_id IS NULL
    UNION ALL
    SELECT c.id, c.parent_id, c.name, t.depth + 1
    FROM categories AS c
    JOIN tree AS t ON c.parent_id = t.id
)
SELECT * FROM tree ORDER BY depth, name;
```

Используйте `UNION ALL`, когда не нужно отбрасывать дубликаты. Используйте `UNION`, когда дубликаты нужно отбросить. Всегда включайте условие остановки (лимит глубины или конечное дерево). Цикл без проверки посещённых может крутиться до `statement_timeout` или предела памяти.

PostgreSQL 14 и новее могут использовать предложения `SEARCH` и `CYCLE` на рекурсивных CTE. PostgreSQL 16 и 17 эти предложения сохраняют. Они помечают циклы и порядок обхода.

CTE, изменяющий данные, может делать `INSERT`, `UPDATE` или `DELETE` в `WITH` и затем `SELECT` строк `RETURNING`. Записи идут в одном операторе.

```sql
WITH moved AS (
    DELETE FROM items WHERE qty = 0 RETURNING *
)
INSERT INTO items_archive SELECT * FROM moved;
```

Не используйте рекурсию для простого списка, который может построить `generate_series`.

## `LEFT JOIN LATERAL`

Латеральное соединение позволяет правому запросу использовать столбцы левой строки.

```sql
SELECT c.id, c.email, recent.id AS order_id, recent.created_at
FROM customers AS c
LEFT JOIN LATERAL (
    SELECT o.id, o.created_at
    FROM orders AS o
    WHERE o.customer_id = c.id
    ORDER BY o.created_at DESC
    LIMIT 1
) AS recent ON true;
```

Без `LATERAL` подзапрос в `FROM` не видит `c.id`. `LATERAL` делает эту ссылку законной.

`LEFT JOIN LATERAL ... ON true` оставляет каждую левую строку. Когда подзапрос не возвращает строк, правые столбцы — `NULL`. `CROSS JOIN LATERAL` или `INNER JOIN LATERAL` отбрасывает левые строки без совпадения.

Функция в `FROM` неявно латеральная:

```sql
SELECT u.id, g
FROM users AS u
CROSS JOIN LATERAL unnest(u.tags) AS g;
```

`unnest` — тема 4. Шаблон тот же: каждая левая строка даёт набор.

Используйте `LATERAL` для «топ N на группу», когда оконная функция (тема 14) ещё не в вашем наборе, или когда функции, возвращающей набор, нужны левые столбцы.

Коррелированный подзапрос в `SELECT` может делать похожую работу. `LATERAL` в `FROM` часто яснее и может быть быстрее, когда из внутреннего запроса нужно несколько столбцов.

Не используйте `LATERAL` для обычного соединения, которое выражает `ON`. Не забывайте `ON true` у подзапроса `LEFT JOIN LATERAL`. Отсутствие `ON` — синтаксическая ошибка для `LEFT JOIN`.

## `DISTINCT ON`

`DISTINCT ON (expr [, ...])` оставляет первую строку каждого различного значения этих выражений. «Первая» значит первая строка в текущем `ORDER BY`.

```sql
SELECT DISTINCT ON (customer_id)
    customer_id, id, created_at
FROM orders
ORDER BY customer_id, created_at DESC;
```

Этот запрос оставляет одну строку на `customer_id`: с самым поздним `created_at`. `ORDER BY` должен начинаться с выражений `DISTINCT ON`. Затем добавляете сортировку, которая выбирает победителя (`created_at DESC`).

`DISTINCT ON` — расширение PostgreSQL. Это не стандартный `DISTINCT`. `DISTINCT` без `ON` отбрасывает полные дубликаты строк.

```sql
SELECT DISTINCT customer_id FROM orders;
```

Правила:

- `ORDER BY` должен начинаться с тех же выражений, что `DISTINCT ON` (или выражений, которые им соответствуют).
- Без подходящего `ORDER BY` победитель не определён.
- `DISTINCT ON` выполняется после `WHERE` и до `LIMIT`.

Используйте `DISTINCT ON` для «лучшая строка на группу», когда правило — сортировка. Оконная функция (`ROW_NUMBER()`) может сделать ту же работу и является стандартным SQL (тема 14). `DISTINCT ON` короче.

Не используйте `DISTINCT ON`, чтобы спрятать плохое соединение, которое размножает строки. Исправьте соединение. Не опускайте `ORDER BY`.

#### Средние практические задания

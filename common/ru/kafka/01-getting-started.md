# 1. Начало работы

## Описание

Apache Kafka — распределённый журнал событий. Программы пишут события в топики. Другие программы читают эти события. Kafka хранит события на диске заданное время или до заданного размера.

Эта тема показывает, что такое Kafka, чем Kafka отличается от очереди сообщений и от базы данных, и как запустить локальный кластер. Завершите эту тему до изучения партиций, продюсеров и консьюмеров.

Используйте один термин для каждого понятия. Событие — факт, который произошёл. Запись — единица, которую Kafka хранит. Топик — именованный журнал записей. Для всех новых кластеров используйте KRaft. Не запускайте ZooKeeper для новой работы.

## Что такое Kafka (распределённый журнал событий / платформа потоков)

Kafka — распределённый журнал событий. Журнал — последовательность записей только на добавление. Продюсеры добавляют записи. Консьюмеры читают записи по позиции. Kafka не удаляет запись, когда один консьюмер её прочитал.

Kafka также платформа потоков. Много продюсеров могут писать. Много групп консьюмеров могут читать один топик одновременно. У каждой группы своя позиция в журнале. Kafka копирует партиции на брокеры, чтобы кластер продолжал работу после остановки одного брокера.

Kafka не является сервисом запрос-ответ. Kafka не является местом, где по умолчанию обновляют одну строку по первичному ключу. Вы добавляете новую запись. Читатели воспроизводят журнал или хранят свой вид.

Kafka работает как кластер брокеров. Новые кластеры используют KRaft. KRaft хранит метаданные кластера в кворуме контроллеров Raft. Кворум контроллеров — часть Kafka. В новый кластер ZooKeeper не добавляют.

Типичные применения Kafka:

- передавать события между сервисами
- собирать логи и метрики
- питать потоковые задачи
- хранить устойчивую историю изменений

## Kafka против очереди сообщений (RabbitMQ) против базы данных

Очередь сообщений, например RabbitMQ, доставляет сообщение консьюмеру. После того как консьюмер подтвердил сообщение, брокер может его удалить. Очередь — буфер работы. Многие системы очередей не хранят длинную историю для новых читателей.

Kafka — журнал. Консьюмер не удаляет запись. Записи удаляет время хранения, размер хранения или компакция. Новая группа консьюмеров может читать старые записи, если записи ещё на диске.

База данных хранит текущее состояние. Вы обновляете строку. Вы запрашиваете по ключу. База данных — правильный инструмент, когда нужны транзакции над текущими записями и богатые запросы. Kafka не заменяет базу данных.

Можно использовать оба. Сервис пишет изменение в Kafka. Другой сервис обновляет базу данных из этих событий. Kafka — устойчивый журнал изменений. База данных — запрашиваемое состояние.

Не считайте Kafka очередью задач без плана. В Kafka нет встроенной очереди с задержкой или приоритетной очереди, как у некоторых брокеров. Не считайте Kafka единственным источником истины для интерактивных запросов.

Короткое сравнение:

- Очередь: потребить и удалить (типичный режим по умолчанию).
- Kafka: потребить и хранить (до ретеншна).
- База данных: хранить и обновлять текущее состояние.

## События, продюсеры, консьюмеры, топики

Событие — факт: «пользователь 9 оформил заказ 55». Продюсер — программа, которая пишет событие в Kafka. Консьюмер — программа, которая читает событие. Топик — именованный журнал, который хранит записи.

У записи есть ключ, значение, метка времени и необязательные заголовки. Тема 2 описывает запись полностью. Продюсер сериализует ключ и значение в байты. Kafka хранит эти байты.

У одного топика одна или несколько партиций. Партиция — упорядоченная последовательность. Продюсер выбирает партицию. Консьюмер читает из одной или нескольких партиций. Тема 3 объясняет, зачем существуют партиции.

Много продюсеров могут писать в один топик. Много консьюмеров могут читать один топик. Консьюмеры, которые делят работу, используют группу консьюмеров. Тема 6 объясняет группы.

Называйте топики по типу события или потоку, а не по одному сервису, который пишет сегодня. Пример: `orders.placed` яснее, чем `order-service-out`.

## Установка Kafka (режим KRaft) или Docker / Confluent / MSK / Redpanda

Используйте KRaft для каждой новой установки. KRaft — режим метаданных Kafka. Кворум контроллеров хранит метаданные топиков и брокеров. Не устанавливайте ZooKeeper для нового кластера.

**Apache Kafka на машине.** Скачайте текущий выпуск Apache Kafka с [https://kafka.apache.org/downloads](https://kafka.apache.org/downloads). Распакуйте архив. Сгенерируйте идентификатор кластера. Отформатируйте каталоги хранения этим идентификатором и файлом свойств сервера. Запустите процесс Kafka. Официальная документация вашей версии показывает точные команды и имя файла свойств.

Типичные имена команд (суффикс `.sh` на macOS и Linux, `.bat` на Windows):

```text
kafka-storage random-uuid
kafka-storage format -t <CLUSTER_ID> -c <server.properties>
kafka-server-start <server.properties>
```

После запуска брокера клиенты используют адрес bootstrap. Обычное локальное значение — `localhost:9092`.

**Docker.** Официальный образ контейнера Apache Kafka запускает брокер KRaft. Используйте Docker, когда нужна короткая локальная установка. Зафиксируйте версию образа. Не используйте compose-файлы ZooKeeper из старых блогов.

**Confluent.** Confluent Platform и Confluent Cloud говорят на протоколе Kafka. Облако скрывает брокеры. Вы всё равно используете топики, продюсеров и консьюмеров.

**Amazon MSK.** MSK — Kafka как управляемый сервис на AWS. Новые кластеры MSK могут использовать KRaft. Следуйте текущему руководству AWS для режима кластера.

**Redpanda.** Redpanda говорит на API Kafka. С Redpanda можно использовать многие клиенты Kafka. Операции не те же, что у Apache Kafka. Этот справочник учит Apache Kafka. Используйте Redpanda только когда вы знаете, что хотите этот продукт.

Проверьте установку:

```text
kafka-topics --bootstrap-server localhost:9092 --list
```

Пустой список или список внутренних топиков означает, что клиент достиг кластера.

4. Нарисуйте одну схему, которая включает продюсера, топик, консьюмера, брокера и контроллер KRaft. Под каждым блоком одно предложение.

#### Средние практические задания

1. Напишите маленький скрипт (PowerShell или bash), который ждёт `localhost:9092` и затем перечисляет топики. Останавливайтесь при ошибке.
2. Создайте два топика. Удалите один. Перечислите топики. Запишите каждую команду и состояние кластера после каждой команды.
3. Опишите локальную установку Kafka в десяти шагах так, чтобы другой новичок мог повторить. Включите KRaft. Не включайте ZooKeeper.

#### Сложные практические задания

1. Запустите два клиента против одного локального кластера: консольные инструменты и одну короткую программу на языке, который вы знаете. Пишите из одного. Читайте из другого.
2. Сравните Apache Kafka в Docker с Redpanda в Docker (или управляемым пробным периодом). Напишите короткий отчёт: время старта, совместимость API Kafka и одна операция, которая отличается.

# 7. Агрегация и группировка

## Описание

Эта тема показывает, как считать итоги и как группировать строки. Вы изучаете агрегатные функции, `GROUP BY` и `HAVING`. Вы также изучаете идею наборов группировки на высоком уровне и как `NULL` ведёт себя в агрегатах.

Используйте один термин для каждого понятия. Агрегат сводит много значений к одному. Группа — набор строк, которые делят один ключ группировки. Завершите эту тему до подробного определения схем.

Называйте зерно каждого результата. Итог без `GROUP BY` — одна строка. Итог с `GROUP BY customer_id` — одна строка на клиента.

## Агрегатные функции: `COUNT`, `SUM`, `AVG`, `MIN`, `MAX`

Агрегатная функция берёт набор значений и возвращает одно значение.

**`COUNT(*)`.** Считать строки в наборе. Этот подсчёт включает строки, где другие столбцы — `NULL`.

**`COUNT(column)`.** Считать строки, где этот столбец не `NULL`.

**`COUNT(DISTINCT column)`.** Считать уникальные непустые значения в этом столбце.

**`SUM(column)`.** Сложить числовые значения. Игнорировать `NULL`. Если каждое значение — `NULL`, `SUM` возвращает `NULL`.

**`AVG(column)`.** Считать среднее непустых числовых значений. `AVG` — это `SUM / COUNT(column)`, не `SUM / COUNT(*)`, когда некоторые значения — `NULL`.

**`MIN(column)` и `MAX(column)`.** Вернуть наименьшее или наибольшее непустое значение. Для текста порядок следует правилам сравнения СУБД.

```sql
SELECT
    COUNT(*) AS order_rows,
    COUNT(shipped_at) AS shipped_rows,
    SUM(qty) AS total_qty,
    AVG(qty) AS avg_qty,
    MIN(ordered_at) AS first_order,
    MAX(ordered_at) AS last_order
FROM orders;
```

Без `GROUP BY` запрос возвращает одну строку для всей таблицы (после `WHERE`, если добавите).

Не смешивайте голый столбец и агрегат в списке `SELECT`, если этот столбец не в `GROUP BY`. Это правило — следующий раздел.

`COUNT(*)` никогда не возвращает `NULL`. Он возвращает `0` для пустого набора. `SUM` пустого набора — `NULL` в SQL. Эта разница удивляет новичков.

```sql
SELECT COUNT(*) AS n, SUM(qty) AS s
FROM order_lines
WHERE order_id = -1;
```

Если ни одна строка не совпадает, `n` равен `0`, а `s` равен `NULL`.

Используйте `COALESCE(SUM(qty), 0)`, когда нужно показать `0` для пустого набора.

## `GROUP BY`

`GROUP BY` делит строки на группы. Каждая группа делит одни значения столбцов группировки. Агрегаты выполняются внутри каждой группы.

```sql
SELECT customer_id, COUNT(*) AS order_count
FROM orders
GROUP BY customer_id;
```

Каждый `customer_id` даёт одну строку результата. `COUNT(*)` — число заказов этого клиента.

Можно группировать по более чем одному столбцу:

```sql
SELECT customer_id, status_code, COUNT(*) AS n
FROM orders
GROUP BY customer_id, status_code;
```

Список `SELECT` может содержать:

- столбцы группировки
- агрегаты
- выражения, которые зависят только от столбцов группировки и агрегатов

Не выбирайте `name`, когда группируете только по `customer_id`, если `name` функционально определён и СУБД это позволяет. Стандартный SQL требует `name` в `GROUP BY` или внутри агрегата. Безопасная привычка: каждый неагрегатный столбец в `SELECT` появляется в `GROUP BY`.

```sql
SELECT c.customer_id, c.name, COUNT(*) AS order_count
FROM customers AS c
INNER JOIN orders AS o
    ON o.customer_id = c.customer_id
GROUP BY c.customer_id, c.name;
```

Логическая идея:

1. Применить `FROM` и `WHERE`.
2. Сформировать группы через `GROUP BY`.
3. Вычислить агрегаты по группе.
4. Применить `HAVING` (следующий раздел).
5. Спроецировать список `SELECT`.
6. Применить `ORDER BY`.

`WHERE` фильтрует строки до формирования групп. Не ставьте проверку `COUNT(*)` в `WHERE`. Используйте `HAVING`.

Запрос с агрегатами и без `GROUP BY` — одна группа: вся отфильтрованная таблица.

## `HAVING` и `WHERE`

`WHERE` фильтрует строки до группировки. `HAVING` фильтрует группы после агрегации.

```sql
SELECT customer_id, COUNT(*) AS order_count
FROM orders
WHERE ordered_at >= DATE '2026-01-01'
GROUP BY customer_id
HAVING COUNT(*) >= 3;
```

`WHERE` оставляет заказы 2026 года. `GROUP BY` строит подсчёты на клиента из этих заказов. `HAVING` оставляет клиентов с хотя бы тремя такими заказами.

Нельзя написать `WHERE COUNT(*) >= 3`. `COUNT(*)` не существует на этапе фильтра строк.

Можно написать `HAVING` по ключу группы, но `WHERE` яснее для этого случая.

```sql
SELECT customer_id, COUNT(*) AS order_count
FROM orders
GROUP BY customer_id
HAVING customer_id = 1;
```

Предпочитайте:

```sql
SELECT customer_id, COUNT(*) AS order_count
FROM orders
WHERE customer_id = 1
GROUP BY customer_id;
```

Вторая форма отбрасывает других клиентов до группировки. Эта форма дешевле и легче читается.

`HAVING` может использовать псевдонимы в некоторых продуктах. Стандартный SQL этого не требует. Повторяйте агрегат в `HAVING`:

```sql
HAVING COUNT(*) >= 3
```

Не используйте `HAVING` как замену `WHERE` по базовым столбцам. Используйте `WHERE` для правил строк. Используйте `HAVING` для правил групп.

Левое соединение плюс `GROUP BY` плюс `HAVING COUNT(o.order_id) = 0` может найти клиентов без заказов. `COUNT(o.order_id)` игнорирует `NULL`. `COUNT(*)` был бы `1` для клиента с одной полностью пустой стороной заказа. Предпочитайте `COUNT(o.order_id)` или `NOT EXISTS` для этого вопроса.

## Идея наборов группировки (высокий уровень)

Набор группировки — один список столбцов группировки. Простой `GROUP BY a, b` — один набор группировки: `(a, b)`.

Иногда отчёту нужно больше одного набора группировки в одном результате:

- итоги по стране
- итоги по стране и городу
- один общий итог

Можно выполнить три запроса и сложить их через `UNION ALL`. SQL также предлагает синтаксис наборов группировки:

```sql
SELECT country, city, SUM(amount) AS total
FROM sales
GROUP BY GROUPING SETS (
    (country, city),
    (country),
    ()
);
```

`()` — пустой набор группировки: один общий итог. В этих строках `country` и `city` — `NULL` (или маркер группировки). Здесь `NULL` значит «все значения», не «неизвестный город». Этот смысл — обычный источник путаницы.

Связанный синтаксис (высокий уровень):

- `ROLLUP (country, city)` строит `(country, city)`, `(country)` и `()`.
- `CUBE (country, city)` строит все комбинации этих столбцов, включая `(city)` отдельно.

Не каждая СУБД поддерживает эти предложения. Если продукта нет, пишите отдельные запросы и `UNION ALL`.

```sql
SELECT country, city, SUM(amount) AS total
FROM sales
GROUP BY country, city
UNION ALL
SELECT country, NULL, SUM(amount)
FROM sales
GROUP BY country
UNION ALL
SELECT NULL, NULL, SUM(amount)
FROM sales;
```

Не считайте `NULL` набора группировки отсутствующими данными. Если `city` также может быть настоящим `NULL`, нужен индикатор группировки (`GROUPING(city)` в продуктах, у которых он есть).

Изучите идею. Сначала используйте простой `GROUP BY`. Добавляйте `ROLLUP`, когда отчёту нужны подытоги и продукт это поддерживает.

## NULL в агрегатах

`NULL` значит отсутствие. Агрегатные функции пропускают входы `NULL`, кроме `COUNT(*)`.

Примеры со значениями `{10, NULL, 30}`:

| Функция | Результат |
| --- | --- |
| `COUNT(*)` | `3`, если это три строки |
| `COUNT(value)` | `2` |
| `SUM(value)` | `40` |
| `AVG(value)` | `20` |
| `MIN(value)` | `10` |
| `MAX(value)` | `30` |

`AVG` использует два значения, не три. Отсутствующее значение не считается нулём.

Если храните `0` вместо `NULL` для «нет измерения», `AVG` и `SUM` меняются. Этот выбор — решение модели (тема 2). Не смешивайте `0` и `NULL` для одного смысла.

`GROUP BY` считает `NULL` одной группой. Все строки с `NULL` в столбце группировки идут вместе.

```sql
SELECT coupon_id, COUNT(*) AS n
FROM orders
GROUP BY coupon_id;
```

Заказы без купона (`coupon_id` `NULL`) образуют одну группу. Эта группа допустима.

`COUNT(DISTINCT col)` игнорирует `NULL`. Несколько значений `NULL` не добавляют отдельный элемент.

В `HAVING` условие `SUM(col) > 0` неизвестно, когда `SUM` равен `NULL`. Группа не проходит. Используйте `COALESCE(SUM(col), 0) > 0`, если нужно считать пустые суммы нулём.

Не используйте `NULL` как тайную дополнительную категорию, если не документируете это. Предпочитайте настоящее справочное значение для «нет», когда отчёты должны легко сортировать и фильтровать эту категорию.

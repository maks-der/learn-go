# 19. Пространственные и многоключевые структуры

## Описание

Эти структуры хранят точки, прямоугольники или приближённые множества. Эта тема объясняет квадродеревья, октодеревья, k-d-деревья, R-деревья, фильтры Блума, списки с пропусками и count-min sketches. Завершите эту тему после деревьев, хеш-таблиц и списков.

Используйте один термин для каждого понятия. **Точка** имеет координаты. **Ограничивающий прямоугольник** — прямоугольник (или ящик), который содержит набор объектов. **Ложное срабатывание** — «да», которое может быть неверным. **Ложный отказ** — «нет», которое неверно. Фильтр Блума может иметь ложные срабатывания. Он не должен иметь ложных отказов, если вы только вставляете.

## Квадродерево / октодерево

**Квадродерево** делит двумерный прямоугольник на четыре равных квадранта. У каждого внутреннего узла четыре ребёнка: NW, NE, SW, SE. **Лист** хранит малое число точек (или одну точку). Когда лист слишком полон, вы делите его на четыре ребёнка и двигаете точки вниз.

**Октодерево** — та же идея в 3-d. Каждое деление делает восемь октантов.

```text
square
  NW | NE
  ---+---
  SW | SE

too many points in one leaf → four child squares
```

**Запрос диапазона.** Чтобы найти точки в прямоугольнике запроса, вы пропускаете узел, если его квадрат не пересекает запрос. Вы тестируете точки только в листьях, которые могут пересекаться.

**Ближайший сосед.** Вы ищете квадрант, который должен содержать цель. Затем отсекаете квадраты, которые не могут побить лучшее расстояние пока.

Квадродерево плохо подходит, когда все точки сидят в одном углу. Вы получаете глубокую цепь делений. K-d-дерево или хорошо построенное R-дерево могут лучше обработать некоторые из этих наборов.

Не храните полный двумерный массив ячеек для разреженного набора точек. Квадродерево растёт там, где точки существуют.

Время запроса зависит от разброса точек. Худший случай может быть линейным. Средний случай на равномерном наборе лучше.

Квадродерево также может делить **области** (цветные карты), не только точки. Правило деления то же.

## K-d-дерево

**K-d-дерево** — двоичное дерево точек в k измерениях. Каждый уровень делит по одной оси. Обычное правило циклирует ось: уровень 0 делит по x, уровень 1 по y, затем снова x (для k = 2). Значение деления часто медиана точек в этом узле.

```text
2-d points
root splits on x = median
left:  points with x < median
right: points with x >= median
children split on y
```

**Построение.** Если вы каждый раз выбираете медиану, высота — Θ(log n) при построении. Время построения — Θ(n log n) с линейной медианой или Θ(n log² n) с сортировкой в каждом узле.

**Ближайший сосед.** Рекурсивно идите в сторону, которая содержит запрос. Затем решите, может ли другая сторона держать более близкую точку. Плоскость деления — тест.

**Поиск диапазона.** Пропустите поддерево, если его область не пересекает ящик запроса.

K-d-дерево хранит **точки**. Оно менее естественно для перекрывающихся прямоугольников. Используйте R-дерево для многих ящиков.

Обновления после статического построения могут разбалансировать дерево. Пересоберите или используйте более сложное правило обновления. Для учёбы стройте один раз из фиксированного набора.

K-d-дерево — не квадродерево. K-d-дерево двоичное. Квадродерево — 4-путевое и делит пространство в середине квадрата, не всегда в медиане данных.

Не используйте k-d-дерево как первое отображение из одного целого ключа. Используйте BST или хеш-таблицу.

## R-дерево (ГИС)

**R-дерево** хранит пространственные **объекты** (часто прямоугольники). У каждого узла есть **минимальный ограничивающий прямоугольник (MBR)**, который покрывает всех детей. Лист хранит id объектов и их MBR. Внутренний узел хранит MBR детей.

**Поиск.** Чтобы найти объекты, которые пересекают ящик запроса, вы посещаете ребёнка только если MBR ребёнка пересекает запрос. Многие дети могут пересекаться. Вы можете посетить больше одного пути.

**Вставка.** Вы выбираете ребёнка, который будет держать новый ящик (наименьшее увеличение MBR — обычное правило). Если узел переполняется, вы **делите** записи на два узла и чините MBR вверх по пути.

```text
query box
visit child if MBR ∩ query is not empty
skip child if MBR is disjoint
```

ГИС и картографические базы данных используют R-деревья (и варианты вроде R* и упакованных R-деревьев) для «что в этом виде» и «что пересекает эту дорогу».

R-дерево — не B+-дерево одного числа. Это многомерный родственник идеи B-дерева: высокое ветвление, узлы размера страницы, баланс делением. Ключ — ящик, не одно целое.

Не реализуйте полное деление R* в первую неделю. Рисуйте MBR. Реализуйте крошечное R-дерево в памяти с простым делением или только изучите диаграмму.

Поиск худшего случая может посетить много узлов, если MBR сильно перекрываются. Хорошие вставка и деление уменьшают перекрытие.

Набор точек может использовать R-дерево, если вы считаете точку вырожденным ящиком.

## Фильтр Блума (вероятностное множество)

**Фильтр Блума** — битовый массив из m бит плюс k хеш-функций. Он отвечает **возможно в множестве** или **точно не в множестве**.

**Insert(x).** Для каждого хеша hi(x) поставьте бит hi(x) mod m в 1.

**Contains(x).** Если какой-то бит hi(x) mod m равен 0, x не в множестве. Если все k бит равны 1, x может быть в множестве, или биты были установлены другими ключами (**ложное срабатывание**).

```text
bits: 0 1 0 1 1 0 0 1
insert x sets two positions
query y sees a 0 → y is absent
query z sees all 1s → z maybe present
```

**Нет ложного отказа**, если вы только вставляете и никогда не очищаете биты (кроме вариантов). Если фильтр говорит нет, ключ не был вставлен.

Вы не можете перечислить ключи. Вы не можете удалить ключ в базовом фильтре (считающий фильтр Блума — вариант).

Память мала: несколько бит на ключ для выбранной доли ложных срабатываний. Используйте фильтр Блума, чтобы пропустить медленный поиск (диск, сеть), когда ответ часто нет.

Не используйте фильтр Блума как единственное хранилище записей, которые вы должны получить. Вам всё равно нужно настоящее множество или отображение.

Выберите m и k из ожидаемого n и доли ошибок. Формулы живут в стандартных заметках. Этот справочник требует идею: больше бит и хорошие хеши понижают долю ложных срабатываний.

Хеш-функции должны быть достаточно независимы. На практике вы выводите k хешей из двух хешей.

## Список с пропусками

**Список с пропусками** — многослойный связный список. Слой 0 — отсортированный список всех ключей. Более высокие слои держат меньше ключей и действуют как экспресс-полосы.

**Insert.** Вы вставляете в слой 0. Затем поднимаете ключ на слой 1, 2, ... подбрасыванием монеты (вероятность 1/2 обычна), пока монета не упадёт. Поиск начинается на верхнем слое и спускается, когда следующий ключ слишком велик.

```text
layer 2:  1 ----------- 9
layer 1:  1 ---- 5 ---- 9
layer 0:  1  3   5  7   9
```

Ожидаемые поиск, вставка и удаление — O(log n). Дополнительная память ожидаемо O(n). Худший случай может быть линейным, если каждая монета неудачна. Вероятность очень плохой формы мала.

Список с пропусками — альтернатива сбалансированному BST. Реализация часто короче красно-чёрного. Отсортированные множества Redis используют список с пропусками (плюс хеш-отображение). Этот факт — задача чтения позже.

Прямые указатели в каждом узле образуют массив ссылок next, по одной на слой, в который узел вошёл.

Не считайте список с пропусками хеш-таблицей. Ключи остаются отсортированными. Сканирование диапазона — обход слоя 0 от первого ключа в диапазоне.

Сторожевые головы (и иногда хвосты) упрощают граничные случаи.

Подбрасывания монеты должны быть случайными. Фиксированный шаблон подъёма может создать плохую форму.

## Count-min sketch (ознакомление)

**Count-min sketch** оценивает частоты элементов в потоке. Он использует d строк счётчиков, каждая ширины w. У каждой строки свой хеш. При увеличении ключа x вы добавляете 1 к одному счётчику в каждой строке. Оценка счёта x — **минимум** этих d счётчиков.

```text
rows:
  h1(x) → +1
  h2(x) → +1
  h3(x) → +1
estimate(x) = min of those cells
```

Оценка никогда не слишком мала (для этой простой формы). Она может быть слишком большой, когда другие ключи сталкиваются в те же ячейки. Эта ошибка — **переоценка**.

Этот раздел — **только ознакомление**. Не реализуйте производственный sketch в этой теме.

Используйте count-min sketch, когда n огромно, вы не можете хранить каждый ключ и приближённого счёта достаточно (тяжёлые элементы, грубая популярность).

Count-min sketch — не фильтр Блума. Фильтр Блума хранит биты принадлежности. Count-min sketch хранит счётчики.

Count-min sketch — не куча. Куча может отслеживать точный top-k, если вы храните ключи. Sketch отслеживает приближённые счёты в малой памяти.

```text
you implement now:  Bloom filter, skip list, one spatial tree
you only name:      count-min sketch
```

Выберите w и d из ошибки, которую допускаете. Формулы живут в стандартных заметках.

2. Объясните в шести предложениях, почему коллизии только поднимают min (базовая форма увеличения).

#### Сложные практические задания

1. Напишите сравнение на одну страницу: точное хеш-отображение счётов, куча top-k, count-min sketch. Не реализуйте sketch.
2. После реализации фильтра Блума напишите один абзац о том, когда вы добавили бы sketch вместо большего числа бит.

## Повторение темы

Эти вопросы не повторяют вопросы разделов выше. Они покрывают всю тему.

### Вопросы

#### Теоретические вопросы

1. Опишите, как вы выбираете квадродерево, k-d-дерево или R-дерево по точкам против ящиков и по стилю двумерного деления.
2. Как фильтры Блума и count-min sketches оба используют хеши, но отвечают на разные вопросы?
3. Напарник говорит, что список с пропусками «не настоящая сбалансированная структура». Какие факты вы используете в аккуратном ответе?
4. Что может быть ложным срабатыванием и что не должно быть ложным отказом в базовом фильтре Блума?
5. Почему этот справочник реализует список с пропусками или фильтр Блума до count-min sketch?

#### Простые практические задания

1. Напишите шпаргалку на одну страницу: квадро/окто, k-d, MBR R-дерева, Блум, список с пропусками, ознакомление count-min.
2. Нарисуйте одно деление квадро, одно деление k-d и одну башню списка с пропусками.
3. Составьте таблицу: «Нужда», «Структура». Шесть строк.
4. Напишите MBR, ложное срабатывание и слой 0 в одном предложении каждое.

#### Средние практические задания

1. Реализуйте одно пространственное дерево (квадро или k-d) и один список с пропусками. Напишите один тест для каждого.
2. Реализуйте фильтр Блума перед хеш-множеством. Посчитайте, как часто вы пропускаете множество на отрицательных запросах.
3. Классифицируйте шесть реальных функций (вид карты, точки автодополнения, фильтр кэша, отсортированная таблица лидеров, счёты пакетов, 3-d воксели) к структуре.

#### Сложные практические задания

1. Постройте крошечный «вид карты»: храните прямоугольники в простом R-дереве или сетке, запросите окно просмотра, проверьте просмотром.
2. Прочитайте следующую тему (продвинутые графы). Напишите пять предложений, почему список с пропусками не заменяет структуру кратчайшего пути графа.

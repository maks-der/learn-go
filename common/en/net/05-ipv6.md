# 5. IPv6

## Description

IPv6 is the internet protocol with 128-bit addresses. This topic shows why IPv6 exists, how you write an address, link-local addresses, SLAAC, DHCPv6, and dual stack. You also learn that a modern operating system uses IPv6 on a home LAN even when you did not plan it.

Use one term for each concept. An IPv6 address is a 128-bit identifier. A link-local address is valid on one link. Dual stack means IPv4 and IPv6 run together. Complete this topic before you study routing in depth.

You do not need every IPv6 extension header. You need to read an address, name `fe80::`, and know why `ping` can use IPv6.

---

## Why IPv6 exists

IPv4 has about 4.3 billion addresses. NAT and private ranges delayed the end of free public IPv4. They did not create more public addresses. Many networks still need unique addresses for hosts, mobiles, and servers.

IPv6 gives a much larger address space. 128 bits can number a huge number of interfaces. Operators can give a home a `/56` or a `/64` and still have room.

IPv6 also aims for a simpler header and for neighbor discovery instead of ARP. The real reason most people meet IPv6 is scarcity of public IPv4 and the default configuration of modern operating systems.

IPv6 is not "IPv4 with longer dotted decimal." The address form is hex. Broadcast is gone. ICMP is required. Some middleboxes treat IPv6 poorly. You still need IPv4 on many paths. That is dual stack.

Do not wait for "the day IPv4 dies" to learn IPv6. Your LAN already has IPv6 link-local addresses. Many providers already offer IPv6 to the home.

Do not treat NAT as a security design that removes the need for IPv6. NAT is an address workaround. Firewalls still matter on IPv6.

## Address form and compression

An IPv6 address is eight groups of 16 bits. Each group is up to four hex digits. Groups use colons. Example: `2001:0db8:0000:0000:0000:0000:0000:0001`.

Compression rules:

- you may omit leading zeros in a group: `2001:db8:0:0:0:0:0:1`
- you may replace one run of groups that are all zero with `::`
- you may use `::` only one time in an address

The compressed form of the example is `2001:db8::1`. `https://example.com` documentation uses `2001:db8::/32` as a documentation prefix. Do not use documentation addresses as real global addresses.

A prefix length uses CIDR. A LAN often uses `/64`. A single address is `/128`. A typical point-to-point link can use `/127` or `/64` by policy.

The interface identifier is often the last 64 bits on a `/64`. SLAAC can build that part. Privacy addresses can change the interface identifier.

Do not mix IPv4 dots into IPv6 except in the special IPv4-mapped form (`::ffff:192.0.2.1`) that some APIs use. Do not write two `::` markers.

Text in URLs puts IPv6 in brackets: `http://[2001:db8::1]:80/`.

## Link-local `fe80::`

A link-local IPv6 address starts with `fe80::/10`. In practice you see `fe80:` and then zeros, then an interface identifier. The address is valid only on one link. Routers do not forward link-local packets to another link.

Every IPv6-capable interface has a link-local address when IPv6 is on. Neighbor discovery uses link-local addresses. Many routing protocols use them as next hops.

The same link-local prefix appears on every link. You must add a zone or interface when you ping: `ping fe80::1%eth0` or `ping fe80::1%12` on Windows. The `%` part is the zone index. It is not part of the 128-bit address on the wire.

Link-local is not a private global prefix. Unique local addresses (`fc00::/7`, commonly `fd00::/8`) are a different idea. Global addresses start with other prefixes (often `2000::/3` for current global unicast).

Do not filter out all `fe80` traffic on a LAN if you want IPv6 to work. Do not use a link-local address as a public server address.

## SLAAC vs DHCPv6 (high-level)

SLAAC is Stateless Address Autoconfiguration. A router sends a router advertisement (RA). The RA contains a prefix. The host builds an address from the prefix and an interface identifier. The host uses neighbor discovery to check that the address is unique (DAD).

DHCPv6 is a stateful or stateless server protocol. A DHCPv6 server can assign addresses, or it can give only options such as DNS (stateless DHCPv6) while SLAAC still builds the address.

The RA can tell the host to use SLAAC, to use DHCPv6, or to use both. Flags in the RA (M and O) guide the host. Exact flag meaning is for later study. This topic needs the idea: the router advertisement is the IPv6 control plane on the LAN.

IPv4 typically uses DHCP for the address. IPv6 often uses SLAAC for the address and DHCP or RA options for DNS. Homes differ by vendor.

Do not expect a DHCPv4 server to configure IPv6. Do not disable RAs on a LAN and then wonder why hosts have no global IPv6 address.

A host can have several IPv6 addresses at the same time: link-local, SLAAC, privacy temporary, and DHCPv6.

## Dual stack

Dual stack means a host and a network run IPv4 and IPv6 at the same time. A program that uses names often gets an A record and an AAAA record. The OS or the library chooses an address family. Happy Eyeballs is a common strategy: try IPv6 and IPv4 in a way that avoids a long wait.

A service can listen on IPv4 only, IPv6 only, or both. `0.0.0.0` is IPv4. `::` is IPv6 (and on some systems it can accept IPv4-mapped connections). Test both families.

A path can be dual stack at the host and IPv4-only on the Internet path, or the reverse. Then one family fails and the other works. Users see "the site works on the phone but not on the PC" when one stack is broken.

Do not disable IPv6 on a modern OS as a first fix. Find the broken path. Disabling IPv6 can hide a fault and can break local services.

Do not assume that a successful IPv4 `ping` proves IPv6. Test `ping -6` or `ping` to an IPv6 address.

## You will see IPv6 on modern OSes even on a home LAN

Windows, macOS, iOS, Android, and Linux enable IPv6 by default. A home LAN with no ISP IPv6 still has `fe80` addresses. Many boxes also send RAs for a ULA or for ISP prefixes.

`ipconfig` and `ip addr` show IPv6. `ping` to a name can use IPv6 first. Windows can show "IPv6 connectivity" in the status page. mDNS and some Windows services use IPv6 on the LAN.

If you ignore IPv6, your capture still contains IPv6 neighbor packets. Your firewall still needs IPv6 rules. Your "IPv4-only" server can be reachable on IPv6 if the OS listens on `::`.

Home Wi-Fi guest networks and IoT VLANs still need an IPv6 plan: allow, block, or isolate. Silence is not a plan.

Do not delete IPv6 addresses by hand every day. Learn to read them. The next topics use the same routing ideas for both families.

Pair this fact with packet capture: filter `ipv6` or `icmpv6` and look. You will see traffic that this topic named.

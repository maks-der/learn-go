# 2. Основы языка

## Описание

Исходный файл Go имеет фиксированный порядок. Файл начинается с предложения `package`. Затем идут объявления импорта. Остальные объявления идут после импортов.

Эта тема объясняет этот каркас файла. Вы изучаете пакеты, пути импорта и `func main`. Вы также изучаете комментарии, имена, правила экспорта и точки с запятой.

Компилятор проверяет эти правила первым. Программа не запускается, когда структура файла неверна. Завершите эту тему до изучения типов.

Используйте один термин для каждого понятия. `package` (пакет) — каталог файлов Go с одним и тем же именем пакета. Команда — это `package main`, который содержит `func main`. Путь импорта — строка в объявлении `import`.

## Пакеты и `package main`

`package` — единица, которую собирает компилятор. Все файлы `.go` в одном каталоге образуют один пакет. Эти файлы должны использовать одно и то же имя пакета. Файл начинается с предложения `package`:

```go
package greet
```

Имя пакета — идентификатор. Имя пакета часто совпадает с именем папки. Имя пакета не является путём импорта. Другие файлы импортируют пакет по пути импорта. Код внутри пакета использует имя пакета как префикс только снаружи.

`package main` — особый случай. `package main` определяет команду. Команда собирается в двоичный файл. Библиотечный пакет использует другое имя, например `greet` или `http`. Библиотечный пакет сам по себе не собирается в двоичный файл.

Точка входа программы находится в `package main`. Модуль может содержать много пакетов. Только `package main` с `func main` запускает процесс. Помещайте команды в папку вида `cmd/app`, когда модуль содержит больше одной команды.

Два файла в одном каталоге не должны использовать разные имена пакетов. Компилятор сообщает об ошибке. Тестовые файлы могут использовать `package name` или `package name_test`. Форма `name_test` — внешний тестовый пакет. Внешние тесты импортируют пакет как клиент.

```go
package main

import "fmt"

func main() {
	fmt.Println("command")
}
```

## `import` и пути импорта

Объявление импорта называет пакет, который использует этот файл. Путь импорта — строка. Для стандартной библиотеки путь импорта — путь после `src`, например `"fmt"` или `"net/http"`. Для модуля путь импорта — путь модуля плюс папка пакета.

```go
package main

import (
	"fmt"
	"os"

	"example.com/hello/msg"
)
```

Группируйте импорты в одном блоке `import`. `gofmt` помещает пути стандартной библиотеки в первую группу. `gofmt` помещает остальные пути в следующую группу. Пустая строка разделяет группы.

Компилятор отклоняет неиспользуемый импорт. Удалите импорт или используйте имя из этого пакета. `goimports` может добавлять и удалять импорты за вас.

Импорт связывает имя пакета в этом файле. Имя по умолчанию — предложение `package` импортированного пакета. Измените имя через псевдоним, когда два пакета имеют одно имя:

```go
import (
	fmt1 "fmt"
	myhttp "net/http"
)
```

Пустой импорт использует `_` как имя. Файл не использует имена из этого пакета. Компилятор всё равно выполняет функции `init` импортированного пакета. Используйте пустой импорт только для требуемого побочного эффекта.

Точечный импорт использует `.` как имя. Имена из этого пакета входят в блок файла без префикса. Не используйте точечный импорт в обычном коде. Префикс показывает источник каждого имени.

Цикл импорта — ошибка. Пакет A не должен импортировать B, если B импортирует A, напрямую или через другие пакеты.

## `func main()` как точка входа программы

Точка входа программы — `func main` в `package main`. Сигнатура не имеет параметров и не имеет результатов:

```go
func main() {
}
```

Среда выполнения запускает процесс. Среда выполнения инициализирует пакет `main`. Среда выполнения сначала выполняет функции `init`. Затем среда выполнения вызывает `func main`. Когда `main` возвращает управление, процесс завершается со статусом `0`.

Не давайте `main` параметры. Не давайте `main` результаты. Читайте аргументы командной строки из `os.Args`. Вызывайте `os.Exit`, когда нужен ненулевой статус. `os.Exit` останавливает процесс сразу. Отложенные вызовы не выполняются после `os.Exit`.

`package main` должен содержать ровно один `func main`. Две функции `main` в одном пакете — ошибка. Библиотечный пакет не должен определять точку входа программы. Вы можете назвать функцию `main` в библиотечном пакете. Эта функция не является точкой входа процесса.

`func main` может вызывать другие функции в том же пакете или в импортированных пакетах. Держите `main` небольшим. Помещайте логику в другие функции и пакеты.

```go
package main

import (
	"fmt"
	"os"
)

func main() {
	if len(os.Args) < 2 {
		fmt.Println("usage: app name")
		os.Exit(1)
	}
	fmt.Println(os.Args[1])
}
```

## Комментарии (`//`, `/* */`)

Комментарий — текст, который компилятор игнорирует. В Go есть две формы комментариев. Строчный комментарий начинается с `//` и заканчивается в конце строки. Блочный комментарий начинается с `/*` и заканчивается `*/`.

```go
// Package greet formats short messages.
package greet

// Hello returns a greeting for name.
func Hello(name string) string {
	/* This block comment
	   spans two lines. */
	return "hi " + name
}
```

Используйте `//` почти для всех комментариев. Используйте `/* */` для длинного комментария или чтобы отключить блок кода для короткой проверки. Блочные комментарии не вкладываются. `/*` внутри блочного комментария не начинает новый комментарий.

Комментарий пакета стоит над предложением `package` без пустой строки. Комментарии пакета документируют пакет на pkg.go.dev. Комментарий функции стоит над функцией. Начинайте комментарий функции с имени функции. То же правило применяется к типам, переменным и константам.

Компилятор также читает некоторые комментарии как директивы. Пример: `//go:build` выбирает файлы во время сборки. Помещайте директиву в начало файла. Следуйте официальному формату. Обычный комментарий не должен случайно выглядеть как директива.

Не пишите комментарии, которые только повторяют код. Пишите комментарии, которые указывают намерение или ограничение. Держите комментарии на том же языке, что и проект.

## Идентификаторы, ключевые слова и соглашения об именах

Идентификатор называет пакет, функцию, тип, переменную, константу или метку. Идентификатор начинается с буквы или `_`. Следующие символы — буквы, цифры или `_`. Буква включает `_` и буквы Unicode.

Эти имена допустимы: `total`, `Total`, `HTTPClient`, `_tmp`, `x2`. Эти имена недопустимы: `2x`, `user-name`, `package`.

Ключевое слово — зарезервированное слово. Запрещено использовать ключевое слово как идентификатор. Ключевые слова включают `package`, `import`, `func`, `var`, `const`, `type`, `if`, `else`, `for`, `range`, `switch`, `case`, `break`, `continue`, `goto`, `defer`, `return`, `go`, `select`, `chan`, `map`, `struct`, `interface`, `fallthrough` и `default`.

Пустой идентификатор `_` отбрасывает значение. Используйте `_`, когда функция возвращает значение, которое вам не нужно.

Называйте пакеты короткими словами в нижнем регистре. Не используйте смешанный регистр в имени пакета. Не используйте `_` в имени пакета, если нет веской причины.

Называйте остальные идентификаторы в стиле MixedCaps. Начинайте экспортируемое имя с заглавной буквы. Начинайте неэкспортируемое имя со строчной буквы. Держите аббревиатуры полностью в верхнем регистре в экспортируемых именах, например `HTTP` и `URL`.

Используйте короткие имена в узкой области видимости. `i` подходит для короткого цикла. Используйте более длинное имя в широкой области видимости. Не повторяйте имя пакета в каждом имени функции.

```go
package counter

func Add(total int, n int) int {
	return total + n
}
```

## Экспортируемые и неэкспортируемые имена (заглавная буква)

Экспорт — правило видимости. Имя экспортируется, когда первая буква — заглавная буква Unicode. Другие пакеты могут использовать экспортируемое имя. Имя не экспортируется, когда первая буква — строчная буква или `_`. Другие пакеты не могут использовать неэкспортируемое имя.

Правило применяется к функциям, типам, переменным, константам, полям и методам. Правило не использует ключевое слово вроде `public`. Регистр первой буквы — единственный переключатель.

```go
package msg

var Default = "hi" // exported
var suffix = "!"   // unexported

func Hello(name string) string { // exported
	return wrap(name)
}

func wrap(name string) string { // unexported
	return Default + " " + name + suffix
}
```

Код в том же пакете может использовать экспортируемые имена и неэкспортируемые имена. Код в другом пакете может использовать только экспортируемые имена. Внешний тестовый пакет `name_test` — другой пакет. Внешние тесты видят только экспортируемые имена.

Экспортируйте имена, которые образуют API пакета. Держите вспомогательные имена неэкспортируемыми. Не экспортируйте имя только потому, что тест в другом пакете хочет его. Поместите такой тест в тот же пакет или экспортируйте небольшой вспомогательный элемент для теста.

`go doc` перечисляет экспортируемые имена. Неэкспортируемые имена остаются скрытыми в публичном документе.

## Точки с запятой и как компилятор их вставляет

Грамматика Go использует точки с запятой между операторами. Вы почти никогда не вводите точку с запятой. Лексер вставляет точку с запятой, когда строка заканчивается после лексемы, которая может завершить оператор.

Лексер вставляет точку с запятой после перевода строки, когда последняя лексема — идентификатор, число, строка, `break`, `continue`, `fallthrough`, `return`, `++`, `--`, `)`, `]` или `}`.

Это правило объясняет, почему открывающая `{` у `func`, `if` и `for` остаётся на той же строке:

```go
func main() {
	x := 1
	if x > 0 {
		return
	}
}
```

Если перенести `{` на следующую строку после `if x > 0`, лексер вставляет точку с запятой после `0`. Затем компилятор читает `if x > 0;` и блок. Эта форма недопустима для `if`.

Возвращаемое значение должно оставаться на той же строке, что и `return`, или нужно использовать скобки:

```go
return x

return (
	x
)
```

Не пишите `return`, а затем `x` на следующей строке. Лексер вставляет точку с запятой после `return`. Функция возвращает управление без значения.

`gofmt` удаляет видимые точки с запятой, которые не нужны. Можно написать `a := 1; b := 2` на одной строке. Предпочитайте один оператор на строку.

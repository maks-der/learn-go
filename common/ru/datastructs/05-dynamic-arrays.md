# 5. Динамические массивы (векторы / срезы / ArrayList)

## Описание

Динамический массив — массив, который может расти. Эта тема объясняет рост, амортизированный append, стоимость геометрического изменения размера, необязательное сжатие, обход и случайный доступ. Завершите эту тему до сравнения списков и массивов в реальном коде.

Используйте один термин для каждого понятия. **Динамический массив** — буфер плюс длина. У буфера есть **ёмкость**. **Append** добавляет один элемент в конец. **Resize** выделяет новый буфер и копирует живые элементы. Языки используют разные имена: **срез** Go, **list** Python, **ArrayList** Java, **vector** C++.

---

## Стратегия роста (обычно ×2)

Динамический массив начинается с ёмкости 0 или малого числа. Когда вы делаете append и длина равна ёмкости, структура полна. Программа выделяет больший буфер.

Обычная **стратегия роста** — умножить ёмкость на 2. Некоторые библиотеки используют 1.5. Точный множитель может меняться. Идея — **геометрический рост**: каждая новая ёмкость — постоянный множитель, умноженный на старую ёмкость.

```text
append when full
  new_capacity = max(1, old_capacity * 2)
  allocate new buffer
  copy length elements
  append the new element
```

```go
// Go: append may grow the slice
s = append(s, x)
```

```python
# Python: list.append grows the inner array
a.append(x)
```

Рост на +1 — другая стратегия. Каждый append, когда полон, копирует все n элементов. Суммарная стоимость копирования для n append — около 1 + 2 + ... + n. Эта сумма — Θ(n²). Не используйте рост +1 для общего динамического массива.

Геометрический рост держит суммарную стоимость копирования линейной по n. Следующий раздел формулирует амортизированную стоимость одного append.

Библиотека может выбрать первую ёмкость 1, 4 или 8. Малая первая ёмкость экономит память для пустых списков. Большая первая ёмкость может уменьшить первые несколько изменений размера.

## Амортизированный append

Большинство операций append пишут одну ячейку и добавляют 1 к длине. Эти append — Θ(1).

Когда буфер полон, append меняет размер. Изменение размера копирует length элементов. Этот append — Θ(n).

**Амортизированный append** — средняя стоимость одного append в последовательности из n append от пустого. При удвоении копирования происходят при размерах 1, 2, 4, ..., n. Сумма этих копий меньше 2n. Амортизированная стоимость одного append — Θ(1).

```text
n appends from empty, doubling
  cheap writes:  n
  copies:        1 + 2 + 4 + ... + n/2  <  n
  total work:    Θ(n)
  per append:    Θ(1) amortized
```

Амортизированное константное время — не константное время худшего случая. Один append всё ещё может быть Θ(n). Система реального времени, которая не может остановиться на копирование, нуждается в другой структуре или заранее выделенном буфере.

Если вы знаете n до начала, вы **резервируете** ёмкость. Резерв выделяет один буфер размера n. Тогда каждый append — Θ(1) в худшем случае, пока вы не превысите n. Go использует `make([]T, 0, n)`. Python использует менее прямые приёмы. В некоторых языках есть `reserve`.

Пишите «амортизированная Θ(1)» для append, когда используете геометрический рост и не резервируете.

## Стоимость геометрического изменения размера

**Стоимость геометрического изменения размера** — суммарная работа всех изменений размера, когда вы растёте от пустого до n.

Для множителя 2 последнее копирование двигает около n элементов. Копирование перед ним двигает около n/2. Сумма меньше 2n. Суммарная стоимость изменения размера — Θ(n). Эта сумма — почему амортизированный append есть Θ(1).

Для множителя 1.5 сумма всё ещё Θ(n). Константа больше, чем константа для множителя 2. Вы копируете большую долю истории.

Для множителя 1 (рост на +1) сумма — Θ(n²).

```text
factor 2, grow to n = 16
  copy sizes: 1, 2, 4, 8
  sum:        15
```

Память после роста может тратить ёмкость. Если длина n, а ёмкость 2n, вы можете тратить n ячеек. Эта трата — цена геометрического роста. Множитель 1.5 тратит меньшую долю после роста. Множитель 2 тратит большую долю и копирует реже.

Когда вы копируете, вы выделяете новый блок. Старый блок становится свободным. Сборщик мусора или аллокатор забирает старый блок. Короткое время вы держите два блока. Пиковая память во время роста — около длины плюс новая ёмкость.

## Сжатие (необязательно)

**Shrink** уменьшает ёмкость, когда длина становится намного меньше ёмкости. Shrink выделяет меньший буфер и копирует length элементов. Shrink необязателен. Многие библиотеки не сжимают при каждом удалении.

Если вы никогда не сжимаете, список, который вырос до большого пика, держит большой буфер. Память остаётся высокой после того, как вы удалите большинство элементов.

Если вы сжимаете слишком рано, шаблон удаления и append вызывает много копий. Этот шаблон — **трэшинг**.

Обычное правило — сжимать, когда длина меньше capacity / 4. Новая ёмкость может быть capacity / 2. Это правило оставляет запасные ячейки. Поздний append не растёт сразу.

```text
optional shrink rule
  if length * 4 <= capacity and capacity > min_capacity:
      new_capacity = max(min_capacity, capacity / 2)
      copy length elements
```

Срезы Go не сжимаются, когда вы делаете reslice до короткой длины. Ёмкость может остаться большой. Вы копируете в новый срез, когда хотите плотный буфер: `append([]T(nil), s...)`.

Списки Python могут сжиматься на некоторых путях изменения размера. Не полагайтесь на shrink без теста.

Этот справочник считает shrink политикой. Вы документируете политику. Вы тестируете политику циклами роста и сжатия.

## Обход и случайный доступ

Динамический массив сохраняет операции массива.

**Случайный доступ** — `get(i)` и `set(i, x)` для 0 ≤ i < length. Стоимость — Θ(1). Формула адреса та же, что у фиксированного массива.

**Обход** посещает индекс 0, затем 1, затем 2, до length − 1. Обход — Θ(n). Локальность хорошая, потому что живые элементы непрерывны.

```go
for i := 0; i < len(s); i++ {
	use(s[i])
}
for _, v := range s {
	use(v)
}
```

```python
for i in range(len(a)):
    use(a[i])
for v in a:
    use(v)
```

Не обходите за длину. Не используйте ёмкость как границу цикла. Неиспользуемые ячейки — не живые элементы.

Вставка и удаление в середине остаются Θ(n). Append остаётся амортизированной Θ(1) при геометрическом росте. Эти стоимости — почему динамический массив — список по умолчанию во многих языках.

Когда вы обходите и делаете append в тот же массив, индексы могут меняться. В некоторых языках итератор падает. В других граница цикла устаревает. Предпочитайте простой цикл по индексу с ясным правилом: не делайте append в цикле range, если не знаете правило языка.

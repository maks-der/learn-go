# 7. Драйверы

## Описание

Эта тема показывает, как приложения говорят с MongoDB. Вы используете официальный драйвер. Настраиваете строку соединения. Управляете `MongoClient` на время жизни процесса. Задаёте таймауты. Изучаете компромиссы библиотек сопоставления объектов. Никогда не запускаете неограниченный `find` в API.

Сначала завершите CRUD и запросы. Завершите эту тему до изучения транзакций в коде приложения.

Используйте один термин для каждого понятия. **Драйвер** — официальная клиентская библиотека для языка. **Строка соединения** (URI) — строка конфигурации. **`MongoClient`** — долгоживущий объект клиента. **ODM** или маппер сопоставляет документы типам языка. Не открывайте новый клиент на каждый запрос.

## Официальные драйверы

MongoDB публикует официальные драйверы. Частые драйверы:

- Node.js (`mongodb`)
- Python (`pymongo`)
- Go (`go.mongodb.org/mongo-driver`)
- Java (`mongodb-driver-sync` и реактивный драйвер)

Есть и другие официальные драйверы (C#, Rust, C). Используйте драйвер своего языка со страницы [https://www.mongodb.com/docs/drivers/](https://www.mongodb.com/docs/drivers/).

Официальный драйвер:

- Кодирует и декодирует BSON
- Управляет пулом соединений
- Реализует auth, TLS и повторяемые записи
- Соответствует командам сервера

Обёртка сообщества может сидеть поверх официального драйвера. Официальный драйвер всё равно должен быть в стеке.

Не используйте заброшенный сторонний клиент, который говорит на частном протоколе.

У версий драйвера есть матрица совместимости с версиями сервера. Читайте матрицу перед обновлением.

Имена API различаются. Идеи те же: клиент, база, коллекция, фильтр, обновление, курсор.

CRUD в драйвере использует те же операторы, что `mongosh`. Передаёте объекты языка или документы BSON, не строку SQL.

Устанавливайте драйвер инструментом пакетов языка (`npm`, `pip`, `go get`, Maven). Зафиксируйте основную версию.

## Строка соединения, жизненный цикл `MongoClient` и таймауты

Строка соединения — URI.

Одиночный сервер:

```text
mongodb://localhost:27017
```

С аутентификацией и именем базы для auth:

```text
mongodb://user:pass@localhost:27017/?authSource=admin
```

Atlas часто использует SRV:

```text
mongodb+srv://user:pass@cluster0.example.mongodb.net/
```

`mongodb+srv` использует DNS, чтобы найти хосты. В обычном случае Atlas это также подразумевает TLS.

Опции URI — параметры запроса. Примеры:

- `retryWrites=true`
- `w=majority`
- `appName=myapp`
- `maxPoolSize=20`

Драйвер также принимает опции в коде. Не задавайте одну опцию в двух местах с разными значениями.

Не кладите пароль в систему контроля версий. Используйте переменную окружения или хранилище секретов.

Экранируйте спецсимволы в имени пользователя и пароле.

`appName` появляется в логах сервера. Задайте его. Это помогает эксплуатации.

Создайте **один** `MongoClient` (или эквивалентное имя), когда процесс стартует. Переиспользуйте его для всех запросов. Закройте его, когда процесс останавливается.

Клиент владеет **пулом** соединений. Новый клиент на каждый запрос создаёт много соединений. Сервер отклонит или замедлится. Приложение будет течь сокетами.

Типичная последовательность:

1. Прочитать URI из окружения.
2. Создать клиент.
3. Один раз пингануть при старте (быстро упасть, если URI неверен).
4. Хранить клиент в состоянии приложения.
5. Использовать `client.Database("app").Collection("orders")` на операцию (эти объекты дёшевы).
6. При остановке вызвать `Disconnect` или `Close`, как документирует драйвер.

Не закрывайте клиент после каждого запроса.

Объекты базы и коллекции не открывают каждый свой пул. Они используют клиент.

В тестах можно создать клиент на набор тестов, не на каждый метод, если не нужна изоляция.

Бессерверные функции сложнее. Глобальный клиент можно переиспользовать между тёплыми вызовами. Новый клиент на каждый холодный старт — нормально. Не создавайте клиент на каждый отдельный запрос внутри тёплого экземпляра.

Таймаут останавливает слишком долгое ожидание. Без таймаутов запрос может зависнуть.

Частые таймауты (имена зависят от драйвера):

- **Таймаут выбора сервера** — сколько драйвер ждёт подходящий сервер
- **Таймаут соединения** — сколько может занять новое TCP/TLS-соединение
- **Таймаут сокета** или **сетевой таймаут** — сколько может занять чтение или запись на сокете
- **Таймаут операции** — дедлайн на команду (`timeoutMS` или `context` с дедлайном)

Go и некоторые современные драйверы используют **дедлайн контекста** для каждой операции. Задайте дедлайн в обработчике API. Передайте контекст в драйвер.

Не используйте 30-минутный таймаут сокета как единственный лимит пользовательского запроса. Пользователь уже ушёл. Соединение пула остаётся занятым.

Не используйте таймаут 1 миллисекунда на запросе, который должен читать диск. Будете видеть случайные ошибки.

Повтор: драйвер может повторять некоторые чтения и записи. Короткий таймаут плюс много повторов всё равно может перегрузить сервер. Задайте один общий дедлайн.

Логируйте ошибки таймаута как таймауты. Не логируйте их как «не найдено».

## Сопоставители объектов (Mongoose и другие)

**ODM** (object-document mapper) сопоставляет объекты языка документам. **Mongoose** — частый ODM для Node. У других языков есть ODM и инструменты кодогенерации.

Плюсы:

- Схема в приложении
- Приведения и значения по умолчанию
- Хуки (до сохранения)
- Стиль, похожий на класс модели

Минусы:

- Лишний слой поверх драйвера
- Магия (неявные приведения, неявные коллекции)
- Отставание версии от возможностей официального драйвера
- Скрытый N+1 или неограниченные запросы, если использовать удобные помощники
- Вторая схема помимо `$jsonSchema`

Используйте ODM, когда команда хочет модели и ODM активен. Используйте официальный драйвер, когда хотите ясный BSON и контроль.

Можно использовать тонкий маппер (структуры и теги в Go, датаклассы в Python) без полного ODM.

Не смешивайте два ODM в одном сервисе. Не игнорируйте документацию официального драйвера, когда ODM его оборачивает.

Схемы Mongoose — валидация в приложении. Они не замена уникальным индексам или валидаторам сервера.

Тестируйте BSON, который пишет ODM. Некоторые библиотеки хранят даты или числа в типах, которых вы не ждали.

## Неограниченный `find()` в API недопустим

API не должен возвращать неограниченную коллекцию.

Плохо:

```javascript
const all = await col.find({}).toArray()
return all
```

Этот шаблон:

- Растёт вместе с таблицей
- Использует ОЗУ на приложении и клиенте
- Может истечь по таймауту
- Может превысить лимиты размера ответа

Хорошо:

- Требовать избирательный фильтр, или
- Требовать `limit` с максимумом (например 100), и
- Использовать сортировку и токен страницы или курсор, и
- Проецировать только поля, которые нужны клиенту

`find({})` в инструменте администратора допустим с принудительным лимитом.

Агрегация без `$limit` на пользовательском пути — та же проблема.

Помощники ODM вроде `Model.find()` без лимита — тот же баг.

Напишите общий помощник: `findPage(filter, { limit, cursor })`. Отклоняйте `limit > 100`.

Тестируйте с большим числом документов, чем лимит. Тест падает, если API возвращает все строки.

Логи: записывайте `limit` и `returned`. Алерт, если `returned == max` часто; клиенту может понадобиться лучший фильтр.

# 6. Агрегация

## Описание

Эта тема показывает, как считать итоги и как группировать строки. Вы изучаете агрегатные функции, `GROUP BY` и `HAVING`. Вы также изучаете, как `NULL` ведёт себя в агрегатах.

Используйте один термин для каждого понятия. Агрегат сводит много значений к одному. Группа — набор строк, которые делят один ключ группировки. Завершите эту тему до подробного определения схем.

Называйте зерно каждого результата. Итог без `GROUP BY` — одна строка. Итог с `GROUP BY customer_id` — одна строка на клиента.

---

## `COUNT`, `SUM`, `AVG`, `MIN`, `MAX`

Агрегатная функция берёт набор значений и возвращает одно значение.

**`COUNT(*)`.** Считать строки в наборе. Этот подсчёт включает строки, где другие столбцы — `NULL`.

**`COUNT(column)`.** Считать строки, где этот столбец не `NULL`.

**`COUNT(DISTINCT column)`.** Считать уникальные ненулевые значения в этом столбце.

**`SUM(column)`.** Сложить числовые значения. Игнорировать `NULL`. Если каждое значение — `NULL`, `SUM` возвращает `NULL`.

**`AVG(column)`.** Считать среднее ненулевых числовых значений. `AVG` — это `SUM / COUNT(column)`, не `SUM / COUNT(*)`, когда некоторые значения — `NULL`.

**`MIN(column)` и `MAX(column)`.** Вернуть наименьшее или наибольшее ненулевое значение. Для текста порядок следует правилам сортировки СУБД.

```sql
SELECT
    COUNT(*) AS order_rows,
    COUNT(shipped_at) AS shipped_rows,
    SUM(qty) AS total_qty,
    AVG(qty) AS avg_qty,
    MIN(ordered_at) AS first_order,
    MAX(ordered_at) AS last_order
FROM orders;
```

Без `GROUP BY` запрос возвращает одну строку для всей таблицы (после `WHERE`, если добавите).

Не смешивайте голый столбец и агрегат в списке `SELECT`, если этот столбец не в `GROUP BY`. Это правило — следующий раздел.

`COUNT(*)` никогда не возвращает `NULL`. Он возвращает `0` для пустого набора. `SUM` пустого набора в SQL — `NULL`. Эта разница удивляет новичков.

```sql
SELECT COUNT(*) AS n, SUM(qty) AS s
FROM order_lines
WHERE order_id = -1;
```

Если ни одна строка не совпадает, `n` равен `0`, а `s` равен `NULL`.

Используйте `COALESCE(SUM(qty), 0)`, когда нужно показать `0` для пустого набора.

## `GROUP BY`

`GROUP BY` делит строки на группы. Каждая группа делит одни значения столбцов группировки. Агрегаты выполняются внутри каждой группы.

```sql
SELECT customer_id, COUNT(*) AS order_count
FROM orders
GROUP BY customer_id;
```

Каждый `customer_id` даёт одну строку результата. `COUNT(*)` — число заказов этого клиента.

Можно группировать по больше чем одному столбцу:

```sql
SELECT customer_id, status_code, COUNT(*) AS n
FROM orders
GROUP BY customer_id, status_code;
```

Список `SELECT` может содержать:

- столбцы группировки
- агрегаты
- выражения, которые зависят только от столбцов группировки и агрегатов

Не выбирайте `name`, когда группируете только по `customer_id`, если `name` функционально не определён и СУБД это не позволяет. Стандартный SQL требует `name` в `GROUP BY` или внутри агрегата. Безопасная привычка: каждый неагрегатный столбец в `SELECT` появляется в `GROUP BY`.

```sql
SELECT c.customer_id, c.name, COUNT(*) AS order_count
FROM customers AS c
INNER JOIN orders AS o
    ON o.customer_id = c.customer_id
GROUP BY c.customer_id, c.name;
```

Логическая идея:

1. Применить `FROM` и `WHERE`.
2. Сформировать группы через `GROUP BY`.
3. Вычислить агрегаты на группу.
4. Применить `HAVING` (следующий раздел).
5. Спроецировать список `SELECT`.
6. Применить `ORDER BY`.

`WHERE` фильтрует строки до формирования групп. Не ставьте проверку `COUNT(*)` в `WHERE`. Используйте `HAVING`.

Запрос с агрегатами и без `GROUP BY` — одна группа: вся отфильтрованная таблица.

## `HAVING` против `WHERE`

`WHERE` фильтрует строки до группировки. `HAVING` фильтрует группы после агрегации.

```sql
SELECT customer_id, COUNT(*) AS order_count
FROM orders
WHERE ordered_at >= DATE '2026-01-01'
GROUP BY customer_id
HAVING COUNT(*) >= 3;
```

`WHERE` оставляет заказы 2026 года. `GROUP BY` строит подсчёты на клиента из этих заказов. `HAVING` оставляет клиентов с хотя бы тремя такими заказами.

Нельзя написать `WHERE COUNT(*) >= 3`. `COUNT(*)` не существует на этапе фильтра строк.

Можно написать `HAVING` по ключу группы, но `WHERE` для этого случая яснее.

```sql
SELECT customer_id, COUNT(*) AS order_count
FROM orders
GROUP BY customer_id
HAVING customer_id = 1;
```

Предпочитайте:

```sql
SELECT customer_id, COUNT(*) AS order_count
FROM orders
WHERE customer_id = 1
GROUP BY customer_id;
```

Вторая форма отбрасывает других клиентов до группировки. Эта форма дешевле и легче читается.

`HAVING` в некоторых продуктах может использовать псевдонимы. Стандартный SQL этого не требует. Повторите агрегат в `HAVING`:

```sql
HAVING COUNT(*) >= 3
```

Не используйте `HAVING` вместо `WHERE` по базовым столбцам. Используйте `WHERE` для правил строк. Используйте `HAVING` для правил групп.

Левое соединение плюс `GROUP BY` плюс `HAVING COUNT(o.order_id) = 0` может найти клиентов без заказов. `COUNT(o.order_id)` игнорирует `NULL`. `COUNT(*)` был бы `1` для клиента с одной полностью нулевой стороной заказа. Для этого вопроса предпочитайте `COUNT(o.order_id)` или `NOT EXISTS`.

## NULL в агрегатах

`NULL` значит отсутствие. Агрегатные функции пропускают входы `NULL`, кроме `COUNT(*)`.

Примеры со значениями `{10, NULL, 30}`:

| Функция | Результат |
| --- | --- |
| `COUNT(*)` | `3`, если это три строки |
| `COUNT(value)` | `2` |
| `SUM(value)` | `40` |
| `AVG(value)` | `20` |
| `MIN(value)` | `10` |
| `MAX(value)` | `30` |

`AVG` использует два значения, не три. Отсутствующее значение не считается нулём.

Если храните `0` вместо `NULL` для «нет измерения», `AVG` и `SUM` меняются. Этот выбор — решение модели. Не смешивайте `0` и `NULL` для одного смысла.

`GROUP BY` считает `NULL` одной группой. Все строки с `NULL` в столбце группировки идут вместе.

```sql
SELECT coupon_id, COUNT(*) AS n
FROM orders
GROUP BY coupon_id;
```

Заказы без купона (`coupon_id` `NULL`) образуют одну группу. Эта группа валидна.

`COUNT(DISTINCT col)` игнорирует `NULL`. Несколько значений `NULL` не добавляют отдельный элемент.

В `HAVING` условие `SUM(col) > 0` неизвестно, когда `SUM` равен `NULL`. Группа не проходит. Используйте `COALESCE(SUM(col), 0) > 0`, если нужно считать пустые суммы нулём.

Не используйте `NULL` как тайную дополнительную категорию, если не задокументируете это. Предпочитайте реальное справочное значение для «нет», когда отчёты должны легко сортировать и фильтровать эту категорию.

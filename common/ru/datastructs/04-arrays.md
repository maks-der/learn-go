# 4. Массивы

## Описание

Массив — непрерывный блок элементов одного типа. Эта тема объясняет массив фиксированного размера. Вы изучаете индексацию за константное время, вставку и удаление в середине, двумерное расположение, проверку границ и слова буфер и ёмкость. Завершите эту тему до изучения динамических массивов.

Используйте один термин для каждого понятия. **Длина** — число элементов в использовании. **Индекс** — целая позиция. Первый индекс — 0 в Go и в Python. **Буфер** — блок памяти. **Ёмкость** — число элементов, которые буфер может держать.

---

## Массив фиксированного размера

**Массив фиксированного размера** имеет длину, которую вы задаёте при создании массива. Длина не растёт. Длина не сжимается.

Элементы сидят в непрерывной памяти. Каждый элемент имеет один и тот же размер. Программа может вычислить адрес индекса i от начального адреса.

```text
array a of length 4
index:  0    1    2    3
value:  10   20   30   40
```

В Go тип `[4]int` — массив фиксированного размера. Размер — часть типа. `[4]int` и `[5]int` — разные типы.

В Python у `tuple` фиксированная длина. Python `list` — не массив фиксированного размера. Python `array.array` или библиотека вроде NumPy могут держать компактный массив.

Массив фиксированного размера прост. Вы используете его, когда знаете n. Вы используете его для маленькой таблицы. Вы используете его как внутренний буфер динамического массива.

Вы не можете добавить элемент за длину. Вы должны создать новый массив, если нужна другая длина. Скопируйте элементы, которые оставляете.

## Индексация за O(1)

**Индексация** — операция, которая читает или пишет элемент по индексу i.

Адрес элемента i:

```text
address(i) = start + i * element_size
```

Формула использует умножение и сложение. Формула не обходит первые i элементов. Время — Θ(1). Время не растёт с n. Время не растёт с i.

Эта индексация за константное время — главная причина использовать массив. У связного списка нет этой формулы. Обход списка — Θ(i), чтобы достичь индекса i.

```go
// Go: a is []int or [n]int
x := a[i]
a[i] = x
```

```python
# Python list uses an array of references; index is still O(1)
x = a[i]
a[i] = x
```

Индекс должен быть целым в допустимом диапазоне. Следующий раздел о проверке границ покрывает недопустимый индекс.

Случайный доступ означает, что вы можете прочитать любой индекс за константное время. Последовательный доступ означает, что вы читаете индекс 0, затем 1, затем 2. Массив поддерживает оба. Последовательный доступ также имеет хорошую локальность.

## Вставка и удаление в середине

**Insert** по индексу i ставит новый элемент в i. Элементы от i до конца сдвигаются на один шаг вправо. Если массив полон, вы не можете вставить, пока не создадите больший массив.

**Delete** по индексу i удаляет элемент в i. Элементы от i+1 до конца сдвигаются на один шаг влево. Длина уменьшается на 1, если массив отслеживает длину. Тип фиксированного размера может оставить дыру. Обычно вы уплотняете дыру.

```text
insert 99 at index 1
before:  10  20  30  40
after:   10  99  20  30  40

delete index 2
before:  10  99  20  30  40
after:   10  99  30  40
```

Число сдвигов — n − i в обычном компактном массиве. Худший случай — вставка или удаление по индексу 0. Вы двигаете n элементов. Стоимость — Θ(n).

Вставка в конец фиксированного массива, который не полон, есть Θ(1), если вы отслеживаете длину. Эта операция — append. Append — не то же самое, что вставка в середину.

Удаление по значению — не то же самое, что удаление по индексу. Удаление по значению сначала находит индекс. Затем оно удаляет по индексу.

## Двумерные массивы / построчный против постолбцового

**Двумерный массив** — таблица строк и столбцов. Вы пишете `a[r][c]` или `a[r, c]`.

Таблица всё равно сидит в одномерной памяти. Расположение отображает (строка, столбец) в один индекс.

**Построчное** расположение хранит полную строку, затем следующую строку. C, C++ и вложенные массивы Go используют построчный порядок. Многие вложенные списки Python — списки строк, но каждая строка — отдельный объект.

**Постолбцовое** расположение хранит полный столбец, затем следующий столбец. Fortran и некоторые числовые библиотеки используют постолбцовый порядок.

```text
table 2 by 3
  1 2 3
  4 5 6

row-major one-dimensional:    1 2 3 4 5 6
column-major one-dimensional: 1 4 2 5 3 6
```

Формулы индекса для таблицы с R строками и C столбцами:

```text
row-major:    index = r * C + c
column-major: index = c * R + r
```

Просмотр, который следует расположению, имеет хорошую локальность. Просмотр, который идёт против расположения, прыгает и имеет плохую локальность.

Настоящий прямоугольный блок — не то же самое, что массив указателей на строки. Массив указателей на строки может иметь строки разной длины. Эта форма — зубчатая таблица. Локальность слабее.

## Проверка границ

**Допустимый индекс** для массива длины n — целое i с 0 ≤ i < n. Некоторые языки также допускают отрицательный индекс. Python отображает −1 в n − 1. Go не допускает отрицательный индекс.

**Проверка границ** — проверка, что i допустим, до того как программа читает `a[i]`.

Если проверка не проходит, язык останавливает доступ. Go делает **panic**. Python поднимает `IndexError`. Программа не читает случайную ячейку.

```go
a := [3]int{1, 2, 3}
_ = a[3] // panic: index out of range
```

```python
a = [1, 2, 3]
# a[3] raises IndexError
```

Проверка границ стоит сравнения. Компиляторы могут убрать проверку, когда доказывают, что i допустим. Вы всё равно пишете код, который остаётся в диапазоне.

**Ошибка на единицу** использует n или использует −1 по ошибке. Циклы должны использовать `i < n`, когда индексы начинаются с 0.

Не отключайте проверку границ ради скорости, если вы не в особом низкоуровневом инструменте и не можете доказать безопасность. Для этого справочника оставляйте проверки.

## Буфер и ёмкость

**Буфер** — блок памяти, который держит элементы. Программа читает и пишет буфер.

**Ёмкость** — число элементов, которые буфер может держать. **Длина** — число элементов в использовании. Длина меньше или равна ёмкости.

```text
buffer cells:  a  b  c  _  _  _
length:        3
capacity:      6
```

У массива фиксированного размера часто длина равна ёмкости. У динамического массива (следующая тема) длина может быть меньше ёмкости.

Буфер может держать сырые байты. Чтение файла заполняет байтовый буфер. Затем вы интерпретируете байты как целые или как текст. Ёмкость — размер байтового блока. Длина — число байт в использовании.

Не читайте за длину. Ячейки между длиной и ёмкостью могут быть нулями или старыми значениями. Эти ячейки не часть логического массива.

Когда вы переиспользуете буфер, вы можете поставить длину в 0 и сохранить ёмкость. Это переиспользование избегает нового выделения. Вы всё равно не должны читать устаревшие значения как живые данные.

1. Постройте небольшой ADT матрицы на одном срезе. Поддержите `get`, `set` и ошибку границ. Используйте построчный порядок.
2. Замерьте сумму по строкам и сумму по столбцам на большой непрерывной сетке. Напишите два времени.
3. Напишите insert и delete на компактном буфере с полем длины. Добавьте тесты для i = 0, i = length−1 и i = length (вставка как append).

#### Сложные практические задания

1. Реализуйте зубчатую таблицу как массив массивов строк. Затем реализуйте прямоугольное представление на одном буфере. Сравните стоимость get и локальность письменно.
2. Прочитайте один документ стандартной библиотеки про массив или срез. Перепишите каждую операцию с полным утверждением о сложности.

# 5. Потоки

## Описание

Поток — контекст исполнения внутри процесса. Эта тема объясняет пользовательские потоки и потоки ядра, общее адресное пространство и локальное хранилище потока. Вы узнаете, зачем программы создают потоки, и получите первый взгляд на гонки.

Завершите эту тему после процессов. Завершите эту тему до планирования и синхронизации. Те темы предполагают больше одного потока.

Используйте один термин для каждого понятия. Поток ядра — поток, который видит планировщик ядра. Пользовательский поток — поток, который планирует библиотека в пользовательском пространстве. Локальное хранилище потока — данные, которые принадлежат одному потоку. Гонка — ошибка, которая зависит от порядка несинхронизированных обращений. Не смешивайте поток с процессом. Не смешивайте гонку со взаимной блокировкой (тема 7).

## Пользовательские потоки и потоки ядра

Ядро планирует потоки ядра (на некоторых системах их также называют легковесными процессами). У каждого потока ядра есть идентификатор планирования ядра. В Linux этот идентификатор — задача со своим идентификатором потока (TID). Вызов `clone` с общим адресным пространством создаёт поток ядра в том же процессе.

Пользовательский поток — контекст вроде сопрограммы, который библиотека переключает в пользовательском пространстве. Ядро видит один поток ядра. Библиотека может запускать много пользовательских потоков на этом одном потоке ядра. Эта модель — N:1 (много пользовательских потоков, один поток ядра).

Модель 1:1 сопоставляет каждый видимый пользователю поток одному потоку ядра. Потоки POSIX (`pthreads`) в современном Linux используют 1:1. `pthread_create` становится `clone`, который делит память.

Модель M:N сопоставляет много пользовательских потоков пулу потоков ядра. Некоторые рантаймы языков используют M:N. Планировщик рантайма сидит поверх планировщика ядра.

Свойства:

- 1:1: блокирующий системный вызов блокирует только этот поток ядра. Другие потоки ядра в процессе могут работать. Ядро может разместить потоки на разных ядрах.
- N:1: блокирующий системный вызов может заблокировать все пользовательские потоки, которые делят один поток ядра. Ядро не может запустить два пользовательских потока этого процесса на двух ядрах.
- M:N: сложнее. Рантайм должен обрабатывать блокировку и вытеснение.

В Linux также есть задачи только ядра (очереди работ, kthreads). Это не потоки `pthread` вашей программы. Они выполняют функции ядра. Вы видите имена вроде `kworker` в `ps`.

Этот путь использует потоки POSIX по умолчанию: один `pthread` — один поток ядра.

## Общее адресное пространство

Потоки одного процесса делят одно виртуальное адресное пространство. Они делят:

- текст программы
- глобальные и статические переменные
- кучу
- открытые дескрипторы файлов (таблица дескрипторов общая)
- текущий рабочий каталог и полномочия (если поток не меняет их особыми вызовами)

У каждого потока свой стек. Локальные переменные в функции потока живут на этом стеке. У каждого потока свои регистры и свой счётчик команд, когда он работает.

Если поток A пишет глобальную переменную, поток B может прочитать новое значение (с учётом видимости памяти; тема 7). Если поток A пишет через указатель кучи, который также держит поток B, оба потока видят один объект.

Это общее — причина, почему потоки полезны. Это также причина, почему существуют гонки. Процессы по умолчанию не делят адресное пространство. Процессы используют каналы, сокеты или разделяемую память, чтобы говорить. Потоки уже делят память.

Переполнение стека в одном потоке теоретически может задеть другое отображение. Ядро может поставить защитную страницу в конце стека потока. Тема 10 покрывает защитные страницы.

`fork` в многопоточном процессе копирует в потомка только вызывающий поток. POSIX перечисляет много ограничений. Избегайте `fork` плюс потоки, кроме шаблона `fork`, затем `exec`.

## Локальное хранилище потока

Локальное хранилище потока (TLS) — память, которую рантайм и ядро дают каждому потоку. У переменной TLS один экземпляр на поток. Запись в потоке A не меняет экземпляр в потоке B.

В C11 `_Thread_local` или `thread_local` помечает переменную TLS. В pthreads `pthread_key_create`, `pthread_setspecific` и `pthread_getspecific` реализуют ключи. Компиляторы также используют TLS для библиотеки C (`errno` обычно локален для потока).

TLS полезен для:

- `errno` и похожих значений ошибок на поток
- буфера на поток, которому не нужна блокировка
- имени потока или локального для потока состояния ГПСЧ

TLS — не блокировка. TLS не делает общий объект кучи безопасным. Если два потока держат указатель на один объект кучи, TLS этот объект не защищает.

Компилятор и динамический загрузчик настраивают TLS при старте потока. Цена мала для нескольких переменных. Огромный блок TLS в программе, которая создаёт тысячи потоков, тратит память.

Не храните указатель на объект стека потока в другом потоке без правила времени жизни. TLS и стеки исчезают, когда поток завершается, если вы не отсоединяете и не теряете, или не делаете join, и стек не переиспользуется.

## Зачем существуют потоки (ожидание ввода-вывода, многоядерность)

Один поток, который ждёт ввода-вывода, не может использовать ЦП для другой работы в этом потоке. Процесс всё ещё может запускать другие потоки. Это причина потоков, связанная с вводом-выводом.

Пример: сервер ждёт клиента на сокете. Если один поток блокируется в `read`, другой поток может обслужить второго клиента. Альтернатива — один поток и неблокирующий ввод-вывод с `epoll` (тема 14). Потоки часто проще писать. Они используют больше памяти на соединение.

Вторая причина — многоядерность. Два вычислительно ограниченных потока могут работать на двух ядрах одновременно. Два процесса тоже могут использовать два ядра. Потоки делят память, поэтому они избегают лишнего IPC для общих данных. Это общее — и польза, и риск.

Потоки не бесплатны:

- у каждого потока есть стек
- ядро должно планировать больше задач
- блокировки могут сериализовать работу так, что критическую часть выполняет только один поток
- ошибки становятся гонками

Используйте процессы, когда нужна сильная граница изоляции. Используйте потоки, когда задачи делят много данных и вы принимаете цену синхронизации. Используйте пул потоков, когда много коротких задач. Не создавайте один поток на крошечную задачу без границы.

Однопоточную программу проще обдумывать. Добавляйте потоки, когда есть измеренное ожидание или измеренная нужда в большем числе ядер.

## Гонки (превью синхронизации)

Гонка возникает, когда результат программы зависит от неконтролируемого порядка операций над общими данными.

Классический пример: два потока увеличивают общий счётчик `n`. Увеличение в абстракции — не одна операция ЦП. Это чтение, сложение и запись. Оба потока могут прочитать одно значение. Оба потока могут записать одно новое значение. Одно увеличение теряется.

```c
/* unsafe */
n = n + 1;
```

Программа может сбоить только иногда. Поэтому гонки трудно найти. Тест может пройти на одном ЦП и упасть на двух ЦП.

Гонка — не то же самое, что гонка данных в модели памяти C, но они пересекаются. Гонка данных — одновременные конфликтующие обращения к неатомарному объекту без синхронизации. Тема 7 покрывает мьютексы и видимость. Этот раздел только показывает проблему.

Исправления, которые вы изучите дальше:

- мьютекс вокруг критической секции
- атомарное увеличение
- не делить данные (использовать TLS или отдельный объект на поток, затем объединить)

Не «добавляйте sleep», чтобы спрятать гонку. Sleep меняет тайминг. Он не делает обращение безопасным.

Инструменты: ThreadSanitizer (`-fsanitize=thread`) в Clang или GCC может сообщить о многих гонках данных C/C++. Используйте его при разработке.

1. Напишите шпаргалку на одну страницу: пользовательский поток, поток ядра, 1:1, TID, общее адресное пространство, TLS, ожидание ввода-вывода, многоядерность, гонка, превью мьютекса.
2. Выполните `ps -T -p $$` на своей оболочке. Запишите, сколько потоков вы видите.
3. Скомпилируйте двухпоточную программу «hello». Выполните `strace -f -e clone,exit ./a.out` и запишите флаги `clone`, если они есть.
4. Нарисуйте один ящик процесса с двумя потоками, по одному слоту TLS каждый и одним гоночным глобальным.

#### Средние практические задания

1. Напишите программу с тремя потоками: два увеличивают заблокированный счётчик, один печатает счётчик каждые 100 мс до join. Задокументируйте форму вывода.
2. Сравните два процесса, которые увеличивают счётчик в файле, с двумя потоками, которые увеличивают глобальный. Напишите, какой паре нужен IPC, а какой — мьютекс.
3. Используйте `/proc/<pid>/task` на своей многопоточной программе. Перечислите TID и сопоставьте их с вашими распечатками.

#### Сложные практические задания

1. Постройте небольшой пул потоков (фиксированные N рабочих потоков, очередь указателей на функции). Запускайте задачи ЦП и задачи ввода-вывода. Напишите, когда пул помогает и когда очереди нужна условная переменная (тема 7).
2. Прочитайте Linux `man 2 gettid` и `man 7 pthreads`. Напишите одностраничную карту от потока POSIX к группе потоков Linux и TID.

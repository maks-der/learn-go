# 1. Начало работы

## Описание

База данных хранит данные, чтобы программы находили их, изменяли и сохраняли после остановки. Эта тема показывает, что такое база данных, чем она отличается от файла и как запустить локальную систему управления базами данных (`DBMS`, СУБД).

Используйте один термин для каждого понятия. Данные — сырые значения. Информация — данные в полезном контексте. База данных — организованная коллекция данных. СУБД — программа, которая управляет базой данных. Завершите эту тему до моделирования таблиц и SQL.

Путь нейтрален к вендорам. Примеры используют стандартный SQL там, где SQL применим. Имена продуктов — только примеры категории.

## Что такое база данных и зачем её используют программы

База данных — коллекция связанных данных, которые программа сохраняет и читает. Данные остаются на диске после выхода программы. Много программ используют одни и те же данные. СУБД решает, кто читает и кто пишет.

Программы используют базу данных, когда факты должны жить между сессиями. Магазин хранит товары, клиентов и заказы. Система билетов хранит места и брони. Сервис журнала хранит события. В каждом случае программа пишет данные и позже читает их снова.

База данных даёт структуру. Вы задаёте таблицы или коллекции. Вы задаёте ключи. Вы задаёте правила. СУБД проверяет эти правила. База данных также даёт одновременный доступ. Два пользователя работают в одно время. СУБД изолирует их изменения.

Программа, которая держит все факты только в памяти, теряет их при остановке процесса. Программа, которая дописывает строки в текстовый файл, может сохранить факты, но не даёт запросов, транзакций и контроля доступа. База данных — обычный инструмент, когда много записей, много пользователей или жёсткие правила.

Пример маленькой базы магазина:

- таблица `products` с именем товара и ценой
- таблица `customers` с именем и email
- таблица `orders` с клиентом, товаром, количеством и датой заказа

Программа магазина вставляет заказ. Позже та же программа или программа отчёта читает заказы. Данные живут в базе, а не только в процессе магазина.

## Данные, информация, база данных и СУБД

Данные — сырое значение. Пример: `42`, `2026-09-13` или текст `Ada`. У данных нет смысла, пока вы не назовёте контекст.

Информация — данные плюс смысл. Пример: «Ada оформила 42 заказа 2026-09-13.» Число `42` — данные. Предложение — информация.

База данных — организованная коллекция. У коллекции есть заданная структура. Пример: таблицы `customers` и `orders` с именованными столбцами. База хранит много строк данных. Запросы превращают эти строки в информацию.

СУБД — программный процесс, который управляет базами. Вы устанавливаете СУБД. Вы создаёте базу в этой СУБД. Вы подключаетесь к СУБД. СУБД читает и пишет файлы на диске. Не правьте эти файлы руками.

Держите термины отдельно:

| Термин | Смысл | Пример |
| --- | --- | --- |
| Данные | Сырое значение | `19.99` |
| Информация | Данные в контексте | Цена SKU `A-10` равна `19.99` |
| База данных | Организованная коллекция | База `shop` |
| СУБД | Управляющая программа | Серверный процесс, который хостит `shop` |

Не называйте СУБД «базой», когда имеете в виду продукт. Говорите «СУБД» про программу. Говорите «база данных» про коллекцию. Одна СУБД может хостить много баз.

## Когда хватает файла и когда лучше база

Файла хватает, когда одна программа пишет данные, один пользователь читает и структура простая. Примеры: файл конфигурации, статический список, маленький кэш или экспорт, который импортирует другой инструмент.

Файл — плохой склад, когда много писателей, когда нужно искать по многим полям, когда нужно держать правила или когда нужно восстановиться после сбоя. В этих случаях лучше база.

Используйте файл, когда верно всё из списка:

- один писатель или писатели, которые никогда не пересекаются
- вы читаете весь файл или сканируете его простым способом
- потеря последней записи приемлема, или вы копируете файл как резерв
- никакая другая программа не должна запрашивать те же данные в то же время

Используйте базу, когда верно любое из списка:

- много пользователей или процессов пишут одновременно
- нужны запросы вроде «все заказы одного клиента за один месяц»
- нужны правила вроде «каждый заказ должен указывать на реального клиента»
- нужна транзакция: все записи успешны или ни одна
- нужны пользователи и права

Пример. Личное приложение заметок может хранить заметки в одном файле JSON. Система брони аудитории не должна отдать одно место двум студентам. Системе брони нужна база.

Не кладите продакшен-склад для многих пользователей в общую таблицу или один файл JSON. Эти инструменты не дают безопасной одновременной записи.

## Клиент, сервер и встроенные базы

Клиент — программа, которая шлёт запросы к базе. Клиент может быть вашим приложением, инструментом командной строки или графической программой.

Серверная СУБД работает как отдельный процесс. Клиент подключается по сети или локальному сокету. Много клиентов подключаются одновременно. Примеры этой формы: PostgreSQL, MySQL, Microsoft SQL Server. Сервер владеет файлами данных. Сервер применяет права и транзакции.

Встроенная СУБД работает внутри вашего процесса. Библиотека открывает файл. Отдельного серверного процесса нет. Пример этой формы: SQLite. Один файл держит базу. Встроенные базы просто запускать. Они подходят для однопользовательских инструментов, тестов и маленьких приложений.

Сравните две формы:

| Форма | Процесс | Типичное применение | Одновременные писатели |
| --- | --- | --- | --- |
| Сервер | Отдельный процесс СУБД | Общие приложения, много пользователей | Рассчитано на это |
| Встроенная | Внутри приложения | Локальные приложения, тесты, инструменты | Ограничено; часто один писатель |

Локальный сервер на вашей машине всё равно сервер. «Локальный» значит, что сетевой адрес — ваш компьютер. «Встроенный» значит, что СУБД — библиотека в том же процессе.

Не считайте SQLite и серверную СУБД одной и той же операционной задачей. Резерв, пользователи и сетевой доступ отличаются. Изучайте идеи на любой форме. Затем изучите операции продукта, который будете запускать.

## Обычные категории: реляционная, документная, ключ-значение, широкие столбцы, граф, поиск

Модель данных — способ, которым СУБД организует значения. Изучите обычные категории. Выбирайте категорию после того, как знаете шаблон доступа. Не выбирайте продукт только по популярности.

**Реляционная.** Данные живут в таблицах. Строки делят фиксированный набор столбцов. Вы связываете таблицы ключами. SQL — обычный язык. Используйте эту модель для структурированных записей и жёстких правил. Примеры доменов: заказы, зарплата, брони.

**Документная.** Данные живут в документах, часто JSON. Один документ может вкладывать связанные поля. Документы в одной коллекции могут отличаться формой. Используйте эту модель, когда каждый элемент — самодостаточный документ и форма меняется. Примеры доменов: профили, страницы контента.

**Ключ-значение.** Вы храните значение под ключом. Вы читаете по ключу. Запрос внутри значения не является первоклассной возможностью. Используйте эту модель для кэшей, сессий и простых поисков. Примеры доменов: склад сессий, флаги функций.

**Широкие столбцы.** Вы храните строки с гибким набором столбцов, сгруппированных по семействам столбцов. Запись и чтение часто идут по ключу строки. Используйте эту модель для большого объёма записи и доступа в стиле временных рядов. Примеры доменов: метрики, большие таблицы событий.

**Граф.** Данные — узлы и рёбра. Вы запрашиваете пути и окрестности. Используйте эту модель, когда связи — главный вопрос. Примеры доменов: социальные связи, пути доступа, рекомендации.

**Поиск.** Поисковый движок индексирует текст и структурированные поля. Вы запрашиваете по релевантности, токенам и фильтрам. Используйте эту модель, когда пользователи ищут текст. Поисковый склад не заменяет систему учёта полностью.

Многие системы используют больше одной категории. Этот подход — полиглот-персистентность. Сначала изучите реляционную модель на этом пути. Другие категории снова появятся в обзорной теме.

```text
Relational   : tables, rows, SQL
Document     : JSON documents
Key-value    : get / set by key
Wide-column  : row key plus columns
Graph        : nodes and edges
Search       : inverted index, ranked hits
```

## Установка локальной СУБД (или Docker)

Установите локальную СУБД, чтобы практиковаться. Локальная установка держит данные на вашей машине. Для этого пути не нужен облачный аккаунт.

Есть два обычных метода:

1. Установить официальный пакет для своей операционной системы.
2. Запустить контейнер в Docker.

Выберите один метод. Используйте тот же метод до конца этой темы.

**Официальный пакет.** Скачайте установщик с сайта вендора. Запустите установщик. Задайте пароль администратора, если установщик спрашивает. Примите порт по умолчанию, если его не занимает другая служба. Типичные порты: PostgreSQL `5432`, MySQL `3306`.

**Docker.** Нужен Docker Engine. Скачайте официальный образ. Пробросьте порт. Задайте пароль в переменной окружения. Сохраняйте данные в именованном томе. Пример формы (PostgreSQL как иллюстрация):

```text
docker run --name learn-db -e POSTGRES_PASSWORD=devpass -p 5432:5432 -v learn-db-data:/var/lib/postgresql/data -d postgres:16
```

Меняйте образ и переменные, когда используете другой продукт. Читайте страницу официального образа. Не копируйте пароли из примеров в продакшен.

После установки проверьте процесс. На хосте подтвердите, что порт слушает. В Docker выполните `docker ps` и подтвердите, что контейнер запущен.

Создайте учебную базу. Используйте имя вроде `learn`. Не используйте системную базу для своих таблиц. Системные базы — для самой СУБД.

Если служба не стартует, читайте журнал сервера. Обычные причины: порт занят, у каталога данных неверный владелец или отсутствует переменная пароля.

## Подключение через GUI-клиент и CLI

Клиент подключается строкой подключения или отдельными полями. Типичные поля:

- хост (пример: `127.0.0.1` или `localhost`)
- порт
- пользователь
- пароль
- имя базы

CLI — терминальный клиент. Вы вводите SQL и видите текстовый результат. Используйте CLI, когда учитесь. CLI показывает точный оператор. Примеры инструментов CLI: `psql`, `mysql`, `sqlite3`, `sqlcmd`. Имя зависит от продукта.

GUI-клиент — графическая программа. Вы просматриваете таблицы, правите строки и выполняете SQL в окне. Используйте GUI, чтобы видеть структуру. Не используйте только GUI. Вы всё равно должны вводить SQL.

Сначала подключитесь через CLI. Пример формы (имя программы меняется по продукту):

```text
psql -h 127.0.0.1 -p 5432 -U learn -d learn
```

После подключения выполните пробный оператор:

```sql
SELECT 1;
```

Результат должен показать `1`. Этот тест доказывает, что аутентификация работает и сессия может выполнять SQL.

В GUI создайте подключение с тем же хостом, портом, пользователем и базой. Снова выполните `SELECT 1`. Просмотрите список баз и схем. Подтвердите, что `learn` появляется.

Не коммитьте пароли в репозиторий. Используйте запрос пароля клиента или локальный файл конфигурации, который не отдаёте. Не открывайте порт СУБД в публичную сеть для учебной установки.

Если клиент не подключается, читайте ошибку. Типичные причины: неверный порт, неверный пользователь, неверное имя базы, сервер не запущен или блокировка файрвола.

### Вопросы

#### Теоретические вопросы

#### Простые практические задания

# 14. Диапазоны, пространственные и эскизные структуры

## Описание

Эта тема обзорно рассматривает структуры для запросов диапазона, вероятностные списки с пропусками, пространственные деревья и фильтры Блума. Вы изучаете деревья отрезков и деревья Фенвика, идею списка с пропусками, короткий обзор квадродеревьев, k-d деревьев и R-деревьев и фильтры Блума.

Завершите эту тему после массивов, деревьев и хеш-таблиц. Считайте пространственные деревья обзором: определения и использования, не полный промышленный код.

Используйте один термин для каждого понятия. **Запрос диапазона** возвращает значение из непрерывного интервала индексов [L, R]. **Точечное обновление** меняет один индекс. **Список с пропусками** — многослойный связный список со случайными лишними указателями. **Пространственное дерево** делит пространство или группирует прямоугольники. **Фильтр Блума** — битовый массив, который может сказать «возможно во множестве» или «точно не во множестве».

## Дерево отрезков и дерево Фенвика

**Дерево отрезков** — двоичное дерево над массивом a[0 .. n−1]. Каждый узел хранит слияние непрерывного отрезка. Корень хранит слияние полного массива. Лист хранит один элемент.

Обычное слияние — сумма, min или max. Слияние должно быть ассоциативным. Вы объединяете два значения детей в родителя.

```text
array:  1  3  2  4
sums:
            10
          /    \
        4        6
       / \      / \
      1   3    2   4
```

**Запрос [L, R]** обходит O(log n) узлов, которые вместе покрывают [L, R] и ни одного лишнего индекса. **Обновление** в индексе i идёт по пути от этого листа к корню и чинит O(log n) узлов.

Время построения есть Θ(n). Время запроса или точечного обновления есть Θ(log n). Память около 4n для массива узлов в стиле кучи (безопасная оценка для раскладки степени двойки).

```text
query(node, segL, segR, L, R):
  if the node segment is outside [L,R]: return identity
  if the node segment is inside [L,R]: return node.value
  return merge(query(left), query(right))
```

**Нейтральный элемент** — 0 для суммы, +∞ для min, −∞ для max.

Дерево отрезков может добавить **ленивое распространение** для обновлений диапазона. Это второй навык. Сначала реализуйте точечное обновление и сумму диапазона.

Дерево отрезков — не BST ключей. Индексы — ключи. Разделение всегда середина диапазона индексов.

**Дерево Фенвика** (двоичное индексированное дерево, BIT) хранит префиксные суммы в массиве t[1 .. n]. Индексы **с единицы**. Следующий индекс после i использует младший установленный бит i.

**Точечное сложение** в i обновляет i, i + lsb(i), i + lsb(i+lsb(i)), ... пока индекс ≤ n.

**Префиксная сумма** 1 .. i читает i, i − lsb(i), ... до 0.

```text
prefix(R) − prefix(L−1)  =  sum of a[L .. R]
```

Код Фенвика короткий. Он подходит обратимым слияниям вроде суммы. Min без лишней структуры — не естественная операция Фенвика. Дерево отрезков подходит min и max.

Время точечного сложения и префикса Фенвика есть Θ(log n). Память есть Θ(n).

Не просматривайте [L, R] в цикле, если n велико и запросов много. Это Θ(n) на запрос.

## Список с пропусками

**Список с пропусками** — связный список с лишними слоями. У каждого узла **высота** (число указателей вперёд). Высота выбирается случайно при вставке, часто так, что около половины узлов, которые появляются на слое k, также появляются на слое k+1.

Слой 0 — полный отсортированный список. Высшие слои пропускают узлы. Поиск начинается слева сверху и идёт вправо, пока следующий ключ слишком мал, затем спускается на один слой.

```text
layer 2:  1 ----------------> 9
layer 1:  1 ----> 5 --------> 9
layer 0:  1 → 3 → 5 → 7 → 9
```

Ожидаемые поиск, вставка и удаление есть O(log n), если случайные высоты независимы и параметр p — константа вроде 1/2.

Не нужно поворачивать или перекрашивать. Вставка вставляет указатели на каждом слое нового узла. Удаление их вынимает.

Список с пропусками может реализовать упорядоченное множество или упорядоченное отображение (тема 6). Обход слоя 0 — отсортированный порядок.

Худший случай может быть линейным, если каждая высота 1 или если случайный выбор неудачен. Вероятность очень высокого худшего случая мала для большого n. Это рандомизированная гарантия, не оценка худшего случая в стиле AVL.

Некоторые базы используют списки с пропусками в памяти (например, индекс в памяти). Этой теме нужна только идея.

Не считайте список с пропусками хеш-таблицей. Ключи остаются упорядоченными. Хеша нет.

**Детерминированный** список с пропусками существует в теории. Обычная учебная структура рандомизирована.

## Квадродерево, k-d дерево, R-дерево (обзор)

Эти структуры хранят **точки** или **прямоугольники** на плоскости или в большем числе измерений. Этот раздел — обзор. Выучите, что значит каждое имя. Не реализуйте все три.

**Квадродерево** делит квадрат на четыре меньших квадрата (СЗ, СВ, ЮЗ, ЮВ). Узел держит ёмкость точек. Когда квадрат полон, он расщепляется. Поиск в области посещает только квадраты, которые пересекают эту область.

```text
world square
  NW | NE
  ---+---
  SW | SE
each cell can split again
```

Используйте квадродерево для точек в 2D, когда пространство — ящик, который можно делить поровну. Неравномерные облака точек могут сделать глубокое дерево в плотном кармане.

**k-d дерево** (k-мерное дерево) — двоичное дерево точек. Уровень 0 делит по x (или оси 0). Уровень 1 делит по y (ось 1). Оси циклируются. Каждый узел держит одну точку (в частой форме). Разделение — гиперплоскость.

Поиск ближайшего соседа отсекает поддерево, когда плоскость разделения дальше, чем лучшее расстояние пока.

k-d деревья подходят ближайшему соседу и поиску диапазона в умеренной размерности. В высокой размерности отсечение чаще отказывает (концентрация расстояний).

**R-дерево** хранит **минимальные ограничивающие прямоугольники** (MBR). Листья держат прямоугольники (или указатели на объекты). Внутренние узлы держат MBR, которые покрывают их детей. Прямоугольники могут пересекаться. Поиск посещает каждого ребёнка, чей MBR пересекает ящик запроса.

```text
query box hits two overlapping MBRs
  you must search both children
```

Базы используют R-деревья для географических ящиков и для «объектов, которые пересекают эту область».

```text
need points in a city grid     → quadtree (often)
need nearest neighbor in 2D/3D → k-d tree (often)
need many overlapping boxes    → R-tree (often)
```

Не используйте эти имена для 1D-индекса диапазона на массиве. Используйте дерево отрезков или дерево Фенвика.

Сетка (фиксированные ячейки) — более простой пространственный индекс. Используйте сетку, когда у ячеек равномерная нагрузка.

## Фильтр Блума

**Фильтр Блума** — компактное вероятностное множество. Он хранит **нет ключей**. Он хранит битовый массив размера m и k хеш-функций.

**Вставка** ключа x: для каждого хеша hi(x) поставьте бит (hi(x) mod m) в 1.

**Запрос** ключа x: если любой из k битов равен 0, x **точно нет** во множестве. Если все k битов равны 1, x **возможно** во множестве.

```text
bits:  0 1 0 1 1 0 1 0
insert "cat" sets three positions
query "dog": a 0 bit → absent
query "cow": all 1s → maybe (could be a false positive)
```

**Ложное срабатывание** — «возможно» для ключа, который вы никогда не вставляли. Другие ключи поставили те же биты.

В стандартном фильтре Блума **нет ложного отрицания**: если вы вставили x и не удаляли, query(x) всегда «возможно» (биты остаются 1).

Нельзя перечислить ключи. Нельзя удалять в базовой форме (если не использовать считающий фильтр Блума).

Частота ложных срабатываний зависит от n, m и k. Больше битов и хороший k снижают частоту. Полная таблица формул — позднее чтение. Идея: вы меняете память и малую ошибку на быстрые проверки принадлежности.

Используйте фильтр Блума, чтобы пропустить медленный поиск (диск, сеть), когда большинство запросов промахивается. Если фильтр говорит нет, не идите на диск. Если фильтр говорит возможно, сделайте настоящий поиск.

Не используйте фильтр Блума как единственное хранилище паролей или записей, которые нужно достать.

Хеш-функции здесь — хеши таблиц, не хеши паролей (тема 5).

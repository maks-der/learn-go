Эта тема закрывает путь MongoDB. Вы проходите вводный путь **MongoDB University**. **Моделируете** одну реляционную схему как документы и сравниваете запросы. **Включаете replica set** на своей машине. ## Включить replica set локально

Локальный **replica set** учит выборы, `hello`, транзакции и change streams. Atlas тоже replica set. Локальный набор позволяет остановить член и смотреть failover.

Минимум для учёбы: один член. Лучше: три члена на трёх портах.

Типичные идеи (Docker или процессы):

- Разные `dbPath` и порт для каждого члена
- Одно и то же `replSetName`
- `rs.initiate()` с конфигурацией, которая перечисляет хосты
- `rs.status()`, пока один член не станет primary

Форма initiate примера:

```javascript
rs.initiate({
  _id: "rs0",
  members: [
    { _id: 0, host: "localhost:27017" },
    { _id: 1, host: "localhost:27018" },
    { _id: 2, host: "localhost:27019" }
  ]
})
```

Имена хостов внутри Docker должны совпадать с тем, что члены используют, чтобы достичь друг друга. `localhost` из контейнера — контейнер, не хост. Следуйте текущему примеру Docker Compose или официальному учебнику.

После того как набор поднят:

- Вставьте с majority write concern
- Запустите транзакцию двух документов
- Откройте change stream
- Сделайте step down primary и подтвердите, что драйвер или `mongosh` находит новый primary

Не открывайте эти порты в публичный интернет.

Не пропускайте это задание, если есть только Atlas. Atlas — верная производственная практика. Локальный failover всё равно стоит одного дня.

Если три процесса запустить нельзя, запустите один член как replica set. Транзакции и change streams работают. Выборам с настоящим большинством нужно больше членов.

## Добавить один составной индекс из настоящего `explain`

Выберите `find` или `$match` агрегации, который уже используете в итоговой модели или лабораторной коллекции. Запустите:

```javascript
db.orders.find({ userId: "u1", status: "open" }).sort({ createdAt: -1 }).explain("executionStats")
```

Если победившая стадия — `COLLSCAN` или `totalDocsExamined` намного больше `nReturned`, спроектируйте **один** составной индекс, который совпадает с фильтром и сортировкой (правило префикса из темы 6).

Создайте индекс. Снова выполните `explain("executionStats")`. Запишите:

- Победившие стадии до и после
- `totalDocsExamined` до и после
- `executionTimeMillis` до и после (тот же размер данных)
- Ключ индекса

Используйте достаточно документов, чтобы разница была видна (тысячи, не три).

Не добавляйте пять индексов. Добавьте один. Докажите его.

Не создавайте индекс до первого `explain`. Смысл — доказательство.

Если запрос уже покрыт или уже `IXSCAN` с плотным счётом просмотра, намеренно выберите худший запрос и исправьте тот.

Удалите индекс, если он только для этого урока и не принадлежит модели. Оставьте, если итоговой модели он нужен.

## Прочитать текущее руководство своей основной версии

Основная версия сервера — первое число `db.version()`. Руководство — [https://www.mongodb.com/docs/manual/](https://www.mongodb.com/docs/manual/). Поставьте селектор версии на это число.

Команды, значения по умолчанию и лимиты меняются. Примеры, которые меняются между версиями:

- Reshard и refine
- Queryable Encryption
- Лимиты временных рядов
- Имена полей `explain`
- Устаревшие помощники оболочки (`mongo` vs `mongosh`)

Читайте, не только скользите по посадочной странице. Минимум страниц для закрытия этого пути:

- Введение в моделирование данных
- Выборы replica set
- Результаты `explain`
- Лимиты транзакций
- Чек-лист безопасности
- Заметки о выпуске вашей основной версии

У Atlas есть дополнительная документация. У драйверов есть дополнительная документация. Откройте страницу драйвера языка, который используете.

Не делайте закладку случайного блога правилом write concern. Ссылайтесь на страницу руководства.

Когда обновляете (тема 16), читайте новое руководство до смены FCV.

Печатайте или сохраняйте PDF только если нужно работать офлайн. Живая страница — та, которую чинят.

# 10. Кучи

## Описание

Куча — дерево, которое вы храните в массиве. Очередь с приоритетом — ADT, который удаляет минимум или максимум первым. Эта тема объясняет раскладку массива, вставку, извлечение, heapify, построение кучи за линейное время, пирамидальную сортировку и случаи использования очереди с приоритетом.

Завершите эту тему после массивов и деревьев. Завершите графы до реализации Дейкстры с кучей (тема 12).

Используйте один термин для каждого понятия. **Двоичная куча** — совершенное двоичное дерево со свойством кучи. **Мин-куча** держит каждого родителя меньше или равным детям. **Макс-куча** использует противоположное правило родителя. **Очередь с приоритетом** — ADT. Куча — обычная реализация. **Heapify** восстанавливает свойство кучи в одном узле. **Build-heap** строит кучу из неупорядоченного массива.

## Двоичная куча в массиве

**Двоичная куча** — совершенное двоичное дерево. Каждый уровень полон, кроме последнего. Последний уровень заполняется слева. Вы храните дерево в массиве. Вы не храните указатели на детей.

Для массива с нуля (индекс 0 — корень):

- левый ребёнок i есть 2i + 1
- правый ребёнок i есть 2i + 2
- родитель i есть floor((i − 1) / 2)

Для массива с единицы (индекс 1 — корень):

- левый ребёнок i есть 2i
- правый ребёнок i есть 2i + 1
- родитель i есть floor(i / 2)

Этот справочник использует индексы **с нуля** в примерах, если строка не говорит «с единицы».

```text
min-heap values: 1, 3, 2, 7, 4, 5

        1
       / \
      3   2
     / \ /
    7  4 5

array: index  0  1  2  3  4  5
       value  1  3  2  7  4  5
```

**Свойство кучи** — не свойство BST. Куча не держит полную сортировку в массиве. Единственный гарантированный порядок — родитель против ребёнка. Левый ребёнок может быть больше или меньше правого ребёнка.

Совершенная форма даёт компактный массив. Нет дыры в диапазоне индексов 0 .. n−1. Локальность лучше, чем у дерева указателей.

Корень — минимум в мин-куче. Find-min есть Θ(1). Поиск произвольного ключа есть Θ(n), если не добавить лишнее отображение.

Выберите min или max и оставайтесь с этим правилом для всей структуры.

## Вставка, извлечение, heapify

**Вставка** дописывает новое значение в индекс n, затем **просеивает вверх** (всплывает). Пока значение меньше родителя (мин-куча), меняйтесь с родителем. Время есть Θ(log n), потому что высота около log2 n.

```text
insert 0 into [1, 3, 2, 7, 4, 5]
append: [1, 3, 2, 7, 4, 5, 0]
sift up: 0 swaps toward the root
```

**Extract-min** убирает корень. Переместите последний элемент в индекс 0. Уменьшите n. Затем **просейте вниз** (heapify корня). Сравните узел с детьми. Меняйтесь с меньшим ребёнком, если этот ребёнок меньше узла. Повторяйте. Время есть Θ(log n).

```text
extract-min from [1, 3, 2, 7, 4, 5]
move 5 to root: [5, 3, 2, 7, 4]
sift down: 5 swaps with 2, then stops or continues
```

**Heapify** (просеивание вниз) в индексе i предполагает, что поддеревья i уже кучи. Оно восстанавливает свойство кучи в i. Время есть Θ(h_i), где h_i — высота узла i.

Не извлекайте из пустой кучи. Определите ошибку.

Decrease-key и increase-key есть на некоторых кучах. Двоичной куче нужен индекс ключа. Отображение из ключа в индекс может помочь. Этой теме нужны только insert, extract и heapify.

Push — insert. Pop — extract. Peek — чтение индекса 0.

## Построение кучи за линейное время

**Build-heap** превращает неупорядоченный массив из n элементов в кучу на месте.

Наивный метод вставляет n элементов в пустую кучу. Каждая вставка есть O(log n). Итого O(n log n).

Более быстрый метод:

1. Считайте массив совершенным деревом (оно уже таково как массив).
2. Вызовите heapify на каждом не-листе, от последнего родителя вниз к корню.

Последний родитель имеет индекс floor(n/2) − 1 в массиве с нуля.

```text
array: [4, 1, 3, 2, 16, 9, 10, 14, 8, 7]
heapify from the last parent toward index 0
result: a min-heap or a max-heap, depending on the compare
```

Почему итог Θ(n)? У большинства узлов малая высота. Около n/2 узлов — листья (heapify ничего не делает). Около n/4 узлов имеют высоту 1. Сумма высот по совершенному дереву меньше n. Стандартное доказательство ограничивает эту сумму константой, умноженной на n.

Используйте build-heap, когда все элементы уже есть. Используйте повторные вставки, когда элементы приходят по одному.

Build-heap не сортирует массив. Он только ставит свойство кучи.

Не делайте heapify от корня к листьям. Допущение про кучи-детей не сработало бы.

## Пирамидальная сортировка

**Пирамидальная сортировка (heap sort)** сортирует массив на месте кучей.

Для порядка **по возрастанию** используйте **макс-кучу**:

1. Постройте макс-кучу на массиве.
2. Для i от n−1 вниз до 1: поменяйте a[0] с a[i]. Максимум оставшейся кучи сидит в i. Уменьшите размер кучи на 1. Сделайте heapify в индексе 0.

```text
max-heap: largest at index 0
swap a[0] with a[n-1]
heap size n-1
heapify root
repeat
array fills from the right with decreasing maxima
```

Время есть Θ(n) на построение плюс (n−1) раз Θ(log n) на извлечение. Итого Θ(n log n). Лишняя память есть Θ(1) кроме массива.

Пирамидальная сортировка не стабильна в обычной реализации. Равные ключи могут сменить порядок.

Пирамидальная сортировка — сортировка сравнением. Класс Θ(n log n) совпадает со сортировкой слиянием и типичной быстрой сортировкой. Константы и локальность различаются. Быстрая сортировка часто быстрее на практике. У пирамидальной сортировки строгий худший случай Θ(n log n).

Не забудьте: после каждой смены куча — только префикс длины i. Суффикс уже отсортирован.

Мин-куча плюс лишний массив тоже может сортировать. Этот метод использует лишнюю память.

## Случаи использования очереди с приоритетом

**Очередь с приоритетом** — ADT. Операции — вставка (с приоритетом) и извлечение лучшего приоритета. Peek лучшего необязателен. Куча — обычная реализация. Insert и extract есть Θ(log n). Peek есть Θ(1).

Случаи использования:

- **Планирование.** Следующая работа — та, у которой высший приоритет или ближайший срок.
- **Симуляция событий.** Следующее событие — то, у которого наименьшее время.
- **Алгоритмы на графах.** Дейкстра и Прим извлекают ближайшую неустановленную вершину (тема 12).
- **Топ-k.** Держите кучу размера k. Для мин-кучи текущих k наибольших корень — наименьший из этих k. Новое значение, которое больше корня, может заменить корень.
- **Слияние отсортированных потоков.** Мин-куча текущей головы каждого потока даёт следующий глобальный минимум.

```text
top-3 largest in a stream
max values live in a min-heap of size 3
root is the smallest of the top 3
a new x > root: extract root, insert x
```

Не используйте кучу, когда нужен поиск по ключу. Используйте отображение. Не используйте кучу, когда нужен отсортированный обход всех ключей. Используйте сбалансированное дерево или отсортируйте один раз.

Отсортированный массив может реализовать очередь с приоритетом. Вставка есть Θ(n). Extract-min с начала есть Θ(n), если сдвигаете, или extract-max с конца есть Θ(1), если сортируете по убыванию. Куча — обычный компромисс: и insert, и extract логарифмические.

Очередь FIFO — не очередь с приоритетом. Порядок прибытия — не приоритет, если вы не используете время прибытия как приоритет.

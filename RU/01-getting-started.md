# 1. Начало работы

## Описание

Go — компилируемый язык программирования. Разработчики Go спроектировали Go для простого синтаксиса, быстрой компиляции и параллельных программ. Эта тема показывает, как установить Go, как организовать `module` (модуль) и как использовать базовые команды Go. Завершите эту тему до того, как писать программы на Go.

Используйте один термин для каждого понятия. Не смешивайте старый режим GOPATH с модулями Go. Для всей новой работы используйте модули Go.

## Что такое Go и зачем он существует

Go — язык со статической типизацией. Компилятор проверяет типы до запуска программы. Go компилирует исходные файлы в нативный двоичный файл. Двоичный файл работает на целевой операционной системе без виртуальной машины.

Разработчики Go создали Go, чтобы решать задачи в крупном серверном ПО. Компиляция больших программ на C++ была медленной. Потоки во многих языках были сложными. Управление зависимостями было трудным. Go даёт небольшой язык, быстрый компилятор и `goroutine` (горутины) для параллельной работы.

Go прост. В языке мало ключевых слов. Стандартная библиотека покрывает файлы, HTTP, JSON и тесты. Go параллелен. Ключевое слово `go` запускает `goroutine`. Go компилируется. Вы распространяете один двоичный файл.

Go не является объектно-ориентированным языком в стиле классов и наследования. Go использует структуры и интерфейсы. Go не является динамическим скриптовым языком. Вы объявляете типы. Ошибки обрабатываете возвращаемыми значениями.

## Установка Go и проверка `go version`

Скачайте официальный установщик с [https://go.dev/dl/](https://go.dev/dl/). Выберите пакет для своей операционной системы. Запустите установщик. Примите путь установки по умолчанию, если нет особого требования.

После установки откройте новый терминал. Новый терминал загружает новый `PATH`. Запустите:

```text
go version
```

Вывод должен показать `go version go1.x.y` и вашу операционную систему и архитектуру. Пример: `go version go1.22.0 windows/amd64`.

Если команда не найдена, `PATH` не включает каталог `bin` Go. В Windows путь по умолчанию — `C:\Program Files\Go\bin`. В macOS и Linux путь по умолчанию — `/usr/local/go/bin`. Добавьте этот каталог в `PATH`. Откройте новый терминал. Снова запустите `go version`.

Также запустите:

```text
go env GOROOT GOPATH GOMODCACHE
```

`GOROOT` — место установки инструментария. `GOPATH` — рабочая область для скачанных модулей и кэшей. В режиме модулей исходный код проекта не размещают в `GOPATH`.

## GOPATH и модули Go (используйте модули)

Старые проекты Go использовали режим GOPATH. Весь исходный код жил в `$GOPATH/src`. Пути импорта были путями каталогов в этом дереве. Эта модель не записывала версии зависимостей в проекте.

Модули Go — текущий стандарт. `module` — набор `package` (пакетов) с файлом `go.mod`. Файл `go.mod` записывает путь модуля и версию Go. Файл `go.mod` записывает требуемые версии модулей. Файл `go.sum` записывает контрольные суммы этих модулей.

Всегда используйте модули. Запустите `go mod init` в корне проекта. Не задавайте `GO111MODULE=off`. Не размещайте исходный код нового проекта внутри `GOPATH/src` по этой причине.

Путь модуля — префикс импорта. Пример: `github.com/user/app`. Пакеты в модуле используют этот префикс в операторах импорта из других модулей.

## Структура рабочей области: `go.mod`, `package`, файлы

Типичный модуль имеет такую структуру:

- `go.mod` в корне
- один или несколько файлов `.go`
- необязательные папки, которые являются дополнительными пакетами

`package` — каталог файлов Go с одним и тем же именем `package`. Все файлы в одном каталоге должны использовать одно и то же имя пакета. Тесты используют `package name` или `package name_test`.

Имена файлов используют буквы, цифры и `_`. Компилятор игнорирует файлы с именами, которые начинаются с `.` или `_`. Компилятор игнорирует файлы с тегами сборки, которые не совпадают. Файлы с именами `*_windows.go` относятся к Windows. Файлы с именами `*_test.go` — тестовые файлы.

Не помещайте много несвязанных пакетов в один каталог. Один каталог — один пакет. Помещайте команды в `cmd/toolname`, когда модуль содержит больше одной команды. Помещайте закрытый код в `internal/`, когда другие модули не должны его импортировать.

## `go run`, `go build`, `go test`, `go fmt`, `go vet`

`go run` компилирует и запускает пакет за один шаг. Используйте `go run .` в каталоге модуля для `package main`. Используйте `go run file.go` только для небольших однофайловых программ.

`go build` компилирует пакет. Для `package main` команда `go build` записывает двоичный файл в текущий каталог. Имя двоичного файла берётся из имени каталога. Используйте `-o name`, чтобы задать имя вывода. Для библиотечного пакета `go build` проверяет компиляцию и не записывает файл в текущий каталог.

`go test` компилирует тестовые файлы и запускает тесты. Тестовые файлы имеют суффикс `_test.go`.

`go fmt` форматирует файлы Go в пакете. Формат — официальный формат Go. Не спорьте об отступах. Запустите `go fmt ./...` для всего модуля.

`go vet` сообщает о подозрительном коде. Примеры: ошибки формата printf, недостижимый код, неверные блокировки. `go vet` не является полным линтером. Выполняйте `go vet ./...` вместе с тестами.

Типичная последовательность для изменения:

1. Напишите код.
2. Запустите `go fmt ./...`.
3. Запустите `go vet ./...`.
4. Запустите `go test ./...`.
5. Запустите `go build -o app .` для команды.

## `gofmt` / `gofumpt` и настройка редактора

`gofmt` — форматтер в инструментарии Go. `go fmt` вызывает `gofmt`. `gofumpt` — более строгий форматтер. `gofumpt` применяет дополнительные правила. Группы разработчиков могут использовать `gofumpt`. Официальное правило по-прежнему — `gofmt`.

Настройте редактор так, чтобы он запускал форматирование при сохранении. Установите расширение Go для Visual Studio Code или плагин Go для GoLand. Задайте инструмент форматирования как `gofmt` или `goimports`. `goimports` форматирует файл и исправляет списки импорта.

Включите `gopls`. `gopls` — языковой сервер Go. `gopls` даёт автодополнение, переход к определению и диагностику. Укажите редактору тот же двоичный файл `go`, который использует терминал.

Не смешивайте табы и пробелы вручную. `gofmt` использует табы для отступов. Выравнивайте другие столбцы пробелами, когда так делает `gofmt`.

## Официальная документация: go.dev/doc и Tour of Go

Основная документация — [https://go.dev/doc/](https://go.dev/doc/). Она содержит спецификацию, Effective Go, учебник и заметки о выпуске.

Tour of Go — [https://go.dev/tour/](https://go.dev/tour/). Тур — интерактивный набор уроков. Пройдите тур в браузере. Тур охватывает типы, методы, интерфейсы и `goroutine`.

Документация пакетов находится на [https://pkg.go.dev/](https://pkg.go.dev/). Для стандартной библиотеки откройте [https://pkg.go.dev/std](https://pkg.go.dev/std). Каждая страница пакета показывает типы, функции и примеры.

Используйте `go doc` в терминале:

```text
go doc fmt.Println
go doc net/http.Client
```

Используйте спецификацию языка, когда нужны точные правила. Используйте Effective Go, когда нужен стиль. Используйте тур, когда изучаете язык в первый раз.

### Вопросы

#### Теоретические вопросы

1. Опишите полный путь от пустой папки до работающей программы Hello World. Назовите каждую команду.
2. Почему файл контрольных сумм является частью модуля?
3. Как `go fmt` и `go vet` работают вместе в ежедневном процессе?
4. В чём разница между документацией на pkg.go.dev и документацией от `go doc`?
5. Коллега использует режим GOPATH. Какие факты вы используете, чтобы объяснить переход на модули?

#### Простые практические задания

1. Создайте новый модуль `example.com/start`. Добавьте `main.go`, который печатает `started`. Отформатируйте, проверьте через vet, протестируйте (добавьте один тест) и соберите.
2. Напишите шпаргалку на одну страницу с этими командами: `go version`, `go env`, `go mod init`, `go run`, `go build`, `go test`, `go fmt`, `go vet`, `go doc`.
3. Экспортируйте `go env` в файл. Выделите `GOOS`, `GOARCH`, `GOROOT`, `GOPATH` и `GOMODCACHE`.
4. Создайте дерево папок для будущего инструмента CLI. Добавьте только `go.mod` и пустые пакеты. Запустите `go list ./...`.

#### Средние практические задания

1. Напишите небольшой скрипт (PowerShell или bash), который последовательно выполняет `go fmt`, `go vet` и `go test`. Остановитесь на первой ошибке.
2. Клонируйте небольшой публичный репозиторий Go. Определите `go.mod`, основной пакет и один библиотечный пакет. Запустите `go test ./...`.
3. Задокументируйте настройку редактора и Go в десяти шагах так, чтобы другой новичок мог её скопировать.

#### Сложные практические задания

1. Соберите один и тот же пакет `main` для `GOOS=linux` и `GOOS=windows`. Покажите два имени двоичных файлов и размеры файлов. Запускать чужой двоичный файл не нужно.
2. Создайте модуль, который использует один внешний модуль с pkg.go.dev. Запишите `go get`, строку require в `go.mod` и успешный `go run`.

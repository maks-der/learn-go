# 6. Маршрутизация

## Описание

Маршрутизация — выбор следующего хопа для пакета. Хост и маршрутизатор оба используют таблицу маршрутизации. Эта тема показывает longest prefix match, маршруты хоста, маршруты по умолчанию, ICMP, traceroute и краткий вид статической и динамической маршрутизации.

Используйте один термин для каждого понятия. Маршрут — префикс плюс следующий хоп или исходящий интерфейс. Таблица маршрутизации — список маршрутов, которые использует устройство. Завершите эту тему до изучения NAT.

Вы уже знаете шлюз по умолчанию. Эта тема ставит этот шлюз в таблицу вместе с другими префиксами.

## Таблица маршрутизации

Таблица маршрутизации сопоставляет префикс назначения со следующим хопом и интерфейсом. Ядро ищет IP назначения каждого пакета. Ядро выбирает один маршрут. Затем ядро делает ARP или neighbor discovery для следующего хопа, если следующий хоп в LAN.

Таблица хоста часто мала: локальная подсеть, маршрут по умолчанию, loopback и, возможно, VPN. Таблица маршрутизатора может быть большой. Маршрутизатор Internet может держать сотни тысяч префиксов.

У каждого маршрута есть длина префикса, следующий хоп, интерфейс и метрика или предпочтение. Некоторые таблицы также показывают источник маршрута: connected, static, DHCP или имя протокола.

Connected-маршруты появляются, когда у интерфейса есть адрес и маска. Назначение в этой подсети локальное. Следующий хоп — не маршрутизатор. Хост отправляет на MAC назначения.

Не редактируйте рабочую таблицу маршрутизации без плана. Не добавляйте маршрут по умолчанию на неверный следующий хоп. Можно обрезать собственный путь управления.

В Linux `ip route` показывает IPv4. `ip -6 route` показывает IPv6. В Windows `route print` показывает оба в одном виде. Читайте столбцы, прежде чем что-то менять.

## Longest prefix match

Когда два маршрута совпадают с одним назначением, устройство выбирает совпадение с самым длинным префиксом (самой конкретной маской). `/32` побеждает `/24`. `/24` побеждает `/0`.

Пример: назначение `192.168.1.50`. Маршруты: `0.0.0.0/0` через G1, `192.168.1.0/24` через интерфейс LAN, `192.168.1.50/32` через G2. Маршрут хоста `/32` побеждает.

Longest prefix match — не то же самое, что наименьшая метрика. Если у двух маршрутов одна длина префикса, устройство использует метрику, предпочтение или разделение равной стоимости. Детали зависят от ОС и от протокола маршрутизации.

Это правило позволяет переопределить путь по умолчанию для одного хоста или одной подсети. VPN может установить более конкретный префикс, чтобы только этот префикс использовал туннель.

Не добавляйте два разных следующих хопа для одного префикса без плана по метрике или ECMP. Не считайте, что меньшая метрика побеждает более длинный префикс. Длина префикса первая в обычной модели.

IPv6 использует ту же идею. `::/0` — маршрут по умолчанию. `/128` — маршрут хоста.

## Маршрут хоста против маршрута по умолчанию

Маршрут хоста — префикс, который называет один адрес. IPv4 использует `/32`. IPv6 использует `/128`. Следующий хоп может быть шлюзом или локальным интерфейсом.

Маршрут по умолчанию совпадает с каждым назначением, которое не совпало ни с одним другим маршрутом. IPv4 использует `0.0.0.0/0`. IPv6 использует `::/0`. Следующий хоп — шлюз по умолчанию.

Сетевой маршрут сидит между ними, например `/24` или `/64`. Большинство connected-маршрутов LAN — сетевые маршруты.

Используйте маршрут хоста, когда один адрес должен использовать особый путь. Используйте маршрут по умолчанию, когда не можете перечислить Internet. Не используйте маршрут по умолчанию вместо отсутствующего connected-маршрута в LAN. Если префикс LAN отсутствует, локальный трафик может пойти по пути по умолчанию и упасть.

DHCP и RA часто устанавливают маршрут по умолчанию. Статический администратор может установить маршрут хоста для адреса управления.

На хосте с двумя uplink двум маршрутам по умолчанию нужны политика или разные метрики. Этот проект больше этого раздела. Сначала поймите один маршрут по умолчанию.

## ICMP: echo, dest unreachable, time exceeded

ICMP — протокол управления для IPv4. ICMPv6 — аналог IPv6. Этот раздел использует имена IPv4. Идеи совпадают с типами ICMPv6, которые вы уже встречали (echo, neighbor, packet too big).

Echo request и echo reply — это `ping`. Они проверяют достижимость и время кругового обхода. Ответ доказывает, что путь сработал для ICMP. Отсутствующий ответ не всегда доказывает, что хост выключен. Межсетевой экран может отбросить ICMP.

Destination unreachable говорит отправителю, что пакет нельзя доставить. Коды включают network unreachable, host unreachable, port unreachable и fragmentation needed. Это сообщение может отправить маршрутизатор или хост назначения.

Time exceeded значит, что TTL (IPv4) или hop limit (IPv6) достиг нуля. Маршрутизатор отбрасывает пакет и может отправить time exceeded. Traceroute использует это сообщение.

Сообщения ICMP несут префикс исходного пакета. Эта копия помогает отправителю сопоставить ошибку с потоком.

Не блокируйте весь ICMP в сети, если хотите, чтобы работали PMTU и traceroute. Не доверяйте ICMP одному как сканеру безопасности. Не затопляйте ping цель, которой не владеете.

## `traceroute` / `mtr`

Traceroute отправляет зонды с растущим TTL. Хоп 1 истекает на первом маршрутизаторе. Хоп 2 истекает на втором маршрутизаторе. Каждый маршрутизатор может отправить time exceeded. Инструмент печатает исходный адрес этого сообщения и время кругового обхода.

Windows использует `tracert`. Многие системы Unix используют `traceroute`. `mtr` (или WinMTR) повторяет зонды и показывает потери и задержку на хоп.

Хоп, который показывает звёзды (`*`), не отправил полезный ответ вовремя. Маршрутизатор может ограничивать ICMP. Межсетевой экран может отбросить зонд. Путь всё равно может работать для TCP.

Адрес, который вы видите, — адрес входящего интерфейса, который маршрутизатор использует для отправки ICMP, в обычных случаях. Это не всегда адрес, который ваш пакет использовал как следующий хоп. Балансировка нагрузки может показывать разные хопы в разных запусках.

Не считайте traceroute юридической картой чужой сети. Не запускайте агрессивный `mtr` против хоста, которым не владеете.

Существуют варианты traceroute UDP, ICMP и TCP. Межсетевые экраны относятся к ним по-разному. Если UDP traceroute падает, TCP traceroute на порт 443 всё ещё может показать хопы.

## Статический маршрут против динамической маршрутизации (обзор: OSPF, BGP)

Статический маршрут — строка, которую пишет администратор. Строка остаётся, пока человек или скрипт её не изменят. Статические маршруты подходят маленькой сети или особому исключению.

Динамический протокол маршрутизации обновляет таблицу из сообщений. Соседи делятся префиксами. Протокол вычисляет путь. Когда канал умирает, таблица может измениться без человека.

OSPF — обычный внутренний протокол. Маршрутизаторы в одной организации затопляют состояние каналов и вычисляют кратчайшие пути. OSPF использует области в больших проектах. Этой теме нужно только: OSPF — для внутренней сети.

BGP — протокол Internet между автономными системами. BGP — протокол path-vector. Провайдеры и большие сети используют BGP, чтобы выбирать политику, а не только число хопов. Поздняя тема покрывает BGP. Этой теме нужно только: BGP соединяет организации.

Не запускайте BGP в домашней LAN для учёбы, если нет лаборатории. Не вставляйте полную таблицу Internet в маленький маршрутизатор.

Выбирайте static, когда сеть мала и стабильна. Выбирайте OSPF (или похожий), когда многие внутренние маршрутизаторы должны сходиться. Выбирайте BGP, когда соединяетесь с провайдерами или с другими организациями с политикой.

Маршрут по умолчанию может быть статическим или выученным. Домашний клиент DHCP учит похожий на статический маршрут по умолчанию от ящика. Ящик может использовать маршрут по умолчанию к провайдеру.

## Обзор темы

Эти вопросы не повторяют вопросы в разделах выше. Они покрывают всю тему.

### Вопросы

#### Теоретические вопросы

1. Опишите поиск пакета от IP назначения до MAC следующего хопа. Используйте таблицу, longest prefix и ICMP, если поиск падает.
2. Как маршруты хоста, сетевые маршруты и маршрут по умолчанию делят одну таблицу без конфликта?
3. Почему ping и traceroute оба используют ICMP, но отвечают на разные вопросы?
4. Когда статического маршрута по умолчанию достаточно и когда нужны OSPF или BGP?
5. Хоп показывает `*` в traceroute, но сайт загружается. Какие факты объясняют этот результат?

#### Простые практические задания

1. Напишите шпаргалку на одну страницу: таблица, LPM, маршрут хоста, маршрут по умолчанию, типы ICMP, traceroute, static, OSPF, BGP.
2. Сохраните `ip route` / `route print` и один вывод `tracert` в файл. Выделите маршрут по умолчанию и хоп 1.
3. Нарисуйте маршрутизатор с тремя интерфейсами и четырьмя строками таблицы, которые придумаете. Покажите LPM для одного назначения.
4. Сделайте ping шлюза и traceroute к публичному хосту. Запишите, как хоп 1 связан со шлюзом.

#### Средние практические задания

1. Постройте бумажную таблицу с пятью маршрутами. Дайте три назначения и побеждающий маршрут для каждого.
2. Напишите план лаборатории, который использует ping, traceroute и печать таблицы маршрутизации, чтобы найти неверный шлюз по умолчанию.
3. Сравните ICMPv4 time exceeded и ICMPv6 time exceeded в таблице из двух столбцов. Используйте захват, если можете.

#### Сложные практические задания

1. Напишите глоссарий из 12 терминов маршрутизации. Каждая запись: термин, одно предложение, одна команда или тип ICMP.
2. Спроектируйте лабораторию из трёх маршрутизаторов (рисунок или симуляция): один статический маршрут, один по умолчанию, одна заметка OSPF. Предскажите traceroute с хоста.

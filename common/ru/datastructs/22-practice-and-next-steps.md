# 22. Практика и следующие шаги

## Описание

Эта тема превращает путь в план практики. Вы реализуете ядерный набор структур, решаете задачи, которые вынуждают выбор, читаете одну реальную реализацию и планируете более глубокое изучение алгоритмов. Завершите эту тему после тем 1–21. Используйте её как контрольный список, не как новую главу теории.

Используйте один термин для каждого понятия. **Ядерная реализация** — структура, которую вы пишете по памяти и тестируете. **Вынужденный выбор** — задача, которая не называет структуру. **Реальная реализация** — производственный исходник, который вы читаете. **Следующий курс** — алгоритмы за пределами этого пути структур данных.

## Реализуйте: динамический массив, стек, очередь, хеш-отображение, BST, куча, BFS/DFS графа

Напишите каждый пункт на языке, который знаете. Скройте расположение за ADT. Тестируйте пустой, один элемент и больший случай. Печатайте стоимости там, где тема просила высоту, коэффициент заполнения или расстояние.

**Динамический массив.** Ручное изменение размера (часто ×2). Append, get, set, length. Знайте амортизированный append.

**Стек.** Push, pop, peek. Массив или список. Вычислите одно постфиксное выражение.

**Очередь.** Enqueue, dequeue, front. Кольцевой буфер или список. Не используйте стек как очередь.

**Хеш-отображение.** Раздельного связывания достаточно. Хеш, insert, find, delete, изменение размера при коэффициенте заполнения. Ключи должны быть стабильными.

**BST.** Insert, search, симметричный обход, height, delete с преемником. Также постройте вырожденный случай намеренно. Затем оставьте одно сбалансированное дерево (AVL), если завершили тему 12.

**Куча.** Мин-куча в массиве: insert, extract-min, build-heap. Используйте её как очередь с приоритетом.

**BFS и DFS графа.** Список смежности. Расстояния BFS и путь parent. Цвета или метки времени DFS. Обнаружьте ориентированный цикл.

```text
minimum kit
  array+grow   stack   queue
  hash map     BST     heap
  graph: list + BFS + DFS
```

Предлагаемый порядок (тот же, что список тем):

1. Динамический массив с ручным изменением размера
2. Стек и постфиксный вычислитель
3. Хеш-отображение с цепочками
4. BST с печатью симметричного обхода
5. Очередь с приоритетом двоичной кучи
6. Кратчайший путь BFS на сетке
7. Union-Find на запросах связности
8. Бор для автодополнения
9. Прочитайте диаграмму B+-дерева. Напишите, почему база данных использует одно
10. Дерево отрезков для сумм диапазона

Пункты 7–10 расширяют минимальный набор. Делайте их после семи имён в заголовке.

Не копируйте полную библиотеку и не называйте это готовым. Напишите операции. Сохраните файлы. Вы перечитаете их.

Срез или map языка — не замена реализации. Используйте языковой тип после того, как можете написать студенческую версию.

## Решайте задачи, которые вынуждают выбрать структуру

Задача **вынужденного выбора** формулирует операции и ограничения. Она не говорит «используй кучу». Вы выбираете ADT и реализацию.

Как вы выбираете:

1. Запишите операции (insert, delete, find, extract-extreme, range, prefix, connect).
2. Запишите ограничения (отсортировано?, взвешено?, память?, много запросов?).
3. Выберите ADT. Затем выберите реализацию. Назовите класс стоимости.
4. Если две структуры подходят, выберите более простую, которая выполняет оценку.

```text
examples of a force
  "return the minimum each time"           →  heap or sorted set
  "is x in the set, average fast"          →  hash set
  "iterate keys in order"                  →  balanced tree or skip list
  "shortest unweighted path"               →  BFS
  "range sum with updates"                 →  Fenwick or segment tree
  "are u and v connected after unions"     →  Union-Find
  "words with this prefix"                 →  trie
```

Конкурсные задачи и рабочие задачи часто прячут структуру в истории. Сначала переведите историю в операции.

Не начинайте со структуры, которую хотите практиковать, если она не выполняет операции. Практикуйте эту структуру на другой задаче.

Ведите журнал: имя задачи, операции, структура, одно предложение о стоимости. Журнал — продукт обучения.

Неверные выборы полезны. Если список слишком медленный, напишите почему. Затем замените его.

Смешивайте простые задачи (одна структура) со средними задачами (две структуры, например хеш-отображение плюс куча).

Этот справочник не включает решения задач. Он включает метод. Используйте онлайн-судью или книгу только как источник формулировок.

## Прочитайте одну реальную реализацию (срез/map Go, Java HashMap, Redis SDS/skiplist)

Прочитайте **одну** производственную реализацию вглубь. Просмотра недостаточно. Проследите одну операцию от публичной функции до расположения в памяти.

Выберите один трек:

- **Срез Go.** Рост, ёмкость, копия при росте, заголовок среза (указатель, длина, ёмкость).
- **Map Go.** Корзины, overflow, хеш, рост. Map рантайма — не маленький файл. Сначала читайте комментарии.
- **Java HashMap.** Таблица, treeify длинных цепочек, изменение размера. Читайте комментарий класса.
- **Redis SDS.** Simple Dynamic String: длина, alloc, флаги. Почему Redis не использует только строки C.
- **Skiplist Redis.** Подложка отсортированного множества (с dict). Уровень, span, обратный указатель.

```text
how to read
  1. public operation
  2. struct fields
  3. one happy path (insert or append)
  4. one grow or rebalance path
  5. comments that state invariants
```

Напишите заметку на одну страницу в стиле STE: поля, инварианты, один факт стоимости, одно отличие от вашей студенческой версии.

Не читайте все пять в одну неделю. Одно глубокое чтение бьёт пять просмотров.

Укажите версию или коммит, если можете. Исходник двигается.

Реальный код может использовать битовые трюки и небезопасные преобразования. Вы не копируете их в первый студенческий файл. Вы записываете, почему они существуют (скорость, компактность).

## Затем изучайте алгоритмы глубже (доказательства сортировки, DP, предварительный взгляд на NP)

Этот путь учил структуры и алгоритмы, которым они служат (BFS, Дейкстра, MST, KMP). Следующий курс — **алгоритмы как доказательства и классы**.

**Доказательства сортировки.** Почему пирамидальная сортировка — Θ(n log n). Почему сортировка сравнениями нуждается в Ω(n log n) сравнениях в худшем случае. Почему сортировка подсчётом — не сортировка сравнениями. Вы уже реализовали пирамидальную сортировку. Теперь прочитайте доказательство.

**Динамическое программирование (DP).** Таблица DP часто массив или матрица. Новый навык — рекуррентность и аргумент, что подзадач достаточно. Структуры остаются простыми. Дизайн — алгоритм.

**Предварительный взгляд на NP.** У некоторых задач нет известного полиномиального алгоритма. Задачи решения в NP имеют короткие сертификаты. NP-полные задачи так же трудны друг как друга при сведениях. Вы не доказываете P ≠ NP здесь. Вы учитесь узнавать «это похоже на точное покрытие / SAT / TSP», чтобы не тратить месяц на полный перебор, который не масштабируется.

```text
keep
  data structures from this path
add
  proof of a bound
  DP recurrence
  a sense of NP-complete names
```

Официальные стартовые точки (из списка тем):

- CLRS — Introduction to Algorithms
- Sedgewick & Wayne — Algorithms
- VisuAlgo
- CP-Algorithms
- Документация языка для встроенных коллекций

Не бросайте практику структур, пока читаете доказательства. Перереализуйте одну структуру каждый месяц по памяти.

Работа, которая использует графы, всё ещё нуждается в BFS и Union-Find. Работа, которая использует DP, всё ещё нуждается в массивах. Следующий курс не заменяет этот путь.

Если хотите системы дальше, идите к памяти ОС, базам данных и B+-деревьям или конкурентным отображениям. Эти треки переиспользуют темы 12, 16, 19 и 21.

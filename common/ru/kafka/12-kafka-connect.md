# 12. Kafka Connect

## Описание

Kafka Connect — фреймворк, который перемещает данные между Kafka и другими системами. Source-коннектор пишет записи в Kafka. Sink-коннектор читает записи из Kafka и пишет их в другую систему.

Эта тема покрывает source- и sink-коннекторы, задачи и конвертеры, single message transforms (SMT), очереди dead letter и обычные коннекторы (JDBC, S3, Elasticsearch, Debezium). Завершите эту тему после тем 4, 5 и 11. Воркеры Connect говорят с кластером Kafka. Используйте KRaft для этого кластера. Не добавляйте ZooKeeper для новой работы.

Используйте один термин для каждого понятия. Коннектор — плагин, который определяет, как движутся данные. Задача — единица работы, которую воркер запускает для коннектора. Конвертер превращает байты в данные Connect и обратно. SMT меняет одну запись в воркере. Очередь dead letter — топик, который хранит записи, которые не удались.

## Source- и sink-коннекторы

Source-коннектор читает внешнюю систему и производит записи в топики Kafka. Примеры: таблица базы данных, каталог файлов, API сообщений.

Sink-коннектор потребляет топики Kafka и пишет во внешнюю систему. Примеры: объектное хранилище, поисковый индекс, хранилище.

Connect работает как один или несколько воркеров. Режим standalone использует один процесс и локальный файл для офсетов. Распределённый режим использует группу воркеров. Распределённый режим хранит конфигурацию коннекторов, офсеты и статус в топиках Kafka. Эти топики — внутренние топики Connect. Не используйте их как прикладные топики.

Вы отправляете конфигурацию коннектора (JSON через REST API или файл в режиме standalone). Конфигурация называет класс коннектора, топики или таблицы и конвертеры. Воркеры запускают коннектор.

Connect не замена каждому своему продюсеру или консьюмеру. Используйте Connect, когда существует поддерживаемый коннектор и вы хотите старт, стоп и масштаб в одном месте.

Кластер Kafka может быть KRaft. Connect не нужен ZooKeeper. Воркеры используют `bootstrap.servers`. Инструменты admin кластера используют `--bootstrap-server`.

Типичные свойства воркера:

```text
bootstrap.servers=localhost:9092
group.id=connect-cluster
key.converter=...
value.converter=...
config.storage.topic=connect-configs
offset.storage.topic=connect-offsets
status.storage.topic=connect-status
```

Создайте эти внутренние топики с фактором репликации, который кластер может поддержать. На учебном кластере из одного брокера используйте фактор репликации 1.

## Задачи и конвертеры

Коннектор может запустить одну или несколько задач. Задача — единица процесса, которая копирует срез работы. Для source задачи могут делить таблицы или диапазоны запросов. Для sink задачи могут делить партиции топика.

`tasks.max` в конфигурации коннектора — верхний предел. Коннектор может запустить меньше задач. Одна задача не может быть больше работы, которую коннектор может разделить. Пример: sink не может полезно использовать больше задач, чем число назначенных партиций.

Конвертер сериализует и десериализует ключи и значения записей на границе Connect. Обычные конвертеры:

- `StringConverter` для простого текста
- `JsonConverter` для JSON
- конвертеры Avro, Protobuf или JSON Schema, которые говорят с Schema Registry (тема 11)

Конвертер на выходе source должен совпадать с тем, чего ждут консьюмеры. Конвертер на входе sink должен совпадать с тем, что на топике. Несовпадение даёт ошибки или мусорные поля.

У Connect есть конвертер ключа и конвертер значения. Могут существовать конвертеры заголовков. Задавайте их в значениях воркера по умолчанию и переопределяйте на коннекторе при необходимости.

Не путайте конвертер с SMT. Конвертер меняет кодировку. SMT меняет содержимое записи или маршрутизацию после того, как конвертер произвёл данные Connect.

Внутренние топики Connect часто используют JSON-конвертер. Прикладные топики могут использовать конвертер Registry. Читайте документацию коннектора для требуемой пары.

## SMT (single message transforms)

Single message transform (SMT) — функция, которую воркер применяет к одной записи. SMT выполняется в Connect, не в вашем приложении.

Типичные действия SMT:

- переименовать или удалить поле
- сменить имя топика (маршрут)
- вставить статическое поле
- замаскировать значение
- расплющить вложенную структуру

Вы цепляете SMT в конфигурации коннектора. Порядок в списке — порядок выполнения. Поздний SMT видит выход более раннего SMT.

SMT не заменяют обработку потоков. SMT должен оставаться простым. У него нет окна и нет join между записями. Для агрегаций используйте Kafka Streams, ksqlDB или Flink (тема 13).

Плохой SMT может удалить обязательные поля или сломать контракт конвертера. Тестируйте SMT сначала на лабораторном топике.

Не кладите секреты в статические поля SMT. Не используйте SMT как единственный механизм контроля доступа. Тема 17 покрывает ACL и шифрование.

Пример ключей конфигурации (имена могут отличаться по версии):

```text
transforms=MaskCard
transforms.MaskCard.type=...
transforms.MaskCard.fields=card_number
```

Прочитайте официальный список SMT для вашей версии Connect. Могут существовать трансформации конкретного коннектора. Предпочитайте поддерживаемые трансформации.

## Очереди dead letter

Очередь dead letter (DLQ) в Connect — топик Kafka, который принимает записи, которые коннектор не может обработать. Типичные причины: ошибка конвертера, ошибка SMT или отказ внешней системы.

Без DLQ ядовитая запись может заблокировать задачу sink. Задача повторяет и не движется вперёд. С DLQ воркер может написать неудачную запись (и заголовки ошибки) в топик DLQ и продолжить.

Включайте DLQ только когда коннектор и ваша версия это поддерживают. Имена конфигурации включают `errors.tolerance` и имя топика DLQ. Прочитайте текущую страницу обработки ошибок Connect для точных ключей.

DLQ — обычный топик Kafka. Задайте ретеншн. Задайте фактор репликации, который соответствует нуждам устойчивости на KRaft. Читайте DLQ отдельным процессом. Исправьте запись или отображение. Не игнорируйте растущий DLQ.

DLQ — не очередь повторов с расписанием. Повторы Connect — отдельная настройка. Не считайте объём DLQ успехом.

Source-коннекторы тоже могут падать. Некоторые source пишут ошибки только в логи. Читайте документацию коннектора.

Тема 4 описывает ядовитые сообщения на пути продюсера. DLQ Connect — эксплуатационный инструмент на пути Connect.

## Обычные коннекторы: JDBC, S3, Elasticsearch, Debezium (CDC)

**JDBC source** читает таблицы или запросы через JDBC и пишет строки в Kafka. Вы выбираете incrementing-режим, timestamp-режим или bulk-режим. Incrementing-режиму нужен растущий идентификатор. Timestamp-режиму нужна надёжная колонка метки времени. Bulk-режим копирует полный результат на каждый poll. Не используйте bulk-режим по умолчанию для больших таблиц.

**JDBC sink** пишет записи Kafka в таблицы. Нужно отобразить поля на колонки. Конфигурация первичного ключа управляет upsert против insert.

**S3 sink** пишет записи в объектное хранилище (Amazon S3 или совместимый с S3 API). Коннектор группирует записи в файлы. Вы задаёте формат (JSON, Avro, Parquet) и размер или интервал flush. Объектное хранилище — не шина сообщений. Читатели S3 видят файлы, не живую группу консьюмеров.

**Elasticsearch sink** пишет записи в индекс. Идентификатор документа часто приходит из ключа записи. Mapping и настройки индекса принадлежат Elasticsearch. Конвертер или SMT должен произвести документ, который индекс принимает.

**Debezium** — проект CDC (change data capture). Коннектор Debezium читает журнал транзакций базы данных (WAL, binlog или эквивалент) и пишет события изменений в Kafka. CDC — не то же самое, что poll JDBC. CDC может захватывать удаления и порядок фиксаций. Нужно задать права базы данных и политику снимка. Коннекторы Debezium часто работают на Kafka Connect.

Устанавливайте плагины коннекторов в путь плагинов Connect. Фиксируйте версии плагинов. Читайте лицензию коннектора. Некоторые коннекторы не часть Apache Kafka.

Всем этим коннекторам нужен работающий кластер Kafka KRaft (или другой кластер API Kafka, который вы принимаете). Они не запускают ZooKeeper.

2. Напишите продакшен-стандарт Connect: только KRaft, фиксации плагинов, политика конвертеров, ревью SMT, runbook DLQ и без ZooKeeper.

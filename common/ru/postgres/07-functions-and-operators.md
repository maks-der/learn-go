# 7. Функции и операторы

## Описание

Эта тема показывает распространённые функции и операторы в PostgreSQL 16 и PostgreSQL 17. Вы узнаёте строковые, датные и математические функции. Узнаёте `COALESCE`, `NULLIF`, `GREATEST` и `LEAST`. Также узнаёте сопоставление с образцом, короткий превью полнотекстового поиска и JSON-операторы.

Сначала завершите тему 6. Вы умеете писать соединения и CTE. Завершите эту тему до изучения индексов.

Используйте один термин для каждого понятия. Функция возвращает значение из аргументов. Оператор — символ вроде `||` или `@>`. В прикладном SQL предпочитайте задокументированные имена функций. Предпочитайте операторы, когда это обычная форма (`||` для текста, `@>` для `jsonb`).

## Строковые, датные и математические функции

Строковые функции работают с `text` и `varchar`.

```sql
SELECT length('PostgreSQL');
SELECT char_length('PostgreSQL');
SELECT lower('ABC'), upper('abc');
SELECT trim(BOTH ' ' FROM '  nail  ');
SELECT substring('washer' FROM 1 FOR 3);
SELECT left('washer', 3), right('washer', 2);
SELECT replace('red nail', 'red', 'blue');
SELECT split_part('a,b,c', ',', 2);
SELECT position('SQL' IN 'PostgreSQL');
```

`||` конкатенирует текст. `NULL` в выражении `||` делает результат `NULL`. Используйте `concat` или `concat_ws`, когда нужно пропустить `NULL`:

```sql
SELECT 'a' || NULL;           -- NULL
SELECT concat('a', NULL, 'b'); -- ab
SELECT concat_ws(',', 'a', NULL, 'c');
```

Функции даты и времени:

```sql
SELECT now();
SELECT current_date;
SELECT date_trunc('hour', now());
SELECT extract(year FROM DATE '2026-09-13');
SELECT date_part('month', DATE '2026-09-13');
SELECT age(DATE '2026-01-01');
SELECT DATE '2026-09-13' + INTERVAL '1 month';
SELECT timestamptz '2026-09-13 12:00:00+00' AT TIME ZONE 'Europe/Kyiv';
```

`date_trunc` обрезает метку времени до единицы (час, день, месяц). `extract` возвращает поле как `numeric`. `age` возвращает `interval`.

Математические функции:

```sql
SELECT abs(-3);
SELECT round(12.56, 1);
SELECT ceil(12.1), floor(12.9);
SELECT mod(10, 3);
SELECT power(2, 10);
SELECT sqrt(9);
```

Целочисленное деление усекает. Используйте `numeric`, когда нужно десятичное деление.

`generate_series` строит множество значений:

```sql
SELECT * FROM generate_series(1, 5);
SELECT * FROM generate_series(
    timestamp '2026-01-01',
    timestamp '2026-01-07',
    interval '1 day'
);
```

Читайте официальные главы функций, когда нужна функция, которой нет в этом списке. Не выдумывайте имена из других баз (`IFNULL`, `DATEDIFF`). В PostgreSQL используют `COALESCE` и вычитание дат.

## `COALESCE`, `NULLIF`, `GREATEST`, `LEAST`

`COALESCE(a, b, ...)` возвращает первый аргумент, который не `NULL`.

```sql
SELECT COALESCE(NULL, NULL, 'nail');
SELECT COALESCE(nickname, email, 'unknown') FROM users;
```

Используйте `COALESCE`, чтобы заменить `NULL` в отображении и в математике (`COALESCE(qty, 0)`).

`NULLIF(a, b)` возвращает `NULL`, когда `a` равно `b`. Иначе возвращает `a`.

```sql
SELECT NULLIF(0, 0);          -- NULL
SELECT NULLIF(qty, 0);        -- NULL when qty is 0
SELECT 100 / NULLIF(qty, 0);  -- avoids division by zero; result NULL
```

`GREATEST(a, b, ...)` возвращает наибольший аргумент. `LEAST` возвращает наименьший. В PostgreSQL эти функции пропускают аргументы `NULL`. Они возвращают `NULL` только когда каждый аргумент `NULL`.

```sql
SELECT GREATEST(1, 5, 3);
SELECT LEAST(1, 5, 3);
SELECT GREATEST(1, NULL, 3);  -- 3
SELECT GREATEST(NULL, NULL);  -- NULL
```

Некоторые другие базы возвращают `NULL` из `GREATEST`, когда любой аргумент `NULL`. Не копируйте это правило в PostgreSQL.

`GREATEST` и `LEAST` нужен общий тип. Смешивайте типы осторожно. Используйте явное приведение, когда тип неясен.

Эти функции не агрегаты. Агрегаты — `max` и `min` по строкам. `GREATEST` сравнивает значения в одной строке.

```sql
SELECT max(qty) FROM items;           -- aggregate
SELECT GREATEST(qty, min_qty) FROM items; -- per row
```

## Сопоставление с образцом: `LIKE`, `SIMILAR TO`, POSIX regex

В PostgreSQL три системы образцов.

**`LIKE` / `ILIKE`** (тема 3): `%` и `_`. `ILIKE` без учёта регистра. Легко выучить. Хватает для многих фильтров.

**`SIMILAR TO`** использует регулярные выражения стандарта SQL. Образец должен совпасть со всей строкой. Синтаксис похож на `LIKE` плюс дополнительные токены (`|`, `*`, `+`, скобки).

```sql
SELECT name FROM items WHERE name SIMILAR TO '%(nail|screw)%';
```

**POSIX-регулярные выражения** используют операторы:

| Оператор | Смысл |
| --- | --- |
| `~` | совпадение, с учётом регистра |
| `~*` | совпадение, без учёта регистра |
| `!~` | нет совпадения, с учётом регистра |
| `!~*` | нет совпадения, без учёта регистра |

```sql
SELECT name FROM items WHERE name ~ '^[Nn]ail';
SELECT name FROM items WHERE name ~* 'nail';
```

POSIX-образцы могут совпасть с подстрокой. `%` с обоих концов не нужны.

Функции:

```sql
SELECT substring('item-42' FROM '[0-9]+');
SELECT regexp_match('item-42', '[0-9]+');
SELECT regexp_replace('a1b2', '[0-9]', 'x', 'g');
SELECT regexp_split_to_table('a,b,c', ',');
```

`regexp_match` возвращает `text[]`. `regexp_matches` может вернуть много строк.

Какую форму использовать:

- `LIKE` / `ILIKE` — префикс и простое «содержит»
- `SIMILAR TO` — редко; некоторые команды его пропускают
- POSIX — проверка, извлечение, сложный поиск

Ведущий шаблон или сложный regex часто не могут использовать обычный индекс B-tree. `pg_trgm` (тема 13) может поддерживать `LIKE '%x%'` и часть regex индексом GIN или GiST.

Не запускайте недоверенный пользовательский regex без лимита времени. Плохой образец может съесть много CPU. Задайте `statement_timeout` на прикладных ролях.

## Превью полнотекстового поиска (`tsvector`, `tsquery`)

Полнотекстовый поиск находит слова в документах. Это не `LIKE '%word%'`. PostgreSQL стеммит слова, отбрасывает стоп-слова и ранжирует результаты.

`tsvector` — отсортированный список лексем. `tsquery` — поисковый запрос.

```sql
SELECT to_tsvector('english', 'The nails were shining');
SELECT to_tsquery('english', 'nail');
SELECT to_tsvector('english', 'The nails were shining')
       @@ to_tsquery('english', 'nail');
```

`@@` значит «вектор совпадает с запросом». Стемминг сопоставляет `nails` с `nail` в конфигурации `english`.

Создайте генерируемый столбец или хранимый `tsvector` для таблицы (тема 13 разбирает генерируемые столбцы):

```sql
CREATE TABLE posts (
    id      bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    title   text NOT NULL,
    body    text NOT NULL,
    tsv     tsvector GENERATED ALWAYS AS (
                to_tsvector('english', title || ' ' || body)
            ) STORED
);
```

Поиск:

```sql
SELECT id, title
FROM posts
WHERE tsv @@ to_tsquery('english', 'nail & shine')
ORDER BY ts_rank(tsv, to_tsquery('english', 'nail & shine')) DESC;
```

Формы запросов:

- `to_tsquery` — операторы `&` `|` `!` и скобки; лексемы пишете сами
- `plainto_tsquery` — обычный текст в AND слов
- `websearch_to_tsquery` — строка в веб-стиле (кавычки, `-`)
- `phraseto_tsquery` — фраза

Для больших таблиц используйте индекс GIN на `tsvector` (тема 8).

Этот раздел — превью. Словари, веса (`setweight`) и ранжирование требуют дополнительного чтения в официальной главе «Full Text Search».

Не используйте полнотекстовый поиск для точного поиска SKU. Используйте `=` или префикс `LIKE`. Не смешивайте языки в одном столбце `english` без плана.

## JSON-операторы: `->`, `->>`, `@>`, `?`

Эти операторы работают с `json` и `jsonb`. Для операторов и индексов предпочитайте `jsonb`.

| Оператор | Смысл |
| --- | --- |
| `->` | получить поле объекта или элемент массива JSON; результат `json` / `jsonb` |
| `->>` | получить поле или элемент как `text` |
| `@>` | содержит ли левый `jsonb` правый `jsonb`? |
| `?` | есть ли у объекта этот ключ верхнего уровня? |

```sql
CREATE TABLE events (
    id      bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    payload jsonb NOT NULL
);

INSERT INTO events (payload) VALUES
    ('{"type":"click","n":2,"tags":["a","b"]}');

SELECT payload -> 'type'     AS as_json;
SELECT payload ->> 'type'    AS as_text;
SELECT payload -> 'n';
SELECT (payload ->> 'n')::int;
SELECT payload @> '{"type":"click"}';
SELECT payload ? 'type';
```

`->` сохраняет тип JSON. `->>'type'` это `text`. Приводите текст к `integer`, когда нужна математика.

Индекс массива через `->` для массивов JSON начинается с 0:

```sql
SELECT payload -> 'tags' -> 0;
SELECT payload -> 'tags' ->> 0;
```

Смежные операторы (выучите имена):

- `?|` — существует любой из этих ключей
- `?&` — существуют все эти ключи
- `||` — конкатенировать `jsonb`
- `-` — удалить ключ

```sql
SELECT payload ?| ARRAY['type','missing'];
SELECT payload - 'n';
```

`@>` — обычный фильтр для индекса GIN `jsonb` (тема 8, тема 14).

Не используйте `->>` в горячем `WHERE`, если можно написать `@>` или хранимый столбец. Приведение `->>` может блокировать простой индекс, пока не создадите индекс по выражению.

PostgreSQL 17 добавляет больше возможностей SQL/JSON, например `JSON_TABLE`. Этот справочник сначала использует операторы, которые нужны на 16 и 17.

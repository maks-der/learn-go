# 5. Функции

## Описание

Функция — это именованный блок операторов. Вы объявляете функцию один раз. Вы вызываете функцию много раз. Эта тема показывает, как писать функции, как возвращать значения и как использовать функции как значения.

Функции в Go могут возвращать больше одного значения. Частый шаблон — результат и ошибка. Поздние темы используют этот шаблон в каждой программе.

Функция может захватывать переменные из внешнего блока. Такая функция — замыкание (`closure`). Функция может вызывать саму себя. Такой вызов — рекурсия. Функция `init` выполняется до `main`. `panic` останавливает обычный поток управления.

Используйте функции, чтобы делить работу. Дайте каждой функции одну ясную задачу. Возвращайте ошибки для ожидаемых сбоев. Используйте `panic` только для неисправностей, которые программа не может обработать.

## Объявление функции и вызов

Объявление функции начинается с `func`. Дальше идёт имя. Дальше идут параметры в круглых скобках. Дальше идёт тип результата, если функция возвращает значение. Тело — это блок.

```go
package main

import "fmt"

func add(a int, b int) int {
	return a + b
}

func main() {
	sum := add(2, 3)
	fmt.Println(sum)
}
```

Соседние параметры одного типа могут делить одно имя типа. `func add(a, b int) int` совпадает с `func add(a int, b int) int`.

Вызов `add(2, 3)` вычисляет аргументы. Затем вызов выполняет тело. Оператор `return` завершает функцию и передаёт результат вызывающему коду.

Функция без типа результата не возвращает значение. `func main()` — точка входа программы. Запрещено объявлять именованную функцию внутри другой функции. Можно объявить анонимную функцию внутри функции.

Пакет (`package`) идентифицирует функцию по имени. Типы параметров не создают вторую функцию с тем же именем. Две функции в одном пакете не могут иметь одно имя. Методы разных типов могут делить имя. Следующая тема разбирает методы.

Вызывайте функцию с верным числом аргументов. Типы аргументов должны совпадать с типами параметров. Go не преобразует типы в вызове.

## Несколько результатов

Функция может возвращать больше одного результата. Пишите типы результатов в круглых скобках.

```go
func div(a, b int) (int, error) {
	if b == 0 {
		return 0, fmt.Errorf("divide by zero")
	}
	return a / b, nil
}
```

Частый шаблон — `(value, error)`. Последний результат часто имеет тип `error`. Ошибка `nil` означает успех. Ненулевая ошибка означает сбой. Проверяйте ошибку до использования значения.

Вызывающий код получает каждый результат. Используйте `:=` или `=` с тем же числом имён.

```go
q, err := div(10, 2)
if err != nil {
	fmt.Println(err)
	return
}
fmt.Println(q)
```

Используйте пустой идентификатор `_`, когда нужно игнорировать один результат. Игнорируйте результат только при ясной причине. Не игнорируйте результат типа `error`.

Функция может возвращать два или больше значений, которые не являются ошибками. Пример: `func split(s string) (string, string)`. Назовите каждый результат так, чтобы вызывающий код видел смысл.

Оператор `return` должен перечислить одно выражение для каждого типа результата. Типы должны совпадать. Go не позволяет пропустить результат в `return`, если результаты не именованы.

## Именованные результаты

Можно именовать параметры результата. Имена становятся переменными в теле функции. Go задаёт им нулевое значение в начале.

```go
func rect(w, h int) (area int, perim int) {
	area = w * h
	perim = 2 * (w + h)
	return
}
```

Оператор `return` без выражений — голый `return`. Голый `return` возвращает текущие именованные результаты. Используйте голый `return` только в короткой функции. Длинная функция с голым `return` трудна для чтения.

Можно всё равно написать `return area, perim`. Эта форма ясна. Предпочитайте явный `return`, когда функция длиннее нескольких строк.

Отложенная функция может изменить именованный результат. Изменение происходит после начала `return` и до того, как функция вернёт управление.

```go
func wrapped() (err error) {
	defer func() {
		if err != nil {
			err = fmt.Errorf("wrapped: %w", err)
		}
	}()
	return fmt.Errorf("fail")
}
```

Именованные результаты остаются типами в сигнатуре. Вызывающему коду не нужно использовать те же имена. Имена документируют результаты.

Не смешивайте голый `return` со многими путями выхода. Читатель не видит значения на каждом выходе.

## Вариативные функции (`...T`)

Вариативный параметр принимает ноль или больше аргументов одного типа. Пишите `...T` как последний параметр. Внутри функции этот параметр — `slice` типа `[]T`.

```go
func sum(nums ...int) int {
	total := 0
	for _, n := range nums {
		total += n
	}
	return total
}

func main() {
	fmt.Println(sum())
	fmt.Println(sum(1, 2, 3))
}
```

Только последний параметр может быть вариативным. `func bad(x ...int, y int)` недопустима.

Можно передать существующий `slice` с `...` после `slice`. `sum(values...)` передаёт элементы. Вызов не копирует новый список параметров в исходном тексте. Функция всё равно видит `slice`.

```go
values := []int{4, 5, 6}
fmt.Println(sum(values...))
```

`append` — встроенная вариативная функция. `fmt.Println` тоже вариативная. Вы уже вызываете обе.

Пустой вызов `sum()` даёт `slice` длины ноль. `slice` может быть `nil`. Обход этого `slice` через `range` безопасен.

Не смешивайте аргумент-`slice` и дополнительные элементы в одном вызове. `sum(values..., 9)` недопустима.

## Функции как значения

Функция — это значение. Можно присвоить функцию переменной. Можно передать функцию как аргумент. Можно вернуть функцию.

Тип функции — её сигнатура. `func(int) int` — это тип. Две функции имеют один тип, когда типы параметров и типы результатов совпадают. Имена в сигнатуре не входят в тип.

```go
func square(n int) int { return n * n }

func apply(n int, fn func(int) int) int {
	return fn(n)
}

func main() {
	f := square
	fmt.Println(apply(4, f))
}
```

Нулевое значение типа функции — `nil`. Вызов значения функции `nil` вызывает `panic`. Проверяйте `nil`, когда параметр-функция необязателен.

Анонимная функция не имеет имени. Вы пишете `func(...) ... { ... }`. Можно вызвать её сразу.

```go
msg := func(s string) {
	fmt.Println(s)
}
msg("hello")
```

Используйте значения функций для обратных вызовов и для небольших стратегий. Пример: сортировка `slice` с функцией «меньше». Держите сигнатуры короткими.

Не храните много несвязанных значений функций в одном пакете без имён, которые показывают работу.

## Замыкания

Замыкание — это значение функции, которое ссылается на переменные внешнего блока. Функция может читать эти переменные. Функция может присваивать этим переменным.

```go
func counter() func() int {
	n := 0
	return func() int {
		n++
		return n
	}
}

func main() {
	next := counter()
	fmt.Println(next())
	fmt.Println(next())
}
```

Внутренняя функция держит `n` живой после возврата из `counter`. Каждый вызов `counter` создаёт новый `n`. Два счётчика не делят состояние.

Замыкание захватывает переменную, а не копию текущего значения. Поздние изменения переменной видны внутри замыкания.

Go 1.22 даёт каждой итерации цикла `for` свою переменную цикла. Замыкания, которые захватывают переменную цикла в Go 1.22, видят значение этой итерации. Старые версии Go повторно использовали одну переменную. Пишите новый код для Go 1.22 или новее.

```go
var fns []func()
for i := range 3 {
	fns = append(fns, func() { fmt.Println(i) })
}
```

В Go 1.22 это печатает `0`, `1` и `2`, когда вы вызываете каждую функцию. Не копируйте старые обходы переменной цикла, если вы не поддерживаете старые версии Go.

Используйте замыкания для небольшого состояния. Не прячьте большое изменяемое состояние во многих замыканиях. Предпочитайте `struct`, когда у состояния несколько полей.

## Рекурсия

Рекурсия — это вызов функции самой себя. Каждый вызов должен двигаться к базовому случаю. Базовый случай возвращает управление без нового рекурсивного вызова.

```go
func fact(n int) int {
	if n <= 1 {
		return 1
	}
	return n * fact(n-1)
}
```

Используйте ясный базовый случай. Отсутствующий базовый случай вызывает бесконечную рекурсию. Бесконечная рекурсия растёт стек. Затем программа паникует из-за переполнения стека.

Go не гарантирует оптимизацию хвостового вызова. Глубокий рекурсивный вызов может переполнить стек даже когда последнее действие — вызов. Используйте цикл, когда глубина может быть большой.

Рекурсия подходит деревьям, вложенным структурам и алгоритмам «разделяй и властвуй». `slice` или число с небольшой границей можно обработать рекурсией для обучения.

Рекурсивная функция может иметь больше одного рекурсивного вызова. Пример: обход дерева, который посещает левого и правого потомка.

Держите рекурсивную функцию чистой, когда можете. Передавайте нужные данные как параметры. Не прячьте прогресс в глобальной переменной.

## Функции `init()`

Функция `init` имеет такой вид:

```go
func init() {
	fmt.Println("init runs")
}
```

Вы не вызываете `init`. Среда выполнения вызывает `init` во время инициализации пакета. У `init` нет параметров и нет результатов. Нельзя ссылаться на `init` по имени.

Инициализация пакета идёт в таком порядке:

1. Среда выполнения сначала инициализирует импортированные пакеты.
2. Среда выполнения инициализирует переменные уровня пакета в текущем пакете.
3. Среда выполнения выполняет функции `init` в текущем пакете.
4. После инициализации всех пакетов среда выполнения вызывает `main` в пакете `main`.

Один файл может иметь больше одной функции `init`. Эти функции выполняются в порядке исходного текста. Команда `go` подаёт файлы компилятору в фиксированном порядке имён. Не зависьте от порядка файлов в пакете, если можете этого избежать.

Пустой импорт `_ "pkg"` импортирует пакет только ради побочных эффектов `init`. Драйверы баз данных используют этот шаблон. Такой импорт легко пропустить при обзоре.

Избегайте многих функций `init`. Они прячут работу. Тесты не могут их пропустить. Порядок старта между пакетами трудно увидеть. Предпочитайте экспортированную функцию `Setup`, которую вызывает `main`.

Используйте `init` только для регистрации, которая должна выполниться при старте. Пример: зарегистрировать драйвер. Держите `init` коротким. Не читайте файлы и не запускайте серверы в `init` без веской причины.

## `panic` и `recover`

`panic` останавливает обычное выполнение текущей горутины (`goroutine`). Среда выполнения выполняет отложенные функции. Затем программа аварийно завершается, если отложенная функция не вызывает `recover`.

```go
func mustPositive(n int) {
	if n < 0 {
		panic("n must be >= 0")
	}
}
```

Ошибка — это значение. Вы возвращаете ошибку для ожидаемых сбоев. Примеры: отсутствующий файл, неверный ввод пользователя, тайм-аут сети. Вызывающий код проверяет ошибку и выбирает следующий шаг.

`panic` нужен для неисправности, которую программа не может обработать чистым способом. Примеры: нарушенный инвариант, разыменование `nil`, индекс вне диапазона. Считайте `panic` ошибкой в программе или последней остановкой.

`recover` останавливает `panic`. `recover` работает только внутри отложенной функции. `recover` возвращает значение, которое передали в `panic`. `recover` возвращает `nil`, когда `panic` нет.

```go
func safe() (err error) {
	defer func() {
		if v := recover(); v != nil {
			err = fmt.Errorf("panic: %v", v)
		}
	}()
	panic("boom")
}
```

Не используйте `panic` для обычного потока управления. Не прячьте `panic` в библиотеке без документированной границы. Некоторые серверы вызывают `recover` на границе запроса. Этот `recover` защищает процесс. Он не исправляет ошибку в программе.

Предпочитайте результаты `error` в своих функциях. Используйте `panic`, когда программа неверна и должна остановиться. Используйте `recover` только на ясной границе.

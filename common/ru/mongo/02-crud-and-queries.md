# 2. CRUD и запросы

## Описание

CRUD значит Create, Read, Update и Delete. Эта тема показывает, как вставлять документы, находить документы, менять поля, заменять документы и удалять документы. Вы также формируете результат проекцией, сортировкой, skip, limit и курсорами. Запрашиваете вложенные поля, массивы и строки.

Сначала завершите тему начала работы. Завершите эту тему до изучения моделирования данных.

Используйте один термин для каждого понятия. **insert** добавляет новый документ. **find** читает документы. **update** меняет поля в документе. **replace** пишет полное новое тело документа. **delete** удаляет документ. **upsert** обновляет совпадение или вставляет документ, если совпадения нет. **Проекция** выбирает поля в результате. **Курсор** — итератор, который сервер использует для `find`.

Все примеры используют `mongosh` и помощники коллекции вроде `db.items.insertOne`.

## `insertOne` / `insertMany`

`insertOne` пишет один документ. Сервер возвращает подтверждение и `_id` нового документа.

```javascript
db.items.insertOne({ name: "nail", qty: 100 })
```

Если `_id` опустить, MongoDB добавит ObjectId. Если задать `_id`, это значение станет ключом.

`insertMany` пишет много документов за один вызов. Передаёте массив.

```javascript
db.items.insertMany([
  { name: "pin", qty: 50 },
  { name: "bolt", qty: 20 }
])
```

По умолчанию `insertMany` останавливается на первой ошибке (`ordered: true`). Задайте `ordered: false`, чтобы продолжить после ошибки. Частая ошибка — дубликат `_id`.

Вставка — запись. Неудачная вставка не меняет коллекцию для этого документа. Не повторяйте вставку с тем же `_id`, если не хотите ошибку дубликата.

Не вызывайте `insertOne` в цикле, когда есть пакет. Используйте `insertMany` или пакетную запись. Цикл одиночных вставок медленнее.

`insertOne` и `insertMany` не заменяют существующий документ. Для этого используйте update, replace или upsert.

## `find` / `findOne` и операторы запроса

`find` возвращает курсор. Курсор — итератор по совпавшим документам. `mongosh` печатает первый пакет, когда вы вводите `find()`.

```javascript
db.items.find()
db.items.find({ qty: 100 })
```

Пустой фильтр `{}` совпадает со всеми документами. Фильтр `{ qty: 100 }` совпадает с документами, где `qty` равно 100. Равенство — режим по умолчанию. Для простого равенства `$eq` не нужен.

`findOne` возвращает один документ или `null`. Курсор не возвращает.

```javascript
db.items.findOne({ name: "nail" })
```

`findOne` — не особая команда сервера с другим правилом совпадения. Это find, который ограничивает результат одним документом.

Не используйте `find()` на большой коллекции в программе без фильтра, лимита или обоих. API не должен возвращать неограниченный результат.

`countDocuments` считает совпадения. `estimatedDocumentCount` использует метаданные. Используйте `countDocuments`, когда нужен верный счёт по фильтру.

Фильтр может использовать операторы. Оператор — ключ, который начинается с `$`.

- `$eq` — равно. `{ qty: { $eq: 100 } }` то же, что `{ qty: 100 }`.
- `$gt` — больше. `$gte`, `$lt` и `$lte` — родственные операторы.
- `$in` — значение поля есть в списке. `{ name: { $in: ["nail", "pin"] } }`.
- `$and` — все условия должны совпасть. Фильтр с несколькими полями — неявное AND.
- `$or` — хотя бы одно условие должно совпасть. Передаёте массив фильтров.
- `$exists` — поле есть (`true`) или нет (`false`). Поле со значением `null` всё равно существует.

Пример:

```javascript
db.items.find({ qty: { $gt: 10 } })
db.items.find({ $or: [ { name: "nail" }, { qty: { $lt: 5 } } ] })
db.items.find({ color: { $exists: false } })
```

`$in` — не `$or` полных документов. `$in` проверяет одно поле против списка значений.

`$and` полезен, когда нужны два оператора на одном поле. Предпочитайте простое неявное AND, когда это ясно.

Не собирайте фильтр из строки, в которую входит текст пользователя. Используйте структурированный объект.

Сравнение использует типы BSON. Строка не сравнивается как число.

## `updateOne` / `updateMany`, `replaceOne`, `deleteOne` / `deleteMany`, upsert

`updateOne` меняет первый совпавший документ. `updateMany` меняет все совпавшие документы.

Обновление использует **документ обновления** с операторами. В эти методы не передают полный документ замены.

- `$set` — задать полю значение. Создаёт поле, если его нет.
- `$unset` — удалить поле.
- `$inc` — прибавить число к числовому полю. Поле должно быть числом или отсутствовать (тогда MongoDB считает его 0).

```javascript
db.items.updateOne({ name: "nail" }, { $set: { qty: 90 } })
db.items.updateMany({ qty: { $gt: 0 } }, { $inc: { qty: -1 } })
db.items.updateOne({ name: "nail" }, { $unset: { obsolete: "" } })
```

Фильтр — первый аргумент. Обновление — второй. Отсутствующий фильтр в `updateOne` совпадает с первым документом. Это опасно. Всегда передавайте фильтр, который задумали.

`$set` может задать вложенные поля точечной нотацией: `{ $set: { "addr.city": "Oslo" } }`.

Обновления атомарны на одном документе. Два `$inc` на одном документе не теряют счёт, если используют `$inc`, а не чтение-потом-запись в клиенте.

`replaceOne` пишет новое тело документа поверх совпавшего документа. Второй аргумент — **документ замены**, а не документ операторов обновления.

```javascript
db.items.replaceOne(
  { name: "nail" },
  { name: "nail", qty: 0, unit: "box" }
)
```

Документ замены не должен содержать операторы обновления вроде `$set`. Замена становится полным содержимым, кроме `_id`. `_id` в замене менять нельзя. Замена может удалить поля, которые вы опустили. В этом смысл. В этом же риск.

`replaceOne` обновляет не больше одного документа. `replaceMany` нет.

`deleteOne` удаляет первый совпавший документ. `deleteMany` удаляет все совпавшие документы.

```javascript
db.items.deleteOne({ name: "pin" })
db.items.deleteMany({ qty: 0 })
```

Отсутствующий или пустой фильтр в `deleteMany` удаляет все документы коллекции. Всегда передавайте фильтр, который задумали. Предпочитайте `drop()`, когда хотите удалить всю коллекцию.

`deleteOne` с фильтром, который совпадает со многими документами, всё равно удаляет только один. Предпочитайте `_id`, когда нужно удалить один конкретный документ.

**Upsert** — обновление или замена, которое вставляет документ, когда ни один документ не совпал с фильтром.

```javascript
db.items.updateOne(
  { name: "wire" },
  { $set: { qty: 10 } },
  { upsert: true }
)
```

Если документ с `name: "wire"` есть, MongoDB применяет `$set`. Если нет, MongoDB создаёт документ. `replaceOne` тоже принимает `upsert: true`.

`$inc` с upsert создаёт документ и затем увеличивает.

Два upsert с одним фильтром могут вызвать ошибку дубликата ключа, если оба вставляют. Обработайте эту ошибку и повторите, либо используйте уникальный индекс по полям фильтра.

Не делайте upsert с свободным фильтром. Можно вставить документы, которые не задумали.

## Проекция, sort, skip, limit и курсоры

Проекция — второй аргумент `find` (или помощник `.project()`). Она выбирает, какие поля вернёт сервер.

Режим включения: поля в `1`.

```javascript
db.items.find({ qty: { $gt: 0 } }, { name: 1, qty: 1 })
```

`_id` включён, пока его не исключить:

```javascript
db.items.find({}, { name: 1, _id: 0 })
```

Режим исключения: поля в `0`. Нельзя смешивать включение и исключение обычных полей в одной проекции. Можно исключить `_id`, включая другие поля.

Проекция уменьшает сетевую нагрузку. Она не меняет хранимый документ. Не проецируйте хеш пароля в публичный API.

`sort` упорядочивает курсор. Передаёте поля и направление: `1` — по возрастанию, `-1` — по убыванию.

```javascript
db.items.find().sort({ qty: -1 }).limit(10)
```

`limit` задаёт максимум документов, которые вернёт курсор. `skip` пропускает столько документов в порядке сортировки, затем возвращает остальные (или лимит).

```javascript
db.items.find().sort({ name: 1 }).skip(20).limit(10)
```

Большой `skip` дорог. Сервер всё равно проходит пропущенные документы. Для глубоких страниц используйте диапазонный фильтр по ключу сортировки (`qty < lastQty`) вместо большого skip.

Всегда задавайте `sort`, когда используете `skip` и `limit`. Без сортировки порядок страниц — не стабильный контракт.

`find` возвращает **курсор**. Курсор — не полный набор результатов в памяти клиента. Сервер шлёт **пакеты**. Когда клиенту нужно больше документов, он шлёт `getMore`.

```javascript
const c = db.items.find({ qty: { $gt: 0 } })
c.forEach((doc) => { print(doc.name) })
```

`toArray` загружает все оставшиеся документы в память. Не вызывайте `toArray` на неограниченном результате.

Курсор может истечь на сервере, если клиент его не потребляет. Простой таймаут простоя на многих развёртываниях — 10 минут.

Можно задать размер пакета. Маленький пакет увеличивает число кругов. Огромный пакет увеличивает память.

Закрывайте курсор, когда останавливаетесь рано в драйвере. `explain` на курсоре показывает план.

## Точечная нотация, запросы к массивам и регулярные выражения

Встроенный документ — поле, значение которого — документ.

```javascript
{
  name: "Ann",
  addr: { city: "Oslo", zip: "0001" }
}
```

**Точечная нотация** именует путь: `"addr.city"`.

```javascript
db.people.find({ "addr.city": "Oslo" })
```

Запрос `{ addr: { city: "Oslo" } }` может не совпасть, если у `addr` ещё есть `zip`. Фильтр значит «addr равен этому точному документу». Для одного поля предпочитайте точечную нотацию.

Можно сделать `$set` вложенного поля тем же точечным путём. Массивы встроенных документов тоже используют точечную нотацию: `"items.sku"`. Этот запрос совпадает, если **любой** элемент массива имеет `sku` с этим значением.

Не используйте точку в имени поля приложения. Точка — разделитель пути.

Массивам нужны особые операторы, когда совпадение — не одно равенство.

**Равенство полному массиву** — `{ tags: ["a", "b"] }`. Важны порядок и точное содержимое.

**Равенство одному элементу** — `{ tags: "a" }`. Документ совпадает, если любой элемент равен `"a"`.

`$all` совпадает, если массив содержит все перечисленные значения (в любом порядке):

```javascript
db.posts.find({ tags: { $all: ["db", "mongo"] } })
```

`$size` совпадает с точной длиной. `$size` не принимает диапазон. Для диапазона длин храните `tagCount` или используйте агрегацию.

`$elemMatch` требует, чтобы **один** элемент массива совпал со всеми условиями:

```javascript
db.orders.find({
  lines: { $elemMatch: { sku: "nail", qty: { $gte: 10 } } }
})
```

Без `$elemMatch` фильтр `{ "lines.sku": "nail", "lines.qty": { $gte: 10 } }` может совпасть с **двумя разными** элементами.

Строки можно искать регулярным выражением.

```javascript
db.items.find({ name: /nail/i })
db.items.find({ name: { $regex: "nail", $options: "i" } })
```

`i` делает совпадение без учёта регистра.

Регулярное выражение без префиксного совпадения часто плохо использует индекс. Ведущий `.*` заставляет сканировать много значений. Префиксное выражение вроде `/^nail/` чаще может использовать индекс по `name`.

Не передавайте сырой текст пользователя в регулярное выражение без экранирования спецсимволов. Пользователь может написать шаблон, который медленный или совпадает слишком широко.

Предпочитайте точное совпадение или `$in`, когда знаете полную строку. Для простого равенства без учёта регистра предпочитайте нормализованное поле в нижнем регистре. Проверяйте regex-запросы через `explain`.

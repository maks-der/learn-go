# 20. Графы (продвинутые)

## Описание

Эта тема расширяет алгоритмы на графах. Вы изучаете минимальные остовные деревья, A*, Флойда–Уоршелла, сильно связные компоненты, максимальный поток и двудольное паросочетание. Завершите эту тему после представления графов, ядерных алгоритмов на графах, куч и Union-Find.

Используйте один термин для каждого понятия. **MST** — минимальное остовное дерево. **Эвристика** в A* — догадка оставшейся стоимости. **SCC** — сильно связная компонента. **Поток** — назначение нагрузки рёбрам при ёмкости.

## MST: Крускал, Прим

**Минимальное остовное дерево** связного неориентированного взвешенного графа — дерево из n − 1 рёбер, которое соединяет все вершины и имеет минимальный суммарный вес.

**Крускал** сортирует рёбра по весу и добавляет ребро, когда оно соединяет два компонента. Union-Find проверяет это условие. Тема 16 уже описала шаги. Реализуйте Крускала здесь, если не закончили там.

**Прим** растит одно дерево от стартовой вершины.

1. Начните с s. Dist[s] = 0. Dist[v] = ∞ для других. Dist здесь означает самое дешёвое ребро от дерева к v.
2. Повторите n раз: извлеките вершину u не в дереве с наименьшим dist. Добавьте u к дереву. Для каждого соседа v вне дерева поставьте dist[v] = min(dist[v], weight(u, v)).
3. Мин-куча реализует extract-min и decrease-key (или дополнительные вставки).

```text
Prim idea
  tree = empty
  add cheapest edge that leaves the tree
  repeat until n vertices are in the tree
```

```text
Kruskal idea
  forest of vertices
  add cheapest edge that does not make a cycle
```

Оба алгоритма дают один вес MST, если все веса различны. Если некоторые веса равны, может существовать больше одного MST. Веса всё равно совпадают.

Время Крускала — O(m log m) от сортировки. Время Прима с двоичной кучей — O(m log n).

Не запускайте эти алгоритмы MST на ориентированном графе как первое MST. Этот справочник считает MST неориентированным.

Если граф несвязен, вы получаете **минимальный остовный лес**. Прим из одного старта заполняет только один компонент. Крускал заполняет все компоненты.

Дерево кратчайших путей Дейкстры — не MST. Другая цель.

## A*

**A*** находит кратчайший путь от s к цели t, когда у вас есть **эвристика** h(v). h(v) оценивает оставшуюся стоимость от v к t.

Приоритет вершины v — f(v) = g(v) + h(v). g(v) — лучшая известная стоимость от s к v (та же роль, что dist в Дейкстре). Куча извлекает наименьший f.

```text
f(v) = g(v) + h(v)
g = cost so far
h = estimate to t
```

**Допустимая** эвристика: h(v) никогда не больше истинной оставшейся стоимости. Тогда A* находит кратчайший путь (при обычных неотрицательных весах и верной реализации).

**Согласованная** (монотонная) эвристика: h(u) ≤ w(u, v) + h(v). Тогда A* ведёт себя как Дейкстра с приведённой стоимостью. Вы можете пометить v закрытой при первом извлечении в обычной форме.

Сетка с 4-сторонними ходами часто использует манхэттенское расстояние как h. Сетка с 8-сторонними ходами часто использует согласованное расстояние. Евклидово расстояние обычно на плоскости.

Если h(v) = 0 для каждого v, A* — Дейкстра.

A* — не BFS. BFS игнорирует веса и игнорирует h.

Плохая эвристика (слишком большая) может вернуть путь, который не кратчайший. Эвристика, которая всегда 0, безопасна, но не быстрее.

Не используйте A*, когда нужны расстояния от s до всех вершин. Используйте Дейкстру. A* — для одной цели (или малого набора) и полезного h.

Восстановите путь массивом parent как в Дейкстре.

## Флойд–Уоршелл

**Флойд–Уоршелл** вычисляет кратчайшие пути между **всеми парами** вершин. Он использует матрицу n × n.

Идея: разрешить вершины 0 .. k как промежуточные, затем k+1.

```text
for k in 0 .. n-1:
  for i in 0 .. n-1:
    for j in 0 .. n-1:
      if dist[i][k] + dist[k][j] < dist[i][j]:
          dist[i][j] = dist[i][k] + dist[k][j]
```

Init: dist[i][i] = 0. dist[i][j] = weight(i, j), если ребро существует. dist[i][j] = ∞, если i ≠ j и ребра нет.

Время — Θ(n³). Память — Θ(n²). Используйте Флойда–Уоршелла, когда n мало (сотни, не миллионы) и нужны все пары.

Отрицательные веса разрешены. Отрицательный цикл существует, если некоторое dist[i][i] становится отрицательным.

Вы можете хранить next[i][j], чтобы восстановить путь.

Не используйте Флойда–Уоршелла на огромном разреженном графе, если нужен только один источник. Используйте Дейкстру n раз (неотрицательные) или алгоритм Джонсона (позднее чтение).

Флойд–Уоршелл — матричный метод. Он подходит матрице смежности. Он не использует кучу.

Три цикла должны использовать k как внешний цикл. Неверный порядок — частая ошибка.

## SCC (Косарайю / Тарьян)

**Сильно связная компонента (SCC)** ориентированного графа — максимальное множество вершин такое, что каждая вершина может достичь каждой другой вершины в множестве по ориентированным путям.

Граф SCC (каждая компонента сжата в одну вершину) — DAG.

**Косарайю** (два прохода DFS):

1. Запустите DFS на G. Запишите порядок закрытия (или кладите вершины на стек при закрытии).
2. Постройте транспонированный граф Gᵀ (разверните каждое ребро).
3. Запустите DFS на Gᵀ. Начинайте вершины в убывающем времени закрытия шага 1. Каждое дерево DFS — одна SCC.

**Тарьян** (один проход DFS) использует стек и значения low-link. Он находит SCC во время одного обхода. Код короче в конкурсной постановке после того, как выучите его. Идея плотнее.

```text
G:   0 → 1 → 2
     ↑________↓     (if 2 → 0)
one SCC {0,1,2}

if you remove 2 → 0, three SCCs
```

Время обоих методов — Θ(n + m).

Не используйте неориентированные компоненты связности как SCC. Направление важно.

Конденсация (DAG SCC) полезна для «может ли A достичь B?» после проверки достижимости внутри компоненты и для 2-SAT (позже).

Реализуйте Косарайю первым, если уже есть времена закрытия DFS. Реализуйте Тарьяна, когда хотите один проход.

Изолированные вершины — SCC размера 1. Одно ориентированное ребро a → b без пути назад даёт две SCC.

## Максимальный поток (Форд–Фалкерсон / ознакомление с Диницем)

**Сеть потока** — ориентированный граф с **источником** s, **стоком** t и **ёмкостью** c(u, v) ≥ 0 на каждом ребре. **Поток** назначает число f(u, v) такое, что 0 ≤ f(u, v) ≤ c(u, v) и поток сохраняется в каждой вершине кроме s и t. **Величина** потока — чистый поток из s.

**Максимальный поток** имеет максимальную величину.

**Остаточная ёмкость** ребра — c − f. **Остаточный граф** также имеет обратное ребро ёмкости f. **Увеличивающий путь** — путь s–t в остаточном графе. Вы можете протолкнуть дополнительный поток по этому пути.

**Форд–Фалкерсон** повторяет: найти любой увеличивающий путь, протолкнуть узкую остаточную ёмкость, обновить остатки. Если вы находите пути BFS (Эдмондс–Карп), каждый поиск кратчайший по числу рёбер, и алгоритм полиномиален.

**Диниц** использует блокирующие потоки и уровневые графы. Он быстрее на многих графах. Это имя — **ознакомление** для первого прохода. Реализуйте Эдмондса–Карпа (Форд–Фалкерсон + BFS) до Диница.

```text
you implement first:  Edmonds–Karp (BFS augmenting paths)
you only name:        Dinic, blocking flow
```

**Минимальный разрез** — разбиение (S, T) с s в S и t в T. Ёмкость разреза — сумма ёмкостей от S к T. Теорема о максимальном потоке и минимальном разрезе говорит, что величина максимального потока равна ёмкости минимального разреза.

Не игнорируйте обратные остаточные рёбра. Они позволяют «отменить» плохой толчок.

Ёмкости нужно обрабатывать осторожно, если они вещественные числа. Этот справочник использует целые.

## Двудольное паросочетание (ознакомление)

**Двудольный граф** имеет две стороны L и R. Каждое ребро соединяет вершину в L с вершиной в R. Нет ребра внутри L или внутри R.

**Паросочетание** — множество рёбер, которые не разделяют вершину. **Максимальное паросочетание** имеет максимальное число рёбер.

Вы можете вычислить максимальное двудольное паросочетание как максимальный поток: добавить s ко всем L, добавить все R к t, поставить каждую ёмкость в 1, вычислить максимальный поток. Величина потока — размер паросочетания. Рёбра от L к R с потоком 1 — паросочетание.

**Хопкрофт–Карп** — более быстрый алгоритм двудольного паросочетания. Считайте его **ознакомлением**, пока поток не ясен.

**Условие Холла** — теорема о том, когда паросочетание покрывает L. Вам не нужно реализовывать проверщик Холла.

```text
L: a b c
R: 1 2 3
edges: a-1, a-2, b-2, c-3
one maximum matching size 3 or less; find one by hand
```

Применения: назначение работ работникам, сопоставление студентов слотам, некоторые модели планирования.

Этот раздел — **ознакомление плюс сведение к потоку**. Реализуйте паросочетание через Эдмондса–Карпа на крошечном двудольном графе. Не начинайте с Хопкрофта–Карпа.

Паросочетание общего графа (не двудольного) труднее (Blossom). Этот алгоритм вне охвата.

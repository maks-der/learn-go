# 2. Базовые абстракции

## Описание

У Kafka небольшой набор базовых объектов. Вы должны знать каждое имя до того, как писать продюсеры и консьюмеры. Эта тема определяет топик, партицию, офсет, запись, брокера, кластер, реплику, лидера и группу консьюмеров.

Завершите эту тему после темы 1. Завершите эту тему до темы 3. Тема 3 объясняет, зачем существуют партиции. Тема 6 подробнее объясняет группы консьюмеров. Тема 9 объясняет реплики и устойчивость.

Используйте один термин для каждого понятия. Топик — именованный журнал. Партиция — упорядоченный срез этого журнала. Офсет — позиция в одной партиции. Запись — хранимая единица. Брокер — серверный процесс Kafka. Кластер — набор брокеров. Реплика — копия партиции. Лидер — реплика, которая обрабатывает чтение и запись. Группа консьюмеров — набор консьюмеров, которые делят партиции топика.

## Топик

Топик — именованный журнал записей только на добавление. Продюсеры пишут в топик по имени. Консьюмеры подписываются на топик по имени. Имя — строка. Используйте ясное стабильное имя. Пример: `orders.placed`.

У топика есть число партиций. У топика есть фактор репликации. Вы задаёте эти значения при создании топика, если не действуют значения брокера по умолчанию. Партиции можно добавить позже. Число партиций в Apache Kafka уменьшить нельзя. Тема 3 покрывает этот предел.

У топика есть конфигурация. Примеры: время ретеншна, политика очистки, тип сжатия. Значения по умолчанию можно задать на брокере. Значения можно переопределить на одном топике. Темы 8 и 10 покрывают хранение и администрирование.

Внутренние топики существуют для самой Kafka. Примеры: `__consumer_offsets` и топики транзакций. Не пишите прикладные события в эти имена. Тема 10 их описывает.

Топик — не папка файлов, которые вы правите. Kafka хранит данные топика как сегменты журнала на брокерах, которые держат партиции.

## Партиция

Партиция — упорядоченная последовательность записей внутри топика. Kafka добавляет каждую новую запись в одну партицию. Записи в одной партиции имеют возрастающие офсеты.

Топик с одной партицией — один упорядоченный журнал. Топик со многими партициями — набор упорядоченных журналов. Kafka не хранит единый глобальный порядок по всем партициям. Тема 3 объясняет это правило.

У каждой партиции есть номер. Номера начинаются с 0. У топика с тремя партициями партиции 0, 1 и 2.

У каждой партиции есть лидер-реплика. Продюсеры пишут лидеру. Консьюмеры в обычном случае читают у лидера. Фолловеры копируют лидера. Тема 9 покрывает процесс копирования.

Партиции позволяют Kafka масштабироваться. Разные партиции могут жить на разных брокерах. Разные консьюмеры в одной группе могут читать разные партиции одновременно.

## Офсет

Офсет — число, которое идентифицирует запись внутри одной партиции. Первая запись в партиции имеет офсет 0 в новой партиции (начальный офсет может отличаться после удаления и некоторых операций, но офсет по-прежнему идентифицирует запись).

Офсеты растут, когда Kafka добавляет записи. Офсет 7 идёт после офсета 6 в той же партиции. Офсеты в партиции 0 не имеют смысла в партиции 1. Всегда называйте и партицию, и офсет, когда указываете на запись.

Консьюмер хранит зафиксированный офсет для каждой назначенной партиции. Зафиксированный офсет — следующая позиция для чтения или последняя обработанная позиция, в зависимости от того, как клиент фиксирует. Тема 5 покрывает правила фиксации. Не смешивайте эти два соглашения в одной команде без письменного правила.

Log end offset (LEO) — следующий офсет, который назначит лидер. High watermark — офсет, который подтвердили фолловеры. Консьюмеры, которые читают только зафиксированные данные, не читают дальше high watermark. Тема 20 пути покрывает эту пару подробнее. Для этой темы запомните: офсет — адрес записи в партиции.

## Запись: ключ, значение, метка времени, заголовки

Запись — единица, которую Kafka хранит в партиции. У записи есть эти части:

- **Ключ.** Байты или null. Партиционер по умолчанию использует ключ, чтобы выбрать партицию. Тема 3 покрывает это правило.
- **Значение.** Байты или null. Значение — полезная нагрузка. Значение null может быть томбстоуном на компактируемом топике. Тема 8 покрывает томбстоуны.
- **Метка времени.** Время, которое задаёт продюсер или брокер. Конфигурация брокера выбирает тип метки времени.
- **Заголовки.** Необязательные пары ключ/значение на записи. Используйте заголовки для малых метаданных (trace id, тип содержимого). Не кладите основную нагрузку в заголовок.

Kafka не разбирает ключ или значение. Kafka хранит байты. Ваш сериализатор пишет байты. Ваш десериализатор читает байты. Тема 11 покрывает схемы.

У записи также есть партиция и офсет после того, как брокер её добавил. Продюсер получает эти метаданные, когда запись успешна (если вы не используете `acks=0`). Тема 4 покрывает подтверждения.

Держите ключ стабильным для одной сущности. Пример: идентификатор заказа как ключ для всех событий об этом заказе. Тогда эти записи идут в одну партицию и остаются по порядку.

## Брокер

Брокер — один серверный процесс Kafka. Брокер хранит реплики партиций на диске. Брокер принимает запросы produce и fetch от клиентов. Брокер — член кластера.

У каждого брокера есть идентификатор брокера. Идентификатор уникален в кластере. Клиенты не выбирают брокера для каждого запроса вручную. Клиенты используют адрес bootstrap. Кластер сообщает клиенту, какой брокер лидирует каждую партицию.

Брокер может выполнять работу контроллера в режиме KRaft. Некоторые узлы — контроллеры, некоторые — брокеры, или один процесс может совмещать обе роли. Совмещённый режим обычен для кластера на ноутбуке. Выделенные узлы контроллеров обычны для большого кластера.

Брокер использует listeners. Listener — хост и порт, которые используют клиенты. Локальная работа часто использует `localhost:9092`. Неверный advertised-адрес — частая причина «я могу перечислить топики, но не могу писать» в Docker.

## Кластер

Кластер — набор брокеров, которые работают как одна система Kafka. Кластер разделяет метаданные: топики, партиции, назначения реплик и конфигурацию. KRaft хранит эти метаданные в кворуме контроллеров.

Клиенты видят один кластер через адрес bootstrap. Любой брокер в списке bootstrap может отправить метаданные. Вы перечисляете больше одного брокера bootstrap, чтобы старт всё ещё работал, когда один брокер недоступен.

У кластера есть идентификатор кластера. Вы задаёте идентификатор при форматировании хранилища. Все брокеры в кластере должны использовать один идентификатор кластера и одни метаданные.

Не смешивайте брокеров из двух кластеров в одной конфигурации клиента. Второй кластер — второй список bootstrap и второй набор топиков. Тема 18 пути покрывает копии между кластерами.

Кластер из одного брокера допустим для обучения. Продакшен-кластер использует больше одного брокера, чтобы реплики могли жить на разных машинах.

## Реплика и лидер

Реплика — копия партиции на брокере. Фактор репликации — число реплик для каждой партиции. Фактор репликации 3 означает три копии.

Одна реплика — лидер. Остальные реплики — фолловеры. Продюсеры пишут лидеру. Фолловеры делают fetch у лидера и добавляют в свой локальный журнал. Консьюмеры в обычной схеме читают у лидера.

Если брокер-лидер останавливается, фолловер из набора in-sync может стать новым лидером. Тема 9 определяет набор in-sync replica (ISR) и опасность unclean leader election.

Реплики — на партицию, а не на топик как один блоб. У партиции 0 лидер может быть на брокере 1. У партиции 1 лидер может быть на брокере 2.

Для учебного кластера из одного брокера фактор репликации должен быть 1. Более высокий фактор не сработает, потому что брокеров недостаточно.

### Вопросы

#### Теоретические вопросы

4. Что происходит, когда брокер-лидер останавливается, на высоком уровне?
5. Почему кластер из одного брокера не может использовать фактор репликации 3?

#### Простые практические задания

1. Опишите топик. Запишите список реплик и лидера для каждой партиции.

#### Средние практические задания

#### Сложные практические задания

## Группа консьюмеров

Группа консьюмеров — набор консьюмеров, которые делят один идентификатор группы. Kafka назначает каждую партицию подписанных топиков не более чем одному активному консьюмеру в этой группе. Два консьюмера в одной группе не читают одну партицию одновременно.

Разные группы независимы. Две группы могут читать один топик одновременно. У каждой группы свои зафиксированные офсеты.

Координатор группы — брокер, который хранит членство группы и помогает назначению. Тема 6 покрывает координатора, статическое членство и типы ребаланса.

Используйте новый идентификатор группы, когда нужен новый независимый читатель. Повторно используйте идентификатор группы, когда хотите делить работу или продолжить с сохранённых офсетов.

Консьюмер с ручным assign в некоторых клиентах может работать без группы. Обычный прикладной путь — subscribe плюс идентификатор группы. Тема 5 покрывает subscribe и assign.

### Вопросы

#### Теоретические вопросы

1. Что такое группа консьюмеров?
2. Сколько активных консьюмеров в одной группе читают одну партицию одновременно?
3. Как две группы делят один топик?
4. Что такое координатор группы на высоком уровне?
5. Когда выбирать новый идентификатор группы?

#### Простые практические задания

1. Запустите один консольный консьюмер с `--group g1` на топике с данными. Запишите одну запись, которую видите.
2. Запустите второй консольный консьюмер с `--group g2` на том же топике с начала. Подтвердите, что обе группы могут читать те же записи.
3. Напишите пять предложений, которые описывают группу консьюмеров. Используйте только факты из этого раздела.
4. Составьте таблицу: Идентификатор группы, Топик, Смысл. Добавьте три строки (биллинг, аудит, поиск).

#### Средние практические задания

1. Создайте топик с двумя партициями. Запустите два консольных консьюмера с одним идентификатором группы. Отправьте шесть записей. Запишите, какой консьюмер печатает какие записи (подпишите терминалы).
2. Используйте `kafka-consumer-groups --describe --group g1`. Запишите назначенные партиции и зафиксированные офсеты.
3. Убейте одного консьюмера в группе из двух участников. Наблюдайте оставшегося консьюмера. Напишите, что происходит с партициями.

#### Сложные практические задания

1. Нарисуйте назначение для трёх партиций и двух консьюмеров в одной группе. Затем нарисуйте трёх консьюмеров. Отметьте простаивающего консьюмера, если он есть.
2. Прочитайте официальное введение в группы консьюмеров. Напишите, как хранятся офсеты (имя топика) и почему идентификатор группы — часть этого ключа хранения.

## Повторение темы

#### Простые практические задания

4. Нарисуйте одну фигуру, которая содержит все базовые термины. Используйте стрелки для produce, replicate и consume.

#### Средние практические задания

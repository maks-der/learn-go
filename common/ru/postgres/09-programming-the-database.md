# 9. Программирование базы

## Описание

Эта тема показывает, как класть логику в PostgreSQL 16 и PostgreSQL 17. Вы узнаёте SQL-функции, PL/pgSQL, триггеры, сгенерированные столбцы и расширения. Также узнаёте частые расширения: `pgcrypto`, `citext`, `pg_trgm` и `pg_stat_statements`.

Сначала завершите тему 8. Вы умеете выдавать `EXECUTE` и знаете риск `SECURITY DEFINER`. Завершите эту тему до секционирования больших таблиц.

Используйте один термин для каждого понятия. Функция — именованная подпрограмма, которая возвращает значение или набор. Процедура — подпрограмма, которую вызываете через `CALL` и которая может фиксировать. Триггер — функция, которую сервер запускает на событие таблицы. Сгенерированный столбец хранит значение, которое вычисляет сервер. Расширение — упакованный набор объектов, который устанавливаете через `CREATE EXTENSION`. Этот справочник рассчитан на PostgreSQL 16 и PostgreSQL 17.

## SQL-функции и PL/pgSQL

Тело SQL-функции — один SQL-оператор или список операторов. Имя языка — `sql`. Функция выполняется в той же транзакции, что вызывающий.

```sql
CREATE FUNCTION shop.item_label(p_name text, p_qty int)
RETURNS text
LANGUAGE sql
STABLE
AS $$
    SELECT p_name || ' (' || p_qty::text || ')';
$$;

SELECT shop.item_label('nail', 10);
```

Метки волатильности помогают планировщику:

- `VOLATILE` — по умолчанию; может менять данные или возвращать разные значения
- `STABLE` — тот же результат внутри одного сканирования для тех же аргументов; может читать таблицы
- `IMMUTABLE` — тот же результат навсегда для тех же аргументов; без чтения таблиц

Используйте `IMMUTABLE` только когда это правда. Неверная метка `IMMUTABLE` может заставить индекс или сгенерированный столбец хранить устаревший результат.

SQL-функции могут возвращать таблицу:

```sql
CREATE FUNCTION shop.low_stock(p_min int)
RETURNS TABLE (id bigint, name text, qty int)
LANGUAGE sql
STABLE
AS $$
    SELECT i.id, i.name, i.qty
    FROM shop.items AS i
    WHERE i.qty < p_min;
$$;
```

Предпочитайте SQL-функции, когда тело — запрос. Планировщик часто может встроить простую SQL-функцию.

PL/pgSQL — процедурный язык, который поставляется с PostgreSQL. Пишете блоки `BEGIN` ... `END`. Тело держит dollar-quoting.

```sql
CREATE FUNCTION shop.clamp_qty(p_qty int)
RETURNS int
LANGUAGE plpgsql
IMMUTABLE
AS $fn$
BEGIN
    IF p_qty IS NULL THEN
        RETURN 0;
    END IF;
    IF p_qty < 0 THEN
        RETURN 0;
    END IF;
    RETURN p_qty;
END;
$fn$;
```

Блок может объявлять переменные. `INTO STRICT` требует ровно одну строку. `EXCEPTION` обрабатывает именованные условия. `RAISE` сообщает ошибку.

```sql
CREATE FUNCTION shop.next_label(p_id bigint)
RETURNS text
LANGUAGE plpgsql
STABLE
AS $$
DECLARE
    v_name text;
BEGIN
    SELECT name INTO STRICT v_name
    FROM shop.items
    WHERE id = p_id;
    RETURN v_name;
EXCEPTION
    WHEN NO_DATA_FOUND THEN
        RETURN 'missing';
    WHEN TOO_MANY_ROWS THEN
        RAISE EXCEPTION 'duplicate id %', p_id;
END;
$$;
```

PL/pgSQL по умолчанию `VOLATILE`. Задавайте `STABLE` или `IMMUTABLE`, когда правила позволяют.

Процедуры используют `CREATE PROCEDURE` и `CALL`. Процедура в некоторых случаях может `COMMIT`. Предпочитайте функцию, которая возвращает значение, когда поведение фиксации процедуры не нужно.

Выдавайте `EXECUTE` ролям, которые должны вызывать функцию. Отзывайте `EXECUTE` у `PUBLIC`, когда функция не публичный помощник.

Не помечайте функцию `IMMUTABLE`, если она вызывает `now()` или читает таблицу. Не кладите пустой `EXCEPTION WHEN OTHERS`, который прячет каждую ошибку. Не циклите построчно, когда работу может сделать один SQL-оператор.

Официально: [https://www.postgresql.org/docs/17/xfunc-sql.html](https://www.postgresql.org/docs/17/xfunc-sql.html), [https://www.postgresql.org/docs/17/plpgsql.html](https://www.postgresql.org/docs/17/plpgsql.html).

## Триггеры

Триггер запускает функцию, когда происходит событие таблицы. Сначала создаёте функцию. Функция возвращает `trigger` и использует переменные `TG_`. Затем прикрепляете через `CREATE TRIGGER`.

Момент:

- `BEFORE` — выполняется до записи строки; можно менять `NEW`; можно вернуть `NULL`, чтобы пропустить строку
- `AFTER` — выполняется после записи; используйте для побочных эффектов, которые должны видеть финальную строку
- `INSTEAD OF` — для представлений

Гранулярность:

- `FOR EACH ROW` — один раз на строку
- `FOR EACH STATEMENT` — один раз на оператор

```sql
CREATE FUNCTION shop.set_updated_at()
RETURNS trigger
LANGUAGE plpgsql
AS $$
BEGIN
    NEW.updated_at := clock_timestamp();
    RETURN NEW;
END;
$$;

CREATE TRIGGER items_set_updated_at
    BEFORE UPDATE ON shop.items
    FOR EACH ROW
    EXECUTE FUNCTION shop.set_updated_at();
```

В PostgreSQL 16 и 17 ключевое слово — `EXECUTE FUNCTION` (в старых текстах `EXECUTE PROCEDURE`). Предпочитайте `EXECUTE FUNCTION`.

`NEW` — новая версия строки на `INSERT` и `UPDATE`. `OLD` — старая версия строки на `UPDATE` и `DELETE`. У операторных триггеров нет записей строк `NEW` и `OLD`. Они могут использовать таблицы перехода (`REFERENCING NEW TABLE AS ...`), когда нужен набор строк.

Используйте триггер `BEFORE ROW`, чтобы заполнять столбцы. Используйте триггер `AFTER`, чтобы писать в аудиторскую таблицу. Триггер `AFTER`, который обновляет ту же строку, может зациклиться. Избегайте такого дизайна.

Default `updated_at` не меняются на `UPDATE`. Обычное исправление — триггер или явный `SET`.

Не используйте триггеры, чтобы заменить внешний ключ или ограничение check. Не наслаивайте много триггеров без задокументированного порядка.

Официально: [https://www.postgresql.org/docs/17/triggers.html](https://www.postgresql.org/docs/17/triggers.html).

## Сгенерированные столбцы

Сгенерированный столбец — столбец, который сервер вычисляет из других столбцов. В PostgreSQL 16 и PostgreSQL 17 обязательна хранимая форма. Ключевое слово — `STORED`. Сервер пишет значение на `INSERT` и `UPDATE`. Столбец можно индексировать. Сгенерированный столбец нельзя `UPDATE` напрямую.

```sql
CREATE TABLE shop.products (
    id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    price_net numeric(12, 2) NOT NULL,
    tax_rate numeric(4, 3) NOT NULL,
    price_gross numeric(12, 2)
        GENERATED ALWAYS AS (price_net * (1 + tax_rate)) STORED
);
```

PostgreSQL 16 и 17 не предлагают виртуальные сгенерированные столбцы. Поздняя мажорная версия может добавить эту возможность. Не пишите `VIRTUAL` в скриптах 16 или 17.

Выражение должно быть `IMMUTABLE`. Может использовать другие базовые столбцы той же строки. Не может использовать подзапрос. Не может использовать волатильную функцию.

Сгенерированный столбец — не триггер. Планировщик видит настоящий столбец. `SELECT *` его включает. Хранимый сгенерированный столбец плюс B-дерево может заменить длинный индекс выражения, когда значение также выбираете.

```sql
CREATE INDEX products_price_gross_idx ON shop.products (price_gross);
```

Не копируйте сгенерированное значение во второй записываемый столбец. Не кладите бизнес-правила, которым нужны другие таблицы, в сгенерированный столбец. Используйте запрос, представление или функцию.

Официально: [https://www.postgresql.org/docs/17/ddl-generated-columns.html](https://www.postgresql.org/docs/17/ddl-generated-columns.html).

## `CREATE EXTENSION`

Расширение — именованный пакет. `CREATE EXTENSION` создаёт его объекты и записывает имя в `pg_extension`. Файлы лежат в каталоге share PostgreSQL. Не копируйте SQL из блога как замену, когда расширение есть.

```sql
CREATE EXTENSION IF NOT EXISTS pg_stat_statements;
```

Многим расширениям нужен суперпользователь или роль с `CREATE` на базе плюс пакет на диске. Облачные вендоры часто разрешают список расширений и блокируют остальные.

Перечислить, что сервер может загрузить:

```sql
SELECT name, default_version, installed_version
FROM pg_available_extensions
ORDER BY name;
```

Перечислить, что есть в этой базе:

```sql
SELECT extname, extversion FROM pg_extension ORDER BY 1;
```

`CREATE EXTENSION ... SCHEMA shop` кладёт объекты в эту схему, когда расширение позволяет. Некоторые расширения должны жить в `public` или в фиксированной схеме.

`DROP EXTENSION` удаляет объекты. `CASCADE` удаляет зависимые объекты. Используйте `CASCADE` только когда принимаете эту потерю.

`ALTER EXTENSION ... UPDATE` переходит на более новую версию расширения, которую даёт пакет.

Не включайте каждое расширение «на случай, если понадобится». Каждое расширение добавляет объекты, работу обновления и поверхность атаки. Не создавайте те же функции вручную, когда поддерживаемый путь — `CREATE EXTENSION`.

Официально: [https://www.postgresql.org/docs/17/extend-extensions.html](https://www.postgresql.org/docs/17/extend-extensions.html).

## Частые расширения: `pgcrypto`, `citext`, `pg_trgm`, `pg_stat_statements`

Эти расширения contrib появляются во многих приложениях PostgreSQL 16 и 17.

**`gen_random_uuid()`** встроен с PostgreSQL 13. Для UUID версии 4 в новой работе расширение не нужно:

```sql
SELECT gen_random_uuid();
```

**`pgcrypto`** даёт `crypt`, `gen_salt`, `digest`, `hmac` и функции шифрования. В старых текстах `pgcrypto` использовали для `gen_random_uuid()`. Для id предпочитайте встроенный `gen_random_uuid()`. Используйте `pgcrypto` для хешей паролей и работы с дайджестами. Не изобретайте свой протокол хеша.

```sql
CREATE EXTENSION IF NOT EXISTS pgcrypto;
SELECT crypt('demo', gen_salt('bf'));
```

**`citext`** — текстовый тип без учёта регистра. `WHERE email = 'A@B.com'` совпадает с `a@b.com`. Уникальный индекс на `citext` без учёта регистра. Предпочитайте `citext` вместо `lower(email)` в каждом запросе, когда столбец всегда без учёта регистра. Можно также использовать `LOWER` плюс уникальный индекс на `lower(email)` без `citext`.

**`pg_trgm`** добавляет триграммное сходство и может индексировать `LIKE '%x%'` через GIN или GiST.

```sql
CREATE EXTENSION IF NOT EXISTS pg_trgm;
CREATE INDEX items_name_trgm ON shop.items USING gin (name gin_trgm_ops);
SELECT name FROM shop.items WHERE name LIKE '%nail%';
```

**`pg_stat_statements`** записывает нормализованный запрос и его суммарное время. Тема 5 его представила. Библиотеку нужно загрузить в `postgresql.conf`:

```text
shared_preload_libraries = 'pg_stat_statements'
```

Перезапустите сервер. Затем `CREATE EXTENSION pg_stat_statements` в каждой базе, которая должна запрашивать представление.

`uuid-ossp` всё ещё даёт другие версии UUID. Создавайте только когда нужны эти функции. В обязательном списке этого пути его нет.

Не храните обратимые ключи шифрования в той же таблице, что шифротекст, без плана ключей. Не включайте `pg_stat_statements` и затем игнорируйте `pg_stat_statements.track`.

# 18. Продвинутые деревья и боры

## Описание

Эти структуры отвечают на вопросы диапазона и сжимают строковые ключи. Эта тема объясняет деревья отрезков, деревья Фенвика, разреженные таблицы, декартовы деревья, персистентные деревья отрезков и radix / Patricia-боры. Завершите эту тему после массивов, двоичных деревьев и строкового бора.

Используйте один термин для каждого понятия. **Запрос диапазона** возвращает значение из непрерывного интервала индексов [L, R]. **Точечное обновление** меняет один индекс. **Идемпотентное** слияние (например min) может использовать разреженную таблицу. **Обратимое** слияние (например сумма) может использовать дерево Фенвика.

## Дерево отрезков

**Дерево отрезков** — двоичное дерево над массивом a[0 .. n−1]. Каждый узел хранит слияние непрерывного сегмента. Корень хранит слияние полного массива. Лист хранит один элемент.

Обычное слияние — сумма, min или max. Слияние должно быть ассоциативным. Вы комбинируете два дочерних значения в родителя.

```text
array:  1  3  2  4
sums:
            10
          /    \
        4        6
       / \      / \
      1   3    2   4
```

**Запрос [L, R]** обходит O(log n) узлов, которые вместе покрывают [L, R] и ни одного лишнего индекса. **Обновление** в индексе i идёт по пути от этого листа к корню и чинит O(log n) узлов.

Время построения — Θ(n). Время запроса или точечного обновления — Θ(log n). Память — около 4n для массива узлов в стиле кучи (безопасная оценка для расположения степени двойки).

```text
query(node, segL, segR, L, R):
  if the node segment is outside [L,R]: return identity
  if the node segment is inside [L,R]: return node.value
  return merge(query(left), query(right))
```

**Нейтральный элемент (identity)** — 0 для суммы, +∞ для min, −∞ для max.

Дерево отрезков может добавить **ленивое проталкивание** для обновлений диапазона. Это второй навык. Сначала реализуйте точечное обновление и сумму диапазона.

Дерево отрезков — не BST ключей. Индексы — ключи. Разбиение всегда середина диапазона индексов.

Не просматривайте [L, R] циклом, если n велико и у вас много запросов. Это Θ(n) на запрос.

## Дерево Фенвика (BIT)

**Дерево Фенвика** (двоично индексированное дерево, BIT) хранит префиксные суммы в массиве t[1 .. n]. Оно использует меньше кода, чем дерево отрезков, для **префиксной суммы** и **точечного сложения**.

Индексы **с единицы**. Следующий индекс после i использует младший установленный бит i.

```text
i & -i     // least set bit (two's complement)
add i:     i += i & -i
parent i:  i -= i & -i
```

**Add(i, delta)** добавляет delta к a[i] (с единицы). Оно обновляет t в i, i + lsb и так далее.

**PrefixSum(i)** возвращает a[1] + ... + a[i]. Оно суммирует t в i, i − lsb и так далее.

**Сумма диапазона [L, R]** — PrefixSum(R) − PrefixSum(L − 1).

```text
add(i, delta):
  while i <= n:
      t[i] += delta
      i += i & -i

sum(i):
  s = 0
  while i > 0:
      s += t[i]
      i -= i & -i
  return s
```

Время add и префиксной суммы — Θ(log n). Память — Θ(n).

Дереву Фенвика нужна **обратимая** операция. Сумма работает. Min не работает в базовой форме, потому что вы не можете вычесть min.

Построение: добавьте каждый a[i] один раз или используйте линейное построение, если выучите его позже. n сложений — Θ(n log n).

Не используйте i с нуля внутри битовых циклов. Преобразуйте пользовательские индексы с нуля в индексы с единицы.

Дерево Фенвика не хранит явное двоичное дерево указателей детей. Дерево — битовое правило.

## Разреженная таблица

**Разреженная таблица** отвечает на **идемпотентные** запросы диапазона по **статическому** массиву. Статический означает, что вы не обновляете элементы после построения таблицы.

Обычный запрос — min диапазона (RMQ) или max диапазона. Слияние должно удовлетворять merge(x, x) = x, чтобы перекрытие было безопасным.

```text
st[k][i] = merge of a[i .. i + 2^k - 1]
st[0][i] = a[i]
st[k][i] = merge(st[k-1][i], st[k-1][i + 2^{k-1}])
```

**Запрос [L, R]:** пусть len = R − L + 1. Пусть k = floor(log2(len)). Верните merge(st[k][L], st[k][R − 2^k + 1]). Два интервала покрывают [L, R] и могут перекрываться.

```text
[L, R] length 6, 2^k = 4
cover [L, L+3] and [R-3, R]
```

Время построения — Θ(n log n). Время запроса — Θ(1) после того, как у вас есть k = log2(len). Память — Θ(n log n).

Предвычислите `log2[len]` в таблице, если нужно много запросов.

Не используйте разреженную таблицу, когда должны обновлять. Пересборка — Θ(n log n). Используйте дерево отрезков для обновлений.

Не используйте разреженную таблицу для суммы диапазона с формулой перекрытия. Перекрытие добавило бы середину дважды. Сумма не идемпотентна.

Разреженная таблица — хороший инструмент RMQ после того, как выучите идею логарифмического покрытия.

## Декартово дерево (ознакомление)

**Декартово дерево** массива — двоичное дерево. Симметричный обход дерева — порядок массива. Свойство кучи на значениях выполняется (обычно мин-куча: наименьшее значение — корень). Корень — минимум (или максимум). Левое поддерево — декартово дерево левого подмассива. Правое поддерево — декартово дерево правого подмассива.

```text
array values:  3  2  4  1  5
min root: 1
left of 1: Cartesian(3,2,4)    right of 1: Cartesian(5)
```

Этот раздел — **только ознакомление**. Не реализуйте полный проект декартова дерева в этой теме, если другие структуры ещё не работают.

Применения, которые вы можете прочитать позже:

- RMQ может свестись к LCA на декартовом дереве.
- Некоторые разговоры о сортировке и quickselect используют ту же идею разбиения по минимуму.
- Дерами — рандомизированные BST, которые выглядят как декартово дерево на (ключ, случайный приоритет).

Декартово дерево — не дерево отрезков. Оно не BST на значениях, если массив не отсортирован.

Линейное построение использует стек правого хребта. Вы можете прочитать этот алгоритм позже.

```text

you only name:      Cartesian tree, treap link
```

## Персистентное дерево отрезков (ознакомление)

**Персистентное** дерево отрезков сохраняет старые версии после обновления. Обновление создаёт O(log n) **новых** узлов на пути, который изменился. Остальные узлы остаются общими с предыдущей версией. Каждая версия — указатель на корень.

```text
version 0: root0
update index i → version 1: root1
root1 path is new
side subtrees still point at version 0 nodes
```

Это **структурное разделение**. Тема 21 расширяет персистентность. Здесь вам нужна только картинка.

Применения: вы запрашиваете прошлую версию или строите одну версию на префикс массива и запрашиваете k-ю порядковую статистику на подмассиве (обычный конкурсный шаблон).

Память — Θ(n + u log n) для u обновлений, если каждое обновление добавляет O(log n) узлов.

Этот раздел — **только ознакомление**. Не реализуйте персистентность, пока обычное дерево отрезков не верно.

Персистентное дерево само по себе не снимок диска. Это трюк разделения в памяти. Долговечность на диске — другая тема.

Не мутируйте общего ребёнка. Мутация изменила бы старую версию. Вы копируете узел на пути (копирование при записи).

```text
you implement now:  mutable segment tree
you only name:      persistent roots, shared children
```

## Radix-дерево / бор Patricia

**Radix-дерево** (**бор Patricia** — двоичное radix-дерево на битовых строках) **сжимает** цепь узлов бора с одним ребёнком в одно ребро. Ребро хранит строку (или битовую строку), не один символ.

```text
trie of "romane" and "romanus" wastes a long one-child chain
radix edge: "roman" then a split at e vs u
```

**Find** сравнивает срез ключа с меткой ребра. Если метка совпадает, вы продолжаете. Если метка различается в позиции, вы следуете разветвлению или сообщаете отсутствие.

Дерево Patricia часто использует биты. Счётчик пропуска говорит, сколько бит одинаковы. Таблицы маршрутизации IP используют эту идею.

Сравните с хеш-отображением: точный поиск полного ключа часто быстрее в хеш-отображении. Radix-дерево держит **порядок префиксов** и может разделять память среди ключей с длинным общим префиксом.

Сравните с B+-деревом строк: B+-дерево — для страниц и сканирования диапазона ключей. Radix-дерево — сжатый бор. Некоторые базы данных используют обе идеи в разных местах.

Реализуйте небольшое radix-дерево после простого бора. Сжимайте только унарные пути. Тестируйте insert и find нескольких слов.

Не начинайте с производственного radix или конкурентного radix. Сначала выучите правило сжатия.

Время find — O(L) по длине ключа, с меньшим числом узлов, чем у простого бора.

### Вопросы

#### Теоретические вопросы

1. Опишите, как вы выбираете дерево отрезков, Фенвика или разреженную таблицу по нужде обновления и типу слияния.
2. Как персистентность и сжатие radix оба экономят память, но на разных объектах?
3. Напарник говорит, что дерево Фенвика «это куча». Какие факты вы используете, чтобы поправить это предложение?
4. Что вы должны реализовать до декартовых или персистентных деревьев и почему?
5. Почему radix-дерево — лучшее продолжение темы 17, чем суффиксное дерево?

#### Простые практические задания

1. Напишите шпаргалку на одну страницу: отрезки, биты Фенвика, покрытие разреженной, ознакомление с декартовым, ознакомление с персистентным, radix.
2. Нарисуйте одно дерево сумм отрезков и одно разветвление radix.
3. Составьте таблицу: «Запрос», «Лучшая первая структура». Пять строк.
4. Напишите нейтральные значения и формулу суммы диапазона Фенвика по памяти.

#### Средние практические задания

1. Реализуйте дерево отрезков и Фенвика на тех же тестах суммы. Они должны совпасть.
2. Реализуйте RMQ разреженной таблицей. Покажите, что Фенвик не может заменить его для min.
3. Реализуйте небольшое radix-дерево и простой бор. Сравните числа узлов.

#### Сложные практические задания

1. Постройте крошечную библиотеку: сумма диапазона (Фенвик), min диапазона (отрезок или разреженная), поиск префикса (radix). Документируйте каждый выбор.
2. Напишите учебный план из пяти шагов от изменяемого дерева отрезков к персистентному в теме 21. Не реализуйте персистентность здесь.

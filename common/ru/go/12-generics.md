# 12. Дженерики

## Описание

Дженерики позволяют писать функции и типы, которые работают с более чем одним типом. Вы объявляете параметры типа. Компилятор подставляет конкретный тип, когда вызываете функцию или инстанцируете тип. Компилятор по-прежнему проверяет типы во время компиляции.

Эта тема показывает параметры типа, ограничения, вывод типов и выбор дизайна. Используйте дженерики, когда один алгоритм применяется ко многим типам и нужна безопасность типов. Не используйте дженерики, чтобы скрыть простой код за сложным API.

Используйте один термин для каждого понятия. Параметр типа — имя в квадратных скобках. Ограничение — интерфейс, который ограничивает аргумент типа. Инстанцирование — шаг, который связывает аргумент типа с параметром типа.

## Параметры типа на функциях и типах

Обобщённая функция объявляет параметры типа после имени функции. Ограничение следует за каждым параметром типа. Затем список параметров функции использует эти имена как типы.

```go
func First[T any](items []T) (T, bool) {
	if len(items) == 0 {
		var zero T
		return zero, false
	}
	return items[0], true
}
```

`T` — параметр типа. `any` — ограничение. Вызывающий код может написать `First[int](nums)` или опереться на вывод из `nums`. Тип результата — `T`. Когда срез пуст, функция возвращает нулевое значение `T`.

Обобщённый тип объявляет параметры типа после имени типа:

```go
type Pair[A any, B any] struct {
	First  A
	Second B
}

type Stack[T any] struct {
	items []T
}

func (s *Stack[T]) Push(v T) {
	s.items = append(s.items, v)
}
```

Методы обобщённого типа могут использовать параметры типа типа. Методы не должны объявлять новые параметры типа. Если нужен второй параметр типа на операции, пишите функцию, не метод.

```go
func Convert[T any, U any](s Stack[T], f func(T) U) Stack[U] {
	out := Stack[U]{}
	for _, v := range s.items {
		out.Push(f(v))
	}
	return out
}
```

Обобщённый тип инстанцируют списком аргументов типа:

```go
var p Pair[string, int]
s := Stack[int]{}
```

Нельзя использовать параметр типа в списке получателя метода как новое имя. Получатель использует параметры типа типа. Два параметра типа с одним ограничением всё равно могут быть разными типами. `A` и `B` в `Pair` — не один тип.

Не ставьте параметр типа на функцию, когда тело функции никогда не использует `T` как тип. Этот параметр — шум.

## Ограничения и `comparable`

Ограничение — интерфейс. Аргумент типа должен удовлетворять этому интерфейсу. `any` разрешает каждый тип. Ограничение с методами требует эти методы.

```go
type Stringer interface {
	String() string
}

func Join[T Stringer](items []T, sep string) string {
	// call items[i].String()
}
```

Интерфейс может перечислять типы. Эта форма — множество типов. Аргумент типа должен быть одним из этих типов или типом, чей базовый тип входит в множество.

```go
type Signed interface {
	~int | ~int8 | ~int16 | ~int32 | ~int64
}
```

Тильда `~` включает именованные типы, чей базовый тип — перечисленный тип. `type Count int` удовлетворяет `~int`. `Count` не удовлетворяет `int` без тильды.

Методы и множества типов можно сочетать в одном интерфейсе. Пакет `golang.org/x/exp/constraints` не входит в стандартную библиотеку. В стандартной библиотеке есть `cmp.Ordered` с Go 1.21 для упорядоченных типов.

```go
func Min[T cmp.Ordered](a, b T) T {
	if a < b {
		return a
	}
	return b
}
```

`comparable` — предопределённое ограничение. Аргумент типа должен поддерживать `==` и `!=`. `comparable` нужен для ключей карт и для `==` в теле функции.

```go
func Contains[T comparable](s []T, v T) bool {
	for i := range s {
		if s[i] == v {
			return true
		}
	}
	return false
}
```

Срезы, карты и функции несравнимы. `Contains` не работает для `T`, равного `[]int`. Значения интерфейсов сравнимы. Сравнение двух интерфейсов паникует, когда динамические типы несравнимы.

`comparable` — не обычный интерфейс для переменных. В обычном коде не пишут `var x comparable`.

Не используйте `comparable`, чтобы принудить `==` на типах, которым нужен пользовательский метод равенства. Напишите метод `Equal` или передайте функцию.

## Вывод типов

Компилятор выводит аргументы типа из значений, которые вы передаёте. Список аргументов типа можно опустить, когда вывод успешен.

```go
n, ok := First([]int{1, 2})
```

Компилятор видит `[]int` и связывает `T` с `int`. Всё равно можно написать `First[int]([]int{1, 2})`.

Вывод использует аргументы, цель присваивания и ограничения. Вывод может не удаться, когда компилятор не может найти один тип.

```go
func Empty[T any]() []T {
	return nil
}

s := Empty[int]() // you must write [int]
```

Нет аргумента, который называет `T`. Компилятор не может вывести `T`.

Когда два параметра делят параметр типа, аргументы должны совпадать.

```go
func Both[T any](a, b T) {}
Both(1, 2)    // T is int
// Both(1, "x") // error
```

Аргумент-функция может помочь выводу. `MapSlice(nums, strconv.Itoa)` может вывести `T` и `U` из `nums` и из `Itoa`.

Неэкспортируемые параметры типа следуют тем же правилам вывода. Выводу всё равно до экспорта.

Если вывод вас удивляет, напишите аргументы типа. Явные аргументы допустимы и ясны.

С Go 1.21 вывод сильнее для некоторых типов функций и неиспользуемых параметров типа. Предпочитайте читаемый вызов. Не боритесь с компилятором лишними обёртками только чтобы скрыть `[T]`.

## Когда не использовать дженерики

Дженерики добавляют параметры типа в API. Читатели должны выучить эти имена. Сообщения компилятора растут. Простая функция часто яснее.

Не используйте дженерики, когда существует только один тип. Пишите `func SumInts(s []int) int`.

Не используйте дженерики, чтобы заменить интерфейс, который уже описывает поведение. Если у каждого типа есть `Read`, принимайте `io.Reader`. Интерфейс — правильный инструмент для смешанных значений в одном срезе. `[]io.Reader` держит разные конкретные типы. `[]T` держит один тип `T`.

Не используйте дженерики, чтобы избежать `any`, когда внутри всё ещё нужен type switch. Type switch по `T` с ограничением `any` часто хуже маленького интерфейса.

Не пишите огромное ограничение, которое перечисляет каждый тип в программе. Разделите функцию или используйте методы.

Не стройте обобщённую «библиотеку контейнеров» для маленького приложения. Среза и карты достаточно. Добавляйте `Stack[T]`, когда используете его в нескольких пакетах и операции стабильны.

Используйте дженерики когда:

- один алгоритм работает для многих типов
- нужны `==` или `<` на параметре типа
- нужна структура данных, которая хранит `T` без `any` и assertion

Стандартная библиотека использует дженерики в `slices`, `maps` и `cmp`. Читайте эти пакеты. Копируйте их стиль: маленькие функции, ясные ограничения, без лишней абстракции.

Измеряйте, прежде чем утверждать, что дженерики быстрее. Инстанцирование может увеличить размер двоичного файла. Метод на интерфейсе может выделять. Профилируйте, если размер или скорость важны.

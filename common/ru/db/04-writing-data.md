# 4. Запись данных

## Описание

Эта тема показывает, как добавлять строки, менять строки и удалять строки. Вы изучаете `INSERT`, `UPDATE`, `DELETE` и `TRUNCATE`. Вы также изучаете идею upsert и почему записи принадлежат транзакции.

Используйте один термин для каждого понятия. Запись — оператор, который меняет сохранённые данные. Транзакция группирует записи так, что все успешны или все падают. Завершите эту тему до изучения изоляции в позже теме.

Практикуйтесь на копии данных. Не выполняйте непроверенный `UPDATE` или `DELETE` на общей базе.

## `INSERT` (одна строка и несколько)

`INSERT` добавляет новые строки в таблицу. Вы называете таблицу и столбцы. Вы даёте значения, которые совпадают с этими столбцами.

```sql
INSERT INTO customers (customer_id, name, email)
VALUES (1, 'Ada', 'ada@example.com');
```

Называйте столбцы. Не полагайтесь на физический порядок столбцов. Позже `ALTER TABLE` может изменить этот порядок.

Вставьте больше одной строки в одном операторе:

```sql
INSERT INTO customers (customer_id, name, email)
VALUES
    (2, 'Alan', 'alan@example.com'),
    (3, 'Grace', 'grace@example.com');
```

Многострочная форма — один оператор. В транзакции она успешна целиком или падает целиком.

Можно вставить из запроса:

```sql
INSERT INTO customers_archive (customer_id, name, email)
SELECT customer_id, name, email
FROM customers
WHERE customer_id < 100;
```

Список `SELECT` должен совпадать со списком столбцов вставки по числу и по типам.

Если у столбца есть `DEFAULT` или генератор идентичности, этот столбец можно опустить. СУБД заполняет его. Если столбец `NOT NULL` и нет значения по умолчанию, вы должны дать значение.

Вставка падает, когда ломает ограничение: дубликат первичного ключа, плохой внешний ключ, `NOT NULL` или `CHECK`. Упавший оператор не добавляет плохую строку. В многострочной вставке многие продукты отклоняют весь оператор.

Не вставляйте текст, которым управляет пользователь, без параметров в программе. Используйте заполнители. Этот справочник использует литералы только для обучения.

## `UPDATE` и отсутствующий `WHERE`

`UPDATE` меняет существующие строки. Вы задаёте столбцы. Вы фильтруете через `WHERE`.

```sql
UPDATE customers
SET email = 'ada.lovelace@example.com'
WHERE customer_id = 1;
```

Предложение `SET` назначает новые значения. Можно назначить больше одного столбца:

```sql
UPDATE products
SET price = 12.50, name = 'Notebook A5'
WHERE product_id = 10;
```

**Опасность.** `UPDATE` без `WHERE` меняет каждую строку таблицы.

```sql
UPDATE products
SET price = 0;
```

Этот оператор ставит цену каждого товара в `0`. Это обычная авария. Всегда сначала пишите `WHERE` в уме. Многие команды пишут `SELECT` с тем же `WHERE` и проверяют число строк. Затем меняют `SELECT` на `UPDATE`.

```sql
SELECT product_id, price
FROM products
WHERE product_id = 10;
```

Подтвердите одну строку. Затем выполните `UPDATE` с тем же `WHERE`.

Можно обновить из выражения:

```sql
UPDATE products
SET price = price * 1.10
WHERE category = 'book';
```

Этот оператор поднимает цены книг на десять процентов.

Обновление падает, когда новые значения ломают ограничение. Пример: новый email, который не уникален.

Некоторые продукты поддерживают `UPDATE ... FROM` или соединение в `UPDATE`. Синтаксис отличается. Переносимая идея: меняйте строки, которые можете назвать ключом. Предпочитайте `WHERE customer_id = ...` или `WHERE customer_id IN (...)`.

Не выполняйте массовый `UPDATE` в продакшене без транзакции и проверенного `WHERE`. Позже тема показывает, как откатить.

## `DELETE` и `TRUNCATE`

`DELETE` удаляет строки, которые совпадают с `WHERE`. Таблица остаётся. Схема остаётся.

```sql
DELETE FROM orders
WHERE order_id = 500;
```

`DELETE` без `WHERE` удаляет каждую строку. Этот оператор так же опасен, как `UPDATE` без `WHERE`. Сначала подтвердите фильтр через `SELECT`.

`DELETE` запускает действия на строку, которые определяет СУБД: проверки внешних ключей, триггеры и журналирование каждой строки. Большой `DELETE` может занять много времени и записать большой журнал.

`TRUNCATE` удаляет все строки таблицы одной операцией хранения. Это сброс данных на уровне схемы. Синтаксис:

```sql
TRUNCATE TABLE products;
```

`TRUNCATE` в обычном использовании не принимает `WHERE`. Это «опустошить эту таблицу». Многие продукты отказывают в `TRUNCATE`, когда другие таблицы ссылаются на таблицу, если не добавить дополнительные предложения. Эти предложения отличаются по вендору. Не очищайте родительскую таблицу без плана для детей.

Сравните:

| Действие | Типичное применение | Фильтр | Откат | Заметки |
| --- | --- | --- | --- | --- |
| `DELETE` | Удалить некоторые или все строки | `WHERE` разрешён | Да, в транзакции | Проверяет каждую строку |
| `TRUNCATE` | Быстро опустошить таблицу | Без `WHERE` | Зависит от продукта | Сбрасывает хранение; следите за внешними ключами |

Некоторые продукты считают `TRUNCATE` безопасным для транзакции оператором. У других есть ограничения. Проверьте свою СУБД в учебной базе.

Не используйте `TRUNCATE`, когда нужно сохранить некоторые строки. Используйте `DELETE` с `WHERE`. Не используйте `DROP TABLE`, когда нужно только удалить строки. `DROP TABLE` удаляет объект таблицы.

Дочерние строки могут блокировать `DELETE` родителя. СУБД защищает ссылочную целостность. Сначала удалите детей или используйте запланированное правило каскада.

## Upsert / `MERGE` (синтаксис отличается по вендору)

Upsert — запись, которая вставляет строку, когда ключ новый, и обновляет строку, когда ключ существует. Бизнес-идея: «положи эту строку; не падай на дубликате ключа».

Стандарт SQL включает `MERGE`. Многие продукты реализуют `MERGE`. Другие продукты используют другую форму:

- `INSERT ... ON CONFLICT` (PostgreSQL)
- `INSERT ... ON DUPLICATE KEY UPDATE` (MySQL)
- `MERGE` (несколько продуктов)

Сначала изучите идею. Затем читайте синтаксис своей СУБД. Не копируйте предложение PostgreSQL `ON CONFLICT` в продукт, у которого его нет.

`MERGE` стандартной формы (только форма; проверьте продукт):

```sql
MERGE INTO products AS t
USING (
    SELECT 10 AS product_id, 'Notebook' AS name, 4.50 AS price
) AS s
ON t.product_id = s.product_id
WHEN MATCHED THEN
    UPDATE SET name = s.name, price = s.price
WHEN NOT MATCHED THEN
    INSERT (product_id, name, price)
    VALUES (s.product_id, s.name, s.price);
```

Предложение `ON` — правило совпадения. Когда строка совпадает, оператор обновляет. Когда строка не совпадает, оператор вставляет.

Upsert нужен уникальный ключ. Совпадение должно быть однозначным. Если совпадают две целевые строки, `MERGE` должен упасть.

Наивная программа, которая делает `SELECT`, затем `INSERT` или `UPDATE` в два шага, может проиграть параллельной сессии. Две сессии могут обе увидеть «нет» и обе вставить. Используйте один оператор upsert или транзакцию с правильной блокировкой.

Не используйте upsert, чтобы спрятать ошибку моделирования. Если дубликат никогда не ожидается, простой `INSERT` плюс ошибка яснее.

## Почему записи принадлежат транзакции

Транзакция — группа операторов, которую СУБД считает одним изменением. Все операторы фиксируются или все откатываются. Частичная группа не остаётся.

Вы начинаете транзакцию, пишете, фиксируете или откатываете.

```sql
BEGIN;

INSERT INTO orders (order_id, customer_id, ordered_at)
VALUES (100, 1, CURRENT_TIMESTAMP);

INSERT INTO order_lines (order_id, product_id, qty)
VALUES (100, 10, 2);

COMMIT;
```

Если вторая вставка падает, вы делаете `ROLLBACK`. Заголовок заказа не должен остаться без строк, если ваше правило требует строк.

```sql
BEGIN;

UPDATE accounts SET balance = balance - 50 WHERE account_id = 1;
UPDATE accounts SET balance = balance + 50 WHERE account_id = 2;

ROLLBACK;
```

После `ROLLBACK` оба баланса возвращаются к началу транзакции. Этот пример — первый взгляд. Позже тема покрывает изоляцию, блокировки и грязное чтение.

Многие клиенты работают в режиме автофиксации. Каждый оператор фиксируется отдельно. Упавший второй оператор не отменяет первый. Для многошаговой записи выключите автофиксацию или начните явную транзакцию.

Не оставляйте транзакцию открытой, пока ждёте человека. Блокировки могут блокировать другие сессии. Фиксируйте или откатывайте, как только записи завершены.

Не фиксируйте до проверки массового изменения, если ещё можете отменить. Проверяйте внутри транзакции, затем фиксируйте. Если клиент отключается, многие продукты откатывают открытую транзакцию.

`SELECT` может выполняться внутри транзакции. Вы можете прочитать строки, которые только что записали, до фиксации. Другие сессии могут ещё не видеть эти строки. Позже тема объясняет почему.

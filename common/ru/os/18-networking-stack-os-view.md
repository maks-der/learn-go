# 18. Сетевой стек (вид ОС)

## Описание

Ядро реализует сокеты, TCP и UDP, маршрутизацию и фильтры пакетов. Эта тема — взгляд операционной системы на этот стек. Вы узнаете API сокетов, как ядро относится к TCP и UDP, сетевые пространства имён и осведомлённость об iptables и nftables. Полный сетевой путь живёт в `net.topics.md`. Эта тема не заменяет тот путь.

Завершите эту тему после безопасности и изоляции. Завершите эту тему до персистентности состояния ОС (тема 19). Вы уже знаете дескрипторы файлов, `epoll`, сокеты Unix и пространства имён. Теперь вы добавляете интернет-сокеты.

Используйте один термин для каждого понятия. Сокет — конечная точка, которую процесс открывает через `socket`. TCP — надёжный протокол потока байтов, который реализует ядро. UDP — протокол датаграмм, который реализует ядро. Сетевое пространство имён — копия вида сетевого стека (интерфейсы, маршруты, таблицы фильтров). Фильтр пакетов — код ядра, который принимает, отбрасывает или меняет пакеты по правилам. Не смешивайте сокет Unix с интернет-сокетом. Не смешивайте iptables с API сокетов.

## API сокетов

Процесс говорит с сетью через API сокетов. Основные вызовы — POSIX и существуют в Linux, BSD и macOS. У Windows похожая модель с другими именами.

Типичный путь потокового сервера:

1. `socket(AF_INET, SOCK_STREAM, 0)` или `AF_INET6`
2. `bind` на адрес и порт
3. `listen`
4. `accept`, чтобы получить новый соединённый дескриптор
5. `read` / `write` или `recv` / `send`
6. `close`

Типичный путь потокового клиента: `socket`, необязательный `bind`, `connect`, затем ввод-вывод, затем `close`.

UDP использует `SOCK_DGRAM`. Нет `listen` или `accept`. `sendto` и `recvfrom` включают адреса.

Сокет — дескриптор файла в Unix. `epoll` может ждать на нём (тема 14). `fork` его наследует. `SCM_RIGHTS` может его передать (тема 15).

Структуры адресов (`sockaddr_in`, `sockaddr_in6`) несут IP и порт. `getaddrinfo` превращает имя и строку службы в эти структуры. Предпочитайте `getaddrinfo` старому `gethostbyname`.

`SO_REUSEADDR` и (в Linux) `SO_REUSEPORT` меняют правила bind. Читайте страницу руководства, прежде чем копировать флаги.

Ошибки в `errno`. TCP `read` 0 означает, что сосед закрыл. `EAGAIN` означает неблокирующий и не готов.

Этот раздел — интерфейс ОС. Форматы пакетов, маршрутизация и детали DNS принадлежат `net.topics.md` (особенно темы 8, 9 и 10).

## TCP/UDP со стороны ядра

Ядро владеет состоянием протокола. Пользовательское пространство видит дескрипторы. Внутри у TCP есть конечный автомат (LISTEN, SYN-SENT, ESTABLISHED, TIME-WAIT и другие учебные состояния). У каждого соединения есть блок управления: номера последовательности, окна, буферы и таймеры.

TCP `write` копирует байты в буфер отправки ядра (или ждёт). Стек сегментирует байты, добавляет заголовки и передаёт пакеты слою IP и драйверу (тема 14). ACK от соседа освобождают буфер. `read` копирует из буфера приёма.

У UDP нет состояния соединения в смысле TCP. Ядро держит очередь приёма сокета из датаграмм. Датаграмма может отброситься, если очередь полна. UDP не передаёт повторно.

Ядро также реализует:

- поиск маршрута (какой интерфейс, какой следующий прыжок)
- поиск соседа (ARP или NDP)
- фрагментацию и сборку (где стек всё ещё это делает)
- контрольные суммы (иногда выгруженные на NIC)

`/proc/net/tcp` и `ss` показывают кортежи соединений и состояния. `netstat` — более старый инструмент.

Процесс не может задать номера последовательности TCP через API POSIX. Это состояние ядра. Параметры сокета (`setsockopt`) открывают маленький безопасный поднабор: флаги повторного использования, размеры буферов, `TCP_NODELAY`, keepalive.

Ядерный TCP — не единственная реализация. Некоторые системы используют пользовательские стеки. Этот путь изучает стек ядра Linux.

TIME-WAIT существует, чтобы задержанный пакет не присоединился к новому соединению, которое переиспользовало тот же кортеж. Студенты, которые быстро привязывают тот же порт, встречают это состояние.

## Сетевые пространства имён

Сетевое пространство имён — пространство имён Linux (тема 16), которое держит частный набор:

- сетевых интерфейсов
- адресов IPv4 и IPv6
- таблиц маршрутизации
- таблиц фильтров пакетов
- вида `/proc/net`

Процесс в новом netns не видит `eth0` хоста, если вы не переместите устройство или не создадите пару.

`ip netns add` создаёт именованное пространство имён. `unshare --net` создаёт анонимное для команды. Рантаймы контейнеров дают каждому контейнеру netns.

Обычный шаблон — пара veth: один конец на хосте (или мосту), другой конец в netns контейнера. Хост маршрутизирует или мостит трафик. NAT на хосте может спрятать много контейнеров за одним адресом (см. `net.topics.md` про NAT).

`lo` существует в каждом netns. Слушание на `127.0.0.1` в контейнере — не петля хоста.

`/proc/self/ns/net` — дескриптор пространства имён. `nsenter --net` к нему присоединяется.

Сетевые пространства имён изолируют стек. Они не шифруют трафик. Они не заменяют политику межсетевого экрана на хосте.

Не удаляйте интерфейсы хоста. Практикуйтесь с `ip netns` в VM.

## iptables / nftables (осведомлённость)

Linux может фильтровать и преобразовывать пакеты в ядре. Существуют два пользовательских интерфейса.

iptables — более старый инструмент. Он говорит с хуками `xtables` и netfilter. Правила сидят в таблицах (`filter`, `nat`, `mangle`) и цепочках (`INPUT`, `FORWARD`, `OUTPUT` и других). Каждое правило сопоставляет пакет, затем принимает, отбрасывает или прыгает.

nftables — более новый интерфейс. Один инструмент `nft` и одна правиловая VM заменяют многие двоичные файлы `iptables`. Дистрибутивы переходят на nftables. `iptables-nft` всё ещё может принимать старый синтаксис.

Netfilter — каркас ядра. Оба инструмента его программируют (с разными бэкендами). Хуки сидят на путях приёма, пересылки и передачи.

Цели осведомлённости:

- Знать, что тихое отбрасывание может быть фильтром, а не ошибкой приложения.
- Знать `iptables -L` против `nft list ruleset` (нужны права).
- Знать, что контейнеры и Kubernetes добавляют больше правил. Не редактируйте их наугад.
- Знать, что фильтр — не API сокетов. Процесс может слушать и всё равно ничего не получать.

Правила NAT переписывают адреса. Эта тема принадлежит `net.topics.md`. Здесь нужно только: ядро может изменить пакет, прежде чем сокет его увидит.

Не сбрасывайте производственный набор правил. Не практикуйте `iptables -F` на хосте, который вам нужен.

## Полный сетевой путь в `net.topics.md`

Эта тема ОС останавливается на интерфейсе ядра и ручках изоляции. `net.topics.md` — учебный путь по сетям. Используйте его для слоёв, адресов, маршрутизации, деталей TCP, DNS, TLS и отладки через `tcpdump`.

Сопоставление:

- Тема ОС 14 (`epoll`) плюс тема сети 10 (программирование сокетов)
- Темы ОС 16–17 (пространства имён, capabilities) плюс тема сети 21 (hardening)
- Тема ОС 18 (этот файл) плюс темы сети 8 и 9 (UDP и TCP)

Не пропускайте `net.topics.md`, если пишете серверы. API сокетов маленький. Производственные сбои часто — маршрутизация, MTU, NAT или TLS.

Не дублируйте тот путь здесь. Когда поздней лаборатории ОС нужен порт или захват пакетов, откройте соответствующую тему сети.

Предлагаемый порядок после этого файла: закончить темы ОС 19–22 или начать `net.topics.md` с темы 1, если сначала хотите пакеты. Оба порядка работают. Если начнёте сеть первой, вернитесь сюда за пространствами имён и netfilter.

Официальные точки старта: Linux `man 7 ip`, `man 7 tcp` и список ресурсов в `net.topics.md`.

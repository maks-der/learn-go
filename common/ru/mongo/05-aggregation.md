# 5. Агрегация

## Описание

Агрегация обрабатывает документы в **конвейере**. Каждый **этап** меняет поток. Эта тема показывает `$match`, `$project`, `$group`, `$sort`, `$limit`, `$lookup`, `$unwind`, `$addFields` и `$facet`. Вы также сравниваете агрегацию со многими мелкими find и изучаете лимиты памяти.

Сначала завершите запросы и моделирование. Завершите эту тему до изучения производительности.

Используйте один термин для каждого понятия. **Конвейер** — массив этапов. **Этап** — объект с одним оператором. `$match` фильтрует. `$group` объединяет документы. `$lookup` читает другую коллекцию. Не используйте агрегацию, когда хватает одного `find`.

## Конвейер: `$match`, `$project`, `$group`, `$sort`, `$limit`

Конвейер запускают через `aggregate`:

```javascript
db.orders.aggregate([
  { $match: { status: "paid" } },
  { $project: { userId: 1, total: 1, _id: 0 } },
  { $group: { _id: "$userId", spent: { $sum: "$total" } } },
  { $sort: { spent: -1 } },
  { $limit: 10 }
])
```

Порядок важен. `$match` сначала уменьшает число документов. Ставьте `$match` как можно раньше. `$match` может использовать индексы, когда стоит в начале.

`$project` формирует поля. `1` оставляет поле. Выражение вычисляет поле. Поздние этапы видят только спроецированные поля.

`$group` требует `_id`. `_id` — ключ группы. `null` группирует весь поток в один документ. Накопители включают `$sum`, `$avg`, `$min`, `$max`, `$push` и `$first`.

`$sort` и `$limit` работают как в `find`. `$sort` плюс `$limit` можно оптимизировать до сортировки top-k.

Поток — документы. После `$group` каждый документ — результат группы. Имена полей меняются. В поздних этапах используйте новые имена.

Пишите конвейеры списком. Именуйте каждый этап в комментарии в заметках. Проверяйте по одному этапу.

## `$lookup`, `$unwind`, `$addFields`

`$lookup` читает документы из другой коллекции. Это обычный этап в стиле соединения.

Простая форма (равенство):

```javascript
{
  $lookup: {
    from: "users",
    localField: "userId",
    foreignField: "_id",
    as: "user"
  }
}
```

Поле результата `user` — **массив**. Совпадение один-к-одному всё равно массив из одного документа. Пустой массив значит, что совпадения нет.

Разверните или используйте `$arrayElemAt`, если нужен один объект.

Более общая форма использует `pipeline` внутри `$lookup`. Можно `$match` и `$project` чужие документы.

`$lookup` может быть дорогим. Это не повод игнорировать встраивание. Если каждое чтение нуждается в lookup, лучше встроить или снять снимок.

Индексируйте `foreignField` на другой коллекции. Без индекса каждый lookup может сканировать.

Коллекции должны быть в одной базе для простой формы (прочитайте текущее руководство про исключения).

`$unwind` разбирает массив. Каждый элемент становится отдельным документом.

```javascript
{ $unwind: "$lines" }
```

Документ `{ _id: 1, lines: [ "a", "b" ] }` становится двумя документами. У каждого `lines: "a"` или `lines: "b"`.

Опции:

- `preserveNullAndEmptyArrays: true` — оставить документы с отсутствующим или пустым массивом
- `includeArrayIndex` — сохранить индекс в поле

`$unwind` умножает число документов. Массив из 1000 элементов делает 1000 документов из одного родителя. Ставьте `$match` до `$unwind`, когда можете.

Не делайте `$unwind` огромного неограниченного массива. Меняйте модель.

`$addFields` добавляет или заменяет поля. Остальные поля остаются.

```javascript
{ $addFields: { totalWithTax: { $multiply: [ "$total", 1.25 ] } } }
```

`$set` в агрегации — псевдоним `$addFields`. Это не тот же объект, что оператор обновления `$set` в `updateOne`.

Используйте `$addFields`, когда нужно вычисленное поле и старые поля всё ещё нужны. Используйте `$project`, когда нужна строгая форма вывода и вы отбрасываете поля.

Выражения используют операторы агрегации: `$concat`, `$ifNull`, `$cond`, `$dateToString` и многие другие. Первый аргумент многих выражений — путь к полю с `$`.

`$addFields` не фильтрует. Не группирует. Только вычисляет.

Частый шаблон: `$unwind`, затем `$group` для агрегации элементов массива, или `$unwind`, затем `$lookup` на каждой строке.

## `$facet`

`$facet` запускает несколько конвейеров на **одних** входных документах. Каждый подконвейер даёт массив в результате.

```javascript
{
  $facet: {
    byStatus: [
      { $group: { _id: "$status", n: { $sum: 1 } } }
    ],
    top: [
      { $sort: { total: -1 } },
      { $limit: 3 }
    ]
  }
}
```

Выход этапа — один документ (или один на входящую группу документов, но обычное использование — после общего `$match`). Каждый ключ фасета держит массив результатов этого подконвейера.

Используйте `$facet` для дашборда: счётчики, топ-списки и выборка за один круг.

Стоимость: сервер держит входы фасетов и выходы фасетов. Большие фасеты используют память. Каждый фасет независим. `$limit` в одном фасете не ограничивает другой.

Не заменяйте `$facet` два дешёвых find, если команда не может читать конвейер. Ясность важна.

Подконвейеры `$facet` в старых правилах не могут использовать `$out` или `$merge`. Прочитайте текущий список ограничений.

## Агрегация против многих мелких find

Данные можно загрузить многими вызовами `find` в приложении. Можно загрузить данные одним конвейером.

Предпочитайте **find**, когда:

- Нужны документы как они хранятся
- Есть фильтр, сортировка и проекция
- Листаете список
- Логику проще тестировать в приложении

Предпочитайте **агрегацию**, когда:

- Группируете, суммируете или перестраиваете форму
- Нужно развернуть и снова сгруппировать
- Нужен join-подобный `$lookup` за одну поездку
- Считаете отчёт

Многие мелкие find — проблема, когда:

- Запускаете find на каждый документ в цикле (N+1)
- Тянете большие документы и потом фильтруете в памяти
- Реализуете group-by в клиенте на огромном массиве

Агрегация — проблема, когда:

- Конвейер — второй язык программирования, который может менять только один человек
- Прячете бизнес-правила в конвейере, который приложение тоже реализует
- Делаете `$lookup` графов, которые должны быть сменой модели

Хороший выбор по умолчанию: find для OLTP-чтений, агрегация для отчётов и вычисленных представлений. Если отчёт идёт на каждый клик пользователя, храните вычисленное поле (позже шаблон).

## Лимиты памяти и `allowDiskUse`

У этапа конвейера есть лимит памяти. Во многих версиях лимит — **100 мегабайт** ОЗУ на этап, пока не разрешите диск.

```javascript
db.orders.aggregate(pipeline, { allowDiskUse: true })
```

`$group`, `$sort` и большие потоки `$facet` или `$unwind` могут упереться в лимит. Ошибка упоминает память или `allowDiskUse`.

`allowDiskUse` позволяет этапу сбрасывать данные во временные файлы. Запрос может завершиться. Он может быть намного медленнее. Сброс на диск — не бесплатное исправление.

Лучшие исправления:

- `$match` раньше
- Проецировать меньше полей
- Избегать `$unwind` огромных массивов
- Индекс, чтобы `$sort` не был огромной сортировкой в памяти
- Сменить модель
- Посчитать заранее

У Atlas и `mongod` есть и другие лимиты (время, размер документа). Лимит документа 16 МБ во многих случаях всё равно применяется к документам в потоке. Очень широкие массивы `$push` могут упереться в размер документа.

Не ставьте `allowDiskUse: true` на каждый OLTP-запрос. Используйте для отчётов.

`explain` в некоторых версиях может показать использование диска. Тестируйте на размере данных, похожем на промышленный.

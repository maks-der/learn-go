# 16. Непересекающиеся множества (Union-Find)

## Описание

Структура непересекающихся множеств (Union-Find) хранит разбиение n элементов. Эта тема объясняет массив родителя, объединение по рангу, сжатие путей, Крускала как клиента и запросы связности. Завершите эту тему после массивов и предварительного взгляда на компоненты графа.

Используйте один термин для каждого понятия. **Множество** здесь — один блок разбиения. **Find** возвращает представителя элемента. **Union** сливает два множества. **Представитель** (корень) — родитель, который называет множество.

---

## Массив родителя

Храните n элементов как целые 0 .. n−1. Массив **parent** имеет длину n. parent[i] — родитель i. Если parent[i] = i, то i — **корень**. Каждый корень называет одно множество.

В начале каждый элемент — своё множество:

```text
parent:  0  1  2  3  4
index:   0  1  2  3  4
```

**Find** без сжатия идёт parent[i], parent[parent[i]], ... пока не достигнет корня. Этот корень — представитель.

**Union** без ранга прикрепляет один корень к другому:

```text
union(a, b):
  ra = find(a)
  rb = find(b)
  if ra == rb: return   // already one set
  parent[rb] = ra
```

```text
union(0, 1) then union(1, 2)

0 ← 1 ← 2     or a star, depending on attach order
parent example: 0, 0, 1, 3, 4   // if 1→0 and 2→1
```

Структура — лес деревьев. Это не BST. Нет порядка ключей. Единственные ссылки — ссылки родителя.

Плохой порядок прикрепления может сделать линию. Find тогда стоит Θ(n). Следующие два раздела останавливают этот распад.

Память — Θ(n) для массива родителя. Вы можете добавить массив ранга или размера.

Не храните полный список членов в каждом множестве, если не нужно обходить членов. Find и union не нуждаются в этом списке.

## Объединение по рангу

**Объединение по рангу** прикрепляет дерево с меньшим рангом под дерево с большим рангом. Ранг — целое на каждом корне. Ранг не всегда точная высота после того, как вы добавляете сжатие путей. Без сжатия ранг равен высоте.

Правила:

1. Init rank[i] = 0 для каждого i.
2. Найдите два корня ra и rb.
3. Если ra == rb, остановитесь.
4. Если rank[ra] < rank[rb], поставьте parent[ra] = rb.
5. Если rank[ra] > rank[rb], поставьте parent[rb] = ra.
6. Если ранги равны, прикрепите один к другому и увеличьте ранг победителя на 1.

```text
unionByRank(a, b):
  ra = find(a)
  rb = find(b)
  if ra == rb: return
  if rank[ra] < rank[rb]:
      parent[ra] = rb
  else if rank[ra] > rank[rb]:
      parent[rb] = ra
  else:
      parent[rb] = ra
      rank[ra] = rank[ra] + 1
```

**Объединение по размеру** — близкий вариант. Вы храните число элементов в дереве. Вы прикрепляете меньшее дерево под больший корень. Вы складываете размеры.

Оба метода держат дерево мелким. Высота — O(log n), если вы объединяете по рангу или размеру и не сжимаете пути.

```text
equal ranks 0 and 0
attach 1 under 0, rank[0] becomes 1
```

Не увеличивайте ранг, когда ранги разные. Только случай равных рангов растит ранг.

Ранг не-корня не используется. Вы можете оставить старое число. Только корням нужен верный ранг.

## Сжатие путей

**Сжатие путей** меняет ссылки родителя во время find. После find(x) каждый узел на пути от x к старому корню указывает на корень. Следующий find на этом пути короткий.

```text
find(x):
  if parent[x] != x:
      parent[x] = find(parent[x])   // recursive compression
  return parent[x]
```

Итеративная форма: идите к корню, затем идите снова и ставьте каждого родителя на корень.

```text
before find(3):  3 → 2 → 1 → 0
after:           3 → 0, 2 → 0, 1 → 0
```

Сжатие путей не сливает два множества. Оно только сплющивает одно дерево.

**Вместе с объединением по рангу (или размеру)** find и union почти O(1) амортизированно. Точная функция — обратная функция Аккермана α(n). α(n) не больше 4 для любого размера, который вы будете использовать. Этот справочник говорит **почти O(1)** после того, как вы назовёте α(n) один раз.

Вы можете сжимать без ранга. Вы можете ранжировать без сжатия. Пара — стандарт.

Не сжимайте структуру, которая должна держать осмысленную форму дерева для другого алгоритма. Деревья Union-Find не имеют дополнительного смысла.

Рекурсивный find может переполнить стек вызовов на очень глубокой цепи до первого сжатия. Для первой реализации n мало. Для большого n с плохим лесом используйте итеративный find.

## MST Крускала использует это

**Минимальное остовное дерево (MST)** связного неориентированного взвешенного графа — множество из n − 1 рёбер. Множество соединяет все вершины. Сумма весов минимальна.

**Крускал:**

1. Отсортируйте все рёбра по возрастанию веса.
2. Init Union-Find на n вершинах.
3. Для каждого ребра {u, v} в этом порядке: если find(u) != find(v), добавьте ребро в MST и union(u, v).
4. Остановитесь, когда у вас n − 1 рёбер, или сообщите, что граф не связен.

```text
edges sorted:  (0,1,1), (1,2,2), (0,2,3)
add (0,1), add (1,2), skip (0,2)  // same set
```

Union-Find отвечает «закрывает ли это ребро цикл?» почти за O(1). Если u и v уже в одном множестве, ребро — цикл в лесу и вы его пропускаете.

Вы увидите Прима в продвинутой теме графов. Прим растит одно дерево кучей. Крускал растит лес Union-Find. Оба вычисляют MST, если граф связен.

Время Крускала доминирует сортировка: O(m log m), плюс почти O(m) работы Union-Find.

Не используйте Крускала на ориентированном графе как первое MST. MST — неориентированная идея в этом справочнике.

Если граф имеет несколько компонентов, Крускал производит **минимальный остовный лес**. Вы получаете одно дерево на компонент.

## Запросы связности

**Запрос связности** спрашивает, находятся ли u и v в одном компоненте.

Офлайн-форма:

1. Init Union-Find.
2. Union каждого ребра графа.
3. Ответьте find(u) == find(v) для каждого запроса.

```text
edges: 0-1, 1-2
query (0,2) → true
query (0,3) → false
```

Онлайн-форма: рёбра и запросы смешиваются. Вы делаете union, когда появляется ребро. Вы делаете find, когда появляется запрос. Union-Find поддерживает это, если рёбра только добавляются (без удаления).

Удаление ребра — не стандартная операция Union-Find. Если рёбра исчезают, нужна другая структура или пересборка.

**Динамическая связность** с удалениями — продвинутая тема. Этот справочник её не требует.

Вы можете хранить дополнительный **размер компонента** на каждом корне. Тогда вы отвечаете «сколько вершин с u?» как size[find(u)].

Вы можете назначить **id компонента** как корень. Корни могут меняться после union. Не храните старый корень как вечный id, если не добавите отдельный массив id, который обновляете осторожно. Предпочитайте find во время запроса.

BFS тоже отвечает на связность. Union-Find лучше, когда вход — список рёбер и вам не нужен порядок посещения вершин.

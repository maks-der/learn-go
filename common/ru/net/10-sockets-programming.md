# 10. Программирование сокетов

## Описание

Сокет — программный интерфейс к транспортному уровню. Эта тема показывает вызовы BSD-сокетов, потоки TCP против датаграмм UDP, блокирующий против неблокирующего ввода-вывода, `SO_REUSEADDR`, частичные чтения и записи TCP, таймауты и стандартную библиотеку в Go и в Python.

Используйте один термин для каждого понятия. Сокет — объект вроде файла, который ядро привязывает к протоколу и адресу. Завершите эту тему после TCP и UDP. Сочетайте её с темами по операционным системам для вида ядра.

Не пропускайте ошибки. Вызов сокета может упасть. Закройте сокет, когда закончите.

## BSD-сокеты: `socket`, `bind`, `listen`, `accept`, `connect`

API BSD-сокетов — общая модель. Многие языки его оборачивают. Имена вызовов сохраняют ту же идею.

`socket` создаёт сокет. Вы выбираете семейство (`AF_INET`, `AF_INET6`) и тип (`SOCK_STREAM` для TCP, `SOCK_DGRAM` для UDP).

`bind` прикрепляет локальный адрес и порт. Сервер привязывает известный порт. Клиент может привязать, или ядро может выбрать эфемерный порт на `connect` или на первой отправке.

`listen` помечает сокет TCP как сервер. Вы передаёте backlog. Ядро ставит в очередь завершённые рукопожатия.

`accept` возвращает новый сокет для одного соединения TCP. Исходный сокет listen остаётся открытым для других клиентов.

`connect` на TCP выполняет рукопожатие к удалённому адресу. `connect` на UDP задаёт узел по умолчанию. Он не делает рукопожатие.

Порядок сервера TCP: `socket`, `bind`, `listen`, цикл `accept`. Порядок клиента TCP: `socket`, необязательный `bind`, `connect`. Сервер UDP: `socket`, `bind`, `recvfrom`. Клиент UDP: `socket`, `sendto` или `connect` затем `send`.

Не делайте `listen` на сокете UDP. Не делайте `accept` на UDP. Не забывайте `bind` на сервере UDP, если нужен известный порт.

Сокеты IPv6 могут использовать `AF_INET6` и id области для link-local адресов.

## Поток TCP против датаграммы UDP

Сокет TCP — поток байтов. `read` может вернуть меньше байт, чем вы просили. Два вызова `write` могут прийти как один `read`. Один `write` может прийти как два `read`. Нужно разбирать протокол: префикс длины, разделитель или разборщик вроде HTTP.

Сокет UDP — сокет датаграмм. Один `recv` возвращает одну датаграмму (до вашего буфера). Если буфер слишком мал, хвост может обрезаться. Две датаграммы остаются двумя датаграммами.

У TCP есть соединение. После `connect` или `accept` `send` и `recv` используют этот узел. UDP может использовать `sendto`/`recvfrom` и говорить со многими узлами на одном сокете.

Ошибки различаются. TCP может вернуть 0 байт при чистом закрытии. У UDP нет этого сигнала закрытия. Ошибки ICMP могут всплыть на соединённом сокете UDP в некоторых системах.

Выбирайте API, который совпадает с протоколом. Не читайте TCP так, будто каждый `read` — одно сообщение. Не отправляйте датаграмму UDP на 10 MB так, будто это поток.

Go `net.Conn` ориентирован на поток для TCP. `net.PacketConn` ориентирован на датаграммы. Python `socket.SOCK_STREAM` и `SOCK_DGRAM` совпадают с тем же разделением.

## Блокирующий против неблокирующего

Блокирующий сокет ждёт. `accept` ждёт клиента. `recv` ждёт данные. `connect` ждёт рукопожатие. Поток или горутина, которая вызывает функцию, не продолжается, пока вызов не вернётся или не произойдёт ошибка.

Неблокирующий сокет возвращается сразу, когда не может завершиться. Ошибка — `EAGAIN` / `EWOULDBLOCK` (или обёртка языка). Программа должна повторить позже. Программа использует `select`, `poll`, `epoll`, `kqueue` или `io_uring` в Unix или завершение ввода-вывода в Windows. Go использует опрос внутри среды выполнения. Вы всё равно пишете вызовы `Read`, похожие на блокирующие. Среда выполнения паркует горутину.

Неблокирующий режим — не то же самое, что таймаут. Таймаут будит вас через время. Неблокирующий режим будит сразу с «попробуй позже».

Сервер, который использует один блокирующий поток на соединение, может упереться в пределы потоков. Сервер, который использует неблокирующий ввод-вывод или горутины, может держать много соединений.

Не крутитесь в тесном цикле на неблокирующем сокете без опроса. Вы потратите ЦП. Не считайте Go `SetNonblock` обычным путём. Пакет `net` уже интегрирован с опросом.

Python может использовать блокирующие сокеты, `selectors` или `asyncio`. Выберите одну модель и держитесь её в маленькой программе.

## `SO_REUSEADDR`

`SO_REUSEADDR` — параметр сокета. На многих системах Unix он позволяет серверу привязать порт, у которого ещё есть соединения в `TIME_WAIT` от предыдущего процесса. После перезапуска `bind` успешен.

Точный смысл различается в Windows и в Unix. На некоторых системах `SO_REUSEADDR` также позволяет больше одной привязки к одному адресу. `SO_REUSEPORT` (Linux и другие) — другой параметр, который позволяет нескольким сокетам делить порт для распределения нагрузки.

Go `Listen` ставит `SO_REUSEADDR` по умолчанию на некоторых платформах. Python позволяет `setsockopt(SOL_SOCKET, SO_REUSEADDR, 1)` до `bind`.

Не считайте `SO_REUSEADDR` «два сервера могут безопасно обслуживать один порт на всех ОС». Читайте правила платформы. Не используйте `SO_REUSEADDR`, чтобы скрыть ошибку, которая никогда не закрывает сокеты.

Клиенту обычно не нужен этот параметр. Серверу, который часто перезапускается, нужен.

`TIME_WAIT` на локальном порту клиента — другая проблема (эфемерные порты). `SO_REUSEADDR` на слушателе — обычный учебный случай.

## Частичные чтения и записи на TCP

`write` TCP может принять только часть вашего буфера. Возвращаемое значение — число байт, которое приняло ядро. Остальное нужно отправить в цикле, если API языка не документирует полную запись (Go `net.Conn.Write` всё ещё может быть коротким в теории; используйте `io.Copy` или цикл. Многие обёртки повторяют).

`read` TCP может вернуть любую длину от 1 до размера буфера (или 0 при закрытии). Нужно крутить цикл, пока не будет полного сообщения. Фиксированный `read` на 1024 — не «один запрос HTTP».

`writev` / `sendmsg` и буферизованные писатели (`bufio` в Go) уменьшают мелкие записи. Они не меняют модель потока. На чтении всё равно разбираете.

Сигналы и прерывания могут обрезать вызов. Проверяйте число байт и ошибку вместе. Сначала обрабатывайте байты, когда API возвращает байты плюс ошибку.

Не игнорируйте короткую запись. Не считайте, что `read` заполняет буфер. Не используйте правила UDP на сокете TCP.

Библиотеки TLS и HTTP делают это за вас. Когда пишете сырой протокол, циклы ваши.

## Таймауты

Таймаут задаёт срок. Если вызов не закончится до срока, API возвращает ошибку. Таймауты останавливают поток от вечного ожидания, когда узел пропал.

Задайте таймаут на `connect`, чтобы мёртвый адрес падал. Задайте таймаут на `read`, чтобы молчаливый узел не держал работника. Задайте таймаут на `write` на медленном узле или с нулевым окном.

Go использует `SetDeadline`, `SetReadDeadline` и `SetWriteDeadline` на `net.Conn`. Python использует `settimeout` на сокете или ожидание `asyncio`. Срок часто абсолютное время. Таймаут часто длительность. Читайте свой API.

Простаивающие соединения в Internet могут умереть без FIN. Keepalive или ping приложения плюс таймаут это обнаруживают.

Не используйте 24-часовой таймаут чтения на работнике публичного сервера, если клиент может держать слот. Не используйте таймаут 1 мс на рукопожатии WAN.

Ошибка таймаута — не всегда ошибка программы. Это сигнал. Закройте сокет или повторите по политике.

## Стандартная библиотека языка (`net` в Go, `socket` в Python)

Пакет Go `net` — стандартная библиотека для сокетов. `net.Listen("tcp", addr)` возвращает `Listener`. `Accept` возвращает `Conn`. `net.Dial("tcp", addr)` возвращает `Conn`. `net.ListenPacket("udp", addr)` — UDP. Используйте `net.JoinHostPort` и `net.SplitHostPort`. Разрешайте имена через `net.Resolver` или дайте `Dial` разрешить.

Предпочитайте интерфейсы `net.Conn` в функциях. Используйте `tcpAddr` только когда нужны дополнительные поля. Всегда проверяйте ошибки. Закрывайте через `defer conn.Close()`, когда владеете соединением.

Python `socket` ближе к именам BSD. `socket.socket(AF_INET, SOCK_STREAM)`, `bind`, `listen`, `accept`, `connect`. `socket.create_server` и `socket.create_connection` — помощники. `socket.timeout` — исключение таймаута.

В обоих языках есть HTTP в стандартной библиотеке или в обычных пакетах. Эта тема — сырой сокет. Используйте библиотеки HTTP для HTTP. Используйте сырые сокеты, когда учитесь или пишете свой протокол.

Не смешивайте блокирующие сокеты Python с двумя потоками без блокировки на одном сокете. Не игнорируйте `Close` в Go. Не используйте `Listen("tcp", ":80")` на привилегированном порту без прав.

IPv6 в обеих библиотеках нуждается в скобках в некоторых строках адресов. Проверьте `::1` и `127.0.0.1`.

### Вопросы

#### Теоретические вопросы

1. Опишите сервер TCP от `socket` до безопасного цикла `read` с таймаутом.

#### Простые практические задания

1. Напишите шпаргалку на одну страницу: вызовы BSD, поток против датаграммы, блокирование, reuse, частичный ввод-вывод, таймауты, имена Go и Python.

#### Средние практические задания

1. Напишите эхо-сервер и клиент TCP на вашем языке. Добавьте таймаут чтения. Задокументируйте, как запускать оба.

#### Сложные практические задания

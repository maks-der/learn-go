# 9. Множества и отображения как ADT

## Описание

Множество и отображение — абстрактные типы данных. Эта тема объясняет неупорядоченные (хеш) формы и упорядоченные (дерево) формы. Вы также изучаете мультимножество, инвалидацию итератора и как выбирать хеш против дерева. Завершите эту тему после хеш-таблиц. Завершите темы про деревья после этого предварительного взгляда.

Используйте один термин для каждого понятия. **Множество** хранит уникальные элементы. **Отображение** хранит уникальные ключи. У каждого ключа одно значение. **Неупорядоченное** означает, что порядок обхода — не порядок сортировки. **Упорядоченное** означает, что обход следует порядку ключей. **Мультимножество** (мешок) допускает повторяющиеся элементы.

## Неупорядоченное множество / отображение (хеш)

**Неупорядоченное множество** поддерживает insert, delete и contains. Множество не держит порядок сортировки. Два равных элемента не появляются дважды.

**Неупорядоченное отображение** поддерживает insert(key, value), delete(key) и find(key). Ключи уникальны. Вторая вставка того же ключа обновляет значение.

Обычная реализация — хеш-таблица. Средние contains и find — Θ(1). Худший случай — Θ(n).

```text
set:   {"cat", "dog"}
map:   {"cat": 3, "dog": 1}
```

```go
seen := map[string]struct{}{"cat": {}, "dog": {}}
count := map[string]int{"cat": 3, "dog": 1}
```

```python
seen = {"cat", "dog"}
count = {"cat": 3, "dog": 1}
```

Обход посещает каждый элемент или каждый ключ один раз. Порядок может измениться после изменения размера. Не пишите программу, которой нужен отсортированный обход хеш-множества.

Множество — не список. Contains на списке — Θ(n). Contains на хеш-множестве — средняя Θ(1). Если вы только спрашиваете «есть ли x?», предпочитайте множество.

Отображение — не пара параллельных массивов, если n не крошечное. Поиск по ключу на хеш-отображении — средняя Θ(1). Поиск по ключу на неотсортированном массиве — Θ(n).

Используйте значения `struct{}` в Go, когда нужно множество. Значение не несёт дополнительной информации. Используйте объект `set` в Python.

## Упорядоченное множество / отображение (дерево)

**Упорядоченное множество** держит элементы в отсортированном порядке. Обход посещает наименьший элемент первым (или в определённом порядке).

**Упорядоченное отображение** держит ключи в отсортированном порядке. Поиск всё равно использует ключ. Вы также можете спросить следующий ключ или диапазон ключей.

Обычная реализация — сбалансированное двоичное дерево поиска или список с пропусками в некоторых библиотеках. Find, insert и delete — Θ(log n) в худшем случае, если дерево сбалансировано. Вы реализуете базовое BST в теме 11. Баланс — более поздняя тема.

```text
ordered set:   1, 3, 8, 20
range 4..10 →  8
```

В Go нет упорядоченного отображения в языке. Вы сортируете срез ключей, когда нужен порядок. В стандартной библиотеке есть `slices.Sort`. Некоторые дополнительные библиотеки дают дерево-отображение.

Python 3.7+ `dict` держит порядок **вставки**. Порядок вставки — не порядок ключей по сортировке. `dict` — не упорядоченное отображение в смысле дерева. Используйте `sorted(d)` для отсортированного вида. Используйте стороннее дерево, если нужен следующий ключ за Θ(log n).

Java `TreeMap` и C++ `std::map` — упорядоченные отображения. Выучите идею, даже если в вашем языке нет встроенного дерева-отображения.

Используйте упорядоченное отображение, когда нужны:

- отсортированный обход
- ближайший ключ
- запросы диапазона

Используйте хеш-отображение, когда нужен только поиск по точному ключу.

## Мультимножество / мешок

**Мультимножество** (мешок) хранит элементы и допускает дубликаты. Мешок считает, сколько раз элемент появляется.

Операции: add(x), remove(x) (удалить одну копию), count(x) и size (всего копий).

```text
add 2, add 2, add 5
count(2) = 2
remove(2)
count(2) = 1
```

Обычная реализация — отображение из элемента в счётчик. Add увеличивает счётчик. Remove уменьшает счётчик. Если счётчик становится 0, вы удаляете ключ.

```go
bag := map[int]int{}
bag[2]++
bag[2]++
bag[5]++
```

```python
from collections import Counter
bag = Counter([2, 2, 5])
```

Список тоже хранит дубликаты. Count на списке — Θ(n). Count на мешке-отображении — средняя Θ(1).

Мультимножество — не множество. Множество теряет вторую копию. Если задача говорит «два жетона типа A», вам нужен мешок или список.

Удаление одной копии — не удаление всех копий. Определите операцию в ADT. Дайте `remove_all`, если нужно.

## Инвалидация итератора (зависит от языка, концептуально)

**Итератор** — объект или состояние цикла, которое посещает элементы. **Инвалидация** означает, что итератор больше не безопасен. Позднее использование может пропустить элементы, посетить дважды, упасть или дать устаревший вид.

Правила зависят от языка и коллекции.

**Изменение размера хеш-отображения.** Рост двигает ключи. Итератор, который держит индекс корзины, может быть неверным. Некоторые языки запрещают вставку во время обхода.

**Map Go.** Вы не должны добавлять новый ключ во время `range` по тому же map. Обновление существующего значения разрешено. Удаление текущего ключа имеет определённые правила. Читайте текущую спецификацию, когда пишете производственный код. Простое студенческое правило: не вставляйте новые ключи в цикле `range`.

**Python dict.** Вы не должны менять набор ключей во время обхода. Вставка или удаление ключа может поднять `RuntimeError`.

**Списки.** Итератор по динамическому массиву может сломаться, когда вы вставляете или удаляете в середине. Индексы сдвигаются.

```text
unsafe idea
  for each key in map:
      map.insert(new_key)   // can invalidate
```

Безопасные шаблоны:

- соберите ключи для добавления во второй список, затем вставьте после цикла
- обходите копию ключей
- используйте цикл for с индексом только когда язык определяет правило

Этот справочник не перечисляет каждое языковое правило. Вы должны прочитать документ своей коллекции. Выучите идею: структурное изменение может инвалидировать обход.

## Выбор хеша против дерева

Выбирайте структуру по операциям.

**Выбирайте хеш-множество или хеш-отображение**, когда:

- нужны точный find, insert и delete
- не нужны отсортированные ключи
- вы принимаете среднюю Θ(1) и худшую Θ(n)
- ключи хешируемы и стабильны

**Выбирайте дерево-множество или дерево-отображение**, когда:

- нужен отсортированный обход
- нужны next, previous или диапазон
- нужна оценка худшего случая Θ(log n)
- ключи сравнимы (порядок существует)

**Выбирайте отсортированный массив**, когда:

- вы строите один раз и ищете много раз
- n мало или обновления редки
- двоичного поиска достаточно
- вы можете заплатить Θ(n) за вставку в середину

```text
need only exact key?          → hash map
need order or range?          → tree map (or sort when you print)
need worst-case log n?        → balanced tree
n tiny and simple code?       → array + scan
```

Не выбирайте дерево, потому что оно выглядит продвинутым. Хеш-отображение — правильный выбор по умолчанию для словаря.

Не выбирайте хеш-отображение, потому что оно популярно, если вам нужен следующий больший ключ. Сортируйте или используйте дерево.

Память: хеш-таблица использует дополнительные корзины. Дерево использует дополнительные указатели на узел. Измеряйте, если память тесна.

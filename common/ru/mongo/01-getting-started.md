# 1. Начало работы

## Описание

MongoDB — документоориентированная база данных. Такая база хранит данные как документы, а не как строки в таблицах. Эта тема показывает, что такое MongoDB, когда подходит документная модель, как установить MongoDB и как пользоваться `mongosh`. Завершите эту тему до того, как писать запросы.

Используйте один термин для каждого понятия. **База данных** содержит коллекции. **Коллекция** содержит документы. **Документ** — один объект BSON с полями. Не называйте коллекцию таблицей. Не называйте документ строкой.

Сначала выучите общие идеи баз данных. Затем идите по этому пути MongoDB.

## Что такое MongoDB (документоориентированная база)

MongoDB — система управления документоориентированной базой данных. Процесс сервера — `mongod`. Клиенты отправляют команды в `mongod`. Atlas — облачный сервис MongoDB. Одна и та же документная модель работает на локальном сервере и в Atlas.

Документ — набор пар поле–значение. Значениями бывают строки, числа, даты, массивы и вложенные документы. Документы в одной коллекции не обязаны иметь одинаковые поля. У приложения всё равно есть схема. База не навязывает одну схему, пока вы не добавите валидацию.

MongoDB хранит документы в BSON. BSON — двоичный формат. Запросы вы пишете в синтаксисе, похожем на JSON. Сервер хранит и возвращает BSON.

MongoDB не является реляционной базой. Она не использует SQL как основной язык. Ей не нужны соединения для каждой связи. Связи всё равно можно моделировать. Связанные данные встраивают или хранят как ссылку.

MongoDB — не только хранилище ключ–значение. У документа может быть много полей. Эти поля можно запрашивать. Эти поля можно индексировать.

Типичные применения:

- Операционные данные веб- и мобильных приложений
- Контент с вложенной формой
- События и каталоги
- Сервисы, которые уже обмениваются JSON

## Когда подходят документы и когда лучше реляционная модель

Документная модель подходит, когда приложение читает и пишет вложенный объект как одну единицу. Пример: заказ со строками. Заказ и строки — один документ. Одно чтение возвращает весь заказ.

Документная модель также подходит, когда форма данных часто меняется. Новые поля не требуют миграции таблицы на каждое изменение. Имена полей всё равно планируют. Типы всё равно планируют.

Реляционная модель лучше, когда многие сущности делят данные и эти данные нужно держать в одном месте. Пример: имя товара, которое многие заказы должны показывать как актуальное. Реляционный внешний ключ и соединение держат одну строку товара.

Реляционная модель также лучше, когда нужны много разовых соединений, строгие ограничения на несколько строк или тяжёлая отчётность по многим таблицам. SQL и нормализованная схема сильны для такой работы.

Используйте документы, когда:

- Данные, к которым обращаются вместе, имеют ясное вложение
- Документ остаётся ниже лимита размера
- Массивы остаются ограниченными
- Схемой владеет приложение

Используйте реляционную модель, когда:

- В центре модели связи многие-ко-многим
- Основной контроль — декларативная ссылочная целостность
- Аналитики запускают много новых запросов с соединениями
- Запись по умолчанию — транзакции по многим независимым строкам

Можно использовать оба. Многие системы хранят операционные документы в MongoDB, а отчёты — в реляционной базе или хранилище.

## Установка MongoDB Community или использование Atlas / Docker

MongoDB обычно запускают тремя способами.

**MongoDB Community Server.** Скачайте установщик со страницы загрузок MongoDB. Выберите операционную систему. Установите сервер. Запустите службу `mongod`. Community Server бесплатен. Хост, диск и обновления вы ведёте сами.

**Atlas.** Atlas — официальный облачный сервис. Создайте проект и кластер. Бесплатного тарифа достаточно для учёбы. Сервер ведёт Atlas. Вы подключаетесь строкой соединения. Нужно задать пользователя базы и список IP-доступа.

**Docker.** Docker запускает `mongod` в контейнере. Типичная учебная команда использует официальный образ `mongo` и публикует порт `27017`. Данные в контейнере пропадут, если не смонтировать том. Используйте том, если данные должны остаться.

Для этого пути выберите один способ и держитесь его. Не смешивайте три среды без пометки, какую используете.

После запуска сервера установите `mongosh`, если установщик его не добавил. `mongosh` — официальная оболочка.

Порт по умолчанию — `27017`. Не открывайте этот порт в публичный интернет на учебной машине без аутентификации.

## Оболочка `mongosh`

`mongosh` — MongoDB Shell. Это клиент командной строки. Им запускают команды, смотрят данные и проверяют запросы. Старая оболочка `mongo` — не текущий инструмент. Используйте `mongosh`.

Подключение к локальному серверу:

```text
mongosh
```

Подключение по URI:

```text
mongosh "mongodb://localhost:27017"
```

Подключение к Atlas — по URI, который показывает Atlas. В URI есть имя пользователя. Оболочка спрашивает пароль, или учётные данные кладут в URI. Не коммитьте URI с паролем.

После подключения вы в среде JavaScript. Базу выбирают командой `use`:

```text
use learn
```

`db` — текущая база. `db.help()` показывает частые помощники. `show dbs` перечисляет базы. `show collections` перечисляет коллекции в текущей базе.

Простая вставка и поиск:

```javascript
db.notes.insertOne({ title: "hello", n: 1 })
db.notes.find()
```

`mongosh` печатает документы как extended JSON. Результаты можно присвоить переменным. Можно писать небольшие скрипты. Для ежедневной учёбы вводите команды по одной.

Выход — `exit` или `Ctrl+C`, как описано в документации оболочки.

## Базы данных, коллекции, документы

**Развёртывание** MongoDB содержит одну или несколько баз. **База данных** содержит коллекции и представления. **Коллекция** содержит документы. **Документ** — единица, которую вставляют, обновляют и ищут.

Имена:

- Имена баз — строки. Не используйте зарезервированные имена вроде `admin`, `local` и `config` для данных приложения.
- Имена коллекций — строки. Используйте ясное существительное во множественном числе, например `orders`.
- Имена полей — строки. Не начинайте имена полей приложения с `$`. Не используйте `.` в имени поля.

MongoDB создаёт базу, когда вы впервые сохраняете в ней данные. MongoDB создаёт коллекцию, когда вы впервые вставляете документ, если не создали коллекцию намеренно.

У каждого документа есть поле `_id`. Если `_id` опустить, MongoDB добавит ObjectId. `_id` уникален в коллекции.

Коллекция — не таблица. Нет фиксированного списка столбцов. Два документа могут выглядеть по-разному. Эта гибкость — не повод хранить случайные формы без плана.

Команды в `mongosh` используют `db.collectionName.method()`. Пример: `db.orders.insertOne({ ... })`.

Удалить коллекцию — `db.orders.drop()`. Удалить базу — `db.dropDatabase()`. Эти команды удаляют данные. Не запускайте их на общем кластере без осторожности.

### Вопросы

#### Теоретические вопросы

#### Простые практические задания

1. Создайте базу `start`. Вставьте `{ ok: true }` в `smoke`. Найдите документ. Запишите `_id`, который видите.
2. Напишите шпаргалку на одну страницу с пунктами: `mongosh`, `use`, `show dbs`, `show collections`, `insertOne`, `find`, порт по умолчанию.
3. Экспортируйте или скопируйте способ соединения (локальный хост или хост Atlas) в личную заметку. Укажите имя базы для практики.
4. Создайте дерево папок в заметках для следующих тем: `crud`, `indexes`, `agg`. Положите в каждую по пустому файлу. Это только журнал учёбы.

#### Средние практические задания

1. Напишите небольшой скрипт (PowerShell или bash), который проверяет `mongosh --version` и затем делает ping. Остановитесь, если оболочки нет.
2. Сбросьте учебную базу: удалите её, создайте снова, вставьте два документа. Запишите каждую команду.
3. Опишите установку в десяти шагах, чтобы другой новичок мог повторить. Укажите ОС и способ (Community, Atlas или Docker).

#### Сложные практические задания

1. Подключитесь к одному кластеру Atlas или одному локальному серверу из `mongosh` и из GUI-клиента (Compass или аналог). Покажите один find в каждом. Сравните отображаемые типы.
2. Прочитайте текущую страницу «Install MongoDB» для своей ОС. Добавьте в заметки одно производственное предупреждение с этой страницы (аутентификация, bind IP или подобное).

# 13. Ввод-вывод и HTTP-серверы

## Описание

Эта тема показывает, как программы Go читают байты, пишут байты и отдают HTTP. Интерфейсы `io.Reader` и `io.Writer` — центр этого дизайна. Файлы, буферы, TCP, HTTP и TLS все реализуют или потребляют эти интерфейсы.

Используйте один термин для каждого понятия. Читатель производит байты. Писатель потребляет байты. Обработчик обслуживает HTTP-запрос. Шаблон в `ServeMux` (Go 1.22 и новее) совпадает с методом и путём. Не игнорируйте ошибки вызовов ввода-вывода. Закрывайте каждый файл и каждое соединение, когда заканчиваете работу.

## `io.Reader` / `io.Writer` и `bufio`

`io.Reader` имеет один метод:

```go
type Reader interface {
	Read(p []byte) (n int, err error)
}
```

`Read` заполняет `p` до `len(p)` байтов. Возвращает число байтов и ошибку. `io.EOF` означает, что байтов больше нет. `Read` может вернуть `n > 0` и `io.EOF` в одном вызове. Сначала обработайте байты. Затем обработайте `EOF`.

`io.Writer` имеет один метод:

```go
type Writer interface {
	Write(p []byte) (n int, err error)
}
```

`Write` пишет `len(p)` байтов или возвращает ошибку. Проверяйте, что `n` равно `len(p)`, когда нужна полная запись.

Полезные помощники в пакете `io`:

- `io.Copy(dst, src)` копирует из читателя в писатель до EOF
- `io.LimitReader(r, n)` останавливается после `n` байтов
- `io.MultiReader` и `io.MultiWriter`
- `io.TeeReader(r, w)` читает из `r` и пишет копию в `w`
- `io.NopCloser(r)` добавляет no-op `Close` к читателю
- `io.ReadAll(r)` читает все оставшиеся байты (следите за памятью)

```go
limited := io.LimitReader(file, 1024)
n, err := io.Copy(os.Stdout, limited)
```

Не используйте `io.ReadAll` на неограниченном сетевом потоке. Используйте `io.LimitReader` или декодер, который останавливается.

Пакет `bufio` добавляет буферизацию. `bufio.NewReader` уменьшает системные вызовы на маленьких чтениях. `bufio.NewWriter` собирает записи. Вызывайте `Flush` на писателе, прежде чем данные нужны на другой стороне. `bufio.Scanner` читает строки или токены.

```go
sc := bufio.NewScanner(f)
for sc.Scan() {
	line := sc.Text()
	_ = line
}
if err := sc.Err(); err != nil {
	return err
}
```

Задайте `sc.Buffer`, когда строка может быть больше размера токена по умолчанию. Проверяйте `sc.Err()` после цикла.

Предпочитайте `io.Reader` и `io.Writer` в параметрах функций. Принимайте интерфейс. Возвращайте конкретный тип, когда владеете реализацией.

## Файлы и каталоги

Пакет `os` открывает файлы. `os.Open` открывает для чтения. `os.Create` обрезает и пишет. `os.OpenFile` принимает флаги вроде `os.O_APPEND` и `os.O_RDWR`. Проверяйте ошибку. Закрывайте файл через `defer f.Close()` после успешного открытия.

```go
f, err := os.Open(path)
if err != nil {
	return err
}
defer f.Close()
```

`os.ReadFile` и `os.WriteFile` покрывают маленькие файлы. `os.ReadFile` загружает весь файл в память. Не используйте его для огромных файлов.

`os.Mkdir` создаёт один каталог. `os.MkdirAll` создаёт родителей. `os.Remove` удаляет файл. `os.RemoveAll` удаляет дерево. `os.Rename` переименовывает или перемещает файл. `os.Stat` возвращает `fs.FileInfo`. Используйте `errors.Is(err, os.ErrNotExist)` для отсутствующего пути.

Пакет `path/filepath` соединяет и разделяет пути на диске. Используйте `filepath.Join`, `filepath.WalkDir` и `filepath.Abs`. Не соединяйте пути на диске через `+` и `/`.

```go
err := filepath.WalkDir(root, func(path string, d fs.DirEntry, err error) error {
	if err != nil {
		return err
	}
	if d.IsDir() {
		return nil
	}
	fmt.Println(path)
	return nil
})
```

`os.DirFS` и `embed.FS` реализуют `fs.FS`. Файлы можно открывать через этот интерфейс. Тема 8 покрывает `embed`.

Всегда проверяйте ошибки ввода-вывода. Успешный `Write` всё равно может не удаться на `Close`, когда система сбрасывает данные. Проверяйте ошибку `Close`, когда запись должна сохраниться.

## TCP через `net`

Пакет `net` говорит TCP и UDP. `net.Listen("tcp", addr)` слушает. `ln.Accept()` возвращает `net.Conn` для каждого клиента. `net.Dial("tcp", addr)` соединяется как клиент.

```go
ln, err := net.Listen("tcp", "127.0.0.1:0")
if err != nil {
	return err
}
defer ln.Close()

go func() {
	conn, err := ln.Accept()
	if err != nil {
		return
	}
	defer conn.Close()
	io.Copy(conn, conn)
}()

c, err := net.Dial("tcp", ln.Addr().String())
```

`net.Conn` реализует `io.Reader` и `io.Writer`. Его можно обернуть через `bufio`. Задавайте дедлайны через `conn.SetDeadline`, `SetReadDeadline` и `SetWriteDeadline`. Дедлайн — основной способ остановить застрявшее чтение.

Закрывайте слушатель, когда процесс останавливается. Закрывайте каждое соединение, когда обмен заканчивается. Accept в настоящем сервере выполняется в цикле. Ограничивайте работу на соединение context или дедлайном.

`net.JoinHostPort` строит `host:port`. `net.SplitHostPort` разделяет его. Используйте этих помощников вместо строкового формата для IPv6.

Резолвьте имена через `net.Resolver` или через `net.Dial`. Предпочитайте `Dialer.DialContext`, чтобы отмена работала.

Не используйте TCP как первый HTTP API. Для HTTP используйте `net/http`. Используйте `net`, когда строите пользовательский протокол или изучаете сокеты.

## HTTP-серверы, mux и middleware

Пакет `net/http` отдаёт HTTP. У `http.Handler` один метод: `ServeHTTP(ResponseWriter, *Request)`. `http.HandlerFunc` преобразует функцию в обработчик.

```go
http.HandleFunc("GET /health", func(w http.ResponseWriter, r *http.Request) {
	w.WriteHeader(http.StatusOK)
	_, _ = w.Write([]byte("ok"))
})
err := http.ListenAndServe(":8080", nil)
```

С Go 1.22 `ServeMux` совпадает с шаблонами метода и пути. `"GET /items/{id}"` связывает `id`. Читайте значение через `r.PathValue("id")`. Старым версиям Go нужен сторонний роутер или ручной разбор пути. В новом коде на Go 1.22 или новее предпочитайте стандартный mux.

`http.ListenAndServe` использует `http.DefaultServeMux`, когда обработчик — `nil`. В продакшене предпочитайте явный `*http.ServeMux`. Тогда не делите глобальные маршруты с тестами.

```go
mux := http.NewServeMux()
mux.HandleFunc("GET /health", health)
s := &http.Server{Addr: ":8080", Handler: mux}
err := s.ListenAndServe()
```

Middleware — функция, которая оборачивает обработчик. Обёртка выполняется до и после следующего обработчика.

```go
func withLog(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		slog.Info("req", "path", r.URL.Path)
		next.ServeHTTP(w, r)
	})
}
```

Задавайте таймауты на `http.Server`: `ReadTimeout`, `WriteTimeout` и `IdleTimeout`. Тема 15 покрывает корректное завершение через `Shutdown`.

Сервер восстанавливается после panic в обработчике, чтобы один запрос не остановил процесс. Логируйте panic в своём middleware, если нужны дополнительные данные.

Всегда пишите статус. `Write` без `WriteHeader` отправляет `200`. Не пишите заголовок дважды.

## JSON API

JSON API читает JSON из тела запроса и пишет JSON в ответ. Используйте `json.NewDecoder(r.Body)` и `json.NewEncoder(w)`.

```go
type Item struct {
	Name string `json:"name"`
}

func create(w http.ResponseWriter, r *http.Request) {
	defer r.Body.Close()
	var in Item
	if err := json.NewDecoder(r.Body).Decode(&in); err != nil {
		http.Error(w, "bad json", http.StatusBadRequest)
		return
	}
	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(http.StatusCreated)
	_ = json.NewEncoder(w).Encode(in)
}
```

Задайте `Content-Type` как `application/json`. Пишите заголовок до тела. Используйте `http.Error` для простой текстовой ошибки. Для объекта ошибки JSON закодируйте структуру и сначала задайте статус.

Ограничивайте тело. Оборачивайте `r.Body` через `http.MaxBytesReader`. Не делайте `Decode` неограниченного тела.

`Decode` читает одно значение JSON. Лишние хвостовые данные могут быть ошибкой, если вызвать `More` или декодировать снова. Неизвестные поля по умолчанию игнорируются. Используйте `DisallowUnknownFields`, когда API должен быть строгим.

Проверяйте метод и путь запроса в mux. Не запускайте декодирование JSON на `GET`, когда тела нет.

Возвращайте полезные коды статуса: `200` или `201` при успехе, `400` для плохого ввода, `404` когда ресурс отсутствует, `409` для конфликта, `500` только для неожиданных неисправностей. Не утекайте внутренние ошибки в теле.

## Основы TLS

TLS шифрует HTTP. HTTPS — HTTP поверх TLS. Пакеты `crypto/tls` и `net/http` поддерживают TLS.

`http.ListenAndServeTLS(addr, certFile, keyFile, handler)` загружает сертификат и ключ с диска. Файлы — PEM.

```go
err := http.ListenAndServeTLS(":8443", "cert.pem", "key.pem", mux)
```

У `http.Server` тоже есть `ListenAndServeTLS`. Можно задать `TLSConfig` на сервере. `MinVersion: tls.VersionTLS12` — частый минимум.

Для клиента URL `https://` используют TLS. Клиент по умолчанию проверяет сертификат сервера против системных корней. `InsecureSkipVerify` отключает эту проверку. Не используйте `InsecureSkipVerify` в продакшене. Используйте только в локальном тесте с известным риском.

```go
tr := &http.Transport{
	TLSClientConfig: &tls.Config{MinVersion: tls.VersionTLS12},
}
client := &http.Client{Transport: tr}
```

Создайте локальный сертификат для разработки через тестовые помощники `crypto/tls` или инструмент вроде `mkcert`. Не коммитьте продакшен-закрытый ключ. Тема 15 покрывает секреты.

`httptest.NewTLSServer` запускает TLS-сервер в тестах. Клиент из `srv.Client()` доверяет этому сертификату.

TLS не заменяет аутентификацию. TLS защищает канал. Вы всё равно проверяете токены или сессии.

3. Задокументируйте, где храните `cert.pem` и `key.pem` на машине разработки. Не кладите ключи в модуль.

#### Сложные практические задания

1. Сгенерируйте самоподписанный сертификат стандартной библиотекой или `openssl`. Отдайте HTTPS на localhost. Curl с `-k` или с сертификатом. Запишите шаги.
2. Прочитайте поля `tls.Config`: `Certificates`, `ClientAuth` и `MinVersion`. Напишите одно предложение для каждого поля.

## Обзор темы

Эти вопросы не повторяют вопросы в разделах выше. Они покрывают всю тему.

### Вопросы

#### Теоретические вопросы

1. Как `io.Reader`, файлы, TCP-соединения и тела HTTP делят одну модель ввода-вывода?
2. Когда выбирать `bufio.Scanner`, `io.Copy` и `json.Decoder`?
3. Как шаблон mux, middleware и JSON-обработчик делят один запрос?
4. Почему дедлайны есть на `net.Conn`, а таймауты — на `http.Server`?
5. Что TLS меняет и чего не меняет для JSON API?

#### Простые практические задания

1. Запишите файл, просканируйте его строки через `bufio` и напечатайте счётчик.
2. Добавьте `GET /health` и `POST /echo` JSON на одном mux. Протестируйте оба через `httptest`.
3. Скопируйте файл в stdout через `io.Copy`. Проверьте `Close`.
4. Нарисуйте стек: TLS, HTTP, mux, middleware, JSON-обработчик, тело `io.Reader`.

#### Средние практические задания

1. Постройте маленький API элементов в памяти: создать и получить по id. Ограничьте размер тела. Возвращайте ошибки JSON.
2. Эхо байтов по TCP в тесте. Затем отдайте то же эхо как HTTP POST.
3. Оберните API middleware лога и лимитом `MaxBytesReader`. Докажите оба через `httptest`.

#### Сложные практические задания

1. Отдайте API через `NewTLSServer`. Вызовите его из клиента, который декодирует JSON. Shutdown пока не требуется.
2. Напишите обработчик, который стримит строки JSON через `json.Encoder` и `Flush` на `http.Flusher`, когда доступен. Протестируйте через recorder.

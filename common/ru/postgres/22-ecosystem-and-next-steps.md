# 22. Экосистема и следующие шаги

## Описание

Эта тема показывает, куда идти дальше после пути PostgreSQL 16 и PostgreSQL 17. Вы узнаёте официальный учебник и версионированную документацию, Postgres Weekly и вики, управляемые облачные продукты и как отправить воспроизводимый отчёт об ошибке.

Сначала завершите тему 21. Вы можете описать продакшен-границу. После этой темы используйте настоящую базу и продолжайте читать.

Используйте один термин для каждого понятия. Официальная документация — страницы на postgresql.org для мажорной версии. Вики — сайт сообщества. Управляемый сервис запускает PostgreSQL (или совместимый движок) за вас. Воспроизводимый отчёт об ошибке позволяет другому человеку увидеть тот же дефект. Этот справочник рассчитан на PostgreSQL 16 и PostgreSQL 17.

## Читайте официальный учебник и документацию текущей версии

Официальный учебник: [https://www.postgresql.org/docs/current/tutorial.html](https://www.postgresql.org/docs/current/tutorial.html). Слово `current` — новейшая стабильная мажорная версия. Эта версия может быть новее 17. Также откройте учебник, который совпадает с вашим сервером:

- [https://www.postgresql.org/docs/16/tutorial.html](https://www.postgresql.org/docs/16/tutorial.html)
- [https://www.postgresql.org/docs/17/tutorial.html](https://www.postgresql.org/docs/17/tutorial.html)

Пройдите учебник на своём кластере, даже если этот путь уже завершили. Учебник использует официальные имена и короткие примеры.

Руководства, которые откроете снова:

| Книга | Назначение |
| --- | --- |
| Tutorial | первый путь и повтор |
| SQL Language | типы, функции, запросы |
| Server Administration | установка, конфигурация, резервные копии, HA |
| Reference | точный синтаксис (`CREATE TABLE`, `SET`) |
| Internals | позже, когда умеете эксплуатировать сервер |

Тема 1 перечислила эти книги. Теперь у вас есть контекст для Administration и Reference.

Заметки о выпуске важны при каждом мажорном обновлении:

- [https://www.postgresql.org/docs/17/release-17.html](https://www.postgresql.org/docs/17/release-17.html)
- [https://www.postgresql.org/docs/16/release-16.html](https://www.postgresql.org/docs/16/release-16.html)

Читайте раздел «Migration», прежде чем переносить данные.

Справка `psql` остаётся полезной:

```text
\h ALTER TABLE
\?
```

Не учите продакшен-поведение из случайного поста, когда есть официальная страница. Не добавляйте в закладки только `docs/current`, если продакшен — 16. Не пропускайте заметки о выпуске потому что новый мажор «выглядит так же».

## Postgres Weekly / вики

**Postgres Weekly** — рассылка на [https://postgresweekly.com/](https://postgresweekly.com/). Она ссылается на статьи, расширения и новости выпусков. Используйте её, чтобы слышать о новых мажорных версиях и инструментах. Это не замена официальной документации.

**Вики PostgreSQL**: [https://wiki.postgresql.org/](https://wiki.postgresql.org/). В вики есть сборники рецептов, заметки по настройке и материалы конференций. Любой может найти устаревшие страницы. Когда вики и официальная документация расходятся, побеждает официальная документация. Тема 1 сформулировала это правило. Держите его.

Полезные привычки вики:

- проверяйте дату страницы и версию PostgreSQL в тексте
- переходите по ссылкам на postgresql.org, когда они есть
- считайте запросы раздутия и фрагменты `postgresql.conf` примерами, а не политикой copy-paste

Другие источники сообщества (обзор): списки рассылки на postgresql.org, Planet PostgreSQL и доклады конференций (PGConf). Для шагов безопасности и обновления предпочитайте первоисточники.

Не применяйте формулу вики `shared_buffers` к управляемому экземпляру без измерения (тема 18). Не считайте ссылку из рассылки договором поддержки поставщика.

## Облако: RDS, Cloud SQL, AlloyDB, Aurora PostgreSQL, Crunchy, Supabase

Управляемый PostgreSQL снижает работу с ОС. Вы всё равно изучаете SQL, привилегии, vacuum и планы. Поставщик скрывает некоторые файлы (`postgresql.conf` может быть группой параметров). Некоторые расширения заблокированы. Суперпользователя часто заменяет мощная админ-роль (тема 12).

Продукты, которые называет этот путь (имена и возможности меняются; читайте страницу поставщика):

| Продукт | Поставщик | Кратко |
| --- | --- | --- |
| Amazon RDS for PostgreSQL | AWS | управляемый экземпляр, группы параметров, опция Multi-AZ |
| Amazon Aurora PostgreSQL | AWS | совместимый движок, хранение и HA поставщика |
| Cloud SQL for PostgreSQL | Google Cloud | управляемый экземпляр, опция HA |
| AlloyDB | Google Cloud | совместим с PostgreSQL, HA и возможности поставщика |
| Crunchy | Crunchy Data | эксперты PostgreSQL; Crunchy Bridge — управляемое облако |
| Supabase | Supabase | PostgreSQL плюс платформа приложения (auth, API) |

Aurora и AlloyDB — совместимые продукты. Это не обещание drop-in для каждого расширения или каждой ручки `postgresql.conf`. Проверьте `pg_dump` из сервиса и восстановление в community PostgreSQL 16 или 17, если нужно уйти.

Что вы всё равно владеете на управляемом сервисе:

- схема, выдачи, RLS
- планы запросов и индексы
- файлы миграций
- размер пула приложения
- что храните в `jsonb`
- политика резервных копий, даже когда поставщик делает снимки
- сетевое правило (тема 21)

Что часто владеет поставщик:

- патчи ОС
- диск и многие механики HA
- некоторые кнопки PITR
- выкат минорной версии (вы выбираете окно)

Не считайте, что `CREATE EXTENSION` работает для каждого имени. Не считайте, что есть SSH-доступ `pg_basebackup`. Не пропускайте тесты `pg_dump` потому что есть снимки. Не используйте preview-версию движка как продакшен без политики.

## Отправьте воспроизводимый отчёт об ошибке

Когда PostgreSQL ведёт себя так, как документация запрещает, можно сообщить. Официальное руководство: [https://www.postgresql.org/docs/current/bug-report.html](https://www.postgresql.org/docs/current/bug-report.html) (также под `/docs/16/` и `/docs/17/`).

Полезный отчёт включает:

- `SELECT version();` и ОС
- точный SQL или шаги
- результат, который получили
- результат, который ожидали, со ссылкой на документацию
- маленькую схему, которую другой человек может загрузить (`CREATE TABLE`, `INSERT`)
- воспроизводится ли на community PostgreSQL 16 или 17, а не только на форке

```sql
SELECT version();
SHOW server_version_num;
```

Используйте официальные каналы, которые называет руководство (форма или список рассылки). Сначала ищите существующие ветки.

Отчёт об ошибке — не:

- вопрос, как написать запрос
- авария поставщика
- запрос возможности без ясного дефекта
- дамп продакшен-базы

Управляемые форки могут добавлять дефекты, которых нет у community PostgreSQL. Воспроизводите на локальном образе `postgres:16` или `postgres:17`, когда можете. Если не можете, скажите, что есть только движок поставщика.

Не прикладывайте секреты, персональные данные или полный дамп клиента. Не требуйте дату исправления. Не пропускайте маленький воспроизводитель.

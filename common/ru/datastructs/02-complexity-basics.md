# 2. Основы сложности

## Описание

Сложность описывает, как стоимость операции растёт, когда растёт вход. Эта тема показывает, как читать O-большое, Тета-большое и Омега-большое. Вы изучаете лучший случай, средний случай и худший случай. Вы также изучаете обычные классы роста и идею амортизированной стоимости. Завершите эту тему до сравнения массивов и списков.

Используйте один термин для каждого понятия. **n** — размер входа. **Класс роста** — семейство функций, например константный или линейный. **Локальность** — использование близких ячеек памяти за короткое время.

## O-большое, Тета-большое, Омега-большое (практическое чтение)

O-большое, Тета-большое и Омега-большое — обозначения роста. Вы используете их, чтобы сравнивать операции. Вы не используете их как точный счёт шагов.

**O-большое** — верхняя оценка. Если операция — O(n), время не растёт быстрее, чем константа, умноженная на n, для больших n. O-большое может быть свободным. O(n) также является O(n²). Более полезна тесная верхняя оценка.

**Омега-большое** — нижняя оценка. Если операция — Ω(n), время не растёт медленнее, чем константа, умноженная на n, для больших n.

**Тета-большое** — тесная оценка. Если операция — Θ(n), время растёт как n. Операция одновременно O(n) и Ω(n).

В повседневной работе вы часто видите O-большое. Многие тексты пишут O(n), когда имеют в виду Θ(n). Читайте текст. Если автор даёт типичную стоимость, автор часто имеет в виду тесную оценку.

```text
find in an unsorted array of n elements
  worst case:  Θ(n)   — you can visit every element
  you may write: O(n) — an upper bound
```

Игнорируйте постоянные множители в обозначении. 2n и 100n оба являются Θ(n). Не игнорируйте константы в реальной программе, когда n мало. Обозначение — для роста. Измерение — для реальной машины.

Отбрасывайте младшие члены. n² + 3n + 10 — это Θ(n²). Член n² доминирует при большом n.

## Лучший / средний / худший случай

У одной операции может быть больше одной стоимости по времени. Стоимость зависит от входа.

**Лучший случай** — самый дешёвый вход размера n. Пример: найти значение, которое сидит в первой ячейке массива.

**Худший случай** — самый дорогой вход размера n. Пример: найти значение, которого нет в массиве. Вы посещаете каждую ячейку.

**Средний случай** — ожидаемая стоимость для типичного входа. Вам нужна модель типичного входа. Если каждая позиция равновероятна, средний поиск в неотсортированном массиве посещает около n/2 ячеек.

Пишите случай, когда пишете оценку. «Поиск есть O(n)» — неполно. «Поиск в неотсортированном массиве есть O(n) в худшем случае» — полно.

Многие структуры дают оценку худшего случая в документации. Некоторые структуры дают оценку среднего случая. Хеш-таблица часто O(1) в среднем и O(n) в худшем случае.

```text
binary search in a sorted array of n elements
  best case:    Θ(1)   — the middle cell is the target
  worst case:   Θ(log n)
  average case: Θ(log n)  for a usual model
```

Не смешивайте случаи. Не сравнивайте лучший случай одной структуры с худшим случаем другой структуры.

## Константный, логарифмический, линейный, линеари<fim-middle>тмический, квадратичный

Эти имена — обычные классы роста. Выучите имена. Выучите одну картинку для каждого класса.

**Константный** — Θ(1). Стоимость не растёт с n. Пример: прочитать индекс i в массиве.

**Логарифмический** — Θ(log n). Стоимость растёт медленно. Каждый шаг отбрасывает долю входа. Пример: двоичный поиск. В этом справочнике **log** означает логарифм по основанию 2, если текст не говорит другое основание. Смена основания — постоянный множитель.

**Линейный** — Θ(n). Стоимость растёт с n. Пример: посетить каждый элемент один раз.

**Линерифмический** — Θ(n log n). Стоимость — n, умноженное на логарифмический множитель. Пример: эффективная сортировка сравнениями.

**Квадратичный** — Θ(n²). Стоимость растёт как n, умноженное на n. Пример: вложенный цикл, который сравнивает каждую пару.

```text
n        1     16      256       4096
1        1      1        1          1
log n    0      4        8         12
n        1     16      256       4096
n log n  0     64     2048      49152
n²       1    256    65536   16777216
```

Существуют кубический класс Θ(n³) и экспоненциальный класс Θ(2ⁿ). В базовых структурах вы видите их реже. Избегайте экспоненциального роста во внутреннем цикле при большом n.

Когда вы вкладываете линейный просмотр внутрь линейного просмотра, часто получаете квадратичную стоимость. Когда вы каждый раз делите вход пополам, часто получаете логарифмическую стоимость.

## Амортизированная стоимость (простая идея)

Амортизированная стоимость — средняя стоимость одной операции в **последовательности** операций. Последовательность может содержать дешёвые операции и редкие дорогие операции.

Динамический массив — обычный пример. Большинство операций append пишут одну ячейку. Иногда массив полон. Тогда программа копирует все n элементов в больший блок. Это копирование дорогое. Если блок удваивается, дорогие копирования редки. Средняя стоимость одного append в длинной последовательности константна.

Амортизированная стоимость — не то же самое, что средний случай. Средний случай использует модель случайного входа. Амортизированная стоимость использует последовательность операций над одной структурой. Вход может выбрать противник. Оценка всё равно держится для последовательности.

```text
append to a dynamic array that doubles
  cheap append:  Θ(1)
  resize copy:   Θ(n) when size is n
  amortized append in a long sequence: Θ(1)
```

Пишите «амортизированная», когда используете эту идею. «Append есть O(1)» — неполно. «Append есть амортизированная O(1)» — полно.

Вы снова используете эту идею в теме про динамический массив. Выучите слово сейчас. Выучите картинку: много дешёвых шагов оплачивают один дорогой шаг.

## Локальность памяти (кэш-дружественные массивы против преследования указателей)

Процессор читает память блоками. Блок в кэше — **строка кэша**. Близкие адреса часто сидят в одной строке кэша.

**Локальность** хороша, когда программа читает близкие ячейки за короткое время. Массив хранит элементы в непрерывной памяти. Просмотр массива имеет хорошую локальность. Кэш помогает.

Связный список хранит узлы по адресам, которые выбирает аллокатор. Узлы часто не рядом. Обход списка прыгает от указателя к указателю. Этот обход — **преследование указателей**. Преследование указателей имеет плохую локальность. Кэш помогает меньше.

```text
array scan:   cell 0, cell 1, cell 2, ...     — nearby addresses
list walk:    node A → node B → node C        — addresses can be far
```

O-большое может быть одинаковым для двух обходов. Оба обхода — Θ(n). Обход массива часто быстрее на реальной машине из-за локальности.

Не игнорируйте локальность, когда n велико. Не игнорируйте O-большое, когда n велико. Используйте обе идеи. O-большое — класс роста. Локальность — эффект постоянного множителя и кэша.

Структура, которая использует массив как внутреннее хранилище, часто кэш-дружественна. Структура, которая использует много мелких узлов, часто не кэш-дружественна.

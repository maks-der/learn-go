# 10. Основы стандартной библиотеки

## Описание

Стандартная библиотека Go — это набор пакетов, которые поставляются с набором инструментов. Вы импортируете эти пакеты без `go get`. Эта тема показывает пакеты, которые нужны большинству программ: текст, числа, время, файлы, кодирование, HTTP-клиенты, журналы, контекст, флаги командной строки, тесты и блокировки.

Сначала завершите темы с 1 по 9. Используйте один термин для каждого пакета. Предпочитайте стандартную библиотеку, когда она решает задачу. Эта тема использует Go 1.22 или новее. Используйте `log/slog` для структурированных журналов. Используйте `math/rand/v2` для новых случайных чисел. Не используйте `io/ioutil` в новом коде. Тема 11 подробно разбирает конкурентность. Тема 12 подробно разбирает `context`. Тема 13 подробно разбирает тесты. Эта тема даёт первый рабочий обзор этих пакетов.

## `fmt` — печать и сканирование

Пакет `fmt` форматирует значения как текст и читает текст в значения. Обычные функции печати:

- `Print`, `Println`, `Printf` пишут в стандартный вывод
- `Fprint`, `Fprintln`, `Fprintf` пишут в `io.Writer`
- `Sprint`, `Sprintln`, `Sprintf` возвращают `string`

`Println` добавляет пробелы между операндами и добавляет перевод строки. `Printf` использует строку формата. Обычные глаголы:

- `%v` формат по умолчанию
- `%+v` формат по умолчанию с именами полей для структур
- `%#v` синтаксис Go
- `%T` тип
- `%s` строка
- `%q` строка в кавычках
- `%d` целое
- `%f` число с плавающей точкой
- `%p` указатель
- `%w` обёртка ошибки только в `fmt.Errorf`

`fmt.Errorf` возвращает `error`. См. тему 8 про `%w`.

Функции сканирования читают текст:

- `Scan`, `Scanln`, `Scanf` читают из стандартного ввода
- `Fscan`, `Fscanln`, `Fscanf` читают из `io.Reader`
- `Sscan`, `Sscanln`, `Sscanf` читают из `string`

Функции сканирования возвращают число элементов и `error`. Проверяйте ошибку. Сканирование ввода пользователя часто завершается неудачей. Предпочитайте `bufio.Scanner` или `strconv`, когда разбираете одну строку или одно число.

Используйте `fmt` для человека и для простых журналов. Используйте `strconv`, когда преобразуете одно число или одно значение `bool`. Используйте `encoding/json`, когда обмениваетесь структурированными данными.

## `strconv` — преобразования строк

Пакет `strconv` преобразует базовые типы и их строковые формы. Используйте этот пакет, когда вход или выход — одно значение.

Преобразования целых:

- `Atoi` разбирает `int` из десятичной строки
- `Itoa` форматирует `int` как десятичную строку
- `ParseInt` и `ParseUint` принимают основание и размер в битах
- `FormatInt` и `FormatUint` принимают основание

Другие преобразования:

- `ParseFloat`, `FormatFloat`
- `ParseBool`, `FormatBool`
- `Quote`, `Unquote` для строковых литералов Go
- `AppendInt` и другие функции `Append*` пишут в `[]byte`

Каждая функция `Parse*` возвращает `error`. Проверяйте ошибку. Не игнорируйте ошибку разбора. Неверная строка — обычный ввод, а не `panic`.

`Atoi` — краткая форма `ParseInt` с основанием 10 и размером в битах 0. Размер в битах 0 означает размер `int` на текущей машине.

`FormatFloat` нуждается в байте формата (`'f'`, `'e'`, `'g'`), точности и размере в битах. Выбирайте точность намеренно. Не используйте `fmt.Sprintf("%f", x)`, когда нужен фиксированный машинный формат. Используйте `strconv`.

`Quote` добавляет кавычки и экранирование. Используйте её, когда печатаете строку, которая может содержать пробелы или кавычки.

## `strings`, `bytes`, `unicode`, `regexp`

Эти пакеты работают с текстом. Используйте `string`, когда не нужно менять байты на месте. Используйте `[]byte`, когда нужен изменяемый буфер. Пакет `strings` и пакет `bytes` имеют много одинаковых имён функций.

Обычные функции `strings`: `Contains`, `HasPrefix`, `HasSuffix`, `Split`, `Join`, `ReplaceAll`, `TrimSpace`, `ToLower`, `ToUpper`, `Cut`, `CutPrefix`, `CutSuffix`. Тип `strings.Builder` собирает строку с малым числом выделений. Тип `strings.Reader` реализует `io.Reader` над строкой.

Пакет `bytes` добавляет `Buffer`. `bytes.Buffer` — это записываемый байтовый буфер. Используйте его, когда собираете байты для `io.Writer`.

Пакет `unicode` классифицирует руны. Примеры: `unicode.IsLetter`, `unicode.IsDigit`, `unicode.IsSpace`, `unicode.ToUpper`. `rune` — это кодовая точка Unicode. Обходите строку через `range`, чтобы видеть руны, а не байты. Пакет `unicode/utf8` кодирует и декодирует UTF-8.

Пакет `regexp` реализует регулярные выражения. Движок — RE2. Движок не поддерживает обратные ссылки. `regexp.Compile` возвращает ошибку. `regexp.MustCompile` паникует. Используйте `MustCompile` только для шаблона, который является константой в исходном коде (тема 8).

Предпочитайте `strings`, когда ищете фиксированную подстроку. Регулярное выражение медленнее. Неверный шаблон — частая ошибка. Компилируйте шаблон один раз. Повторно используйте значение `*regexp.Regexp`.

## `time` — время, длительность, таймеры, тикеры

Пакет `time` представляет момент (`time.Time`) и длину (`time.Duration`). `Duration` — это счётчик наносекунд типа `int64`. Пакет определяет `time.Second`, `time.Millisecond` и другие единицы.

`time.Now()` возвращает текущее местное время. Используйте `t.UTC()` для UTC. Используйте `time.Date`, чтобы собрать время из частей. Используйте `time.Parse` и `t.Format` с макетом. Макет — это опорное время, а не шаблон `YYYY`:

```text
Mon Jan 2 15:04:05 MST 2006
```

Эта дата — единственный язык макета. Пример: `"2006-01-02"` форматирует год-месяц-день. `"15:04:05"` форматирует 24-часовые часы.

`time.Since(t)` — это `time.Now().Sub(t)`. `time.Until(t)` — это `t.Sub(time.Now())`.

`time.Sleep` блокирует текущую горутину (`goroutine`). `time.After` возвращает канал, который принимает один раз. `time.NewTimer` возвращает `*time.Timer`, который можно остановить. `time.NewTicker` возвращает `*time.Ticker`, который принимает с периодом.

Останавливайте тикер, когда он больше не нужен:

```go
ticker := time.NewTicker(time.Second)
defer ticker.Stop()
```

Если игнорировать `Stop`, горутина тикера может утечь. Таймер, который вы не останавливаете, тоже может утечь, пока не сработает. Для отмены работы предпочитайте `context.WithTimeout` (см. раздел `context` и тему 12).

Загружайте часовой пояс через `time.LoadLocation`. Имя `"Local"` — системный пояс. Имя `"UTC"` — UTC. Отсутствующая база поясов — ошибка на некоторых системах.

Не сравнивайте времена через `==`, когда пояса различаются. Используйте `t.Equal`.

## `math` / `math/rand/v2`

Пакет `math` предоставляет функции и константы с плавающей точкой. Примеры: `math.Sqrt`, `math.Pow`, `math.Abs`, `math.Hypot`, `math.Floor`, `math.Ceil`, `math.Mod`, `math.NaN`, `math.Inf`, `math.IsNaN`, `math.Pi`. `math.Max` и `math.Min` принимают `float64`. Для целых используйте встроенные `min` и `max` (Go 1.21 и новее).

Не используйте `math` для денег, которые должны быть точными. Значения с плавающей точкой имеют ошибку округления.

Пакет `math/rand/v2` — пакет случайных чисел для Go 1.22 и новее. Импортируйте `math/rand/v2`. Функции верхнего уровня безопасны для одновременного использования и используют скрытое зерно от среды выполнения:

```go
n := rand.IntN(100) // 0 <= n < 100
```

`rand.N` работает для других целых типов. `rand.Float64` возвращает значение в `[0.0, 1.0)`.

Создайте локальный генератор, когда нужна повторяемая последовательность:

```go
src := rand.NewPCG(1, 2)
r := rand.New(src)
```

`rand.NewChaCha8` — другой источник. Передавайте зерно, которое вы контролируете, в тестах. Не используйте фиксированное зерно, когда каждый запуск должен давать другую последовательность.

Старый пакет `math/rand` всё ещё существует. Новый код должен использовать `math/rand/v2`. Старому глобальному источнику нужен был `Seed`. API верхнего уровня v2 не использует эту функцию `Seed`.

Не используйте `math/rand/v2` для ключей, токенов или паролей. Используйте `crypto/rand` для этих значений.

## `os`, `os/exec`, `path/filepath`, `io/fs`

Пакет `os` взаимодействует с операционной системой. Обычные файловые функции: `os.Open`, `os.Create`, `os.OpenFile`, `os.ReadFile`, `os.WriteFile`, `os.ReadDir`, `os.MkdirAll`, `os.Remove`, `os.CreateTemp`, `os.MkdirTemp`. Всегда проверяйте ошибку. Закрывайте файл, который открываете через `Open` или `Create`. `ReadFile` закрывает файл за вас.

`os.Args` — срез аргументов командной строки. `os.Args[0]` — имя программы. `os.Getenv` и `os.LookupEnv` читают переменные окружения. `os.Exit` сразу останавливает процесс. `os.Exit` не выполняет отложенные вызовы. Предпочитайте `return` из `main`, когда можете.

Пакет `os/exec` запускает другие программы. `exec.Command("go", "version")` строит `*exec.Cmd`. `Output` запускает команду и возвращает stdout. `CombinedOutput` возвращает stdout и stderr вместе. `Run` ждёт и возвращает ошибку. Используйте `exec.CommandContext`, когда есть `context.Context` (тема 12).

Пакет `path/filepath` собирает и разделяет пути операционной системы. Используйте `filepath.Join`, чтобы разделители соответствовали системе. Используйте `filepath.Clean`, `filepath.Abs` и `filepath.WalkDir`. Пакет `path` использует косую черту и предназначен для путей вроде URL. Не используйте `path` для файловых путей Windows.

Пакет `io/fs` определяет интерфейсы файловой системы. `fs.FS` — основной интерфейс. `os.DirFS` превращает каталог в `fs.FS`. `embed.FS` тоже реализует `fs.FS` (тема 9). `fs.WalkDir` обходит любой `fs.FS`. Предпочитайте `fs.WalkDir` и `filepath.WalkDir` старому `filepath.Walk`.

Сентинел-ошибки вроде `os.ErrNotExist` требуют `errors.Is` (тема 8).

## `io` и `io/ioutil` (предпочитайте `io` и `os`)

Пакет `io` определяет интерфейсы потоков. Основные интерфейсы: `io.Reader`, `io.Writer`, `io.Closer` и `io.Seeker`. Многие типы их реализуют: файлы, буферы, тела HTTP и компрессоры.

Обычные помощники:

- `io.Copy` копирует из `Reader` в `Writer`
- `io.ReadAll` читает до EOF
- `io.LimitReader` ограничивает число байтов
- `io.MultiReader` и `io.MultiWriter` составляют потоки
- `io.TeeReader` пишет копию во время чтения
- `io.NopCloser` оборачивает `Reader` закрытием, которое ничего не делает
- `io.Discard` — это `Writer`, который отбрасывает байты
- `io.EOF` — сентинел конца ввода. Считайте `EOF` успехом, когда чтение завершилось. Не считайте каждый `EOF` жёстким сбоем.

Пакет `io/ioutil` устарел с Go 1.16. Новый код не должен импортировать `io/ioutil`. Используйте эту карту:

- `ioutil.ReadAll` → `io.ReadAll`
- `ioutil.ReadFile` → `os.ReadFile`
- `ioutil.WriteFile` → `os.WriteFile`
- `ioutil.ReadDir` → `os.ReadDir`
- `ioutil.NopCloser` → `io.NopCloser`
- `ioutil.Discard` → `io.Discard`
- `ioutil.TempFile` → `os.CreateTemp`
- `ioutil.TempDir` → `os.MkdirTemp`

`os.ReadDir` возвращает `[]os.DirEntry`. Старый `ioutil.ReadDir` возвращал `[]fs.FileInfo`. Типы возврата различаются. Поправьте место вызова.

Предпочитайте небольшие функции, которые принимают `io.Reader` или `io.Writer`. Тогда тесты могут передать `bytes.Buffer` вместо настоящего файла.

## `encoding/json`, `encoding/xml`, `encoding/csv`

Эти пакеты кодируют структурированные данные.

Пакет `encoding/json` преобразует значения Go в JSON и обратно. `json.Marshal` возвращает `[]byte`. `json.Unmarshal` заполняет указатель. Используйте экспортированные поля. Задавайте имена тегом структуры:

```go
type User struct {
    Name string `json:"name"`
    Age  int    `json:"age,omitempty"`
}
```

`omitempty` убирает пустое поле из вывода. Используйте `json.NewEncoder` и `json.NewDecoder` для потоков. Декодер читает одно значение за другим из `io.Reader`. `Decoder.DisallowUnknownFields` отклоняет лишние ключи. Когда вы разбираете в `any`, числа становятся `float64`. Используйте структуру, когда знаете форму.

Пакет `encoding/xml` — та же идея для XML. `xml.Marshal` и `xml.Unmarshal` используют теги вроде `xml:"name"` и `xml:",attr"`. XML обычен для старых API. Предпочитайте JSON для новых HTTP API, если другая сторона не требует XML.

Пакет `encoding/csv` читает и пишет записи через запятую. `csv.NewReader(r).Read()` возвращает одну запись (`[]string`) или ошибку. `ReadAll` читает все записи. `csv.NewWriter(w)` пишет записи. Вызовите `Flush` и затем проверьте `w.Error()`. Задайте `Comma`, когда файл использует точку с запятой или табуляцию.

Проверяйте каждую ошибку кодирования и декодирования. Неверный ввод — обычное дело. Не вызывайте `panic` при ошибке декодирования.

## Основы клиента `net/http` (`http.Get`, `http.Client`)

Пакет `net/http` содержит клиент и сервер. Этот раздел — только клиент. Тема 16 разбирает серверы.

`http.Get(url)` отправляет запрос GET через `http.DefaultClient`. Проверьте ошибку. Затем проверьте `resp.StatusCode`. Затем прочитайте `resp.Body`. Затем закройте тело:

```go
resp, err := http.Get(url)
if err != nil {
    return err
}
defer resp.Body.Close()
body, err := io.ReadAll(resp.Body)
```

Если `err` равен nil, вы должны закрыть `Body`. Статус не-2xx не является `error` от `Get`. Нужно проверять код состояния.

У `http.DefaultClient` нет таймаута. Зависший сервер может надолго заблокировать горутину. Создайте клиент с таймаутом:

```go
client := &http.Client{Timeout: 10 * time.Second}
resp, err := client.Get(url)
```

Используйте `http.NewRequestWithContext` и `client.Do`, когда есть `context.Context`. Тема 12 показывает отмену. Для этой темы задайте `Timeout` у клиента.

`http.Post` и `http.PostForm` отправляют тело. Действуют те же правила: проверьте ошибку, закройте тело, проверьте статус.

Не допускайте утечки соединений. Закрывайте тело, даже когда не читаете его. Если нужен только статус, прочитайте небольшой объём или используйте `io.Copy(io.Discard, resp.Body)` перед закрытием, чтобы транспорт мог повторно использовать соединение.

Для практики используйте `https://example.com` или локальный сервер `httptest`. Не отправляйте тесты на сервер, который вы не контролируете.

## `log` и `log/slog`

Пакет `log` пишет простые строки в писатель. Журнал по умолчанию пишет в стандартную ошибку. Обычные вызовы: `log.Print`, `log.Printf`, `log.Println`. `log.Fatal` пишет в журнал и затем вызывает `os.Exit(1)`. `log.Panic` пишет в журнал и затем паникует. `log.SetFlags` меняет префикс (дата, время, файл). `log.SetOutput` меняет писатель.

`log.Fatal` пропускает отложенную очистку, потому что вызывает `os.Exit`. Не используйте `Fatal` внутри библиотеки. Возвращайте `error`.

Пакет `log/slog` — структурированный журнал в Go 1.21 и новее. Запись журнала имеет уровень, сообщение и атрибуты. Обычные уровни: `Debug`, `Info`, `Warn`, `Error`.

```go
slog.Info("listen", "port", 8080)
slog.Error("open", "path", path, "err", err)
```

Можно использовать типизированные атрибуты: `slog.Int("port", 8080)`, `slog.String("path", path)`.

Создайте журнал с обработчиком:

```go
h := slog.NewJSONHandler(os.Stdout, nil)
logger := slog.New(h)
logger.Info("ready")
```

`slog.NewTextHandler` пишет текст key=value. `slog.SetDefault` меняет журнал по умолчанию, который использует `slog.Info`. `logger.With("req_id", id)` возвращает журнал, который всегда включает этот атрибут.

Используйте `log` для крошечного инструмента, которому нужна одна строка. Используйте `slog` для служб и для любой программы, которую должна разбирать другая система. Не собирайте JSON вручную через `fmt`, когда это может сделать `slog`.

`slog` не заменяет возврат значений `error`. Пишите в журнал на границе. Возвращайте ошибку вызывающему коду, когда вызывающий код должен действовать.

## Обзор пакета `context`

Пакет `context` несёт крайний срок, сигнал отмены и необязательные значения запроса через границы API. Этот раздел — введение. Тема 12 — подробный разбор.

Корневые контексты: `context.Background()` и `context.TODO()`. Используйте `Background` в начале `main` или в тесте, когда другого контекста нет. Используйте `TODO` только тогда, когда вы ещё не передали настоящий контекст и позже исправите вызов.

Дочерние контексты добавляют управление:

- `WithCancel` возвращает контекст и функцию `cancel`
- `WithTimeout` отменяет после `time.Duration`
- `WithDeadline` отменяет в момент `time.Time`
- `WithValue` сохраняет пару ключ-значение

Всегда вызывайте `cancel`, когда создаёте отменяемый контекст. Используйте `defer cancel()`. Вызов безопасен после того, как контекст уже завершён.

Первый параметр функции, которая может блокироваться, должен быть `ctx context.Context`. Не храните контекст в структуре надолго, если структура не представляет именно эту одну операцию.

Слушайте конец работы:

```go
select {
case <-ctx.Done():
    return ctx.Err()
case res := <-out:
    return res, nil
}
```

`ctx.Err()` равен `context.Canceled` или `context.DeadlineExceeded` после завершения контекста.

Не используйте `WithValue` для необязательных параметров, которые принадлежат сигнатуре функции. Тема 12 объясняет риски. Для этой темы знайте, что API значений существует и что ключи нужно держать закрытыми.

`http.NewRequestWithContext` присоединяет контекст к клиентскому запросу. `exec.CommandContext` останавливает дочерний процесс, когда контекст завершён.

## `flag` / `os.Args` для CLI

Программа командной строки получает аргументы в `os.Args`. `os.Args[0]` — имя программы или путь двоичного файла. `os.Args[1:]` — аргументы, которые вводит пользователь.

Пакет `flag` разбирает флаги вроде `-n` и `--name`. Определите флаги до разбора:

```go
n := flag.Int("n", 1, "count")
name := flag.String("name", "", "user name")
flag.Parse()
```

`flag.Int` возвращает указатель. Читайте `*n` после `Parse`. `flag.Parse` завершает процесс с текстом справки, когда пользователь передаёт `-h` или неверный флаг. Набор `flag.CommandLine` по умолчанию пишет это сообщение в стандартную ошибку.

`flag.Args()` возвращает оставшиеся аргументы, которые не являются флагами. `flag.NArg()` — число этих аргументов. `flag.NFlag()` — число флагов, которые задал пользователь.

Используйте `flag`, когда нужны типизированные флаги и текст справки. Используйте `os.Args`, когда есть только позиционные аргументы и нет флагов. Не разбирайте `os.Args` вручную, когда `flag` уже покрывает синтаксис.

Определяйте флаги в `main` или в `init`, который принадлежит пакету команды. Не регистрируйте глобальные флаги внутри библиотечного пакета. Библиотека должна принимать значения как параметры.

`flag.Duration` разбирает значения вроде `250ms`. Этот тип совпадает с `time.Duration`.

## Пакет `testing` (обзор; см. тему 13)

Пакет `testing` — это каркас тестов, который запускает `go test`. Этот раздел — обзор. Тема 13 разбирает табличные тесты, бенчмарки, примеры, фаззинг и покрытие.

Имя тестового файла заканчивается на `_test.go`. Тестовая функция имеет такой вид:

```go
func TestSum(t *testing.T) {
    if sum(2, 3) != 5 {
        t.Fatalf("got %d", sum(2, 3))
    }
}
```

Имя должно начинаться с `Test` и затем заглавной буквы или цифры. Параметр — `*testing.T`.

`t.Error` и `t.Errorf` проваливают тест и продолжают. `t.Fatal` и `t.Fatalf` проваливают тест и останавливают эту функцию. Используйте `Fatal`, когда следующие строки не могут выполняться. Используйте `t.Helper()` в помощнике, чтобы сообщаемая строка была местом вызова.

`t.Run` запускает подтест. Тема 13 показывает табличные тесты, которые используют `t.Run`.

Запускайте тесты:

```text
go test ./...
go test -v
```

Есть и другие точки входа: функции `Benchmark`, функции `Example` и функции `Fuzz`. Вы напишете их в теме 13. Для этой темы напишите одну функцию `Test` на каждый пакет, который вам важен.

Тесты живут в том же пакете (`package store`) или во внешнем тестовом пакете (`package store_test`). Внешняя форма может импортировать только экспортированный API.

Не помещайте `t.Fatal` в рабочий код. Пакет `testing` предназначен для тестов.

## `sync` и `sync/atomic` (обзор; см. тему 11)

Пакет `sync` предоставляет блокировки и другие примитивы для горутин, которые разделяют память. Этот раздел — обзор. Тема 11 разбирает горутины, каналы, гонки и полный набор шаблонов.

У `sync.Mutex` есть `Lock` и `Unlock`. Разблокируйте в `defer` после успешной блокировки. Не копируйте `Mutex` после использования. Помещайте мьютекс выше данных, которые он защищает, в той же структуре.

`sync.RWMutex` разрешает многих читателей или одного писателя. Используйте его только когда измерение показывает потребность. `Mutex` проще.

`sync.WaitGroup` ждёт набор горутин. Вызывайте `Add` до запуска горутины. Вызывайте `Done` в конце горутины. Вызывайте `Wait` в родителе. Предпочитайте `Add(1)` рядом с каждым оператором `go`. Не используйте отрицательный `Add` по ошибке.

Другие типы, которые объясняет тема 11: `sync.Once`, `sync.Map`, `sync.Pool`, `sync.Cond`. Знайте имена. Не используйте `sync.Map` как `map` по умолчанию. Используйте обычную `map` плюс мьютекс, если документация `sync.Map` не совпадает с вашим случаем.

Пакет `sync/atomic` предоставляет атомарные операции над целыми и указателями. Go 1.19 добавил типы вроде `atomic.Int64` и `atomic.Bool`:

```go
var n atomic.Int64
n.Add(1)
v := n.Load()
```

Атомарные операции нужны для простых счётчиков и флагов. Сами по себе они не делают полный алгоритм безопасным. Если нужно менять два поля вместе, используйте `Mutex`.

Детектор гонок — `go test -race`. Тема 11 показывает, как читать отчёт. Гонка данных — это ошибка.

Предпочитайте канал, когда горутины должны передать значение. Используйте мьютекс, когда горутины должны обновить структуру на месте. Тема 11 развивает этот выбор.

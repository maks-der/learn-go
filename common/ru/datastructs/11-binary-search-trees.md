# 11. Двоичные деревья поиска

## Описание

Двоичное дерево поиска (BST) хранит ключи в двоичном дереве с правилом порядка. Эта тема объясняет свойство BST, поиск, вставку, удаление, обходы дерева, вырожденную форму и почему важен баланс. Завершите эту тему после рекурсии и деревьев. Завершите хеш-отображения до сравнения поиска по точному ключу.

Используйте один термин для каждого понятия. **Свойство BST** — правило порядка на левом и правом поддеревьях. **Преемник** — следующий ключ в отсортированном порядке. **Вырожденное** BST — линия. **Баланс** держит высоту около log n.

---

## Свойство BST

**Двоичное дерево поиска** — двоичное дерево ключей (и необязательных значений). Для каждого узла u:

- каждый ключ в левом поддереве u **меньше** ключа u
- каждый ключ в правом поддереве u **больше** ключа u

Этот справочник использует **строгое** неравенство. Дубликаты ключей не хранятся. Если нужны дубликаты, храните счётчик в узле или храните равные ключи на одной стороне и запишите это правило.

```text
        8
       / \
      3   10
     / \    \
    1   6    14
```

Свойство BST сильнее, чем «левый ребёнок < u < правый ребёнок». Правило применяется ко всему поддереву, не только к ребёнку.

Симметричный обход BST посещает ключи в отсортированном порядке. Этот факт — главная причина использовать BST.

Сравните BST с хеш-таблицей. Хеш-таблица не держит ключи отсортированными. BST держит. Поиск в сбалансированном BST — Θ(log n). Поиск в хеш-таблице — средняя Θ(1).

Сравните BST с отсортированным массивом. Поиск в обоих — Θ(log n) двоичным поиском или поиском по дереву. Вставка в отсортированный массив — Θ(n). Вставка в BST — Θ(высота).

Ключи должны быть **сравнимыми**. Вам нужен полный порядок: меньше, равно, больше.

## Поиск, вставка, удаление (преемник)

**Поиск** начинается в корне. Если ключ равен узлу, вы нашли его. Если ключ меньше, идёте налево. Если ключ больше, идёте направо. Если достигаете нуля, ключа нет. Время — Θ(h), где h — высота.

**Вставка** ищет ключ. Если ключ существует, вы отклоняете или обновляете значение. Если достигаете нуля, прикрепляете новый узел в этом месте. Время — Θ(h).

**Удаление** имеет три случая:

1. Узел — лист. Удалите его. Ссылка родителя становится нулём.
2. У узла один ребёнок. Замените узел этим ребёнком.
3. У узла два ребёнка. Найдите **преемника**. Преемник — минимальный ключ в правом поддереве (следующий ключ в отсортированном порядке). Скопируйте ключ преемника (и значение) в узел. Затем удалите узел преемника. У преемника нет левого ребёнка, поэтому применяется случай 1 или случай 2.

```text
successor of 8 in the picture: minimum of the right subtree = 10
successor of 3: minimum of right subtree of 3 = 6
```

**Предшественник** — максимум левого поддерева. Некоторые реализации удаления используют предшественника. Оба метода верны, если вы последовательны.

```go
func Search(n *BinNode, k int) *BinNode {
	for n != nil {
		if k == n.Value {
			return n
		}
		if k < n.Value {
			n = n.Left
		} else {
			n = n.Right
		}
	}
	return nil
}
```

Не удаляйте узел с двумя детьми простой отвязкой. Вы потеряете поддерево. Используйте метод преемника (или предшественника).

## Симметричный / прямой / обратный / по уровням

**Обход** посещает каждый узел один раз.

**Симметричный (in-order).** Идите налево, посетите узел, идите направо. На BST порядок посещения — отсортированные ключи.

**Прямой (pre-order).** Посетите узел, идите налево, идите направо. Прямой обход полезен, чтобы скопировать дерево или напечатать префиксную форму.

**Обратный (post-order).** Идите налево, идите направо, посетите узел. Обратный обход полезен, чтобы удалить дерево или вычислить дерево выражений. Вы посещаете детей до родителя.

**По уровням (level-order).** Посетите корень, затем глубину 1, затем глубину 2. Обход по уровням использует **очередь** (BFS). Обход по уровням не рекурсивный в простой форме.

```text
        8
       / \
      3   10
     / \
    1   6

in-order:     1, 3, 6, 8, 10
pre-order:    8, 3, 1, 6, 10
post-order:   1, 6, 3, 10, 8
level-order:  8, 3, 10, 1, 6
```

```text
in-order(node):
  if node is null: return
  in-order(node.left)
  visit node
  in-order(node.right)
```

Время каждого обхода — Θ(n). Дополнительная память — Θ(h) для рекурсивных обходов (стек вызовов). Дополнительная память — Θ(ширина) для обхода по уровням (очередь).

Используйте симметричный, когда нужны отсортированные ключи. Используйте по уровням, когда нужны уровни. Используйте обратный, когда освобождаете узлы снизу вверх.

## Вырожденное дерево (связный список)

**Вырожденное** BST — линия. У каждого узла только левый ребёнок или у каждого узла только правый ребёнок. Высота — n − 1.

Вы получаете вырожденное дерево, когда вставляете ключи в отсортированном порядке в пустое BST:

```text
insert 1, 2, 3, 4
1
 \
  2
   \
    3
     \
      4
```

Поиск, вставка и удаление становятся Θ(n). BST тогда так же медленно, как связный список для поиска. У вас всё ещё дополнительные указатели и худшая локальность, чем у простого списка или массива.

Последовательность вставки в обратном порядке тоже делает линию (все левые дети).

Случайный порядок вставки обычно даёт высоту около 2 ln n для простого BST. Этот факт — теория среднего случая. Не полагайтесь на случайный порядок вставки в продакшене. Противник может вставить отсортированные ключи намеренно.

Отсортированный массив плюс двоичный поиск не становится линией. Высота поиска массива всегда около log n. Стоимость — вставка, не поиск.

Обнаружьте плохую форму: сравните высоту с log₂ n. Если n — 1 000, а высота — 999, дерево вырожденное.

## Почему важен баланс

**Баланс** держит высоту малой. Если высота — Θ(log n), поиск, вставка и удаление — Θ(log n). Если высота — Θ(n), эти операции — Θ(n).

n = 1 000 000. log₂ n около 20. Сбалансированное дерево делает около 20 сравнений. Вырожденное дерево может сделать 1 000 000 сравнений.

Баланс не меняет свойство BST. Баланс меняет форму. Деревья AVL и красно-чёрные деревья восстанавливают баланс после вставки и удаления. Эти методы — следующая тема после этой. Эта тема только формулирует нужду.

```text
same keys, two shapes
  balanced: height ≈ log n    → fast
  line:     height = n - 1    → slow
```

Завершённое дерево сбалансировано в практическом смысле. Случайное BST часто достаточно мелкое для учебной программы. Реальная система, которая не должна деградировать, использует сбалансированное дерево или хеш-таблицу.

Поворот — обычное локальное изменение, которое укорачивает длинный путь. Вы выучите поворот в теме про сбалансированные деревья. Не изобретайте произвольные обмены, которые ломают свойство BST.

Когда вы реализуете BST для учёбы, всегда печатайте высоту и симметричный обход. Высота говорит вам форму. Симметричный обход говорит вам свойство.

# 1. Начало работы

## Описание

Redis — хранилище данных в памяти. Программы используют Redis как кэш, как брокер сообщений и как базу данных. Эта тема показывает, что такое Redis, как Redis сравнивают с двумя частыми альтернативами и как запустить экземпляр Redis. Вы также изучаете `redis-cli` и первые команды.

Завершите эту тему до изучения ключей, типов и персистентности.

Используйте один термин для каждого понятия. Экземпляр — один работающий процесс Redis. Клиент — программа, которая отправляет команды этому экземпляру. Команда — один запрос с именем и аргументами. Не смешивайте слова «база данных» и «логическая БД» без нужды. Логическая БД — нумерованное пространство имён внутри одного экземпляра.

## Что такое Redis (хранилище в памяти: кэш, брокер и база)

Redis хранит данные в ОЗУ. Клиент отправляет команду. Redis применяет команду к ключам в памяти. Затем Redis отправляет ответ. Путь короткий. Задержка часто меньше одной миллисекунды в локальной сети.

Redis — хранилище данных. Вы пишете ключ. Вы читаете этот ключ. Redis также поддерживает больше, чем простое строковое значение. Позже темы покрывают хеши, списки, множества, упорядоченные множества, потоки и другие типы.

Коллективы используют Redis в трёх частых ролях:

- Кэш. Приложение записывает результат, который дорого считать. Следующее чтение идёт в Redis. TTL может удалить ключ через время.
- Брокер. Приложение публикует сообщения или пишет записи потока. Другие процессы читают эти сообщения.
- База данных. Приложение хранит состояние в Redis и считает Redis источником истины. Тогда важны персистентность и репликация.

Redis не заменяет любую базу. Redis не заменяет реляционный движок для сложных соединений и ограничений на много строк. Redis не является полной платформой сообщений с долгой историей по сравнению с журналом вроде Apache Kafka.

Redis быстр, потому что данные живут в памяти и потому что выполнение команд идёт в одном основном потоке. Запись на диск необязательна. Можно запустить Redis без файлов на диске. Можно включить снимки или файл только для добавления. Позже темы покрывают эти режимы.

Типичная промышленная схема: один или несколько экземпляров Redis, клиентская библиотека в приложении и явная политика имён ключей и TTL. Типичная учебная схема: один экземпляр на вашей машине и `redis-cli`.

## Redis против Memcached против кэш-таблицы SQL

Memcached — кэш в памяти. Memcached хранит ключи и значения. У Memcached небольшой набор команд. Memcached не даёт типы Redis вроде списков, множеств и упорядоченных множеств. Memcached не даёт персистентность в стиле Redis, репликацию или потоки.

Кэш-таблица SQL — таблица в реляционной базе. Приложение пишет строки кэша в эту таблицу. Тот же движок хранит кэш и долговечные данные. SQL даёт транзакции, ограничения и средства запросов. Строка кэша в SQL медленнее ключа Redis для простого чтения. Кэш также использует тот же диск и те же блокировки, что и другие таблицы.

Выбирайте Redis, когда нужны низкая задержка, богатые типы и отдельный кэш или хранилище сессий. Выбирайте Memcached, когда нужен простой кэш и команда уже эксплуатирует Memcached. Выбирайте кэш-таблицу SQL, когда кэш должен соединяться с другими таблицами, когда нельзя добавить новый сервис или когда кэш должен жить в той же транзакции, что и долговечная запись.

Redis и Memcached оба вытесняют ключи при заполнении памяти, если вы настроили вытеснение. Таблица SQL растёт, пока диск не заполнится, если приложение не удаляет строки.

Redis может сохранять данные. Memcached — кэш. Перезапуск процесса Memcached теряет кэш. Перезапуск процесса Redis может загрузить данные, если включена персистентность.

Не считайте эти три варианта одним продуктом. Измерьте путь чтения. Измерьте стоимость эксплуатации. Используйте одно основное хранилище для долговечных бизнес-записей, если только вы специально не проектируете Redis как это хранилище.

## Установка Redis или Docker / Redis Cloud

Вы можете запустить Redis на своей машине, в контейнере или в хостинговом сервисе.

В Linux установите пакет Redis из дистрибутива или скачайте официальную сборку. После установки запустите процесс `redis-server`. Порт по умолчанию — `6379`.

В Windows проект Redis не поставляет полноценный нативный сервер Windows для текущих версий. Используйте Docker Desktop, Windows Subsystem for Linux (WSL) или хостинговый сервис Redis.

Docker — частый учебный путь. Скачайте официальный образ. Запустите контейнер, который публикует порт `6379`:

```text
docker run --name redis-learn -p 6379:6379 redis
```

Контейнер запускает `redis-server`. Остановите контейнер, когда сессия закончится. Запустите тот же контейнер снова, чтобы сохранить данные, если контейнер ещё есть и вы не удалили том.

Redis Cloud — хостинговый сервис. Вы создаёте базу в браузере. Сервис даёт хост, порт и пароль. Вы подключаетесь через `redis-cli` или клиентскую библиотеку по сети. Используйте TLS, если сервис требует TLS.

Redis Stack — дистрибутив, который добавляет модули вроде JSON и Search. Используйте Redis Stack, когда более поздняя тема нужна этим модулям. Используйте обычный Redis для тем 1–11, если задание не называет модуль.

После старта экземпляра убедитесь, что клиент может подключиться. Следующий раздел использует `redis-cli` для этой проверки.

Не открывайте учебный экземпляр в публичный интернет. Привяжите к `127.0.0.1` на локальной машине. Задайте пароль любому экземпляру, который не только на localhost.

## `redis-cli`

`redis-cli` — официальный клиент командной строки. Инструмент отправляет команды Redis и печатает ответы. Используйте `redis-cli` для обучения, проверок здоровья и разовых операций.

Запустите интерактивную сессию к хосту и порту по умолчанию:

```text
redis-cli
```

Приглашение показывает хост и номер логической БД, например `127.0.0.1:6379>`. Введите команду. Нажмите Enter. Прочитайте ответ.

Подключитесь к другому хосту или порту:

```text
redis-cli -h 127.0.0.1 -p 6379
```

Отправьте одну команду без интерактивной сессии:

```text
redis-cli PING
```

Если экземпляр требует пароль, передайте `-a` или используйте `AUTH` после подключения. Предпочитайте переменную окружения или запрос пароля, а не пароль в истории оболочки. Хостинговые сервисы часто требуют имя пользователя и пароль. Используйте `--user` и `--pass` или `AUTH`, как показывает документация сервиса.

`redis-cli` печатает типы ответов в читаемом виде. Простая строка, целое, bulk-строка, массив и ошибка выглядят по-разному. Научитесь читать эти формы. Ошибка начинается с сообщения сервера.

Выйдите из интерактивной сессии через `QUIT` или `exit`, либо закройте терминал.

Не запускайте `KEYS *` на промышленном экземпляре. Эта команда может заблокировать сервер на большом пространстве ключей. Этот путь обучения использует `KEYS` только на локальном пустом экземпляре. Позже темы вводят `SCAN`.

## `PING`, `INFO`, `SELECT` (логические БД: в современных приложениях одна БД)

`PING` проверяет соединение. Redis отвечает `PONG`, когда экземпляр принимает команду. Можно отправить сообщение:

```text
PING
PING hello
```

Вторая форма повторяет `hello`. Используйте `PING` после подключения. Клиентские библиотеки также используют `PING` как проверку здоровья.

`INFO` возвращает текстовые разделы об экземпляре. Запустите `INFO` для полного отчёта. Запустите `INFO server`, `INFO memory`, `INFO clients`, `INFO replication` или `INFO keyspace` для одного раздела.

Полезные строки для новичков:

- `redis_version` — версия сервера
- `used_memory_human` — используемая память
- `connected_clients` — открытые клиентские соединения
- `db0` в `INFO keyspace` — число ключей и число сроков для логической БД 0

Вывод не JSON. Разбирайте его как строки `key:value`.

`SELECT` меняет логическую БД для текущего соединения. По умолчанию БД `0`. Установка по умолчанию имеет 16 логических БД (`0`–`15`). Ключи в БД `0` не видны в БД `1`.

```text
SELECT 0
SET learn:flag 1
SELECT 1
GET learn:flag
```

`GET` в БД `1` не видит ключ из БД `0`.

Современные приложения используют одну логическую БД, обычно БД `0`. Они разделяют данные префиксами ключей, а не через `SELECT`. Redis Cluster не поддерживает `SELECT`. Многие хостинговые сервисы открывают только БД `0`. Не проектируйте новую систему, которая зависит от многих логических БД.

`SELECT` всё ещё полезен в локальной лаборатории, когда нужно чистое пространство имён. Верните соединение в БД `0`, когда закончите.

Справочник команд — [https://redis.io/commands/](https://redis.io/commands/). Каждая страница команды показывает синтаксис, временную сложность, тип возврата и примеры. Открывайте страницу команды, когда учите новую команду.

Страницы типов данных начинаются с [https://redis.io/docs/data-types/](https://redis.io/docs/data-types/). Читайте страницу типа до запоминания каждой команды.

Redis University — [https://university.redis.io/](https://university.redis.io/). Курсы — необязательное дополнение. Этот справочник — путь по темам в `redis.topics.md`.

Используйте `HELP` в `redis-cli` для короткой подсказки на сервере, если сервер это поддерживает. Веб-страница команды — полный справочник.

Когда страница и этот справочник расходятся по новому флагу, доверяйте странице команды для вашей версии Redis. Проверьте `INFO server` на `redis_version`.

Добавьте в закладки главную страницу документации, индекс команд и индекс типов данных. Вы будете открывать эти страницы в каждой следующей теме.

## Обзор темы

Эти вопросы не повторяют вопросы из разделов выше. Они охватывают всю тему.

### Вопросы

#### Теоретические вопросы

1. Опишите путь от пустой машины до рабочего `PING`. Назовите метод установки и клиент.
2. Как роли кэша, брокера и базы меняют потребность в персистентности?
3. Почему префикс ключа лучше изолирует данные, чем `SELECT`, в новом приложении?
4. В чём разница между интерактивным режимом `redis-cli` и одноразовой командой `redis-cli`?
5. Коллега хочет Memcached, потому что «Redis — только кэш». Какие факты вы используете в коротком ответе?

#### Простые практические задания

1. Запустите Redis. Выполните `PING`, `INFO server` и `SET learn:start 1`, затем `GET learn:start`. Сохраните все ответы.
2. Напишите шпаргалку на одну страницу: команда установки, флаги `redis-cli`, `PING`, `INFO`, `SELECT` и три URL документации.
3. Экспортируйте `INFO` в текстовый файл. Выделите `redis_version`, `tcp_port`, `used_memory_human` и `connected_clients`.
4. Создайте заметку в папке, которая фиксирует хост, порт и «только БД 0» как правила лаборатории.

#### Средние практические задания

1. Напишите небольшой скрипт (PowerShell или bash), который ничего не запускает, но проверяет Redis через `redis-cli PING` и выходит с ненулевым статусом при ошибке.
2. Положите один ключ в Docker Redis и один ключ во второй экземпляр (другой порт или хостинг). Задокументируйте, как направить `redis-cli` на каждый экземпляр.
3. Опишите лабораторную схему Redis в десяти шагах, чтобы другой новичок мог её скопировать (Docker или установка, порт, `redis-cli`, первый `PING`).

#### Сложные практические задания

1. Запустите два контейнера Redis на портах `6379` и `6380`. Составьте таблицу полей `INFO server`, которые отличаются (`tcp_port`, `process_id`, `run_id`).
2. Подключите клиентскую библиотеку на языке, который вы знаете. Отправьте `PING` из кода и из `redis-cli`. Запишите оба ответа и имя библиотеки.

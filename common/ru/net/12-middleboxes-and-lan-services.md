# 12. Промежуточные устройства и службы LAN

## Описание

Промежуточное устройство — устройство или программа на пути, которая не исходный клиент и не исходный сервер. Хостам LAN также нужны адрес, часы и способ найти соседние службы. Эта тема показывает stateful-экраны. Вы узнаете балансировщики L4 против L7 и CDN. Вы узнаете DHCP, NTP и mDNS. Вы узнаете задержку против пропускной способности.

Завершите эту тему после NAT, TCP, HTTP и TLS.

Используйте один термин для каждого понятия. Stateful-экран отслеживает потоки. Балансировщик нагрузки распределяет соединения или запросы. CDN кэширует и завершает рядом с пользователями. Аренда — временная выдача конфигурации. NTP синхронизирует часы. mDNS — похожий на DNS поиск имён на локальном канале. Задержка — ожидание. Пропускная способность — байты в единицу времени. Не смешивайте экран с NAT, даже когда один ящик делает оба. Не смешивайте задержку с пропускной способностью.

Практикуйтесь с `curl -v`, traceroute и таймингами. Не меняйте продакшен-экран без плана. Не запускайте второй сервер DHCP в офисной LAN.

## Stateful-экраны

Фильтр пакетов может разрешать или отбрасывать по адресу, порту и протоколу. Stateful-экран также держит таблицу потоков. Ответ, который совпадает с разрешённым исходящим потоком, может пройти. Новый входящий SYN на закрытый или отфильтрованный порт может отброситься.

Ключ состояния часто — 5-кортеж: протокол, локальный IP, локальный порт, удалённый IP, удалённый порт. Состояние UDP использует таймауты, потому что нет FIN. Устройства NAT stateful. Тема 4 покрыла NAT. Домашний маршрутизатор часто — NAT плюс stateful-экран.

Правила без состояния всё равно важны для ICMP и некоторых путей anycast. Политика, которая отбрасывает весь ICMP, может сломать path MTU discovery.

Экраны уровня приложения (WAF) осматривают HTTP. Они всё равно промежуточные устройства. Они могут сломать необычных клиентов. Журналируйте отбрасывание.

`curl` к закрытому порту отказывает быстро. `curl` к отфильтрованному порту может зависнуть до таймаута. Эта разница — подсказка отладки.

Не добавляйте разрешить-всё, чтобы скрыть ошибку. Не забывайте правила IPv6 на хосте dual stack. Не считайте экран заплаткой для службы, которая слушает на всех интерфейсах без подлинности.

## Балансировщики L4 против L7 и CDN

Балансировщик нагрузки (LB) сидит перед несколькими backend. Клиент говорит с одним виртуальным адресом или именем. LB выбирает backend.

LB уровня 4 пересылает TCP или UDP по 5-кортежу. Он не читает HTTP. Он может быть быстрым. Он не может маршрутизировать по пути URL или по заголовку Host. TLS может пройти насквозь. Тогда backend завершает TLS.

LB уровня 7 читает HTTP. Он может маршрутизировать по пути, по заголовку или по cookie. Он часто завершает TLS. Он может добавить `X-Forwarded-For`. LB L7 — обратный прокси с алгоритмом выбора.

Алгоритмы включают round robin, least connections и хеш адреса клиента. Проверки здоровья снимают мёртвый backend. Липкие сессии шлют одного клиента на один backend, когда приложение держит локальное состояние. Предпочитайте приложения без состояния.

CDN — сеть доставки содержимого. Это набор кэшей и конечных точек TLS рядом с пользователями. Браузер говорит с ближайшей точкой присутствия. CDN забирает у origin при промахе кэша. Статические файлы выигрывают больше всего. Персонализированные вызовы API могут всё равно идти к origin.

Anycast (тема 14) часто стоит перед CDN. Пользователь всё равно набирает одно имя.

Не ставьте LB L4 перед gRPC и не ждите маршрутизации HTTP по пути. Не скрывайте все ошибки backend как `502` без журналов. Не используйте липкость как замену общего хранилища. Тяжёлая проверка здоровья может стать нагрузкой.

## DHCP, NTP, mDNS

DHCP (IPv4) даёт хосту временную конфигурацию: адрес IPv4, маску подсети, шлюз по умолчанию и часто резолверы DNS. Выдача — аренда. Хост должен продлить аренду до конца времени, если хочет сохранить адрес.

Обычный танец IPv4: discover, offer, request, acknowledge. Реле может переслать на сервер DHCP в другой подсети. Когда аренда кончается и продление не удаётся, хост должен перестать использовать этот адрес. Некоторые хосты держат адрес link-local IPv4 (`169.254/16`), если DHCP не удаётся. Этот адрес не заменяет шлюз.

DHCPv6 может назначать адреса IPv6 или только опции. Тема 3 покрыла SLAAC против DHCPv6. Не ждите, что DHCPv4 задаст IPv6.

Резервации связывают MAC или идентификатор клиента со стабильным адресом. Выдача всё равно аренда. Аренда — не выдача безопасности. Любой, кто может использовать LAN, часто может получить аренду.

NTP — Network Time Protocol. Хост спрашивает серверы времени и подстраивает часы. Верное время важно для сертификатов TLS, журналов и подписанных токенов. Большая ошибка часов выглядит как истёкший сертификат. NTP задаёт UTC. Часовой пояс — смещение отображения. Не чините TLS сменой только часового пояса.

mDNS — multicast DNS на локальном канале. Хосты публикуют имена вроде `printer.local`. Bonjour — обычная реализация. mDNS не заменяет глобальный DNS. Он не работает через маршрутизаторы, пока нет шлюза. Не публикуйте внутренние имена во враждебную LAN.

Не запускайте два несогласованных сервера DHCP в одной LAN. Не направляйте продакшен-флот на случайный публичный сервер NTP в огромном масштабе. Не отключайте синхронизацию времени, чтобы скрыть тест.

## Задержка против пропускной способности

Задержка — сколько ждёт одно действие. Время круговой поездки (RTT) — обычная мера задержки. `ping` берёт выборки RTT. Рукопожатию TLS нужно несколько RTT. Короткий запрос на пути с большой задержкой ограничен задержкой.

Пропускная способность — сколько байт движется в единицу времени. Большой файл на широком пути ограничен пропускной способностью, когда окно и путь позволяют. Тема 6 покрыла окно и управление перегрузкой.

Полоса — ёмкость канала. Пропускная способность — то, что достигаете. Пропускная способность не может превысить ёмкость узкого места. Заголовки и потери её снижают.

Канал 1 Gbit/s с RTT 200 мс всё равно может казаться медленным для маленького вызова API. Тот же канал может двигать большой файл с высокой пропускной способностью после slow start. Пользователи смешивают слова. Вы не должны.

Произведение полосы на задержку (BDP) — ёмкость умножить на RTT. Окно TCP должно быть достаточно большим, чтобы заполнить трубу. Масштабирование окна существует по этой причине.

Nagle и задержанный ACK могут добавить задержку на маленьких записях. Измерьте, прежде чем настраивать. Не отключайте управление перегрузкой, чтобы гнаться за пропускной способностью в публичном Internet.

Не добавляйте больше параллелизма без измерения. Лишние соединения помогают задержке HTTP/1.1 для многих маленьких файлов. Они также добавляют стоимость рукопожатия.

# 3. Основы CRUD

## Описание

CRUD значит Create, Read, Update и Delete. Эта тема показывает базовые методы записи и чтения в MongoDB. Вы вставляете документы, ищете документы, обновляете поля, заменяете документы и удаляете документы. Завершите эту тему до изучения проекций, сортировки и запросов к массивам.

Используйте один термин для каждого понятия. **insert** добавляет новый документ. **find** читает документы. **update** меняет поля в документе. **replace** записывает полное новое тело документа. **delete** удаляет документ. **upsert** обновляет совпадение или вставляет документ, если совпадения нет.

Все примеры используют `mongosh` и помощники коллекции вроде `db.items.insertOne`.

## `insertOne` / `insertMany`

`insertOne` записывает один документ. Сервер возвращает подтверждение и `_id` нового документа.

```javascript
db.items.insertOne({ name: "nail", qty: 100 })
```

Если `_id` опустить, MongoDB добавит ObjectId. Если задать `_id`, это значение станет ключом.

`insertMany` записывает много документов за один вызов. Передают массив.

```javascript
db.items.insertMany([
  { name: "pin", qty: 50 },
  { name: "bolt", qty: 20 }
])
```

По умолчанию `insertMany` останавливается на первой ошибке (`ordered: true`). Задайте `ordered: false`, чтобы продолжить после ошибки. Частая ошибка — дубликат `_id`.

Вставка — запись. Неудачная вставка не меняет коллекцию для этого документа. Не повторяйте вставку с тем же `_id`, если не хотите ошибку дубликата.

Не вызывайте `insertOne` в цикле, когда есть пакет. Используйте `insertMany` или пакетную запись. Цикл одиночных вставок медленнее.

`insertOne` и `insertMany` не заменяют существующий документ. Для этого используйте update, replace или upsert.

## `find` / `findOne`

`find` возвращает курсор. Курсор — итератор по совпавшим документам. `mongosh` печатает первый пакет, когда вы вводите `find()`.

```javascript
db.items.find()
db.items.find({ qty: 100 })
```

Пустой фильтр `{}` совпадает со всеми документами. Фильтр `{ qty: 100 }` совпадает с документами, где `qty` равно 100. Равенство — поведение по умолчанию. Для простого равенства `$eq` не нужен.

`findOne` возвращает один документ или `null`. Курсор он не возвращает.

```javascript
db.items.findOne({ name: "nail" })
```

`findOne` — не особая команда сервера с другим правилом совпадения. Это find, который ограничивает результат одним документом.

Не используйте `find()` на большой коллекции в программе без фильтра, лимита или обоих. Следующая тема покрывает `limit`. API не должен возвращать неограниченный результат.

`countDocuments` считает совпадения. `estimatedDocumentCount` использует метаданные. Используйте `countDocuments`, когда нужен точный счёт по фильтру.

## Операторы запросов: `$eq`, `$gt`, `$in`, `$and`, `$or`, `$exists`

Фильтр может использовать операторы. Оператор — ключ, который начинается с `$`.

- `$eq` — равно. `{ qty: { $eq: 100 } }` то же, что `{ qty: 100 }`.
- `$gt` — больше. Родственные операторы — `$gte`, `$lt` и `$lte`.
- `$in` — значение поля есть в списке. `{ name: { $in: ["nail", "pin"] } }`.
- `$and` — все условия должны совпасть. Фильтр с несколькими полями — неявный AND.
- `$or` — должно совпасть хотя бы одно условие. Передают массив фильтров.
- `$exists` — поле есть (`true`) или нет (`false`). Поле со значением `null` всё равно существует.

Пример:

```javascript
db.items.find({ qty: { $gt: 10 } })
db.items.find({ $or: [ { name: "nail" }, { qty: { $lt: 5 } } ] })
db.items.find({ color: { $exists: false } })
```

`$in` — не `$or` полных документов. `$in` проверяет одно поле против списка значений.

`$and` полезен, когда нужны два оператора на одном поле или явный список. Предпочитайте простой неявный AND, когда он ясен.

Не собирайте фильтр из строки, которая включает текст пользователя. Используйте структурированный объект. Инъекции — в следующих темах.

Сравнение использует типы BSON. У типов есть порядок сравнения. Строка не сравнивается как число.

## `updateOne` / `updateMany` с `$set`, `$unset`, `$inc`

`updateOne` меняет первый совпавший документ. `updateMany` меняет все совпавшие документы.

Обновление использует **документ обновления** с операторами. В эти методы не передают полный документ замены (это `replaceOne`).

- `$set` — задать полю значение. Создаёт поле, если его нет.
- `$unset` — удалить поле.
- `$inc` — прибавить число к числовому полю. Поле должно быть числом или отсутствовать (тогда MongoDB считает его 0).

```javascript
db.items.updateOne({ name: "nail" }, { $set: { qty: 90 } })
db.items.updateMany({ qty: { $gt: 0 } }, { $inc: { qty: -1 } })
db.items.updateOne({ name: "nail" }, { $unset: { obsolete: "" } })
```

Фильтр — первый аргумент. Обновление — второй. Отсутствующий фильтр в `updateOne` совпадает с первым документом. Это опасно. Всегда передавайте задуманный фильтр.

`updateMany` с фильтром, который совпадает слишком широко, тоже опасен. То же правило, что у SQL `UPDATE` без хорошего `WHERE`.

`$set` может задавать вложенные поля точечной нотацией: `{ $set: { "addr.city": "Oslo" } }`.

Обновления атомарны на одном документе. Две операции `$inc` на одном документе не теряют счёт, если используют `$inc`, а не чтение-затем-запись на клиенте.

## `replaceOne`

`replaceOne` записывает новое тело документа поверх совпавшего. Фильтр выбирает документ. Второй аргумент — **документ замены**, а не документ операторов обновления.

```javascript
db.items.replaceOne(
  { name: "nail" },
  { name: "nail", qty: 0, unit: "box" }
)
```

Документ замены не должен содержать операторы обновления вроде `$set`. Замена становится полным содержимым, кроме `_id`. `_id` остаётся тем же, если не включить тот же `_id`. Изменить `_id` при замене нельзя.

Используйте `replaceOne`, когда у клиента есть полный новый документ. Используйте `updateOne`, когда меняете несколько полей.

Замена может удалить поля, которые вы опустили. В этом смысл. В этом и риск. Если клиент по ошибке пришлёт частичный объект, поля пропадут.

`replaceOne` обновляет не больше одного документа. `replaceMany` нет.

## `deleteOne` / `deleteMany`

`deleteOne` удаляет первый совпавший документ. `deleteMany` удаляет все совпавшие документы.

```javascript
db.items.deleteOne({ name: "pin" })
db.items.deleteMany({ qty: 0 })
```

Отсутствующий или пустой фильтр у `deleteMany` удаляет все документы коллекции. Это частая авария. Всегда передавайте задуманный фильтр. Предпочитайте `drop()`, когда хотите удалить всю коллекцию.

Удаления не ведут журнал в стиле SQL `TRUNCATE` тем же способом. Они удаляют документы. Индексы обновляются. Значения `_id` пропадают. Поздняя вставка может снова использовать свой `_id`, если вы его зададите.

`deleteOne` с фильтром, который совпадает со многими документами, всё равно удаляет только один. Не угадывайте какой, если фильтр не уникален (например `_id`).

Удалённых данных в коллекции нет. Восстановление нужно из резервной копии или с delayed-члена. Не используйте delete, чтобы проверять восстановление на производственных данных.

## `upsert`

**Upsert** — обновление или замена, которая вставляет документ, когда ни один документ не совпал с фильтром.

```javascript
db.items.updateOne(
  { name: "wire" },
  { $set: { qty: 10 } },
  { upsert: true }
)
```

Если документ с `name: "wire"` есть, MongoDB применяет `$set`. Если нет, MongoDB создаёт документ. Новый документ включает поля фильтра и поля обновления по правилам, которые описывает руководство.

`replaceOne` тоже принимает `upsert: true`. Документ замены становится новым документом.

Upsert полезен для «задать этому ключу это значение» и для счётчиков, которые должны начинаться с нуля. `$inc` с upsert создаёт документ и затем увеличивает.

Гонка: два upsert с одним фильтром могут дать ошибку дубликата ключа, если оба вставляют. Обработайте ошибку и повторите или используйте уникальный индекс по полям фильтра.

Не делайте upsert с широким фильтром. Можно вставить документы, которые не задумывали.

Путь вставки upsert всё равно требует уникальный `_id`. MongoDB генерирует `_id`, если вы его не задали.

### Вопросы

#### Теоретические вопросы

1. Сопоставьте Create, Read, Update, Delete с именами методов MongoDB. Включите replace и upsert.
2. Почему MongoDB разделяет `updateOne` (операторы) и `replaceOne` (полное тело)?
3. Какие методы записи могут создать документ, а какие только меняют или удаляют существующие?
4. Как фильтры работают одинаково для find, update и delete?
5. Коллега хочет «отредактировать документ» на клиенте и отправить его обратно. Какой метод нужен и что можно потерять?

#### Простые практические задания

1. В одной коллекции вставьте два документа, найдите один, обновите одно поле, замените другой, удалите один. Запишите итоговый вывод `find`.
2. Напишите шпаргалку с именами методов и одной строкой каждый: insert, find, update, replace, delete, upsert.
3. Выполните `insertOne`, затем `updateOne` с `$inc`, затем `findOne`. Запишите три команды и итоговый `qty`.
4. Создайте `crud-notes.md` с шестью именами методов и одним предупреждением для каждого (пустой фильтр, упорядоченная вставка и подобное).

#### Средние практические задания

1. Напишите небольшой скрипт, который 20 раз делает upsert документа-счётчика через `$inc`. Запишите итоговый счёт.
2. Скопируйте один документ, измените его и напишите и обновление `$set`, и версию `replaceOne`. Запустите оба на двух клонах. Сравните оставшиеся поля.
3. Используйте `bulkWrite` с одной вставкой, одним обновлением и одним удалением. Подтвердите состояние коллекции.

#### Сложные практические задания

1. Прочитайте `bulkWrite` ordered vs unordered. Вызовите одну ошибку дубликата ключа в пакете. Запишите, сколько операций применилось.
2. На replica set выполните мультидокументную транзакцию, которая вставляет и затем удаляет. Зафиксируйте. Затем выполните одну, которая прерывается. Покажите коллекцию после каждой.

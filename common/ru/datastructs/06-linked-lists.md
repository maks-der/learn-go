# 6. Односвязные и двусвязные списки

## Описание

Связный список хранит элементы в узлах. Каждый узел держит значение и один или больше указателей. Эта тема объясняет голову, хвост, вставку, удаление, сторожевые узлы, разворот, обнаружение цикла и стоимость кэша. Завершите эту тему после массивов. Вы сравните два расположения.

Используйте один термин для каждого понятия. **Узел** — ячейка со значением и ссылками. **Голова** — первый узел. **Хвост** — последний узел. **Односвязный список** имеет указатель next. **Двусвязный список** имеет указатели next и previous. **Сторожевой узел (sentinel)** — фиктивный узел, который не является настоящим элементом.

## Узел, голова, хвост

**Узел** держит значение и ссылку на следующий узел. Последний узел держит нулевой указатель next.

Указатель **головы** называет первый узел. Если список пуст, голова — нуль.

Указатель **хвоста** называет последний узел. Хвост необязателен. Если вы храните хвост, append в конец есть Θ(1). Если вы не храните хвост, append идёт от головы. Этот обход — Θ(n).

```text
head → [10|•] → [20|•] → [30|null]
                     ↑
                    tail
```

```go
type Node struct {
	Value int
	Next  *Node
}
```

```python
class Node:
    def __init__(self, value, next=None):
        self.value = value
        self.next = next
```

**Двусвязный узел** также держит указатель previous. У головы нулевой указатель previous. У хвоста нулевой указатель next. Вы можете идти в двух направлениях.

```text
null ← [10] ⇄ [20] ⇄ [30] → null
        ↑               ↑
       head            tail
```

Объект списка обычно хранит голову, и часто хвост и длину. Длина делает `len` операцией Θ(1). Если вы не храните длину, `len` обходит список.

Не путайте указатель головы с первым значением. Указатель головы — ссылка. Первое значение сидит внутри первого узла.

## Вставка и удаление у головы и хвоста

**Вставка в голову** создаёт узел и направляет его на старую голову. Затем голова становится новым узлом. Стоимость — Θ(1). Если список был пуст, хвост тоже становится новым узлом.

**Удаление у головы** двигает голову на head.next. Старый первый узел не используется. Стоимость — Θ(1). Если список становится пустым, хвост становится нулём.

**Вставка в хвост** с указателем хвоста: старый tail.next становится новым узлом. Затем хвост становится новым узлом. Стоимость — Θ(1). Без указателя хвоста вы сначала идёте к последнему узлу. Этот обход — Θ(n).

**Удаление у хвоста** в односвязном списке — Θ(n). Вы должны найти узел перед хвостом. Указатель хвоста не даёт вам предыдущий узел. В двусвязном списке удаление у хвоста — Θ(1). Вы используете tail.previous.

```text
insert 5 at head
before:  10 → 20
after:    5 → 10 → 20

insert 30 at tail (tail stored)
before:   5 → 10 → 20
after:    5 → 10 → 20 → 30
```

Вставка в середину у известного узла — Θ(1) для обновлений ссылок. Поиск этого узла всё ещё Θ(n), если вы начинаете с головы.

Удаление в середине односвязного списка нуждается в предыдущем узле. Вы не можете перелинковать, если у вас только целевой узел, если не скопируете следующее значение (особый приём). Предпочитайте держать предыдущий узел.

## Фиктивные / сторожевые узлы

**Сторожевой узел (sentinel, dummy)** — узел, который не является элементом. Сторожевой узел упрощает случаи пустого списка.

**Сторожевой узел головы** сидит перед первым настоящим элементом. Голова объекта списка всегда называет сторожевой узел. Первый настоящий элемент — sentinel.next. У пустого списка sentinel.next == null (или sentinel.next == сторожевой узел хвоста).

**Сторожевой узел хвоста** может сидеть после последнего настоящего элемента. Некоторые списки используют два сторожевых узла. Некоторые кольцевые списки используют один сторожевой узел, который ссылается на себя.

```text
head sentinel → [10] → [20] → null

empty list:
head sentinel → null
```

Без сторожевого узла вставка в голову и вставка после узла — разные функции. Со сторожевым узлом головы вставка после узла покрывает вставку в начало: вы вставляете после сторожевого узла.

Удаление тоже становится единообразным. Вы всегда удаляете узел после некоторого предшественника. Предшественник первого элемента — сторожевой узел.

Сторожевые узлы используют дополнительную память. Дополнительная память — один или два узла. Выигрыш — меньше ветвлений в коде. Меньше ветвлений уменьшает ошибки пустого списка.

Кольцевой список может использовать сторожевой узел так, что ни один указатель next не нулевой. Обход останавливается, когда вы возвращаетесь к сторожевому узлу.

Не считайте сторожевой узел живым элементом. Длина не включает сторожевой узел.

## Разворот списка

**Reverse** меняет направление указателей next. Старая голова становится хвостом. Старый хвост становится головой.

**Итеративный разворот** использует три указателя: previous, current и next. Вы обходите список один раз. На каждом узле вы ставите current.next = previous. Затем двигаетесь вперёд. Стоимость — Θ(n). Дополнительная память — Θ(1).

```text
before:  1 → 2 → 3 → null
after:   3 → 2 → 1 → null
```

```text
steps (idea)
  prev = null
  curr = head
  while curr != null:
      next = curr.next
      curr.next = prev
      prev = curr
      curr = next
  head = prev
```

**Рекурсивный разворот** разворачивает хвост, затем направляет старый хвост на старую голову. Рекурсия использует стек вызовов. Дополнительная память — Θ(n). Предпочитайте итеративный разворот, если не изучаете рекурсию.

Если вы храните хвост, поменяйте голову и хвост после разворота указателей или поставьте хвост на старую голову.

Разворот двусвязного списка может менять next и previous на каждом узле или менять голову и хвост и идти. Всё ещё Θ(n).

Reverse не копирует значения в новый массив, если вы не выбираете этот метод. Метод массива использует Θ(n) дополнительной памяти. Метод указателей на месте использует Θ(1) дополнительной памяти.

## Обнаружение цикла (Флойд)

**Цикл** существует, когда обход указателей next возвращается к узлу, который вы уже посетили. Правильный список конечной длины не имеет цикла. Ошибка или ребро графа могут создать цикл.

Если цикл существует, наивный обход не достигает нуля. Программа крутится вечно.

**Алгоритм Флойда** (черепаха и заяц) использует два указателя. Медленный указатель двигается на один узел за шаг. Быстрый указатель двигается на два узла за шаг. Если цикла нет, быстрый указатель достигает нуля. Если цикл есть, быстрый указатель встречает медленный указатель внутри цикла.

```text
slow = head
fast = head
while fast != null and fast.next != null:
    slow = slow.next
    fast = fast.next.next
    if slow == fast:
        return has cycle
return no cycle
```

Время — Θ(n). Дополнительная память — Θ(1). Вы не храните множество посещённых.

Множество посещённых тоже обнаруживает цикл. Вы храните личность каждого узла. Дополнительная память — Θ(n). Алгоритм Флойда лучше, когда нужна константная дополнительная память.

Алгоритм Флойда также может найти начало цикла. После встречи переместите один указатель на голову. Двигайте оба указателя по одному шагу. Они встречаются в начале цикла. Вторую фазу можно выучить позже. Эта тема требует идею обнаружения.

Не используйте алгоритм Флойда как замену правильному коду списка. Используйте его, чтобы обнаружить испорченный список или решить задачу о цикле.

## Когда списки проигрывают массивам (кэш)

Связный список проигрывает массиву для многих реальных программ. Класс O-большого всё ещё может выглядеть хорошо.

**Локальность.** Узлы сидят по адресам кучи, которые далеко. Обход — преследование указателей. Обход массива читает непрерывные ячейки. Кэш помогает массиву.

**Дополнительная память.** Каждый узел хранит один или два указателя и часто заголовок. Массив целых хранит целые. Список использует больше байт на элемент.

**Случайный доступ.** `get(i)` есть Θ(i) на списке и Θ(1) на массиве.

**Append.** Append динамического массива — амортизированная Θ(1) и кэш-дружественен. Append списка — Θ(1) с указателем хвоста, но следующий просмотр всё ещё медленный.

Списки выигрывают, когда вы вставляете или удаляете у известного узла и не должны двигать остальные элементы. Списки также выигрывают, когда вы сращиваете два списка за Θ(1) обновлениями указателей. Эти случаи реальны. Они реже, чем «мне нужна последовательность значений».

```text
prefer a dynamic array when:
  you iterate often
  you index by i
  you append at the end
  n is large and elements are small

prefer a list when:
  you insert or delete at the head often
  you splice lists
  you already hold the node
```

Измеряйте, когда n велико. Не выбирайте список только потому, что вставка в середину есть Θ(1) после того, как у вас есть узел. Поиск узла всё ещё может быть Θ(n).

1. Реализуйте обе структуры. Запустите scan, get(i), insert_head и append. Напишите таблицу результатов.
2. Напишите политику на одну страницу: по умолчанию динамический массив. Перечислите исключения с причиной для каждого исключения.

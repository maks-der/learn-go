# 5. Составные типы

## Описание

Составной тип хранит другие значения. Эта тема покрывает массивы, срезы, карты и структуры. Вы используете эти типы почти в каждой программе на Go.

У массива фиксированная длина. Срез — вид на массив. Карта хранит ключи и значения. Структура группирует именованные поля.

Для большинства последовательностей предпочитайте срезы массивам. Для поиска по ключу предпочитайте карты. Для записей с известным набором полей предпочитайте структуры.

Длина входит в тип массива. Заголовок среза хранит указатель, длину и ёмкость. Значение карты ссылается на хеш-таблицу. Значение структуры хранит свои поля.

## Массивы

Тип массива — `[N]T`. `N` — длина. `T` — тип элемента. Длина входит в тип. `[3]int` и `[4]int` — разные типы.

```go
var a [3]int
b := [3]int{1, 2, 3}
c := [...]int{4, 5, 6}
```

`var a [3]int` задаёт каждому элементу нулевое значение. Форма `[...]int{4, 5, 6}` позволяет компилятору посчитать элементы. Тип `c` — `[3]int`.

Присваивание копирует массив. Копия имеет свои элементы. Изменение `b` не меняет `a` после `a = b`. Передача массива в функцию тоже копирует массив. Большой массив как параметр дорог. Используйте срез, когда длина может меняться или когда хотите избежать копии.

```go
a := [2]int{1, 2}
b := a
b[0] = 9
fmt.Println(a[0], b[0]) // 1 9
```

Массивы сравнимы, когда тип элемента сравним. Можно использовать `==` на двух значениях `[3]int`. Массив сравнимых элементов можно использовать как ключ карты.

Индексируйте массив через `a[i]`. Индекс должен быть от `0` до `N-1`. Индекс вне диапазона вызывает panic.

Многомерный массив — массив массивов. `[2][3]int` имеет две строки. Каждая строка имеет три значения `int`. Присваивание копирует каждый внутренний массив. `[2][3]int` — не то же, что `[][]int`.

Используйте массивы, когда размер входит в смысл. Примеры: хеш-дайджест, точка размера 2, маленькая таблица поиска. Для списков используйте срезы.

## Срезы: длина, ёмкость, `append` и backing-массив

Срез — дескриптор сегмента массива. Заголовок среза имеет три части: указатель, длину и ёмкость.

Длина — число элементов, которые можно индексировать. `len(s)` возвращает длину. Допустимые индексы — от `0` до `len(s)-1`. Ёмкость считает элементы в backing-массиве от начала среза до конца массива. `cap(s)` возвращает ёмкость. Ёмкость всегда больше или равна длине.

```go
s := make([]int, 3, 5)
fmt.Println(len(s), cap(s)) // 3 5
```

Можно индексировать `s[0]`, `s[1]` и `s[2]`. Нельзя индексировать `s[3]`. Этот индекс паникует. Лишняя ёмкость не используется, пока `append` или выражение среза не увеличат длину.

`make` создаёт срез. Используйте `make([]T, len)` или `make([]T, len, cap)`. `append` добавляет элементы в конец. `append` возвращает срез. Нужно использовать возвращённый срез.

```go
s := []int{1, 2}
s = append(s, 3)
s = append(s, 4, 5)
s = append(s, []int{6, 7}...)
```

Когда длина меньше ёмкости, `append` пишет в backing-массив. Когда длина равна ёмкости, `append` выделяет новый массив. Среда копирует старые элементы.

`copy` копирует элементы из исходного среза в целевой срез. `copy` возвращает число скопированных элементов.

Выражение среза делает новый заголовок среза. Новый срез может делить тот же backing-массив. Выражение — `x[low:high]`. Новая длина — `high - low`. Форма с тремя индексами `x[low:high:max]` задаёт ёмкость как `max - low`. Используйте её, когда следующий `append` не должен писать в более поздние элементы исходного массива.

Изменение элемента подсреза меняет backing-массив. Другие срезы, которые делят этот массив, видят изменение. Когда нужен независимый срез, скопируйте элементы в новый срез.

Срез может быть `nil`. Срез может быть пустым и не `nil`. Оба имеют длину `0`. `append` работает на срезе `nil`. `encoding/json` кодирует срез `nil` как `null`. Пустой срез кодирует как `[]`. Предпочитайте `len(s) == 0`, когда вас интересуют только элементы.

`append` может писать в неиспользованную ёмкость, которую всё ещё использует другой срез. Исправьте разделение трёхиндексным срезом или `copy`. Не игнорируйте результат `append`. Маленький срез большого backing-массива держит большой массив живым. Скопируйте маленькую часть, когда храните её долго.

## Карты: поиск, comma-ok, delete и итерация

Тип карты — `map[K]V`. `K` — тип ключа. `V` — тип элемента. Тип ключа должен быть сравним.

`make` создаёт пустую карту, в которую можно писать. Составной литерал тоже создаёт карту.

```go
m := make(map[string]int)
m["a"] = 1
m := map[string]int{"a": 1, "b": 2}
```

Поиск использует `m[key]`. Результат — значение. Когда ключа нет, результат — нулевое значение `V`. Форма comma-ok сообщает о наличии.

```go
v, ok := m["a"]
if !ok {
	fmt.Println("missing")
}
```

`ok` — `true`, когда ключ есть в карте. `ok` — `false`, когда ключа нет. `make(map[K]V, hint)` принимает подсказку размера. Подсказка — не предел длины. `len(m)` — число ключей. У карты нет `cap`.

`delete` удаляет ключ. `delete(m, key)` ничего не делает, когда ключа нет. `delete` на карте `nil` тоже ничего не делает. `clear(m)` удаляет все ключи. После `clear` `len(m)` — `0`. Карта всё ещё не `nil`.

Range по карте посещает каждый ключ и значение. Порядок итерации случаен. Не пишите тесты, которые требуют фиксированный порядок печати. Если нужен стабильный порядок, соберите ключи, отсортируйте ключи, затем найдите каждый ключ.

```go
for k, v := range m {
	fmt.Println(k, v)
}
```

Карта может быть `nil`. Чтение из карты `nil` возвращает нулевое значение. Запись в карту `nil` паникует. Создайте карту через `make` или литерал до первой записи.

Значение карты ссылается на хеш-таблицу. Присваивание копирует заголовок карты. Копия ссылается на ту же таблицу. Функция, которая получает карту, может вставлять, обновлять и удалять ключи. Вызывающий код видит эти изменения.

Карты небезопасны для параллельной записи. Две горутины не должны писать в одну карту одновременно. Параллельное чтение без записей безопасно. Защищайте общую карту через `sync.Mutex`. Тема 10 покрывает горутины и `sync`.

## Структуры, встраивание и теги структур

Структура — последовательность именованных полей. У каждого поля есть имя и тип.

```go
type Point struct {
	X int
	Y int
}
```

Нулевое значение структуры имеет нулевое значение в каждом поле. Доступ к полю — через точку. `p.X = 3`. Два именованных типа структур различны даже когда поля совпадают. Структура сравнима, когда каждое поле сравнимо.

В составном литерале предпочитайте имена полей. Имена остаются верными, когда кто-то добавляет поле. Можно взять адрес составного литерала: `p := &Point{X: 3, Y: 4}`. Не смешивайте позиционные поля и именованные поля в одном литерале структуры.

Имя поля, которое начинается с заглавной буквы, экспортируется. Другие пакеты могут читать и писать это поле. Имя поля, которое начинается со строчной буквы, не экспортируется. Только тот же пакет может использовать это имя. `encoding/json` по умолчанию кодирует экспортируемые поля. Тег JSON не экспортирует поле.

Встроенное поле перечисляет тип без нового имени. Имя поля становится именем типа. Поля внутреннего типа продвигаются.

```go
type Circle struct {
	Point
	Radius int
}

type Disk struct {
	Center Point
	Radius int
}
```

Для `Circle` можно писать `c.X`. Для `Disk` нужно писать `d.Center.X`. Встраивание — не наследование. `Circle` не является `Point`. Функция, которая принимает `Point`, не принимает `Circle`.

Используйте встраивание, когда внутренний тип — часть внешнего типа и продвижение помогает. Используйте именованное поле, когда внутреннее значение — роль, например `Center`. Можно встроить тип указателя. Встроенный указатель `nil` паникует, когда вы используете продвинутое поле.

Тег структуры — строковый литерал после типа поля. Такие пакеты, как `encoding/json`, используют теги.

```go
type User struct {
	Name string `json:"name"`
	Age  int    `json:"age,omitempty"`
	Pass string `json:"-"`
}
```

`json:"name"` сопоставляет поле с именем JSON `name`. `omitempty` опускает поле, когда значение — нулевое. `json:"-"` пропускает поле в JSON. Тег не меняет имя поля Go. Для строки тега используйте обратные кавычки.

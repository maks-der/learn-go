# 8. HTTP

## Описание

HTTP — протокол приложения для сообщений запроса и ответа. Эта тема показывает URL, метод, статус, заголовки и тело. Вы узнаете keep-alive HTTP/1.1 и заголовок Host. Вы узнаете cookie, прокси и `curl -v`. Вы получите предварительный обзор HTTPS.

Завершите эту тему после TCP и сокетов. Поздние темы покрывают HTTP/2, HTTP/3 и TLS глубже.

Используйте один термин для каждого понятия. Запрос — сообщение клиента. Ответ — сообщение сервера. Заголовок Host именует виртуальный хост. Keep-alive переиспользует TCP-соединение. Не смешивайте фрагмент URL с запросом. Не считайте HTTPS другим набором глаголов приложения. HTTPS — HTTP поверх TLS.

Практикуйтесь с `curl -v` и браузером. Захватывайте HTTP на порту 80, когда сайт ещё позволяет. HTTPS скрывает байты HTTP. Вы всё равно видите TCP и TLS.

## URL, метод, статус, заголовки, тело

URL именует ресурс. Обычная форма — `scheme://host:port/path?query#fragment`. Схема — `http` или `https`. Хост — имя или IP-адрес. Порт по умолчанию — 80 для HTTP и 443 для HTTPS. Путь — ресурс на сервере. Запрос — строка параметров. Фрагмент остаётся в клиенте. Клиент не отправляет фрагмент серверу.

Метод — глагол запроса. Обычные методы: `GET` (чтение), `POST` (отправить тело), `PUT` (сохранить), `DELETE` (удалить), `HEAD` (только заголовки), `OPTIONS` (разрешённые методы). Используйте `GET` для безопасных чтений. Используйте `POST`, когда у запроса есть побочный эффект, который кэш не должен повторять как GET.

Код статуса — трёхзначное число в ответе. 1xx — информационный. 2xx — успех (`200` OK). 3xx — перенаправление (`301`, `302`, `304`). 4xx — ошибка клиента (`400`, `403`, `404`). 5xx — ошибка сервера (`500`, `502`, `503`). Сначала читайте класс, затем точный код.

Заголовки — строки имя-значение. Заголовки запроса включают `Host`, `User-Agent`, `Accept` и `Content-Type`, когда есть тело. Заголовки ответа включают `Content-Type`, `Content-Length` или `Transfer-Encoding`, `Location` на перенаправлениях и `Set-Cookie`.

Тело необязательно. У `GET` часто нет тела. У `POST` часто есть тело. Тело — байты. `Content-Type` называет формат (`text/html`, `application/json`).

Текст HTTP/1.1 начинается со строки запроса или строки статуса, затем заголовки, затем пустая строка, затем тело. Не забывайте пустую строку.

Не используйте `GET` для банковского перевода. Не отправляйте секрет в запросе URL, если можете положить его в заголовок или тело POST. Журналы часто хранят URL.

## Keep-alive HTTP/1.1 и заголовок Host

HTTP/1.0 часто закрывал TCP-соединение после одного ответа. HTTP/1.1 по умолчанию использует постоянные соединения. Клиент и сервер могут слать больше запросов и ответов на том же TCP-соединении. Это keep-alive.

Keep-alive избегает нового рукопожатия и нового slow start для каждой картинки или скрипта. Клиент всё равно должен разобрать каждый ответ. HTTP/1.1 на одном соединении последовательный: клиент обычно ждёт ответ перед следующим запросом. Конвейер редок и хрупок. Многие браузеры открывают несколько TCP-соединений к одному хосту.

Заголовок `Connection: close` просит закрыть после этого ответа. Таймауты простоя закрывают тихое соединение keep-alive. У прокси может быть более короткое время простоя, чем у клиента.

Заголовок Host обязателен в HTTP/1.1. Он именует сайт. Многие серверы держат несколько имён на одном IP-адресе. Заголовок Host выбирает сайт. Запрос без Host недействителен в HTTP/1.1.

Порт по умолчанию можно опустить в заголовке Host (`example.com` значит порт 80 или 443 по схеме). Нестандартный порт появляется как `example.com:8080`.

HTTP/2 мультиплексирует много потоков на одном соединении. Это тема 11. Keep-alive HTTP/1.1 в обычном случае всё ещё один запрос за раз на соединение.

Не считайте, что один `curl` без `-v` показывает keep-alive. Смотрите заголовки и захват пакетов. Не отправляйте запрос на IP и не забывайте Host, когда сервер основан на имени.

## Cookie, прокси, `curl -v`

Cookie — маленький кусок состояния, который сервер задаёт через `Set-Cookie`. Клиент хранит его и отправляет обратно в поздних запросах заголовком `Cookie`. Cookie реализуют сессии, предпочтения и отслеживание. Флаги важны: `HttpOnly`, `Secure`, `SameSite`, `Path` и `Domain`.

Не считайте cookie паролем, который печатаете в тикете. Не храните секреты в cookie без `Secure` и короткой жизни на настоящем сайте. Захват HTTP показывает значения cookie открытым текстом.

Прокси сидит между клиентом и origin. Прямой прокси — выбор клиента (офисный фильтр, `HTTP_PROXY`). Обратный прокси сидит перед серверами (балансировщик нагрузки, ingress). Клиент обратного прокси думает, что говорит с origin.

Прокси могут добавлять `X-Forwarded-For` или `Forwarded`. Эти заголовки — утверждения. Последний хоп, которому доверяете, может их задать. Тема 12 покрывает балансировщики нагрузки.

`curl -v` печатает запрос, заголовки ответа, факты TLS на HTTPS и ошибки. Используйте его до написания клиента. Полезные флаги: `-I` для HEAD, `-d` для тела, `-H` для заголовка, `-x` для прокси, `-o` для файла тела, `-w` для таймингов.

Не коммитьте строку `curl`, в которой есть bearer-токен. Не доверяйте прокси, которым не управляете, с HTTPS, пока не понимаете перехват TLS (тема 10).

## Предварительный обзор HTTPS

HTTPS — HTTP поверх сессии TLS на TCP в обычном веб-случае. Схема URL — `https`. Порт по умолчанию — 443. Клиент сначала строит TCP, затем завершает рукопожатие TLS, затем отправляет HTTP.

TLS даёт конфиденциальность, целостность и подлинность, когда клиент проверяет сертификат. Тема 10 покрывает TLS. Этому разделу нужен предварительный обзор: замочек — не другой HTTP.

`curl -v` на HTTPS показывает субъект сертификата, издателя и версию TLS, когда инструмент их печатает. Браузер показывает диалог сертификата.

Открытый HTTP на порту 80 может перенаправить на HTTPS с `301` или `308` и заголовком `Location`. HSTS говорит браузеру в следующий раз использовать HTTPS. TLS на 443 всё равно нужен.

На проводе наблюдатель пути видит IP-адреса, порты и часто SNI (имя в рукопожатии TLS). Наблюдатель не видит путь или cookie в обычной сессии HTTPS.

Не отправляйте пароли по `http://` на публичном пути. Не отключайте проверку сертификата, чтобы скрыть лабораторную ошибку на пути настоящего пользователя. Не думайте, что HTTPS снимает нужду в заголовке Host. SNI TLS и Host HTTP оба именуют сайт.

HTTP/3 использует QUIC на UDP. Схема всё равно `https`. Тема 11 покрывает это сопоставление.

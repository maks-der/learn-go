# 7. Рекурсия и деревья

## Описание

Рекурсия — функция, которая вызывает себя. Дерево — связная структура с корнем и без цикла. Эта тема объясняет базовый случай и рекурсивный случай, слова дерева (корень, лист, родитель, ребёнок, глубина, высота), двоичные деревья и определения полного, совершенного, идеального и сбалансированного.

Завершите эту тему после стеков. Вам понадобится идея стека вызовов. Завершите эту тему до двоичных деревьев поиска.

Используйте один термин для каждого понятия. **Базовый случай** — вход, который не рекурсирует. **Рекурсивный случай** — вход, который вызывает ту же функцию на меньшем входе. **Дерево** — множество узлов со связями родитель–ребёнок и ровно одним корнем. **Двоичное дерево** имеет не больше двух детей на узел. **Высота** и **глубина** — не одно число. Эта тема определяет оба.

## Базовый случай и рекурсивный случай

У рекурсивной функции две части.

**Базовый случай** останавливает вызовы. Он возвращает значение или ничего не делает. Без базового случая вызовы не кончаются. Стек вызовов растёт, пока программа не откажется.

**Рекурсивный случай** вызывает ту же функцию на меньшей задаче. Вход должен приближаться к базовому случаю. Обычная мера — n, или оставшийся список, или оставшееся поддерево.

```text
factorial(n):
  base:      if n = 0, return 1
  recursive: return n * factorial(n - 1)
```

```text
list length:
  base:      if head is null, return 0
  recursive: return 1 + length(head.next)
```

У каждого вызова свой кадр. Кадр держит n или текущий узел. Тема 4 объяснила стек вызовов.

**Доверяйте рекурсивному вызову.** Вы пишете базовый случай. Вы пишете, как объединить результат меньшего вызова. Вы не проигрываете полную цепочку в голове для большого n.

**Неверная мера** не уменьшается. Пример: factorial(n), который снова вызывает factorial(n). Этот вызов не приближается к 0.

**Отсутствующий базовый случай** не останавливается. Пример: обход дерева, который всегда посещает левого и правого и никогда не проверяет null.

Рекурсия — метод писать алгоритм. Это не структура данных. Деревья подходят рекурсии, потому что каждое поддерево — меньшее дерево.

Итеративный цикл может заменить часть рекурсии. Используйте рекурсию, когда структура — дерево или когда форма меньшей задачи ясна. Используйте явный стек, когда стек вызовов слишком мал.

## Корень, лист, родитель, ребёнок, глубина, высота

**Дерево** — связное множество узлов без цикла. Один узел — **корень**. У каждого другого узла ровно один **родитель**.

**Ребёнок** узла u — узел, у которого u — родитель. У узла может быть ноль или больше детей.

**Лист** — узел без детей.

**Ребро** в дереве — связь родитель–ребёнок.

```text
        A          ← root
       / \
      B   C
     / \
    D   E          ← D and E and C are leaves
```

**Глубина** узла — число рёбер от корня до этого узла. У корня глубина 0.

**Высота** узла — число рёбер на самом длинном пути от этого узла вниз до листа. У листа высота 0.

**Высота дерева** — высота корня. На картинке height(A) = 2. Depth(D) = 2.

Некоторые тексты считают узлы на пути вместо рёбер. Тогда у корня глубина 1. Этот справочник считает **рёбра**. Пишите соглашение, когда читаете другую книгу.

**Путь** в дереве — последовательность различных узлов, которые следуют рёбрам. Между любыми двумя узлами ровно один путь.

**Лес** — множество деревьев. Если убрать корень, дети становятся корнями леса.

Не смешивайте глубину и высоту. Глубина измеряется от корня. Высота измеряется к листьям.

## Двоичное дерево

**Двоичное дерево** — дерево, где у каждого узла не больше двух детей. Дети имеют имена: **левый** и **правый**. Левый и правый различны. Узел только с правым ребёнком — не то же самое, что узел только с левым ребёнком.

```text
    10
   /  \
  4    15
        \
         18
```

Узел держит значение, левый указатель и правый указатель. Указатель null значит, что ребёнка нет.

**Обход двоичного дерева** использует рекурсию:

```text
walk(node):
  if node is null: return
  walk(node.left)
  visit node
  walk(node.right)
```

Позиция «visit» меняет порядок. Тема 8 называет in-order, pre-order и post-order. Этому разделу нужен только базовый случай null.

Максимальное число узлов на глубине d есть 2^d. Уровень 0 держит 1 узел. Уровень 1 держит не больше 2 узлов. Уровень 2 держит не больше 4 узлов.

Двоичное дерево — не двоичное дерево поиска, пока оно также не держит порядок ключей. Тема 8 добавляет это свойство.

Узел с тремя детьми — не узел двоичного дерева. Общее дерево может иметь много детей. Можно хранить детей в списке.

Пустое дерево значит, что указатель корня — null. Дерево из одного узла имеет корень, который также лист.

## Полное, совершенное, идеальное и сбалансированное (определения)

Эти слова описывают форму. Они не описывают порядок ключей.

**Полное (full)** двоичное дерево: у каждого узла 0 детей или 2 ребёнка. Ни у одного узла нет ровно одного ребёнка.

**Совершенное (complete)** двоичное дерево: каждый уровень полон, кроме возможно последнего. Последний уровень заполняется слева. Нет дыры слева от узла на последнем уровне.

**Идеальное (perfect)** двоичное дерево: каждый уровень полон. У каждого листа одна глубина. Идеальное дерево полное и совершенное.

**Сбалансированное** двоичное дерево (этот справочник): высота есть O(log n). Частое точное правило — **правило AVL**: для каждого узла высота левого поддерева и высота правого поддерева отличаются не больше чем на 1. Тема 9 использует это правило. Другие книги используют другие правила баланса. Пишите правило, которое используете.

```text
full, not complete:
      A
     / \
    B   C
       / \
      D   E

complete, not perfect:
      A
     / \
    B   C
   /
  D

perfect:
      A
     / \
    B   C
   / \ / \
  D  E F  G
```

Идеальное дерево высоты h имеет 2^(h+1) − 1 узлов. Высота считает рёбра.

Кучи (тема 10) нуждаются в совершенной форме, чтобы дерево помещалось в массив без дыр.

Деревьям поиска нужен баланс, чтобы высота оставалась логарифмической. Длинная линия узлов имеет высоту n − 1. Поиск тогда становится линейным.

Не говорите «сбалансированное», когда имеете в виду «идеальное». Совершенное дерево из n узлов почти сбалансировано, но проверяйте определение, которое используете.

Не говорите «полное», когда имеете в виду «идеальное». Полное только запрещает узлы с одним ребёнком.

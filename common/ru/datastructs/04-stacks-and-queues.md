# 4. Стеки и очереди

## Описание

Стек и очередь — абстрактные типы данных. Стек удаляет последний элемент, который вы вставили. Очередь удаляет первый элемент, который вы вставили. Эта тема объясняет реализации на массиве и на списке, кольцевые буферы, деки, стек вызовов и использование очереди в BFS и стека в DFS.

Завершите эту тему после массивов и связных списков.

Используйте один термин для каждого понятия. **LIFO** значит last in, first out. **FIFO** значит first in, first out. **Дек** — очередь с двумя концами. Вы вставляете и удаляете на обоих концах. **Кольцевой буфер** — фиксированный массив, который заворачивает индексы модулем. **Стек вызовов** — неявный стек, который язык использует для вызовов функций. **Явный стек** — стек, который вы храните в своих данных.

## Стек LIFO: массив против списка

**Стек** — ADT. Главные операции — **push** (вставка на верх), **pop** (удаление верха) и **peek** (чтение верха без удаления). Empty сообщает, держит ли стек ноль элементов.

LIFO — правило порядка. Последний push — первый pop.

```text
push 10, push 20, push 30
stack top → 30
            20
            10
pop → 30, now top is 20
```

**Реализация на массиве.** Храните элементы в динамическом массиве. Верх — последний индекс. Push — append. Pop удаляет последний элемент. Peek читает последний элемент. При геометрическом росте push амортизированно Θ(1). Pop и peek есть Θ(1). Локальность хорошая.

**Реализация на списке.** Храните элементы в односвязном списке. Верх — голова. Push вставляет в голову. Pop удаляет в голове. Peek читает голову. Каждая операция есть Θ(1). Локальность плохая. Каждый узел хранит указатель.

Обе реализации — стеки, если они выполняют одни и те же операции. Стоимости и локальность различаются.

Не делайте pop пустого стека. Определите ошибку или ясный пустой результат в ADT.

Стек не даёт get(i) для произвольного i в ADT. Если нужен доступ по индексу, вы выбрали неверный ADT.

## Очередь FIFO: кольцевой буфер против списка

**Очередь** — ADT. Главные операции — **enqueue** (вставка в конец), **dequeue** (удаление из начала) и **front** (чтение начала без удаления). Empty сообщает, держит ли очередь ноль элементов.

FIFO — правило порядка. Первый enqueue — первый dequeue.

```text
enqueue 10, enqueue 20, enqueue 30
front 10, then 20, then 30 at the back
dequeue → 10, now front is 20
```

**Реализация на списке.** Используйте односвязный список с головой и хвостом. Enqueue вставляет в хвост. Dequeue удаляет в голове. Оба есть Θ(1). Не делайте enqueue в голову и dequeue в хвосте. Удаление в хвосте есть Θ(n) в односвязном списке.

**Реализация на кольцевом буфере.** Используйте фиксированный массив ёмкости m. Храните индекс головы и длину, или индекс головы и индекс хвоста. Enqueue пишет по индексу хвоста, затем двигает хвост как (tail + 1) mod m. Dequeue читает по индексу головы, затем двигает голову как (head + 1) mod m.

```text
capacity 4
cells:  [10] [20] [  ] [  ]
head=0  tail=2  length=2

enqueue 30
cells:  [10] [20] [30] [  ]
head=0  tail=3

dequeue
cells:  [  ] [20] [30] [  ]
head=1  tail=3
```

Когда голова или хвост проходит последнюю ячейку, индекс заворачивается в 0. Это заворачивание и есть кольцо.

Полный кольцевой буфер не может сделать enqueue, пока вы не сделаете dequeue или не вырастете. Динамическое кольцо может выделить больший массив и скопировать в порядке очереди. Копия должна начинаться с головы, а не с ячейки 0, если живые элементы заворачиваются.

Очередь на массиве без кольца — плохой выбор по умолчанию. Dequeue по индексу 0 сдвигает все элементы. Этот dequeue есть Θ(n).

Не делайте dequeue пустой очереди. Определите ошибку в ADT.

## Дек

**Дек** (очередь с двумя концами) — ADT. Вы вставляете и удаляете в начале и в конце.

Типичные операции: push_front, push_back, pop_front, pop_back, peek_front, peek_back.

Дек может делать работу стека и работу очереди. Стек использует только один конец. Очередь использует два конца: один для вставки и один для удаления.

```text
deque:  front [10, 20, 30] back
push_front 5  →  [5, 10, 20, 30]
pop_back      →  [5, 10, 20]
```

**Реализация на двусвязном списке.** Вставка и удаление на обоих концах есть Θ(1), если вы храните голову и хвост или используете сентинелы.

**Реализация на кольцевом буфере.** Голова и хвост двигаются в обоих направлениях. Уменьшение использует (i − 1 + m) mod m. Все четыре операции на концах есть Θ(1), когда буфер не полон.

**Динамического массива только на одном конце недостаточно.** push_front на обычном динамическом массиве сдвигает все элементы. Эта стоимость есть Θ(n). Кольцо или блочный дек избегает этого сдвига.

Частый блочный дек хранит динамический массив блоков. Каждый блок — маленький массив. Этой теме нужна только идея: ADT — четыре операции на концах. Реализация должна сделать эти четыре операции дешёвыми.

Не смешивайте deque и dequeue. Dequeue — операция удаления очереди. Дек — имя ADT.

## Стек вызовов против явного стека

**Стек вызовов** — стек, который использует среда выполнения языка. Каждый **кадр вызова** держит адрес возврата, локальные переменные и аргументы одного вызова функции. Вызов кладёт кадр. Возврат снимает кадр.

Вы не называете этот стек в своей программе. Компилятор и среда выполнения управляют им. Рекурсия использует стек вызовов. Глубокая рекурсия может переполнить стек вызовов.

**Явный стек** — стек, который вы создаёте. Вы кладёте значения, которые выбираете. Вы снимаете их в своём коде. Тема 7 использует явный стек, чтобы обойти дерево без рекурсии. Тема 11 использует явный стек для DFS.

```text
function f calls g, g calls h
call stack (top is h):
  h frame
  g frame
  f frame

explicit stack in your data:
  you push node C
  you push node B
  you push node A
  pop → A
```

Два стека — одна идея ADT (LIFO). Они хранят разное. Стек вызовов хранит кадры. Явный стек хранит ваши элементы.

Хвостовой вызов может переиспользовать кадр в некоторых языках. Не предполагайте это переиспользование. Считайте глубину как один кадр на активный вызов, пока не измерили иное.

Преобразуйте рекурсию в цикл плюс явный стек, когда нужен контроль памяти или когда стек языка мал.

Не путайте стек вызовов со структурой данных стека в куче. У стека вызовов ограниченный размер, который задаёт ОС или среда выполнения.

## BFS использует очередь; DFS использует стек

**Поиск в ширину (BFS)** посещает вершины в порядке расстояния от старта, когда у каждого ребра длина 1. BFS использует **очередь**. Вы делаете enqueue соседей. Вы делаете dequeue следующей вершины для посещения. Порядок FIFO посещает слой 0, затем слой 1, затем слой 2.

**Поиск в глубину (DFS)** идёт как можно глубже по одному пути, затем возвращается. DFS использует **стек**. Рекурсия использует стек вызовов. Итеративный DFS использует явный стек.

```text
graph:
  A — B — D
  |
  C

BFS from A, queue: A, then B and C, then D
order can be: A, B, C, D

DFS from A, stack (or recursion): A, then B, then D, then back, then C
order can be: A, B, D, C
```

Порядок соседей может менять точный список посещения. Выбор ADT не меняется: BFS нужен FIFO. DFS нужен LIFO.

Не используйте стек для невзвешенного кратчайшего пути. Стек не посещает по расстоянию. Тема 11 даёт полные алгоритмы. Этот раздел только связывает ADT с двумя обходами.

Дек может реализовать оба, если вы используете его как очередь или как стек. Смысл идёт от того, какие концы вы используете.

Помечайте вершину, когда впервые кладёте её в структуру, или когда впервые достаёте её. Два момента пометки — не одно и то же. Тема 11 объясняет обычное правило для BFS: помечать при enqueue.

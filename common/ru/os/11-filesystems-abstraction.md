# 11. Файловые системы (абстракция)

## Описание

Файловая система — абстракция ОС для именованных постоянных данных. Эта тема объясняет файлы, каталоги и пути. Вы узнаете абсолютные и относительные пути, inode Unix, жёсткие ссылки и символические ссылки и биты разрешений. Вы также узнаете дескрипторы файлов и вызовы `open`, `read`, `write`, `close` и `lseek`.

Завершите эту тему после процессов и отображений памяти. Дескриптор файла живёт в процессе. Завершите эту тему до реализации файловой системы (тема 12). Эта тема остаётся на видимом пользователю интерфейсе.

Используйте один термин для каждого понятия. Файл — именованный inode с данными. Каталог — файл, который отображает имена на номера inode. Путь — строка имён. Дескриптор файла — целое в одном процессе. Жёсткая ссылка — другое имя того же inode. Символическая ссылка — маленький файл, который хранит путь. Не смешивайте путь с inode. Не смешивайте дескриптор файла с номером inode.

## Файл, каталог, путь

Файл — объект, который ОС именует и который программа читает или пишет. В Unix файл — не только документ. Каталог, узел устройства, сокет и именованный канал — файлы в смысле inode. Тип — поле inode.

Каталог — файл, который хранит список имён. Каждое имя указывает на номер inode. Ядро использует каталог, чтобы разрешить путь.

Путь — последовательность имён, которую ядро обходит. Имена разделены `/` в Unix. Путь `/home/ada/notes.txt` означает: начать с корневого каталога, затем `home`, затем `ada`, затем `notes.txt`.

Ядро не хранит полный путь внутри inode. Многие пути могут достичь одного inode (жёсткие ссылки). Inode хранит тип, биты разрешений, размер, метки времени и указатели на данные.

Пользовательские программы видят дерево. Дерево начинается с `/`. Монтирование может прикрепить другую файловую систему к каталогу. Тема 12 покрывает монтирования. Эта тема рассматривает одно дерево.

`.` — текущий каталог в пути. `..` — родительский каталог. У корня `..` — корень.

Не думайте о файле как о «байтах на одном секторе диска». Файл — inode плюс блоки данных плюс хотя бы одно имя в каталоге (кроме некоторых безымянных объектов).

## Абсолютные и относительные пути

Абсолютный путь начинается с `/`. Ядро начинает обход с корня процесса (корневой каталог, который `chroot` может сменить). Пример: `/etc/passwd`.

Относительный путь не начинается с `/`. Ядро начинает обход с текущего рабочего каталога (CWD) процесса. Пример: `notes.txt` или `../bin/app`.

CWD — состояние процесса. `chdir` его меняет. Потомок наследует CWD при `fork`. `exec` сохраняет CWD.

Один и тот же относительный путь может именовать два разных файла, если у двух процессов два CWD. Один и тот же абсолютный путь именует один файл (если корень тот же и ничего не гоняет).

Скрипты должны использовать абсолютные пути для системных файлов (`/etc`, `/usr`). Относительные пути правильны для файлов рядом с проектом пользователя. Программа, которая открывает `config.ini` без каталога, зависит от того, как пользователь её запустил. Эта зависимость — обычная ошибка.

`realpath` и `readlink -f` печатают канонический абсолютный путь, когда путь существует. Символические ссылки могут сделать канонический путь отличным от пути, который набрал пользователь.

`PATH` — не путь файловой системы файла. `PATH` — список каталогов, в которых оболочка ищет имя команды. Не смешивайте `PATH` с путём открытого файла.

## Inode (Unix)

Inode — объект ядра и файловой системы, который хранит метаданные файла. У каждого inode есть номер в этой файловой системе. `ls -i` и `stat` печатают номер.

Inode держит:

- тип файла (обычный, каталог, symlink, устройство, ...)
- биты разрешений и владельца
- счётчик ссылок (сколько жёстких ссылок)
- размер
- метки времени (доступ, смена, изменение — точные поля зависят от файловой системы)
- указатели на данные (или на экстенты; тема 12)

Inode не держит имя. Каталог держит имя и номер inode.

Команды:

```text
stat file
ls -i file
```

Два имени с одним устройством и одним номером inode — один файл (жёсткие ссылки). Два файла на двух файловых системах могут показать один номер inode. Пара (файловая система, номер inode) — личность.

Когда последняя жёсткая ссылка удалена и ни один процесс не держит файл открытым, файловая система может освободить inode и данные. Если процесс всё ещё держит файл открытым, данные могут остаться до `close`. Поэтому удалённый журнал всё ещё может расти.

`stat` против `lstat`: `lstat` не следует символической ссылке. `stat` следует ей и показывает целевой inode.

Тема 12 описывает, как ext4 хранит таблицу inode. Этому разделу нужна только абстракция.

## Жёсткая ссылка и символическая ссылка

Жёсткая ссылка — запись каталога, которая указывает на существующий inode на той же файловой системе. `ln file other` создаёт второе имя. Оба имени равны. В inode нет «оригинала». Счётчик ссылок растёт. `unlink` одного имени уменьшает счётчик.

Правила:

- нельзя сделать жёсткую ссылку на каталог в Linux (кроме `.` и `..`, которыми управляет файловая система)
- нельзя сделать жёсткую ссылку через файловые системы
- жёсткая ссылка работает после переименования другого имени

Символическая ссылка (symlink) — файл типа symlink. Данные этого файла — строка пути. `ln -s target name` её создаёт. Ядро следует строке, когда вы делаете `open` имени (если не используете `lstat` или `O_NOFOLLOW`).

Правила:

- symlink может указывать через файловые системы
- symlink может быть висячим (цели нет)
- symlink может образовать цикл; ядро останавливается после предела прыжков (`ELOOP`)
- `rm` symlink удаляет ссылку, а не цель

`ls -l` показывает `->` для symlink. `readlink` печатает сохранённый путь.

Используйте жёсткую ссылку, когда нужны два имени для одних данных на одной файловой системе. Используйте symlink, когда нужен указатель, который может пересекать монтирования или который можно перенацелить.

Не используйте symlink, когда запутанная программа может последовать ссылке, которую атакующий контролирует в `/tmp`. Это тема безопасности (гонки symlink). Предпочитайте `openat` и `O_NOFOLLOW` в осторожных программах.

## Разрешения: пользователь, группа, остальные; `chmod`, `chown`

Биты разрешений Unix сидят в inode. Есть три класса:

- пользователь (владелец)
- группа
- остальные (все остальные)

У каждого класса три бита: чтение `r`, запись `w`, исполнение `x`. `ls -l` показывает их как `rwxr-xr-x`. Первый символ — тип (`-` файл, `d` каталог, `l` symlink).

Для обычного файла:

- `r` позволяет `open` на чтение
- `w` позволяет менять данные
- `x` позволяет `exec` файла как программы

Для каталога:

- `r` позволяет перечислять имена
- `w` позволяет создавать и удалять имена (с дополнительными правилами)
- `x` позволяет пройти через каталог (поиск). Без `x` вы обычно не можете использовать файл внутри, даже если знаете имя

`chmod` меняет биты. Можно использовать восьмеричный (`chmod 644 file`) или символы (`chmod u+x file`).

`chown` меняет владельца и необязательно группу. Только root может сменить владельца в типичном Linux. `chgrp` меняет группу, когда у вас есть право.

У ядра также есть дополнительные биты: setuid, setgid и sticky bit. На каталоге sticky bit (`/tmp`) ограничивает, кто может удалять имена. Этот раздел требует, чтобы вы знали, что они существуют. Не ставьте setuid на учебные файлы.

В Linux также есть ACL и capabilities. Тема 17 покрывает больше изоляции. Девять битов `rwx` — база.

У процесса есть реальный идентификатор пользователя и эффективный идентификатор пользователя. Ядро использует эффективные ID для проверки разрешений. `sudo` меняет эффективного пользователя.

## Дескрипторы файлов

Дескриптор файла (FD) — маленькое целое, которое ссылается на описание открытого файла в ядре. Процесс держит таблицу FD. Первые три стандартных FD:

- `0` stdin
- `1` stdout
- `2` stderr

`open` возвращает следующий свободный FD (наименьший номер). `close` освобождает этот слот. После `close` этот номер может ссылаться на новое открытие.

FD — не номер inode. Два FD могут ссылаться на один inode. Один FD можно дублировать через `dup`, чтобы два номера ссылались на одно описание открытого файла. Эти два делят смещение файла.

Описание открытого файла — объект ядра. Оно держит смещение, режим доступа и указатель на inode (точнее на объект файла). `fork` копирует таблицу FD. Родитель и потомок делят одни описания открытых файлов для FD, которые были открыты при `fork`. `read` в потомке двигает смещение, которое также видит родитель.

`/proc/self/fd` — каталог символических ссылок от номеров FD к путям (когда ядро может показать путь). `ls -l /proc/self/fd` — практический вид.

Есть предел на процесс (`ulimit -n`) и системный предел. Утечка FD (`open` без `close`) упирается в предел.

Не путайте FD `1` с inode `1`. Это разные пространства.

## `open`, `read`, `write`, `close`, `lseek`

Эти пять вызовов — ядро интерфейса файлового ввода-вывода POSIX.

`open` или `openat` превращает путь в FD. Флаги включают `O_RDONLY`, `O_WRONLY`, `O_RDWR`, `O_CREAT`, `O_TRUNC`, `O_APPEND` и `O_CLOEXEC`. Всегда проверяйте `-1` и читайте `errno`. Когда передаёте `O_CREAT`, также передаёте режим (биты разрешений, изменённые `umask`).

`read` копирует до `n` байт из открытого файла в пользовательский буфер. Возвращаемое значение — число байт, `0` в конце файла или `-1` при ошибке. Короткое чтение разрешено. Цикл нужен, если нужны ровно `n` байт (кроме некоторых устройств).

`write` копирует байты из пользовательского буфера в файл. Короткая запись разрешена. Цикл нужен для точных счётчиков. `O_APPEND` заставляет каждую запись идти в текущий конец (атомарно относительно других писателей `O_APPEND` на обычных файлах, с задокументированными пределами).

`close` освобождает FD. Он не всегда сбрасывает хранилище на устройство. `fsync` — поздняя тема. `close` всё ещё может вернуть ошибку (например, отложенная ошибка записи). Проверяйте его в осторожных программах.

`lseek` меняет смещение описания открытого файла. `SEEK_SET`, `SEEK_CUR` и `SEEK_END` задают новую позицию. `lseek` не работает на всех типах FD (каналы, некоторые сокеты). Он возвращает новое смещение или `-1`.

```c
int fd = open("notes.txt", O_RDONLY);
if (fd < 0)
	return 1;
char buf[64];
ssize_t n = read(fd, buf, sizeof buf);
close(fd);
```

`stdio` (`fopen`, `fread`) использует эти вызовы внутри библиотеки C. Сначала изучите системные вызовы. Затем вы поймёте буферы и `fflush`.

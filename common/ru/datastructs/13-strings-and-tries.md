# 13. Строки и боры

## Описание

Строка — последовательность символов. Эта тема объясняет наивный поиск, идею Кнута–Морриса–Пратта (KMP), Рабина–Карпа, боры (деревья префиксов) и суффиксные массивы на высоком уровне.

Завершите эту тему после массивов, хеш-таблиц и деревьев.

Используйте один термин для каждого понятия. **Текст** T имеет длину n. **Образец** P имеет длину m. **Совпадение** — индекс i, где T[i .. i+m−1] равно P. **Бор** — дерево префиксов. **Суффиксный массив** — отсортированный список стартовых индексов суффиксов.

## Наивный поиск, KMP (идея), Рабин–Карп

**Наивный поиск** пробует P на каждом старте i от 0 до n − m. На каждом i он сравнивает символы до несовпадения или полного совпадения.

```text
T = A B A B C A B A B
P = A B A B
starts: 0 (match), 1 (fail), 2 (match), ...
```

Время худшего случая есть Θ((n − m + 1) m). Повторённая буква может заставить почти m сравнений почти на каждом i.

**KMP (идея).** KMP никогда не двигает указатель текста назад. После несовпадения он использует **таблицу префиксов** (функцию отказа) π. π[j] — длина самого длинного собственного префикса P[0 .. j], который также суффикс этой подстроки.

Когда T[i] ≠ P[j], KMP ставит j в π[j − 1] (с границей в 0) и пробует снова. Он не перезапускается в i = i+1 и j = 0, если префикс P уже совпал с суффиксом текста, который вы прочитали.

Время есть Θ(n + m) после построения π за Θ(m).

Полная реализация KMP в первом проходе не нужна. Нужна идея: предобработать P, переиспользовать совпавший префикс, просмотреть T один раз.

**Рабин–Карп** хеширует образец и хеширует каждое окно длины m в T. **Скользящий хеш** обновляет хеш окна за Θ(1), когда окно двигается на один символ.

```text
window hash at i+1 from hash at i
  drop T[i]
  add T[i+m]
  use a modulus and a base
```

Если хеши различаются, окно — не совпадение. Если хеши равны, сравните символы, чтобы подтвердить. Коллизия может сделать хеши равными, когда строки различаются.

Среднее время есть O(n + m) при хорошем хеше. Худший случай всё ещё Θ(n m), если каждое окно сталкивается и вы проверяете.

Рабин–Карп расширяется на несколько образцов множеством хешей образцов. KMP — для одного образца (Ахо–Корасик обобщает идею автомата).

Не пропускайте шаг проверки после попадания хеша, если хеш не определён как уникальный (например, большой отпечаток с принятым риском).

## Бор / дерево префиксов

**Бор** (дерево префиксов) хранит множество строк. Каждое ребро помечено символом. Путь от корня — префикс. Узел может помечать **конец слова**.

```text
words: can, cat, cot

        *
       /
      c
     / \
    a   o
   / \   \
  n   t   t
  $   $   $
```

**Вставка** идёт от корня. Она создаёт отсутствующего ребёнка для каждого следующего символа. Она помечает последний узел как конец.

**Поиск** идёт тем же путём. Если ребёнок отсутствует, слова нет. Если обход кончается без метки конца, строка — только префикс другого слова (или префикс, который вы никогда не вставляли как слово).

**Поиск префикса** идёт по префиксу, затем обходит поддерево, чтобы перечислить все слова с этим префиксом. Автодополнение использует этот обход.

Время вставки или поиска есть Θ(L), где L — длина строки. Оно не зависит от числа других слов, кроме как через память и ветвление.

Память может быть большой: один узел на символ всех уникальных префиксов. Алфавит размера σ даёт до σ указателей на детей на узел. Отображение из символа в ребёнка экономит память, когда алфавит велик.

Бор — не BST полных строк. Сравнение — по символу на ребре, не сравнение полной строки в узле (если вы не храните сжатое ребро).

**Сжатый бор** (radix / Patricia) сливает унарный путь в одно ребро, которое держит строку. Этому разделу нужна только несжатая идея.

Не храните одно слово дважды как два конца, если не хотите мультимножество слов.

Удаление не должно убирать узлы, которые всё ещё нужны другим словам. Удаление труднее вставки. Можно поставить end = false и оставить узлы, или обрезать неиспользуемые хвосты.

## Суффиксный массив (высокий уровень)

**Суффикс** T есть T[i .. n−1] для стартового индекса i.

**Суффиксный массив** SA — массив из n стартовых индексов, отсортированных по строке суффикса в этом индексе.

```text
T = banana
indexes: 0:banana  1:anana  2:nana  3:ana  4:na  5:a

sorted suffixes:
  a        → 5
  ana      → 3
  anana    → 1
  banana   → 0
  na       → 4
  nana     → 2

SA = [5, 3, 1, 0, 4, 2]
```

Вы не храните n полных строк суффиксов. Вы храните n целых. Сравнение двух суффиксов читает T с этих стартов.

**Найти образец.** Двоичный поиск на SA. Каждое сравнение mid — сравнение строк P с суффиксом T[SA[mid] ..]. Время есть O(m log n) сравнений, если каждое сравнение O(m). Лишние таблицы (LCP) могут ускорить это. Этой теме нужна только идея: отсортированные суффиксы, двоичный поиск.

**Наибольший общий префикс** двух суффиксов полезен для повторённых подстрок. **Массив LCP** хранит LCP SA[k] и SA[k−1]. Алгоритмы построения существуют. Считайте их поздним чтением.

**Суффиксное дерево** — сжатый бор всех суффиксов. Оно отвечает на те же вопросы с большей памятью и более сложным построением. Суффиксный массив — компактный родственник.

Наивное построение: создать n индексов, отсортировать полным сравнением строк. Время есть O(n² log n) в простой модели. Существуют линейные и n log n алгоритмы построения. Вам не нужно реализовывать линейный построитель в этой теме.

Не путайте суффиксный массив с префиксным бором словаря. Суффиксный массив индексирует один текст. Бор хранит много слов.

# 16. Ввод-вывод, файлы и сеть

## Описание

Эта тема показывает, как программы на Go читают байты, пишут байты и общаются по сети. Интерфейсы `io.Reader` и `io.Writer` — центр этого дизайна. Файлы, буферы, TCP, HTTP и TLS реализуют эти интерфейсы или потребляют их.

Для каждого понятия используйте один термин. Читатель производит байты. Писатель потребляет байты. Обработчик обслуживает HTTP-запрос. Шаблон в `ServeMux` (Go 1.22 и новее) сопоставляет метод и путь. Не игнорируйте ошибки вызовов ввода-вывода. Не держите файл или соединение открытым после окончания работы. Закройте ресурс, обычно через `defer`.

## Композиция `io.Reader` / `io.Writer`

У `io.Reader` один метод:

```go
type Reader interface {
    Read(p []byte) (n int, err error)
}
```

`Read` заполняет `p` не более чем `len(p)` байтами. Он возвращает число байтов и ошибку. `io.EOF` значит, что байтов больше нет. Один `Read` может вернуть `n > 0` и `io.EOF` в одном вызове. Сначала обработайте байты. Затем обработайте `EOF`.

У `io.Writer` один метод:

```go
type Writer interface {
    Write(p []byte) (n int, err error)
}
```

`Write` записывает `len(p)` байтов или возвращает ошибку. Проверяйте, что `n` равно `len(p)`, когда нужна полная запись. `io.ErrShortWrite` сообщает о короткой записи без более конкретной ошибки.

Читатели и писатели составляют. Вы оборачиваете одно значение другим значением. Обёртка тоже реализует `io.Reader` или `io.Writer`.

Полезные помощники в пакете `io`:

- `io.Copy(dst, src)` копирует из читателя в писатель до EOF
- `io.CopyN(dst, src, n)` копирует не более `n` байтов
- `io.LimitReader(r, n)` останавливается после `n` байтов
- `io.MultiReader(r1, r2, ...)` читает каждого читателя по порядку
- `io.MultiWriter(w1, w2, ...)` пишет те же байты в каждого писателя
- `io.TeeReader(r, w)` читает из `r` и пишет копию в `w`
- `io.NopCloser(r)` добавляет пустой `Close` к читателю
- `io.ReadAll(r)` читает все оставшиеся байты (следите за памятью)

```go
limited := io.LimitReader(file, 1024)
n, err := io.Copy(os.Stdout, limited)
```

`io.ReadCloser` и `io.WriteCloser` добавляют `Close()`. Тела HTTP и файлы — closers. Закрывайте их.

Предпочитайте `io.Reader` и `io.Writer` в параметрах функций. Принимайте интерфейс. Возвращайте конкретный тип, когда владеете реализацией. Это совпадает с правилом «принимайте интерфейсы, возвращайте структуры».

Не игнорируйте число байтов. Не считайте каждую ошибку фатальной, пока не использовали `n`. Не используйте `io.ReadAll` на неограниченном сетевом потоке. Используйте `io.LimitReader` или декодер, который останавливается.

`io.Pipe` создаёт связанную пару `PipeReader` и `PipeWriter`. Запись блокируется, пока чтение не потребит данные (с деталями внутренней буферизации). Используйте канал-трубу, когда одна горутина производит байты, а другая их потребляет.

## `bufio` для эффективного ввода-вывода

Сырой `Read` или `Write` на файле или сокете может делать один системный вызов на каждый вызов. Много малых вызовов медленны. Пакет `bufio` добавляет буфер памяти в процессе.

`bufio.Reader` оборачивает `io.Reader`. Он заполняет внутренний буфер из внутреннего читателя. `Read`, `ReadByte`, `ReadString` и `Peek` используют этот буфер.

`bufio.Writer` оборачивает `io.Writer`. `Write` кладёт байты в буфер. `Flush` пишет буфер во внутренний писатель. Нужно вызвать `Flush`, прежде чем данные понадобятся на другой стороне. Часто пишут `defer writer.Flush()`. Всё равно проверяйте ошибку `Flush`.

`bufio.Scanner` читает токены. Разбиение по умолчанию — по строкам. Scanner — простой инструмент для текста, ориентированного на строки.

```go
f, err := os.Open("data.txt")
if err != nil {
    return err
}
defer f.Close()

sc := bufio.NewScanner(f)
for sc.Scan() {
    line := sc.Text()
    _ = line
}
if err := sc.Err(); err != nil {
    return err
}
```

У Scanner есть максимальный размер токена по умолчанию (64 КиБ). Более длинная строка ломает сканирование. Поднимите предел через `sc.Buffer(buf, max)`, когда вы контролируете ввод. Не поднимайте предел для ненадёжного ввода без границы, которую вы принимаете.

`Peek` возвращает следующие байты, не убирая их из буфера. Используйте `Peek`, когда нужно посмотреть префикс (например, магическое число).

`bufio.NewReadWriter` держит читатель и писатель для двунаправленного потока, например TCP-соединения.

Правила:

- оборачивайте файл или сетевое соединение, когда делаете много малых чтений или записей
- не оборачивайте читатель, который уже полностью в памяти, если вам не нужны `Scanner` или `Peek`
- сбрасывайте писатели
- обрабатывайте `Scanner.Err`
- не разделяйте один `bufio.Reader` или `bufio.Writer` между горутинами без мьютекса

## Чтение и запись файлов, каталоги, права

Пакет `os` открывает файлы и каталоги. Пакет `path/filepath` строит пути для операционной системы. Пакет `io/fs` описывает дерево файлов только для чтения.

Откройте файл для чтения:

```go
f, err := os.Open(name)
if err != nil {
    return err
}
defer f.Close()
```

Создайте или обрежьте файл для записи:

```go
f, err := os.Create(name) // mode 0666 before umask
```

Откройте с полным контролем:

```go
f, err := os.OpenFile(name, os.O_RDWR|os.O_CREATE|os.O_EXCL, 0o600)
```

Флаги управляют созданием, дописыванием, обрезкой и исключительным созданием. Биты прав (`0o600`) применяются, когда функция создаёт файл. Umask процесса может сбросить биты. В Windows биты прав влияют меньше, чем в Unix.

Читайте малый файл через `os.ReadFile`. Пишите малый файл через `os.WriteFile`. Оба закрывают файл за вас. Не используйте их для огромных файлов.

```go
data, err := os.ReadFile("config.json")
err = os.WriteFile("out.txt", data, 0o644)
```

Каталоги:

- `os.Mkdir` создаёт один каталог
- `os.MkdirAll` создаёт полный путь
- `os.ReadDir` перечисляет каталог
- `os.Remove` удаляет файл или пустой каталог
- `os.RemoveAll` удаляет дерево
- `os.Rename` переименовывает или перемещает файл (не всегда атомарно между дисками)

`filepath.Join` соединяет элементы правильным разделителем. `filepath.Clean` убирает лишние разделители. `filepath.EvalSymlinks` разрешает ссылки. Для ненадёжных частей пути используйте `filepath.Join` с фиксированным корнем и проверьте, что результат остаётся под этим корнем. Go 1.24 добавляет `os.Root` для операций, которые остаются внутри каталога. Предпочитайте этот API, когда нужен изолированный корень.

Режимы файлов используют `fs.FileMode`. `info.IsDir()` сообщает о каталоге. `info.Mode().Perm()` сообщает биты прав.

Всегда закрывайте файлы. Пропущенное закрытие утекает дескрипторы. `defer f.Close()` — обычная форма. Если ошибка закрытия нужна при записи, назначьте `defer` именованному возврату или закройте явно после `Flush`.

Не стройте пути только через конкатенацию строк и `/`. Windows использует `\`. `filepath` обрабатывает оба варианта.

## TCP/UDP в пакете `net`

Пакет `net` даёт TCP и UDP. `net.Listen` принимает TCP-соединения. `net.Dial` открывает клиентское соединение. Оба возвращают `net.Conn`.

`net.Conn` реализует `io.Reader` и `io.Writer`. У него также есть `Close`, `SetDeadline`, `SetReadDeadline` и `SetWriteDeadline`.

```go
ln, err := net.Listen("tcp", "127.0.0.1:0") // :0 selects a free port
if err != nil {
    return err
}
defer ln.Close()

go func() {
    conn, err := ln.Accept()
    if err != nil {
        return
    }
    defer conn.Close()
    io.Copy(conn, conn) // echo
}()

addr := ln.Addr().String()
c, err := net.Dial("tcp", addr)
```

Для каждого `Accept` запускайте горутину, если обрабатываете соединения параллельно. Закрывайте соединение, когда обработчик заканчивает. Задавайте сроки, чтобы застрявший партнёр не блокировал горутину навсегда.

```go
conn.SetDeadline(time.Now().Add(10 * time.Second))
```

Срок действует на будущий ввод-вывод, пока вы его не измените. `SetReadDeadline` и `SetWriteDeadline` разделяют два направления.

UDP основан на датаграммах. `net.ListenPacket("udp", addr)` возвращает `net.PacketConn`. `ReadFrom` и `WriteTo` включают адрес партнёра. Цикла accept нет. Один сокет может говорить со многими партнёрами. UDP не гарантирует порядок и доставку.

```go
pc, err := net.ListenPacket("udp", "127.0.0.1:0")
n, addr, err := pc.ReadFrom(buf)
_, err = pc.WriteTo(buf[:n], addr)
```

Разрешайте адреса через `net.ResolveTCPAddr` или передавайте строку в `Dial` и `Listen`. Используйте `context` с `net.Dialer.DialContext`, чтобы отмена останавливала медленный набор.

`net.Pipe` создаёт пару соединений в памяти. Используйте её в тестах вместо реального порта, когда можно.

Не используйте пакет `io/ioutil`. Этот пакет устарел. Используйте `io` и `os`. Не слушайте `:80` в примерах, которые запускаете без прав. Используйте `127.0.0.1:0` или высокий порт.

## HTTP-серверы: `http.Handler`, `ServeMux` (шаблоны Go 1.22+)

`http.Handler` — серверный интерфейс:

```go
type Handler interface {
    ServeHTTP(ResponseWriter, *Request)
}
```

`http.HandlerFunc` превращает функцию в обработчик. `http.ResponseWriter` пишет заголовки и тело. `http.Request` держит метод, URL, заголовки, тело и контекст.

Go 1.22 расширил `http.ServeMux`. Шаблон может включать метод, хост и подстановки пути.

```go
mux := http.NewServeMux()
mux.HandleFunc("GET /health", health)
mux.HandleFunc("GET /items/{id}", getItem)
mux.HandleFunc("POST /items", createItem)
mux.HandleFunc("GET /files/{path...}", getFile)
```

Правила шаблонов:

- `GET /path` сопоставляет GET (и HEAD для шаблонов GET)
- `{name}` сопоставляет один сегмент пути
- `{name...}` сопоставляет остаток пути (включая слэши)
- `{$}` сопоставляет конец пути (`/{$}` — только `/`)
- более конкретный шаблон побеждает
- mux сообщает о конфликте, когда два шаблона неоднозначно пересекаются при регистрации

Читайте подстановку через `Request.PathValue`:

```go
func getItem(w http.ResponseWriter, r *http.Request) {
    id := r.PathValue("id")
    fmt.Fprintln(w, id)
}
```

`Request.SetPathValue` существует для других маршрутизаторов, которым нужен тот же API.

Запустите сервер:

```go
s := &http.Server{
    Addr:              "127.0.0.1:8080",
    Handler:           mux,
    ReadHeaderTimeout: 5 * time.Second,
}
err := s.ListenAndServe()
```

Задавайте тайм-ауты на сервере. Отсутствующий `ReadHeaderTimeout` — частый комментарий на ревью. Используйте `Server.Shutdown` с контекстом для корректной остановки (полный шаблон покрывают более поздние темы).

`http.NotFound`, `http.Error` и `http.Redirect` пишут обычные ответы. Пишите статус через `WriteHeader` до тела. Заголовок можно полезно записать только один раз: поздние вызовы `WriteHeader` статус не меняют.

Не используйте глобальный `http.DefaultServeMux` в библиотеке. Соберите свой mux и передайте его в `http.Server`. Глобальный mux легко использовать неправильно из-за неожиданных регистраций.

Go 1.22 по-прежнему принимает старые шаблоны вроде `/static/`. Эти шаблоны сохраняют поведение перенаправления со слэшем в конце. Для новых маршрутов предпочитайте явные шаблоны методов.

## Шаблон middleware

Middleware — функция, которая принимает `http.Handler` и возвращает `http.Handler`. Возвращённый обработчик выполняет код до и после `next.ServeHTTP`.

```go
func withLog(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        start := time.Now()
        next.ServeHTTP(w, r)
        log.Printf("%s %s %s", r.Method, r.URL.Path, time.Since(start))
    })
}
```

Middleware складывают снаружи:

```go
h := withLog(withAuth(mux))
```

Внешняя обёртка выполняется первой на входе. Она выполняется последней на выходе. Порядок важен. Ставьте восстановление после panic снаружи. Ставьте auth после логирования, если хотите логировать неудачный auth. Ставьте генерацию request-id рано, чтобы поздние обёртки могли прочитать id.

Обычные задачи middleware:

- логировать метод, путь, статус и длительность
- восстанавливаться после panic и писать статус 500
- требовать заголовок или cookie
- задавать тайм-аут через `http.TimeoutHandler` или контекст
- добавлять заголовки безопасности
- ограничивать размер тела запроса через `http.MaxBytesReader`

Чтобы записать код статуса, оберните `http.ResponseWriter`:

```go
type statusWriter struct {
    http.ResponseWriter
    code int
}

func (w *statusWriter) WriteHeader(code int) {
    w.code = code
    w.ResponseWriter.WriteHeader(code)
}
```

Если обработчик никогда не вызывает `WriteHeader`, `Write` отправляет статус 200. Ваша обёртка должна считать `code == 0` как 200 после возврата обработчика.

`http.TimeoutHandler` — стандартное middleware для лимита времени. `http.AllowQuerySemicolons` и другие адаптеры есть в `net/http`. Предпочитайте малые обёртки, которые можно тестировать через `httptest`.

Не кладите бизнес-правила, которые принадлежат одному маршруту, в глобальное middleware. Не проглатывайте ошибки без лога или метрики. Не держите мьютекс вокруг `next.ServeHTTP`, если не хотите сериализовать все запросы.

Передавайте значения через `context.WithValue` только для данных области запроса, например request id. Не используйте значения контекста для необязательных параметров функций в обычном коде. Тема 12 покрывает это правило.

## JSON API: декодирование, кодирование, проверка

Для JSON API используйте `encoding/json`. Декодируйте тело запроса через `json.NewDecoder(r.Body)`. Кодируйте ответ через `json.NewEncoder(w)`.

```go
type CreateItem struct {
    Name string `json:"name"`
    Qty  int    `json:"qty"`
}

func createItem(w http.ResponseWriter, r *http.Request) {
    defer r.Body.Close()
    r.Body = http.MaxBytesReader(w, r.Body, 1<<20)

    var in CreateItem
    dec := json.NewDecoder(r.Body)
    dec.DisallowUnknownFields()
    if err := dec.Decode(&in); err != nil {
        http.Error(w, "invalid json", http.StatusBadRequest)
        return
    }
    if err := dec.Decode(&struct{}{}); err != io.EOF {
        http.Error(w, "invalid json", http.StatusBadRequest)
        return
    }
    if in.Name == "" || in.Qty < 1 {
        http.Error(w, "invalid fields", http.StatusBadRequest)
        return
    }

    w.Header().Set("Content-Type", "application/json")
    w.WriteHeader(http.StatusCreated)
    _ = json.NewEncoder(w).Encode(map[string]string{"name": in.Name})
}
```

`Decoder` читает из потока. `json.Unmarshal` читает полный `[]byte`. Предпочитайте `Decoder` для тел HTTP. Предпочитайте `Encoder` для ответов HTTP. `Encoder` добавляет завершающий перевод строки. Клиенты это принимают.

`DisallowUnknownFields` отклоняет лишние ключи. Второй `Decode`, который должен вернуть `io.EOF`, отклоняет тело с двумя JSON-значениями. Обе проверки помогают отклонять неаккуратный ввод.

Проверка — не свойство JSON. После декодирования проверяйте поля в Go. Используйте дополнительные типы (`uuid`, `time.Time` с пользовательским форматом), когда их требует предметная область. Теги структур называют ключи JSON. Экспортируемые поля участвуют в кодировании и декодировании. Неэкспортируемые поля — нет.

`json.Number` и `Decoder.UseNumber` сохраняют большие числа как строки. Декодирование числа в `any` по умолчанию использует `float64` и может потерять точность целого.

Go 1.24 добавляет `omitzero` для некоторых случаев пропуска нулевых значений. `omitempty` по-прежнему пропускает пустые значения, как определено в документации пакета. Читайте текущую документацию `encoding/json` для тега, который используете.

Не декодируйте в `map[string]any`, когда схема стабильна. Структура документирует API. Не доверяйте данным клиента. Задавайте `Content-Type` при успехе. Пишите тело проблемы со стабильной формой для ошибок, когда строите настоящий API.

## WebSocket (обзор; `gorilla/websocket` или `nhooyr.io/websocket`)

WebSocket — постоянный двунаправленный канал, который начинается как HTTP-запрос. Клиент отправляет запрос Upgrade. Сервер переключает протокол, если принимает. После рукопожатия обе стороны отправляют сообщения: текст, двоичные данные и управляющие кадры (ping, pong, close).

Стандартная библиотека Go не даёт полной реализации WebSocket для приложений. Используют библиотеку.

`github.com/gorilla/websocket` — широко используемая библиотека. Она повышает протокол через `Upgrader.Upgrade`. Она читает и пишет сообщения через `ReadMessage` и `WriteMessage`. Нужно запускать один цикл чтения. Нельзя писать из двух горутин без мьютекса. Проект документирует эту модель конкурентности.

```go
var upgrader = websocket.Upgrader{
    CheckOrigin: func(r *http.Request) bool { return true }, // do not use this in production
}

func echo(w http.ResponseWriter, r *http.Request) {
    c, err := upgrader.Upgrade(w, r, nil)
    if err != nil {
        return
    }
    defer c.Close()
    for {
        mt, msg, err := c.ReadMessage()
        if err != nil {
            break
        }
        if err := c.WriteMessage(mt, msg); err != nil {
            break
        }
    }
}
```

`nhooyr.io/websocket` — старый путь модуля. Этот модуль устарел. Новый код должен использовать `github.com/coder/websocket`. Модуль Coder — поддерживаемое продолжение. У него первоклассная поддержка `context.Context` и помощники в `websocket/wsjson`.

```go
c, err := websocket.Accept(w, r, nil)
defer c.CloseNow()
_, data, err := c.Read(r.Context())
err = c.Write(r.Context(), websocket.MessageText, data)
```

Общие правила для обеих библиотек:

- считайте рукопожатие HTTP; проверяйте origin, auth и метод до повышения
- не ставьте `CheckOrigin` всегда в true на публичном сервере
- используйте TLS (`wss:`) в публичной сети
- закрывайте с кодом закрытия, когда можете
- применяйте обратное давление; не разрешайте неограниченные очереди исходящих сообщений
- отменяйте контекст, когда HTTP-запрос заканчивается

Используйте WebSocket для живых обновлений, совместных редакторов и игр. Не используйте WebSocket, когда хватает одного HTTP-запроса или короткого опроса. Балансировщики и прокси должны разрешать путь Upgrade.

Этот справочник остаётся обзорным. Перед выпуском нужно прочитать документацию выбранной библиотеки про периоды ping и коды закрытия.

## Основы TLS в `crypto/tls`

TLS шифрует TCP-соединение и аутентифицирует сервер (и при необходимости клиент). HTTPS — это HTTP поверх TLS. `wss` — WebSocket поверх TLS.

Пакет `crypto/tls` реализует TLS. `http.Server.ListenAndServeTLS` его использует. Можно также обернуть `net.Listener`:

```go
cert, err := tls.LoadX509KeyPair("cert.pem", "key.pem")
cfg := &tls.Config{
    Certificates: []tls.Certificate{cert},
    MinVersion:   tls.VersionTLS12,
}
ln, err := tls.Listen("tcp", "127.0.0.1:8443", cfg)
```

`tls.Config` — управляющий тип. Важные поля:

- `Certificates` — сертификаты сервера
- `GetCertificate` — выбрать сертификат по Server Name Indication (SNI)
- `ClientCAs` и `ClientAuth` — аутентификация клиентским сертификатом
- `RootCAs` — дополнительные корни доверия для клиента
- `MinVersion` — отказывать старым версиям протокола
- `NextProtos` — ALPN, например `h2` и `http/1.1`

Не ставьте `InsecureSkipVerify` в true, кроме локального эксперимента. Этот флаг пропускает проверки сертификата сервера. Публичный клиент должен проверять имя сервера и цепочку.

Для HTTP:

```go
err := http.ListenAndServeTLS(":8443", "cert.pem", "key.pem", mux)
```

Или задайте `Server.TLSConfig` и вызовите `ListenAndServeTLS`.

Локальная разработка использует самоподписанный сертификат. Браузеры и клиенты `net/http` отклоняют его, пока вы не добавите сертификат в пул доверия или (только в тесте) не используете пользовательские `RootCAs`. Инструменты вроде `mkcert` устанавливают локальный CA. Не коммитьте закрытый ключ в публичный репозиторий.

`crypto/tls` также даёт `tls.Dial` и `tls.Dialer` для клиентов. `http.Client` использует TLS для URL `https`. Можно задать `http.Transport.TLSClientConfig`.

Предпочитайте TLS 1.2 как минимум. Предпочитайте TLS 1.3, когда обе стороны его поддерживают (рукопожатие его выбирает). Не изобретайте свою криптографию поверх сырого TCP, когда TLS уже решает задачу.

Сертификаты истекают. Автоматизируйте продление (например ACME). Эта тема требует только API Go и идеи сертификата плюс закрытый ключ.

2. Задайте `MinVersion: tls.VersionTLS12`. Задокументируйте, как тестировать клиента, который предлагает только более старую версию (опишите установку; запускать старый TLS не нужно, если набор инструментов его блокирует).
3. Добавьте перенаправления HTTPS или HSTS только как письменный план из трёх шагов. Не включайте HSTS на хосте, которым не управляете.

#### Сложные практические задания

1. Настройте необязательные клиентские сертификаты (`tls.RequestClientCert` или `RequireAndVerifyClientCert`). Задокументируйте хранилище доверия (`ClientCAs`).
2. Оберните сырой TCP echo-сервер в `tls.Listen` и клиент `tls.Dial`. Повторно используйте протокол echo из раздела TCP. Запишите дополнительные файлы и поля конфигурации, которые понадобились.

## Обзор темы

Эти вопросы не повторяют вопросы из разделов выше. Они охватывают всю тему.

### Вопросы

#### Теоретические вопросы

1. Опишите путь байтов из файла через `bufio` и `io.Copy` в TCP-соединение. Назовите каждый интерфейс.
2. Как шаблоны `ServeMux` Go 1.22 и middleware работают вместе на одном сервере?
3. Какие проверки применяют к телу JSON-запроса, прежде чем доверять полям?
4. Как TLS, HTTP и WebSocket связаны на одном прослушиваемом порту?
5. Коллега хочет игнорировать ошибки ввода-вывода, пропускать `Flush`, принимать каждый origin WebSocket и отключать проверку TLS. Какие факты из этой темы вы используете на ревью?

#### Простые практические задания

1. Создайте модуль `example.com/iox`. Добавьте команду копирования файла, сервер `GET /health` и обработчик эха JSON. Запустите тесты через `httptest`.
2. Напишите одностраничную шпаргалку: `io.Copy`, `LimitReader`, `bufio.Scanner`, флаги `os.OpenFile`, `PathValue`, сигнатура middleware, `DisallowUnknownFields`, повышение WebSocket, `MinVersion`.
3. Используйте `curl` или `http.Get` против `httptest.NewServer` для `GET /health`. Сохраните статус и тело.
4. Нарисуйте диаграмму последовательности: клиент, TLS, HTTP-обработчик, декодирование JSON.

#### Практические задания среднего уровня

1. Соберите `GET /files/{name}`, который читает файл из фиксированного каталога. Отклоняйте имена, которые выходят из каталога. Возвращайте ошибки JSON.
2. Добавьте middleware логирования и лимит тела 1 МиБ к обработчику JSON `POST /items`. Напишите три случая `httptest`.
3. Напишите TCP-клиент, который отправляет один JSON-объект, и сервер, который декодирует его через `json.Decoder` на соединении.

#### Сложные практические задания

1. Соберите небольшой HTTPS JSON API с mux Go 1.22, middleware и маршрутом WebSocket на `GET /ws`. Используйте самоподписанный сертификат в тестах. Задокументируйте, как клиент браузера будет ему доверять.
2. Нагрузочно протестируйте обработчик, который использует `bufio`, против обработчика, который пишет малые куски без буфера. Сообщите времена и вывод. Оставьте TLS выключенным для локального теста, если нужна более простая установка. Укажите, что продакшен всё равно использует TLS.

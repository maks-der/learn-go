# 3. SQL в PostgreSQL

## Описание

Эта тема показывает базовый SQL в PostgreSQL 16 и PostgreSQL 17. Вы пишете `SELECT`, `INSERT`, `UPDATE` и `DELETE`. Узнаёте вывод типов, неявные приведения и `RETURNING`. Также узнаёте `LIMIT`, `OFFSET`, `FETCH`, `LIKE`, `ILIKE` и доллар-квотирование.

Сначала завершите темы 1 и 2. Нужно подключение и схема, где можно создавать таблицы. Завершите эту тему до глубокого изучения типов.

Используйте один термин для каждого понятия. Оператор — одна SQL-команда. Приведение меняет значение с одного типа на другой. Неявное приведение — то, которое вы не пишете. Доллар-квотирование — способ записать строку без экранирования кавычек.

## `SELECT` / `INSERT` / `UPDATE` / `DELETE`

Эти четыре оператора — команды данных. `SELECT` читает строки. `INSERT` добавляет строки. `UPDATE` меняет строки. `DELETE` удаляет строки.

Создайте учебную таблицу:

```sql
CREATE TABLE items (
    id   integer PRIMARY KEY,
    name text NOT NULL,
    qty  integer NOT NULL DEFAULT 0
);
```

Вставка строк:

```sql
INSERT INTO items (id, name, qty) VALUES (1, 'nail', 100);
INSERT INTO items (id, name, qty)
VALUES
    (2, 'screw', 50),
    (3, 'bolt', 25);
```

Выборка строк:

```sql
SELECT id, name, qty
FROM items
WHERE qty > 10
ORDER BY name;
```

Обновление строк:

```sql
UPDATE items
SET qty = qty + 5
WHERE name = 'nail';
```

Удаление строк:

```sql
DELETE FROM items
WHERE id = 3;
```

Правила:

- `WHERE` ограничивает `UPDATE` и `DELETE`. `UPDATE` без `WHERE` меняет каждую строку. `DELETE` без `WHERE` удаляет каждую строку.
- `INSERT` должен удовлетворять ограничениям. Тема 5 разбирает ограничения.
- `SELECT` без `FROM` допустим. Пример: `SELECT 1 + 1;`.
- PostgreSQL использует параметры стиля `$1` в клиентских API. В `psql` пишете литералы. Не склеивайте пользовательский текст в SQL. В программах используйте параметры.

`INSERT ... SELECT` копирует из запроса:

```sql
INSERT INTO items (id, name, qty)
SELECT id + 100, name, qty FROM items WHERE qty < 10;
```

`UPDATE` может использовать `FROM` для соединения с другими таблицами. `DELETE` может использовать `USING`. Эти формы учите после соединений в теме 6.

PostgreSQL не требует `FROM DUAL`. Для выражений используйте `SELECT` без `FROM`.

## Вывод типов PostgreSQL и неявные приведения (осторожно)

У каждого типа есть функция ввода и функция вывода. `psql` показывает форму вывода. Хранимое значение может отличаться от текста, который вы видите.

Примеры:

```sql
SELECT 1;
SELECT 1.0;
SELECT DATE '2026-09-13';
SELECT TIMESTAMP '2026-09-13 12:00:00';
SELECT 'hello';
```

Нетипизированный строковый литерал имеет тип `unknown`, пока PostgreSQL не назначит тип. Контекст решает тип:

```sql
SELECT '2026-09-13';              -- text-like unknown
SELECT '2026-09-13'::date;        -- explicit date
SELECT DATE '2026-09-13';         -- typed literal
```

Неявное приведение — то, которое вы не пишете. PostgreSQL добавляет его, когда приведение помечено как implicit в каталогах. Пример: `integer` во многих выражениях может повышаться до `bigint` или `numeric`.

Осторожные случаи:

- `'1' = 1` может сработать, потому что PostgreSQL приводит unknown или text. Не полагайтесь на это в прикладном SQL. Для целочисленного столбца пишите `1`.
- `UNION` выбирает общий тип. Смешанные `integer` и `numeric` становятся `numeric`.
- Списки `IN` и ветки `CASE` следуют правилам разрешения типов. Несовпадение даёт ошибку или приведение, которого вы не ждали.
- Вывод `char(n)` дополняется пробелами. Сравнение с `text` может удивить. Предпочитайте `text` или `varchar`.
- `timestamp` и `timestamptz` — разные типы. Неявное преобразование использует `TimeZone` сессии. Тема 4 разбирает эту пару.

Пишите явное приведение, когда тип важен:

```sql
SELECT '42'::integer;
SELECT CAST('42' AS integer);
```

Посмотреть приведение:

```sql
SELECT pg_typeof(1), pg_typeof(1.0), pg_typeof('x');
```

`pg_typeof` показывает разрешённый тип. Используйте его, когда запрос падает с ошибкой типа.

Не отключайте проверки типов. Не храните числа как `text`, чтобы избежать приведений.

## `RETURNING`

`RETURNING` — расширение PostgreSQL. Оно возвращает строки из `INSERT`, `UPDATE` или `DELETE` в том же операторе. Второй `SELECT` не нужен.

```sql
INSERT INTO items (id, name, qty)
VALUES (4, 'washer', 80)
RETURNING id, name;

UPDATE items
SET qty = qty - 1
WHERE id = 4
RETURNING id, qty;

DELETE FROM items
WHERE id = 4
RETURNING *;
```

`RETURNING *` возвращает каждый столбец затронутой строки. После `UPDATE` значения новые. После `DELETE` значения старые.

Используйте `RETURNING`, чтобы получить сгенерированный ключ:

```sql
CREATE TABLE notes (
    id   integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    body text NOT NULL
);

INSERT INTO notes (body)
VALUES ('hello')
RETURNING id;
```

Тема 5 разбирает столбцы identity. Клиентские драйверы читают возвращённую строку через `Query` или `QueryRow`, не только `Exec`.

`RETURNING` может вычислять выражения:

```sql
UPDATE items
SET qty = qty + 10
WHERE id = 1
RETURNING id, qty, qty * 2 AS qty_double;
```

`WITH` может использовать результат `RETURNING` как CTE. Тема 6 разбирает `WITH`.

Не запускайте отдельный `SELECT` по тому же ключу, если `RETURNING` уже дал строку. Не считайте, что `RETURNING` есть в каждой другой SQL-базе.

## `LIMIT` / `OFFSET` и `FETCH`

`LIMIT` ограничивает, сколько строк возвращает запрос. `OFFSET` пропускает строки. PostgreSQL применяет сначала `OFFSET`, затем `LIMIT`, после `ORDER BY`.

```sql
SELECT id, name
FROM items
ORDER BY id
LIMIT 10;

SELECT id, name
FROM items
ORDER BY id
LIMIT 10 OFFSET 20;
```

Всегда используйте `ORDER BY` вместе с `LIMIT` и `OFFSET`. Без `ORDER BY` набор строк — не стабильная страница.

`FETCH` — форма стандарта SQL:

```sql
SELECT id, name
FROM items
ORDER BY id
FETCH FIRST 10 ROWS ONLY;

SELECT id, name
FROM items
ORDER BY id
OFFSET 20
FETCH NEXT 10 ROWS ONLY;
```

`FETCH FIRST 10 ROWS ONLY` совпадает с `LIMIT 10`. Можно писать `ROW` или `ROWS`. Можно писать `FIRST` или `NEXT`.

`LIMIT ALL` значит без ограничения. `OFFSET 0` ничего не пропускает.

Проблемы большого `OFFSET`:

- Сервер всё равно читает и сортирует пропущенные строки.
- Страница 1000 медленнее страницы 1.
- Конкурентные вставки меняют страницы.

Тема 19 разбирает пагинацию по ключу (`WHERE id > $1 ORDER BY id LIMIT 10`). Для больших списков предпочитайте пагинацию по ключу.

`FETCH` также встречается у курсоров (`FETCH FORWARD`). Это другая команда. Этот раздел имеет в виду предложение `SELECT`.

## `ILIKE` против `LIKE`

`LIKE` сопоставляет строку с шаблоном. `%` совпадает с любой длиной. `_` совпадает с одним символом.

```sql
SELECT name FROM items WHERE name LIKE 'n%';
SELECT name FROM items WHERE name LIKE '_olt';
```

`LIKE` чувствителен к регистру при обычных collation. `nail` не совпадает с `LIKE 'N%'`.

`ILIKE` — форма PostgreSQL без учёта регистра:

```sql
SELECT name FROM items WHERE name ILIKE 'N%';
```

`ILIKE` нет в стандарте SQL. Другие базы используют `UPPER` и `LIKE` или отдельный collation.

Экранируйте литеральный `%` или `_` через `ESCAPE`:

```sql
SELECT name FROM items WHERE name LIKE '%\%%' ESCAPE '\';
```

Можно писать `NOT LIKE` и `NOT ILIKE`.

Локаль и collation влияют на `ILIKE`. У некоторых локалей особые правила регистра. Для стабильного столбца без учёта регистра команды часто используют `citext` (тема 13) или хранят нормализованную копию.

`LIKE 'abc%'` может использовать индекс B-tree. `LIKE '%abc'` не может использовать обычный индекс B-tree. Тема 8 разбирает индексы. Тема 7 разбирает `SIMILAR TO` и POSIX-регулярные выражения.

Не используйте `LIKE '%' || user_input || '%'` без плана по производительности и по символам шаблона во вводе.

`~~` — оператор для `LIKE`. `~~*` — оператор для `ILIKE`. В прикладном SQL предпочитайте ключевые слова.

## Доллар-квотирование `$tag$ ... $tag$`

Обычная строка использует одинарные кавычки. Кавычка внутри строки становится двумя кавычками:

```sql
SELECT 'it''s a nail';
```

Доллар-квотирование пишет строку между совпадающими тегами:

```sql
SELECT $$it's a nail$$;
SELECT $body$it's a nail$body$;
```

Форма: `$tag$` + текст + `$tag$`. Тег необязателен. `$$` допустим. Тег — буквы и цифры. Тег чувствителен к регистру.

Используйте доллар-квотирование для:

- тел функций (тема 13)
- длинного SQL в блоках `DO`
- строк с множеством кавычек
- динамического SQL, который содержит кавычки

Пример тела функции:

```sql
CREATE FUNCTION add_one(i integer)
RETURNS integer
LANGUAGE sql
AS $fn$
    SELECT i + 1;
$fn$;
```

Тело — строка. Доллар-теги избегают наслоения кавычек.

Правила:

- Закрывающий тег должен совпадать с открывающим.
- Текст может содержать `$other$`, если `other` — не тот же тег.
- Доллар-квотирование не раскрывает последовательности вроде `E'\n'`. Переводы строк остаются переводами строк.
- Не смешивайте `$$` во вложенных строках, когда внутренняя тоже использует `$$`. Используйте именованный тег.

Интерполяция переменных `psql` всё равно действует вне правил, которые вы задали. В скриптах предпочитайте явные теги.

Доллар-квотирование — возможность PostgreSQL. Другие базы могут его не принимать.

### Вопросы

#### Теоретические вопросы

1. Опишите один `INSERT`, который использует доллар-квотирование в столбце `text` и возвращает новый `id`.
2. Почему неявные приведения плюс `LIMIT` без `ORDER BY` делают постраничный API небезопасным?
3. Когда выбирать `ILIKE` вместо `LOWER(col) LIKE LOWER(pattern)`?
4. Чем `RETURNING` и поздний `SELECT` отличаются при конкурентном `UPDATE` той же строки?
5. Чем типизированный литерал даты отличается от unknown-строки, которая выглядит как дата?

#### Простые практические задания

1. Создайте таблицу, вставьте две строки одним оператором, обновите одну строку с `RETURNING` и выберите через `LIKE`.
2. Напишите шпаргалку: четыре оператора данных, `RETURNING`, `LIMIT`/`FETCH`, `LIKE`/`ILIKE`, доллар-квотирование.
3. Постраничьте отсортированный список через `FETCH FIRST 3 ROWS ONLY` и через `OFFSET`.
4. Используйте `pg_typeof` на столбце `RETURNING` из `INSERT` строки в столбец `text`.

#### Средние практические задания

1. Напишите скрипт `psql`, который создаёт таблицу, загружает пять строк, показывает `ILIKE` и печатает `RETURNING` из `DELETE`.
2. Найдите несовпадение типов в предложении `WHERE`. Исправьте явным приведением. `EXPLAIN` не требуется; покажите два текста SQL.
3. Задокументируйте десять правил безопасного SQL в PostgreSQL для коллеги-новичка (параметры, `WHERE`, `ORDER BY`, приведения).

#### Сложные практические задания

1. Соберите маленькую процедуру пагинации: размер страницы и номер страницы как аргументы в блоке `DO` или SQL-функции. Используйте `LIMIT` и `OFFSET`. Затем напишите вторую версию с ключом.
2. Прочитайте страницы Reference для `INSERT`, `UPDATE` и `SELECT`. Перечислите три предложения, которых эта тема не покрыла. Напишите по одному предложению на каждое.

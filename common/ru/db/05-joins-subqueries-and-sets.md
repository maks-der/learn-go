# 5. Соединения, подзапросы и множества

## Описание

Эта тема показывает, как комбинировать строки из больше чем одной таблицы. Вы изучаете внутренние соединения, внешние соединения, декартовы соединения и самосоединения. Вы также изучаете операторы множеств и подзапросы.

Используйте один термин для каждого понятия. Соединение сопоставляет строки двух таблиц по условию. Оператор множества складывает два результата запроса. Подзапрос — запрос внутри другого оператора. Завершите эту тему до группировки строк.

Квалифицируйте имена столбцов, когда две таблицы делят имя. Используйте псевдонимы таблиц.

## Внутреннее соединение

Внутреннее соединение возвращает строки, которые совпадают по условию соединения. Строка без совпадения не появляется.

```sql
SELECT o.order_id, c.name, o.ordered_at
FROM orders AS o
INNER JOIN customers AS c
    ON o.customer_id = c.customer_id;
```

`INNER JOIN` в стандартном SQL то же самое, что `JOIN`. Пока учитесь, пишите `INNER JOIN`. Слово ясно.

Предложение `ON` — правило совпадения. Большинство соединений сопоставляют внешний ключ с первичным ключом. Это обычный и безопасный шаблон.

Если у клиента три заказа, в результате три строки. Имя клиента повторяется. Это повторение верно. Зерно результата — заказ, не клиент.

Если у заказа есть `customer_id`, которого нет, внутреннее соединение отбрасывает этот заказ. Внешний ключ должен предотвращать этот случай. Если видите отброшенные заказы, проверьте данные и условие соединения.

```text
customers          orders
id  name           id  customer_id
1   Ada            10  1
2   Alan           11  1
                   12  2

INNER JOIN on customer_id
→ (10, Ada), (11, Ada), (12, Alan)
```

Не опускайте предложение `ON`. Соединение без условия в некоторых диалектах становится декартовым. Этот результат — взрыв строк.

Не соединяйте по неверному столбцу. `ON o.order_id = c.customer_id` может выполниться и всё равно быть бессмысленным. Проверяйте имена.

## Левое, правое и полное внешнее соединение

Внешнее соединение оставляет несовпавшие строки с одной или обеих сторон. Столбцы стороны без совпадения — `NULL`.

**Левое внешнее соединение.** Оставить каждую строку левой таблицы. Добавить совпадающие строки правой таблицы. Когда совпадения нет, столбцы справа — `NULL`.

```sql
SELECT c.customer_id, c.name, o.order_id
FROM customers AS c
LEFT OUTER JOIN orders AS o
    ON o.customer_id = c.customer_id;
```

Клиент без заказов всё равно появляется. `order_id` для этой строки — `NULL`.

**Правое внешнее соединение.** Оставить каждую строку правой таблицы. Это левое соединение с переставленными таблицами. Предпочитайте `LEFT OUTER JOIN` и пишите нужную таблицу слева. Команды легче читают левые соединения.

**Полное внешнее соединение.** Оставить несовпавшие строки с обеих сторон. Клиент без заказов появляется. Заказ без клиента появляется. Многие продукты поддерживают `FULL OUTER JOIN`. Некоторые нет. Проверьте свою СУБД.

```sql
SELECT c.customer_id, o.order_id
FROM customers AS c
FULL OUTER JOIN orders AS o
    ON o.customer_id = c.customer_id;
```

`LEFT JOIN` — обычная короткая форма `LEFT OUTER JOIN`. Пока учитесь, пишите `OUTER`, если это помогает.

Фильтр в `WHERE` по столбцу справа может превратить левое соединение во внутреннее.

```sql
SELECT c.name, o.order_id
FROM customers AS c
LEFT OUTER JOIN orders AS o
    ON o.customer_id = c.customer_id
WHERE o.ordered_at >= DATE '2026-01-01';
```

Строки с `o.ordered_at` `NULL` не проходят этот `WHERE`. Клиенты без заказов исчезают. Фильтры по необязательной таблице ставьте в предложение `ON`, когда нужно сохранить несовпавшие левые строки.

```sql
LEFT OUTER JOIN orders AS o
    ON o.customer_id = c.customer_id
   AND o.ordered_at >= DATE '2026-01-01';
```

## Декартово соединение и самосоединение

Декартово соединение спаривает каждую строку одной таблицы с каждой строкой другой. Размер результата — произведение двух размеров.

```sql
SELECT c.name, p.name AS product_name
FROM customers AS c
CROSS JOIN products AS p;
```

Если 100 клиентов и 500 товаров, в результате 50000 строк. Каждая пара — строка.

Декартово соединение верно, когда нужна полная комбинация. Пример: каждый размер в таблице `sizes` с каждым цветом в таблице `colors`, чтобы построить сетку каталога.

Декартово соединение — ошибка, когда вы имели в виду внутреннее соединение и забыли `ON`. Некоторые старые синтаксисы делают это легко:

```sql
SELECT *
FROM orders, customers;
```

Эта форма — декартово соединение. Позже `WHERE orders.customer_id = customers.customer_id` превращает его во внутреннее. Если забыть `WHERE`, клиент возвращает огромную сетку. Используйте `INNER JOIN ... ON`, чтобы совпадение было обязательным.

Не используйте декартово соединение, чтобы «посмотреть, совпадёт ли что-то» на больших таблицах. СУБД может построить огромный промежуточный результат.

Тестируйте декартово соединение только на маленьких справочных таблицах. Отмените запрос, если число строк неожиданно.

```text
sizes: S, M
colors: red, blue
CROSS JOIN → (S,red), (S,blue), (M,red), (M,blue)
```

Самосоединение — соединение таблицы с собой. Вы используете два псевдонима. Каждый псевдоним — одна роль.

Пример. Сотрудники с руководителем в той же таблице:

```sql
SELECT e.name AS employee_name, m.name AS manager_name
FROM employees AS e
INNER JOIN employees AS m
    ON e.manager_id = m.employee_id;
```

`e` — сотрудник. `m` — руководитель. Соединение сопоставляет внешний ключ `manager_id` с `employee_id`.

Левое самосоединение оставляет сотрудников без руководителя (верхний человек):

```sql
SELECT e.name AS employee_name, m.name AS manager_name
FROM employees AS e
LEFT OUTER JOIN employees AS m
    ON e.manager_id = m.employee_id;
```

Таблицу нужно псевдонимить дважды. Без псевдонимов СУБД не отличит две роли.

Не стройте в голове цикл как рекурсивный обход, пока не используете рекурсивный запрос. Одно самосоединение проходит один шаг (сотрудник к руководителю). Полная цепочка нуждается в больше соединениях или рекурсивном общем табличном выражении.

```text
employees
id  name   manager_id
1   Ada    NULL
2   Alan   1
3   Grace  1

self-join → (Alan, Ada), (Grace, Ada)
left self-join also → (Ada, NULL)
```

## `UNION`, `UNION ALL`, `INTERSECT`, `EXCEPT`

Операторы множеств комбинируют два результата запроса. У каждого запроса должно быть одно число столбцов. Типы должны быть совместимы. Имена столбцов берутся из первого запроса.

**`UNION`.** Сложить строки. Удалить дубликаты.

**`UNION ALL`.** Сложить строки. Оставить дубликаты.

```sql
SELECT name FROM staff
UNION
SELECT name FROM contractors;
```

```sql
SELECT name FROM staff
UNION ALL
SELECT name FROM contractors;
```

Если `Ada` появляется в обеих таблицах, `UNION` возвращает одну `Ada`. `UNION ALL` возвращает две.

**`INTERSECT`.** Вернуть строки, которые появляются в обоих результатах.

**`EXCEPT`.** Вернуть строки первого результата, которых нет во втором. Некоторые продукты используют `MINUS` для этой идеи. Предпочитайте `EXCEPT`, когда продукт его имеет.

```sql
SELECT customer_id FROM orders
INTERSECT
SELECT customer_id FROM newsletter;

SELECT customer_id FROM customers
EXCEPT
SELECT customer_id FROM banned_customers;
```

Операторы множеств сравнивают полные строки. `SELECT a, b UNION SELECT a, b` использует оба столбца.

Используйте `UNION ALL`, когда знаете, что множества не пересекаются, или когда нужно оставить дубликаты. `UNION` сортирует или хеширует, чтобы удалить дубликаты. Эта лишняя работа имеет цену.

Обе стороны должны значить одно зерно. Не объединяйте список клиентов со списком заказов, если хотите только мешок id и помечаете источник.

```sql
SELECT customer_id, 'order' AS source
FROM orders
UNION ALL
SELECT customer_id, 'newsletter' AS source
FROM newsletter;
```

Не каждый продукт реализует `INTERSECT` и `EXCEPT`. Смотрите руководство. Часть этих идей можно выразить соединениями и `EXISTS`.

## Подзапросы: скалярный, `IN`, `EXISTS`

Подзапрос — `SELECT` внутри другого оператора. Скобки оборачивают его.

**Скалярный подзапрос.** Подзапрос возвращает один столбец и не больше одной строки. Его можно использовать в списке `SELECT` или в сравнении.

```sql
SELECT name,
       (SELECT COUNT(*) FROM orders AS o WHERE o.customer_id = c.customer_id) AS order_count
FROM customers AS c;
```

Если скалярный подзапрос возвращает две строки, оператор падает. Если не возвращает строку, значение — `NULL`.

**Подзапрос `IN`.** Внешняя строка совпадает, когда значение равно одному значению из подзапроса.

```sql
SELECT name
FROM customers
WHERE customer_id IN (
    SELECT customer_id
    FROM orders
    WHERE ordered_at >= DATE '2026-01-01'
);
```

**Подзапрос `EXISTS`.** Внешняя строка совпадает, когда подзапрос возвращает хотя бы одну строку. Обычно коррелируют: внутренний запрос ссылается на внешнюю строку.

```sql
SELECT c.name
FROM customers AS c
WHERE EXISTS (
    SELECT 1
    FROM orders AS o
    WHERE o.customer_id = c.customer_id
);
```

`EXISTS` останавливается, когда находит одну строку. `SELECT 1` — обычный фиктивный список. Столбцы не важны.

`NOT EXISTS` находит внешние строки без совпадающей внутренней строки. Эта форма — ясный способ найти клиентов без заказов.

```sql
SELECT c.name
FROM customers AS c
WHERE NOT EXISTS (
    SELECT 1
    FROM orders AS o
    WHERE o.customer_id = c.customer_id
);
```

Предпочитайте `EXISTS` вместо `IN`, когда внутренний запрос может вернуть `NULL` в ловушке `NOT IN`. Предпочитайте соединение, когда нужны столбцы из обеих таблиц в результате. Предпочитайте подзапрос, когда только фильтруете.

Коррелированный подзапрос ссылается на внешний запрос. Некоррелированный не ссылается. СУБД может выполнить некоррелированный подзапрос один раз.

5. Коллега пишет `FROM a, b` и забывает `WHERE`. Какое соединение он написал и в чём исправление?

#### Простые практические задания

1. Напишите шпаргалку: внутреннее, левое, правое, полное, декартово, самосоединение, операторы множеств, виды подзапросов.
2. Выполните одно внутреннее и одно левое соединение на учебных таблицах.
3. Выполните `UNION ALL` двух списков id.
4. Выполните `EXISTS`, чтобы проверить, что у клиента есть хотя бы один заказ.

#### Средние практические задания

1. Постройте отчёт: имя каждого клиента, id заказа или `NULL`, имена товаров через второе соединение. Укажите зерно.
2. Найдите неиспользуемые товары левым соединением и через `NOT EXISTS`. Подтвердите те же id.
3. Самосоедините маленькую иерархию или запрос пар в одном городе.

#### Сложные практические задания

1. Напишите переносимое «клиенты в A не в B» тремя способами: `EXCEPT`, `NOT EXISTS`, левое соединение плюс `IS NULL`. Выполните формы, которые позволяет СУБД.
2. Спроектируйте отчёт из трёх таблиц с одним внешним и одним внутренним соединением. Задокументируйте, почему каждый тип соединения нужен.

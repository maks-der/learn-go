# 2. Массивы и динамические массивы

## Описание

Массив — непрерывный блок элементов одного типа. Динамический массив — массив, который может расти. Эта тема объясняет массивы фиксированного размера, индексацию за константное время, вставку и удаление в середине, границы, раскладки по строкам и по столбцам, рост, амортизированный append, длину и ёмкость.

Завершите эту тему после основ. Завершите эту тему до изучения связных списков.

Используйте один термин для каждого понятия. **Длина** — число элементов в использовании. **Индекс** — целочисленная позиция. Этот справочник использует 0 как первый индекс. **Буфер** — блок памяти. **Ёмкость** — число элементов, которое буфер может держать. **Append** добавляет один элемент в конец. **Resize** выделяет новый буфер и копирует живые элементы.

## Массив фиксированного размера и индексация O(1)

**Массив фиксированного размера** имеет длину, которую вы задаёте при создании массива. Длина не растёт. Длина не сжимается.

Элементы лежат в непрерывной памяти. У каждого элемента один и тот же размер. Программа может вычислить адрес индекса i от начального адреса.

```text
array a of length 4
index:  0    1    2    3
value:  10   20   30   40
```

**Индексация** — операция, которая читает или пишет элемент по индексу i.

Адрес элемента i:

```text
address(i) = start + i * element_size
```

Формула использует умножение и сложение. Формула не обходит первые i элементов. Время есть Θ(1). Время не растёт с n. Время не растёт с i.

Эта индексация за константное время — главная причина использовать массив. У связного списка нет этой формулы. Обход списка есть Θ(i), чтобы дойти до индекса i.

Массив фиксированного размера прост. Вы используете его, когда знаете n. Вы используете его для маленькой таблицы. Вы используете его как внутренний буфер динамического массива.

Нельзя сделать append за пределами длины. Нужно создать новый массив, если нужна другая длина. Скопируйте элементы, которые вы сохраняете.

## Вставка и удаление в середине

**Вставка по индексу i** кладёт новый элемент в i. Элементы от i до старого конца должны сдвинуться на одну ячейку вправо. Этот сдвиг есть Θ(n − i). В худшем случае вы вставляете по индексу 0. Сдвиг есть Θ(n).

**Удаление по индексу i** убирает элемент в i. Элементы от i + 1 до конца должны сдвинуться на одну ячейку влево. Этот сдвиг тоже Θ(n − i). Удаление по индексу 0 есть Θ(n).

```text
array:  10  20  30  40
insert 25 at index 2
shift:  30 and 40 move right
result: 10  20  25  30  40

delete index 1 (value 20)
shift:  25, 30, 40 move left
result: 10  25  30  40
```

Вставка и удаление в конце не сдвигают большой блок. Append пишет одну ячейку. Удаление последнего элемента уменьшает длину. Эти операции есть Θ(1) на фиксированном массиве, в котором ещё есть место, или на динамическом массиве, который не делает resize.

Поиск по значению — просмотр. Просмотр есть Θ(n) в худшем случае. После того как вы нашли индекс, удаление всё равно сдвигает.

Не говорите «вставка в массив медленная» без позиции. Вставка в конец дешёвая, когда есть место. Вставка в начало дорогая.

Дыра в середине не разрешена, если вы хотите, чтобы формула адреса оставалась простой. После удаления живые элементы остаются непрерывными от 0 до length − 1.

## Границы, по строкам и по столбцам

Допустимый индекс i удовлетворяет 0 ≤ i ≤ length − 1. Индекс вне этого диапазона — доступ **за границами**.

Доступ за границами — дефект. Некоторые языки останавливают программу. Некоторые языки не проверяют и пишут в неверную ячейку. Не используйте индекс, который вы не проверили.

```text
length = 4
valid indexes: 0, 1, 2, 3
invalid:       -1, 4, 99
```

**Двумерный массив** хранит таблицу строк и столбцов. Память машины всё равно одна линия ячеек. Нужно выбрать порядок.

Порядок **по строкам (row-major)** хранит полную строку, затем следующую строку. Элемент (r, c) лежит в:

```text
index = r * number_of_columns + c
```

Порядок **по столбцам (column-major)** хранит полный столбец, затем следующий столбец. Элемент (r, c) лежит в:

```text
index = c * number_of_rows + r
```

```text
table 2 rows × 3 columns
values:
  A B C
  D E F

row-major block:    A B C D E F
column-major block: A D B E C F
```

Обходите в том же порядке, что и раскладка, если нужна хорошая локальность. Обход по строкам хорош в раскладке по строкам. Обход по столбцам хорош в раскладке по столбцам.

Границы действуют для каждого измерения. Допустимой паре (r, c) нужны 0 ≤ r < rows и 0 ≤ c < columns.

Не смешивайте два порядка, когда передаёте блок другому компоненту. Запишите порядок в контракте.

## Стратегия роста и амортизированный append

Динамический массив начинает с ёмкости 0 или малого числа. Когда вы делаете append и длина равна ёмкости, структура полна. Программа выделяет больший буфер.

Частая **стратегия роста** — умножить ёмкость на 2. Некоторые библиотеки используют 1.5. Точный множитель может меняться. Идея — **геометрический рост**: каждая новая ёмкость — постоянный множитель от старой ёмкости.

```text
append when full
  new_capacity = max(1, old_capacity * 2)
  allocate new buffer
  copy length elements
  append the new element
```

Рост на +1 — другая стратегия. Каждый полный append копирует все n элементов. Общая стоимость копий для n append около 1 + 2 + ... + n. Эта сумма есть Θ(n²). Не используйте рост на +1 для общего динамического массива.

Геометрический рост держит общую стоимость копий линейной по n. Большинство операций append пишут одну ячейку и добавляют 1 к длине. Эти append есть Θ(1). Когда буфер полон, append делает resize. Resize копирует length элементов. Этот append есть Θ(n).

При удвоении копирования происходят при размерах 1, 2, 4, ..., n. Сумма этих копий меньше 2n. Амортизированная стоимость одного append есть Θ(1).

Библиотека может выбрать первую ёмкость 1, 4 или 8. Малая первая ёмкость экономит память для пустых списков. Большая первая ёмкость может сократить первые несколько resize.

Некоторые библиотеки сжимают буфер, когда длина становится намного меньше ёмкости. Сжатие необязательно. Сжатие может снова копировать. Не сжимайте при каждом удалении. Частый правило — сжимать только когда длина — малая доля ёмкости.

## Длина и ёмкость

**Длина** — число живых элементов. Живые элементы лежат в индексах 0 .. length − 1.

**Ёмкость** — число ячеек в буфере. Ёмкость всегда больше или равна длине.

```text
buffer:   10  20  30  ??  ??
length:   3
capacity: 5
live:     indexes 0, 1, 2
unused:   indexes 3, 4
```

Неиспользуемые ячейки — лишняя память. Они делают следующие append дешёвыми. Они используют память.

Не обходите дальше длины. Неиспользуемые ячейки могут держать старые значения. Эти значения не часть коллекции.

После resize длина остаётся той же, пока вы не сделаете append. Ёмкость становится размером нового буфера. После append длина увеличивается на 1.

У массива фиксированного размера длина равна ёмкости. В контракте нет неиспользуемой ячейки. Динамический массив разделяет эти два числа.

Когда вы сообщаете размер пользователю, вы сообщаете длину. Когда вы планируете память, вы смотрите на ёмкость.

Очистка или сброс могут поставить длину в 0 и сохранить буфер. Следующие append используют ёмкость снова. Это повторное использование избегает нового выделения.

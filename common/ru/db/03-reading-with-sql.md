# 3. Чтение с SQL

## Описание

SQL — язык, которым вы читаете реляционные данные. Эта тема показывает `SELECT`, фильтры, сортировку, лимит, различные строки и псевдонимы. Вы изучаете проекцию и селекцию как две разные операции.

Используйте один термин для каждого понятия. Запрос — оператор `SELECT`. Проекция выбирает столбцы. Селекция выбирает строки. Завершите эту тему до соединений и агрегатов.

Пишите SQL, нейтральный к вендорам. Некоторые продукты используют `LIMIT`. Стандарт SQL также использует `FETCH FIRST`. Оба появляются в этой теме. Не смешивайте диалекты в одном операторе.

---

## Что такое SQL

SQL — декларативный язык. Вы указываете результат, который хотите. Вы не указываете алгоритм сканирования. СУБД выбирает путь доступа.

SQL покрывает больше, чем запросы. У языка есть части:

- запрос данных: `SELECT`
- изменение данных: `INSERT`, `UPDATE`, `DELETE`
- схема: `CREATE`, `ALTER`, `DROP`
- транзакция: `BEGIN`, `COMMIT`, `ROLLBACK`

Эта тема покрывает запрос. Позже темы покрывают остальные части.

Декларативный оператор называет таблицы, столбцы и условия. Пример:

```sql
SELECT name, email
FROM customers
WHERE email IS NOT NULL;
```

Вы не пишете цикл. Вы не пишете «открой файл». СУБД находит строки.

SQL — стандарт (ISO/IEC). Продукты расширяют стандарт. Сначала изучайте стандартные формы. Смотрите руководство продукта, когда оператор падает.

Не собирайте SQL конкатенацией пользовательского текста. В программах используйте параметры. Этот путь показывает литералы в примерах только для обучения.

SQL — не общий язык программирования. В ядре языка ограниченное управление потоком. Держите циклы приложения в приложении. Держите операции над множествами в SQL.

## `SELECT`, `FROM`, `WHERE`

Базовый запрос имеет три предложения.

`FROM` называет таблицу (или таблицы), которую вы читаете. СУБД начинает с этой таблицы.

`SELECT` называет столбцы, которые вы возвращаете. Можно использовать `*`, чтобы вернуть все столбцы. Используйте `*` только для исследования. В сохранённых запросах называйте столбцы.

`WHERE` оставляет строки, которые удовлетворяют условию. Строки, которые не проходят условие, не появляются.

```sql
SELECT customer_id, name
FROM customers
WHERE name = 'Ada';
```

Идея вычисления (логическая):

1. Начните со строк в `FROM`.
2. Оставьте строки, которые совпадают с `WHERE`.
3. Верните столбцы в `SELECT`.

Продукт может использовать другой физический порядок. Результат должен совпадать с этим смыслом.

`WHERE` необязателен. Без `WHERE` запрос возвращает каждую строку. Результат может быть большим. Добавляйте фильтр, когда тестируете на реальных данных.

```sql
SELECT *
FROM customers;
```

В большинстве клиентов заканчивайте оператор точкой с запятой. Некоторые клиенты шлют один оператор за раз и не требуют её. В скриптах используйте точку с запятой.

Не ставьте фильтр по псевдониму столбца в `WHERE`, если продукт это не позволяет. В стандартном SQL `WHERE` применяется до псевдонимов списка `SELECT`. В `WHERE` используйте имя столбца.

## Проекция и селекция

Проекция и селекция — две операции. Не смешивайте слова.

**Проекция** выбирает атрибуты (столбцы). `SELECT name, email` — проекция. В результате меньше столбцов. Число строк может остаться тем же.

**Селекция** выбирает кортежи (строки). `WHERE price > 10` — селекция. В результате меньше строк. Число столбцов может остаться тем же.

Типичный запрос делает оба:

```sql
SELECT name, price
FROM products
WHERE price > 10;
```

Этот запрос выбирает строки с `price > 10`. Он проецирует `name` и `price`.

В математике селекция использует условие на отношении. Проекция использует список атрибутов. SQL использует `WHERE` для селекции и список `SELECT` для проекции. Ключевое слово `SELECT` — не то же самое, что слово *селекция*. Это столкновение путает новичков. Запомните: список `SELECT` = проекция. `WHERE` = селекция.

```text
products (all columns, all rows)
    | selection: price > 10
    v
fewer rows, all columns
    | projection: name, price
    v
fewer rows, two columns
```

Не называйте `WHERE` проекцией. Не называйте список столбцов селекцией.

## `ORDER BY`, `LIMIT` / `FETCH`, `DISTINCT`

У отношения нет порядка. `ORDER BY` даёт порядок результату. Вы называете столбцы или выражения. Используйте `ASC` для возрастания (по умолчанию). Используйте `DESC` для убывания.

```sql
SELECT name, price
FROM products
ORDER BY price DESC, name ASC;
```

Строки сортируются по `price` от высокого к низкому. Строки с одной ценой сортируются по `name`.

Всегда используйте `ORDER BY`, когда пользователь должен видеть стабильный порядок. Без `ORDER BY` СУБД может вернуть любой порядок. Этот порядок может измениться после обновления или после смены индекса.

`LIMIT` оставляет первые *n* строк отсортированного результата. Многие продукты поддерживают `LIMIT`. Форма стандарта SQL — `FETCH FIRST`.

```sql
SELECT name, price
FROM products
ORDER BY price DESC
FETCH FIRST 5 ROWS ONLY;
```

```sql
SELECT name, price
FROM products
ORDER BY price DESC
LIMIT 5;
```

Используйте `ORDER BY` вместе с `LIMIT` или `FETCH`. Лимит без порядка — не результат «топ 5». Это любые пять строк.

Некоторые продукты используют `TOP (5)` в списке `SELECT`. Эта форма не стандартна. Предпочитайте `FETCH FIRST` или `LIMIT` продукта в одном диалекте.

Не используйте `LIMIT` вместо правильного `WHERE`. Лимит прячет строки. Он не определяет бизнес-множество.

`DISTINCT` удаляет дубликаты строк из результата. СУБД сравнивает полную выбранную строку. Две строки, которые совпадают в каждом выбранном столбце, становятся одной строкой.

```sql
SELECT DISTINCT city
FROM customers;
```

Этот запрос перечисляет каждый город один раз. Много клиентов могут жить в одном городе.

Без `DISTINCT` запрос возвращает один город на строку клиента.

Используйте `DISTINCT`, когда вопрос про уникальные комбинации. Не используйте `DISTINCT`, чтобы спрятать плохое соединение, которое размножило строки. Сначала исправьте соединение.

`SELECT DISTINCT a, b` считает пару строкой. `(Paris, 10)` и `(Paris, 11)` остаются двумя строками.

`DISTINCT` может быть дорогим на большом результате. Предпочитайте правильный `WHERE` и правильное соединение. Добавляйте `DISTINCT`, когда уникальный список — настоящий вопрос.

Некоторые продукты позволяют `DISTINCT ON`. Эта форма не стандартна. Не используйте её на этом пути.

## Сравнение, `AND` / `OR` / `NOT`, `IN`, `BETWEEN`, `LIKE`, `IS NULL`

`WHERE` использует предикаты. Предикат истинен, ложен или неизвестен (`NULL`).

Операторы сравнения:

- `=` равно
- `<>` не равно (также `!=` во многих продуктах)
- `<` меньше
- `>` больше
- `<=` меньше или равно
- `>=` больше или равно

Комбинируйте предикаты через `AND`, `OR` и `NOT`.

```sql
SELECT product_id, name, price
FROM products
WHERE price >= 10
  AND price < 50;
```

`AND` требует, чтобы обе стороны были истинны. `OR` требует, чтобы одна сторона была истинна. `NOT` инвертирует предикат.

Пишите скобки, когда смешиваете `AND` и `OR`. В SQL `AND` связывается сильнее, чем `OR`. Не полагайтесь на память. Пишите скобки.

```sql
SELECT *
FROM products
WHERE (category = 'book' OR category = 'map')
  AND price < 20;
```

Сравнение с `NULL` неизвестно, не истинно. `WHERE price = NULL` не возвращает строку. Используйте `IS NULL`.

В стандартном SQL для «не равно» используйте `<>`. Проверьте, что продукт принимает `<>`.

**`IN`.** Значение равно одному элементу списка.

```sql
SELECT *
FROM products
WHERE category IN ('book', 'map', 'card');
```

Эта форма совпадает с `OR` равенств. В `IN` может появиться подзапрос (позже тема).

**`BETWEEN`.** Значение лежит в замкнутом диапазоне. `x BETWEEN a AND b` значит `x >= a AND x <= b`. Оба конца включены. Для меток времени пара `>=` и `<` часто безопаснее.

**`LIKE`.** Значение совпадает с текстовым шаблоном. `%` значит любую строку. `_` значит один символ.

```sql
SELECT *
FROM customers
WHERE email LIKE '%@example.com';
```

`LIKE` чувствителен к регистру в одних продуктах и нет в других. Проверьте свою СУБД. Не используйте `LIKE '%x%'` на больших таблицах как первый план. Этот шаблон может заставить широкое сканирование.

**`IS NULL` и `IS NOT NULL`.** Проверяйте отсутствующие значения.

```sql
SELECT *
FROM orders
WHERE shipped_at IS NULL;
```

Не пишите `= NULL` или `<> NULL`. Эти предикаты неизвестны.

`NOT IN` со списком, который содержит `NULL`, — ловушка. Результат может быть пустым. Позже предпочитайте `NOT EXISTS` или держите `NULL` вне списка.

## Псевдонимы

Псевдоним — временное имя в запросе. Вы даёте псевдоним столбцу или таблице. Псевдоним существует только для этого оператора.

Псевдонимы столбцов называют выходные столбцы. Для ясности используйте `AS`.

```sql
SELECT name AS product_name, price AS unit_price
FROM products;
```

Заголовки результата — `product_name` и `unit_price`. Столбцы таблицы остаются `name` и `price`.

Псевдонимы таблиц сокращают имена и готовят соединения.

```sql
SELECT c.customer_id, c.name
FROM customers AS c
WHERE c.name = 'Ada';
```

`c` — псевдоним для `customers`. После задания псевдонима во многих продуктах используйте его для столбцов. Будьте последовательны.

Используйте псевдонимы, когда имена длинные или когда соединяете одну таблицу дважды (самосоединение в позже теме). Используйте короткие имена, которые всё ещё что-то значат (`c` для customers, `o` для orders). Не используйте `t1`, `t2`, когда можно использовать букву, которая совпадает с таблицей.

Некоторые продукты позволяют опустить `AS`. На этом пути пишите `AS`. Лишнее слово ясно.

Не ссылайтесь на псевдоним столбца в `WHERE` в стандартном SQL. Повторите выражение или используйте подзапрос. Некоторые продукты позволяют псевдоним в `ORDER BY`. Проверьте `ORDER BY product_name` на своей СУБД.

```sql
SELECT price * qty AS line_total
FROM order_lines
ORDER BY line_total;
```

Если `ORDER BY line_total` падает, пишите `ORDER BY price * qty`.

### Вопросы

#### Теоретические вопросы

1. Опишите логический путь запроса, который фильтрует, проецирует, сортирует и ограничивает.
2. Как проекция и селекция появляются в одном `SELECT`, который также использует `DISTINCT`?
3. Когда выбирают `IN`, `BETWEEN`, `LIKE` или `IS NULL`?
4. Почему SQL декларативен, даже когда вы добавляете `ORDER BY` и `FETCH`?
5. Коллега пишет `WHERE alias_name = 1` и `LIMIT 5` без `ORDER BY`. Какие две проблемы вы называете?

#### Простые практические задания

1. Напишите шпаргалку: `SELECT`, `FROM`, `WHERE`, `ORDER BY`, `FETCH`/`LIMIT`, `DISTINCT`, предикаты, псевдонимы.

# 4. Основы SQL

## Описание

SQL — язык, которым вы читаете реляционные данные. Эта тема показывает `SELECT`, фильтры, сортировку, ограничение и псевдонимы. Вы изучаете проекцию и селекцию как две разные операции.

Используйте один термин для каждого понятия. Запрос — оператор `SELECT`. Проекция выбирает столбцы. Селекция выбирает строки. Завершите эту тему до соединений и агрегатов.

Пишите SQL, нейтральный к вендорам. Некоторые продукты используют `LIMIT`. Стандарт SQL также использует `FETCH FIRST`. Оба появляются в этой теме. Не смешивайте диалекты в одном операторе.

## Что такое SQL (декларативный язык запросов)

SQL — декларативный язык. Вы указываете результат, который хотите. Вы не указываете алгоритм сканирования. СУБД выбирает путь доступа. Тема 11 показывает, как читать этот выбор.

SQL покрывает больше, чем запросы. У языка есть части:

- запрос данных: `SELECT`
- изменение данных: `INSERT`, `UPDATE`, `DELETE`
- схема: `CREATE`, `ALTER`, `DROP`
- транзакция: `BEGIN`, `COMMIT`, `ROLLBACK`

Эта тема покрывает запрос. Поздние темы покрывают остальные части.

Декларативный оператор называет таблицы, столбцы и условия. Пример:

```sql
SELECT name, email
FROM customers
WHERE email IS NOT NULL;
```

Вы не пишете цикл. Вы не пишете «открой файл». СУБД находит строки.

SQL — стандарт (ISO/IEC). Продукты расширяют стандарт. Сначала изучайте стандартные формы. Проверяйте руководство продукта, когда оператор падает.

Не собирайте SQL конкатенацией пользовательского текста. Используйте параметры в программах. Этот путь показывает литеральные значения в примерах только для обучения.

SQL не общий язык программирования. В ядре языка ограниченное управление потоком. Держите циклы приложения в приложении. Держите операции над множествами в SQL.

## `SELECT`, `FROM`, `WHERE`

Базовый запрос имеет три предложения.

`FROM` называет таблицу (или таблицы), которую вы читаете. СУБД начинает с этой таблицы.

`SELECT` называет столбцы, которые вы возвращаете. Можно использовать `*`, чтобы вернуть все столбцы. Используйте `*` только для исследования. Называйте столбцы в сохранённых запросах.

`WHERE` оставляет строки, которые удовлетворяют условию. Строки, которые не проходят условие, не появляются.

```sql
SELECT customer_id, name
FROM customers
WHERE name = 'Ada';
```

Идея вычисления (логическая):

1. Начните со строк в `FROM`.
2. Оставьте строки, которые совпадают с `WHERE`.
3. Верните столбцы в `SELECT`.

Продукт может использовать другой физический порядок. Результат должен совпадать с этим смыслом.

`WHERE` необязателен. Без `WHERE` запрос возвращает каждую строку. Этот результат может быть большим. Добавляйте фильтр, когда тестируете на реальных данных.

```sql
SELECT *
FROM customers;
```

Используйте точку с запятой, чтобы закончить оператор в большинстве клиентов. Некоторые клиенты шлют один оператор за раз и не нуждаются в ней. Используйте точку с запятой в скриптах.

Не ставьте фильтр по псевдониму столбца в `WHERE`, если продукт этого не позволяет. `WHERE` применяется до псевдонимов списка `SELECT` в стандартном SQL. Используйте имя столбца в `WHERE`.

## Проекция и селекция

Проекция и селекция — две операции. Не смешивайте слова.

**Проекция** выбирает атрибуты (столбцы). `SELECT name, email` — проекция. У результата меньше столбцов. Число строк может остаться тем же.

**Селекция** выбирает кортежи (строки). `WHERE price > 10` — селекция. У результата меньше строк. Число столбцов может остаться тем же.

Типичный запрос делает оба:

```sql
SELECT name, price
FROM products
WHERE price > 10;
```

Этот запрос выбирает строки с `price > 10`. Он проецирует `name` и `price`.

В математике селекция использует условие на отношении. Проекция использует список атрибутов. SQL использует `WHERE` для селекции и список `SELECT` для проекции. Ключевое слово `SELECT` не то же самое, что слово *селекция*. Это столкновение путает новичков. Запомните: список `SELECT` = проекция. `WHERE` = селекция.

```text
products (all columns, all rows)
    | selection: price > 10
    v
fewer rows, all columns
    | projection: name, price
    v
fewer rows, two columns
```

Не называйте `WHERE` проекцией. Не называйте список столбцов селекцией.

## `ORDER BY`, `LIMIT` / `FETCH`

У отношения нет порядка. `ORDER BY` даёт порядок результату. Вы называете столбцы или выражения. Используйте `ASC` для возрастающего порядка (по умолчанию). Используйте `DESC` для убывающего порядка.

```sql
SELECT name, price
FROM products
ORDER BY price DESC, name ASC;
```

Строки сортируются по `price` от высокого к низкому. Строки с одной ценой сортируются по `name`.

Всегда используйте `ORDER BY`, когда пользователь должен видеть стабильный порядок. Без `ORDER BY` СУБД может вернуть любой порядок. Этот порядок может измениться после обновления или после смены индекса.

`LIMIT` оставляет первые *n* строк отсортированного результата. Многие продукты поддерживают `LIMIT`. Форма стандарта SQL — `FETCH FIRST`.

```sql
SELECT name, price
FROM products
ORDER BY price DESC
FETCH FIRST 5 ROWS ONLY;
```

```sql
SELECT name, price
FROM products
ORDER BY price DESC
LIMIT 5;
```

Используйте `ORDER BY` с `LIMIT` или `FETCH`. Ограничение без порядка — не результат «топ 5». Это любые пять строк.

Некоторые продукты используют `TOP (5)` в списке `SELECT`. Эта форма не стандарт. Предпочитайте `FETCH FIRST` или `LIMIT` продукта в одном диалекте.

Не используйте `LIMIT` как замену правильному `WHERE`. Ограничение скрывает строки. Оно не определяет бизнес-множество.

## `DISTINCT`

`DISTINCT` убирает дубликаты строк из результата. СУБД сравнивает полную выбранную строку. Две строки, которые совпадают в каждом выбранном столбце, становятся одной строкой.

```sql
SELECT DISTINCT city
FROM customers;
```

Этот запрос перечисляет каждый город один раз. Много клиентов могут жить в одном городе.

Без `DISTINCT` запрос возвращает один город на строку клиента.

```sql
SELECT city
FROM customers;
```

Используйте `DISTINCT`, когда вопрос про уникальные комбинации. Не используйте `DISTINCT`, чтобы скрыть плохое соединение, которое размножило строки. Сначала исправьте соединение (тема 6).

`SELECT DISTINCT a, b` считает пару строкой. `(Paris, 10)` и `(Paris, 11)` остаются двумя строками.

`COUNT(DISTINCT column)` считает уникальные непустые значения в агрегатах. Тема 7 покрывает эту функцию. `DISTINCT` в списке `SELECT` — идея уровня строки.

`DISTINCT` может быть дорогим на большом результате. Предпочитайте правильный `WHERE` и правильное соединение. Добавляйте `DISTINCT`, когда уникальный список — настоящий вопрос.

Некоторые продукты позволяют `DISTINCT ON`. Эта форма не стандарт. Не используйте её на этом пути.

## Сравнение и `AND` / `OR` / `NOT`

`WHERE` использует предикаты. Предикат истинен, ложен или неизвестен (`NULL`).

Операторы сравнения:

- `=` равно
- `<>` не равно (также `!=` во многих продуктах)
- `<` меньше
- `>` больше
- `<=` меньше или равно
- `>=` больше или равно

Объединяйте предикаты через `AND`, `OR` и `NOT`.

```sql
SELECT product_id, name, price
FROM products
WHERE price >= 10
  AND price < 50;
```

`AND` требует, чтобы обе стороны были истинны. `OR` требует, чтобы одна сторона была истинна. `NOT` инвертирует предикат.

Используйте скобки, когда смешиваете `AND` и `OR`. `AND` связывается сильнее, чем `OR`, в SQL. Не полагайтесь на память. Пишите скобки.

```sql
SELECT *
FROM products
WHERE (category = 'book' OR category = 'map')
  AND price < 20;
```

Без скобок смысл может удивить.

`NOT` применяется к предикату:

```sql
SELECT *
FROM products
WHERE NOT (price < 10);
```

Предпочитайте ясное сравнение (`price >= 10`), когда его легче читать.

Сравнение с `NULL` неизвестно, не истинно. `WHERE price = NULL` не возвращает строку. Используйте `IS NULL` (следующий раздел).

Используйте `<>` в стандартном SQL для неравенства. Проверьте, что продукт принимает `<>`.

## `IN`, `BETWEEN`, `LIKE`, `IS NULL`

Эти предикаты часто появляются в `WHERE`.

**`IN`.** Значение равно одному элементу списка.

```sql
SELECT *
FROM products
WHERE category IN ('book', 'map', 'card');
```

Эта форма совпадает с `OR` равенств. В `IN` может появиться подзапрос (тема 6).

**`BETWEEN`.** Значение лежит в замкнутом диапазоне. `x BETWEEN a AND b` значит `x >= a AND x <= b`.

```sql
SELECT *
FROM orders
WHERE ordered_at BETWEEN DATE '2026-01-01' AND DATE '2026-01-31';
```

Оба конца включены. Для дат и времени подтвердите конец последнего дня. Метка времени `2026-01-31 15:00:00` внутри этого диапазона. Метка времени на `2026-02-01` — нет. Для меток времени пара `>=` и `<` часто безопаснее.

**`LIKE`.** Значение совпадает с текстовым шаблоном. `%` значит любая строка. `_` значит один символ.

```sql
SELECT *
FROM customers
WHERE email LIKE '%@example.com';
```

`LIKE` чувствителен к регистру на одних продуктах и нет на других. Проверьте свою СУБД. Не используйте `LIKE '%x%'` на больших таблицах как первый план. Этот шаблон может заставить широкое сканирование.

**`IS NULL` и `IS NOT NULL`.** Проверяют отсутствующие значения.

```sql
SELECT *
FROM orders
WHERE shipped_at IS NULL;
```

Не пишите `= NULL` или `<> NULL`. Эти предикаты неизвестны.

`NOT IN` со списком, который содержит `NULL`, — ловушка. Результат может быть пустым. Предпочитайте позже `NOT EXISTS` или держите `NULL` вне списка.

## Псевдонимы

Псевдоним — временное имя в запросе. Вы даёте псевдоним столбцу или таблице. Псевдоним существует только для этого оператора.

Псевдонимы столбцов называют столбцы вывода. Используйте `AS` для ясности.

```sql
SELECT name AS product_name, price AS unit_price
FROM products;
```

Заголовки результата — `product_name` и `unit_price`. Столбцы таблицы остаются `name` и `price`.

Псевдонимы таблиц сокращают имена и готовят соединения.

```sql
SELECT c.customer_id, c.name
FROM customers AS c
WHERE c.name = 'Ada';
```

`c` — псевдоним для `customers`. После того как задали псевдоним, используйте этот псевдоним для столбцов во многих продуктах. Стандартный SQL позволяет имя таблицы или псевдоним. Будьте последовательны.

Используйте псевдонимы, когда имена длинные или когда соединяете одну таблицу дважды (самосоединение в теме 6). Используйте короткие имена, которые всё ещё что-то значат (`c` для клиентов, `o` для заказов). Не используйте `t1`, `t2`, когда можете использовать букву, которая совпадает с таблицей.

Некоторые продукты позволяют опустить `AS`. Пишите `AS` на этом пути. Лишнее слово ясно.

Не ссылайтесь на псевдоним столбца в `WHERE` в стандартном SQL. Повторите выражение или используйте подзапрос. Некоторые продукты позволяют псевдоним в `ORDER BY`. Проверьте `ORDER BY product_name` на вашей СУБД.

```sql
SELECT price * qty AS line_total
FROM order_lines
ORDER BY line_total;
```

Если `ORDER BY line_total` падает, пишите `ORDER BY price * qty`.

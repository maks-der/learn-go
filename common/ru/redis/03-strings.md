# 3. Строки

## Описание

Тип string — базовое значение Redis. Строка — двоично-безопасный блоб. Можно хранить текст, JSON, число или сырые байты. Эта тема показывает команды записи и чтения, опции `SET`, целочисленные счётчики и правки диапазона. Вы также видите превью счётчиков и простых блокировок.

Завершите эту тему до глубокого изучения сроков и до изучения хешей и списков.

Используйте один термин для каждого понятия. Строковый ключ держит один блоб. `SET` пишет блоб. `GET` читает блоб. `INCR` считает блоб целым числом в базе 10. Превью блокировки использует `SET` с `NX` и TTL. Не смешивайте команды строк с командами хеша на одном ключе.

## `SET`, `GET`, `MSET`, `MGET`

`SET key value` пишет строку. Redis создаёт ключ или заменяет старое значение. Тип становится string. Ответ — `OK`.

`GET key` читает строку. Отсутствующий ключ возвращает null-ответ. Ключ другого типа возвращает `WRONGTYPE`.

```text
SET user:1:name Ada
GET user:1:name
```

`MSET` пишет много строковых ключей одной командой. Все пары применяются как одна атомарная команда. Другие клиенты не видят частичный `MSET`.

```text
MSET user:1:name Ada user:1:city London
```

`MGET` читает много строковых ключей одной командой. Ответ — массив. Каждый слот — значение или null. Порядок совпадает с порядком аргументов.

```text
MGET user:1:name user:1:city user:1:missing
```

Используйте `MGET` и `MSET`, чтобы сократить круги. Ключи должны существовать как строки или отсутствовать. Один неверный тип в `MGET` может провалить команду.

У строки максимальный размер 512 МБ. Не храните большие файлы в Redis. Держите значения маленькими. Несколько килобайт — частый размер кэша. Измеряйте `MEMORY USAGE`, когда не уверены.

`GET` сам по себе не меняет TTL. `SET` без опций TTL снимает любой старый TTL с этого ключа. Тема 4 покрывает `KEEPTTL` и опции срока.

## `SETNX`, `GETSET`, опции `SET` (`EX`, `NX`, `XX`)

Старые версии Redis поставляли `SETNX` и `GETSET` как отдельные команды. Текущий Redis их всё ещё принимает. Новый код предпочитает `SET` с опциями.

`SET key value NX` пишет только когда ключа нет. Ответ — `OK` при успехе или null, когда ключ есть. `SETNX` — та же идея.

`SET key value XX` пишет только когда ключ уже есть. Ответ — `OK` или null.

`SET key value EX seconds` задаёт значение и TTL в секундах. `PX` использует миллисекунды. `EXAT` и `PXAT` используют время Unix (когда ваша версия их поддерживает).

Можно сочетать опции:

```text
SET lock:order:9 worker1 NX EX 30
```

Эта команда пишет `worker1` только если `lock:order:9` отсутствует, и срок истекает через 30 секунд.

`GETSET key value` возвращает старую строку и затем пишет новую. Redis 6.2 и новее также позволяют `SET key value GET`, что можно сочетать с `NX` или `XX`. Предпочитайте `SET ... GET` на новых серверах.

`KEEPTTL` сохраняет текущий TTL, когда вы заменяете значение. Обычный `SET` снял бы TTL.

Читайте страницу команды `SET` для вашей версии. Список опций рос со временем. Не угадывайте. Проверяйте `redis_version`.

## `INCR` / `DECR` / `INCRBY`

`INCR key` читает строку как целое в базе 10, добавляет `1` и пишет новое целое. Ответ — новое значение. Если ключа нет, Redis считает старое значение `0`.

`DECR` вычитает `1`. `INCRBY key n` добавляет целое `n`. `n` может быть отрицательным. `DECRBY` вычитает `n`. `INCRBYFLOAT` добавляет число с плавающей точкой.

Значение должно выглядеть как целое (или как float для `INCRBYFLOAT`). Строка вроде `hello` вызывает ошибку. Хеш-ключ вызывает `WRONGTYPE`.

```text
INCR views:post:10
INCR views:post:10
INCRBY views:post:10 5
```

Каждая команда атомарна. Два клиента могут сделать `INCR` одного ключа. Redis не теряет счёт из-за перемешивания двух одиночных команд.

`INCR` не задаёт TTL. Если нужен счётчик, который сбрасывается, задайте TTL на первом увеличении (см. превью блокировки и счётчика и Lua в теме 8). Частый шаблон — ключ на окно времени: `views:post:10:2026-09-13`.

У целых есть пределы. Redis использует 64-битные знаковые целые для `INCR`. Переполнение возвращает ошибку.

Не используйте `GET`, прибавление единицы в клиенте и `SET`. Этот путь не атомарный. Два клиента могут записать одно число. Используйте `INCR`.

## `APPEND`, `GETRANGE`, `SETRANGE`

`APPEND key value` добавляет байты в конец строки. Если ключа нет, `APPEND` создаёт его. Ответ — новая длина.

`STRLEN key` возвращает длину в байтах. Отсутствующий ключ возвращает `0`.

`GETRANGE key start end` возвращает подстроку. Индексы с нуля. Отрицательный индекс считает с конца. Конечный индекс включительный.

```text
SET word HELLO
GETRANGE word 0 1
GETRANGE word -2 -1
```

`SETRANGE key offset value` перезаписывает байты, начиная с `offset`. Если строка короче, Redis дополняет нулевыми байтами. Ответ — новая длина.

Эти команды правят блоб без полного `GET` и `SET`. Они полезны для записей фиксированной ширины и для небольших журналов только для добавления. Они плохо подходят для JSON, который вы разбираете в клиенте. Хеш или модуль JSON яснее для объектов.

`SETRANGE` может создать большую строку, если `offset` большой. Redis тогда выделяет ОЗУ. Не используйте огромный offset на лабораторном экземпляре без осторожности.

`GETRANGE` огромного диапазона копирует много байт клиенту. Предпочитайте маленькие диапазоны.

Битовые команды (`SETBIT`, `GETBIT`) тоже считают строку массивом байт. Тема 7 покрывает битовые карты.

## Счётчики и простые блокировки (превью)

Счётчик — строка, которую вы меняете через `INCR`, `DECR` или `INCRBY`. Типичные применения — счёт просмотров, номера билетов и окна ограничения частоты.

Простая блокировка — ключ, который может создать только один работник. Частый шаблон:

```text
SET lock:resource-name holder-id NX EX 30
```

Если ответ `OK`, этот работник держит блокировку. Если ответ null, блокировку держит другой работник. TTL снимает блокировку, если работник умер.

Этот шаблон — превью. У него есть пределы:

- Работник должен удалять только свою блокировку. Наивный `DEL lock:resource-name` может снять блокировку другого работника после истечения и повторного использования.
- Один экземпляр Redis — не полная система консенсуса. Алгоритмы блокировки на нескольких экземплярах — более поздний спор (Redlock).
- В распределённых системах есть проблемы часов и пауз.

Для обучения используйте один экземпляр, короткий TTL и уникальный id держателя. Снимайте блокировку с проверкой, что значение всё ещё равно вашему id держателя. Тема 8 показывает Lua для этой проверки в одном атомарном скрипте.

Не используйте блокировку, когда `INCR` или одна команда Redis уже делает обновление безопасным. Блокировки нужны для работы вне Redis (файлы, платежи, медленные API).

Счётчики и блокировки оба зависят от атомарных `SET` и `INCR`. Это шаблоны строк, а не новые типы.

# 10. Драйверы и приложения

## Описание

Эта тема показывает, как приложения говорят с MongoDB. Вы используете официальный драйвер. Настраиваете строку соединения. Управляете `MongoClient` на жизненный цикл процесса. Задаёте таймауты. Изучаете компромиссы библиотек отображения объектов. Никогда не запускаете неограниченный `find` в API. Сначала завершите CRUD и запросы.

Используйте один термин для каждого понятия. **Драйвер** — официальная клиентская библиотека для языка. **Строка соединения** (URI) — строка конфигурации. **`MongoClient`** — долгоживущий объект клиента. **ODM** или mapper отображает документы в типы языка. Не открывайте нового клиента на каждый запрос.

---

## Официальные драйверы (Node, Python, Go, Java)

MongoDB публикует официальные драйверы. Частые драйверы:

- Node.js (`mongodb`)
- Python (`pymongo`)
- Go (`go.mongodb.org/mongo-driver`)
- Java (`mongodb-driver-sync` и реактивный драйвер)

Есть и другие официальные драйверы (C#, Rust, C). Используйте драйвер своего языка с [https://www.mongodb.com/docs/drivers/](https://www.mongodb.com/docs/drivers/).

Официальный драйвер:

- Кодирует и декодирует BSON
- Управляет пулом соединений
- Реализует auth, TLS и повторяемые записи
- Соответствует командам сервера

Обёртка сообщества может сидеть поверх официального драйвера. Официальный драйвер всё равно должен быть в стеке.

Не используйте заброшенный сторонний клиент, который говорит на частном протоколе.

У версий драйверов есть матрица совместимости с версиями сервера. Читайте матрицу до обновления.

Имена API отличаются. Идеи те же: клиент, база, коллекция, фильтр, обновление, курсор.

CRUD в драйвере использует те же операторы, что `mongosh`. Передаёте объекты языка или документы BSON, не строку SQL.

Устанавливайте драйвер инструментом пакетов языка (`npm`, `pip`, `go get`, Maven). Зафиксируйте основную версию.

## Строка соединения и опции

Строка соединения — URI.

Одиночный узел:

```text
mongodb://localhost:27017
```

С auth и именем базы для auth:

```text
mongodb://user:pass@localhost:27017/?authSource=admin
```

Atlas часто использует SRV:

```text
mongodb+srv://user:pass@cluster0.example.mongodb.net/
```

`mongodb+srv` использует DNS, чтобы найти хосты. В обычном случае Atlas это также подразумевает TLS.

Опции URI — параметры запроса. Примеры:

- `retryWrites=true`
- `w=majority`
- `appName=myapp`
- `maxPoolSize=20`

Драйвер также принимает опции в коде. Не задавайте одну опцию в двух местах разными значениями.

Не кладите пароль в контроль версий. Используйте переменную окружения или хранилище секретов.

Экранируйте спецсимволы в имени пользователя и пароле.

`appName` появляется в логах сервера. Задайте его. Это помогает эксплуатации.

Читайте текущую страницу опций URI. Опции меняются. Некоторые опции Atlas живут в UI Atlas (список IP, роли пользователей), а не только в URI.

## Жизненный цикл `MongoClient`

Создайте **один** `MongoClient` (или эквивалентное имя), когда процесс стартует. Переиспользуйте его для всех запросов. Закройте его, когда процесс останавливается.

Клиент владеет **пулом** соединений. Новый клиент на каждый запрос создаёт много соединений. Сервер отклонит или замедлится. Приложение будет терять сокеты.

Типичная последовательность:

1. Прочитать URI из окружения.
2. Создать клиент.
3. Один раз пингануть при старте (быстро упасть, если URI неверен).
4. Сохранить клиент в состоянии приложения.
5. Использовать `client.Database("app").Collection("orders")` на операцию (эти объекты дёшевы).
6. При остановке вызвать `Disconnect` или `Close`, как документирует драйвер.

Не закрывайте клиент после каждого запроса.

Объекты базы и коллекции не открывают каждый новый пул. Они используют клиент.

В тестах можно создать клиент на набор тестов, не на каждый метод, если не нужна изоляция.

Бессерверные функции сложнее. Глобальный клиент можно переиспользовать между тёплыми вызовами. Новый клиент на каждый холодный старт нормален. Не создавайте клиент на каждый отдельный запрос внутри тёплого экземпляра.

## Таймауты

Таймаут останавливает ожидание, которое слишком долгое. Без таймаутов запрос может зависнуть.

Частые таймауты (имена зависят от драйвера):

- **Server selection timeout** — сколько драйвер ждёт подходящий сервер
- **Connect timeout** — сколько может занять новое соединение TCP/TLS
- **Socket timeout** или **network timeout** — сколько может занять чтение или запись на сокете
- **Operation timeout** — срок на команду (`timeoutMS` или `context` со сроком)

Go и некоторые современные драйверы используют **срок контекста** на каждую операцию. Задайте срок в обработчике API. Передайте контекст в драйвер.

Не используйте 30-минутный таймаут сокета как единственный лимит пользовательского запроса. Пользователь уже ушёл. Соединение пула остаётся занятым.

Не используйте таймаут 1 миллисекунда на запросе, который должен читать диск. Увидите случайные ошибки.

Повтор: драйвер может повторить некоторые чтения и записи. Короткий таймаут плюс много повторов всё равно может перегрузить сервер. Задайте один общий срок.

У Atlas и `mongod` тоже есть таймауты простоя и таймауты курсора. Они не заменяют сроки приложения.

Логируйте ошибки таймаута как таймауты. Не логируйте их как «не найдено».

## Библиотеки отображения объектов (Mongoose и другие) — компромиссы

**ODM** (object-document mapper) отображает объекты языка в документы. **Mongoose** — частый ODM для Node. У других языков есть ODM и инструменты генерации кода.

Плюсы:

- Схема в приложении
- Приведения и значения по умолчанию
- Хуки (перед сохранением)
- Стиль, похожий на класс модели

Минусы:

- Лишний слой поверх драйвера
- Магия (неявные приведения, неявные коллекции)
- Отставание версии от возможностей официального драйвера
- Скрытый N+1 или неограниченные запросы, если использовать удобные помощники
- Вторая схема помимо `$jsonSchema`

Используйте ODM, когда команда хочет модели и ODM активен. Используйте официальный драйвер, когда хотите ясный BSON и контроль.

Можно использовать тонкий mapper (структуры и теги в Go, dataclass в Python) без полного ODM.

Не смешивайте два ODM в одном сервисе. Не игнорируйте документацию официального драйвера, когда ODM его оборачивает.

Схемы Mongoose — валидация приложения. Они не заменяют уникальные индексы или валидаторы сервера.

Тестируйте BSON, который пишет ODM. Некоторые библиотеки хранят даты или числа в типах, которых вы не ждали.

## Избегать неограниченного `find()` в API

API не должен возвращать неограниченную коллекцию.

Плохо:

```javascript
const all = await col.find({}).toArray()
return all
```

Этот шаблон:

- Растёт вместе с таблицей
- Использует ОЗУ в приложении и у клиента
- Может истечь по таймауту
- Может превысить лимиты размера ответа

Хорошо:

- Требовать избирательный фильтр, или
- Требовать `limit` с максимумом (например 100), и
- Использовать сортировку и токен страницы или курсор, и
- Проецировать только поля, которые нужны клиенту

`find({})` в инструменте администратора приемлем с принудительным лимитом.

Агрегация без `$limit` на пользовательском пути — та же проблема.

Помощники ODM вроде `Model.find()` без лимита — тот же баг.

Напишите общий помощник: `findPage(filter, { limit, cursor })`. Отклоняйте `limit > 100`.

Тестируйте с большим числом документов, чем лимит. Тест падает, если API возвращает все строки.

Логи: записывайте `limit` и `returned`. Сигнализируйте, если `returned == max` часто; клиенту может нужен лучший фильтр.

1. Напишите небольшую программу: URI из env, один клиент, ping, `find` с `limit(5)`, отключение.
2. Напишите шпаргалку: имена драйверов, формы URI, жизненный цикл клиента, типы таймаутов, компромисс ODM, лимит API.
3. Задайте `appName` и срок операции 5 секунд. Запустите ping.
4. Опишите хук остановки своего веб-фреймворка в пяти шагах.

#### Средние практические задания

1. Соберите крошечную HTTP-конечную точку списка, которая требует `limit` ≤ 50 и проекцию. Проверьте её на 80 документах.
2. Сравните вставку официальным драйвером и вставку ODM одной структуры. Выведите типы BSON дат и decimal.
3. Сломайте URI (плохой пароль). Покажите быстрый отказ на ping при старте, а не на первом пользовательском запросе.

#### Сложные практические задания

1. Измерьте соединения пула при 50 одновременных запросах с одним клиентом. Запишите `maxPoolSize` и пик соединений.
2. Напишите производственный чек-лист из десяти пунктов этой темы. Примените его к примеру приложения и отметьте pass или fail.

# 10. Введение в рекурсию и деревья

## Описание

Рекурсия и деревья используют одну идею: у задачи есть маленькая база и меньшая копия той же задачи. Эта тема объясняет базовый случай, рекурсивный случай, дерево вызовов, слова дерева, двоичные деревья и имена форм. Завершите эту тему до двоичных деревьев поиска.

Используйте один термин для каждого понятия. **Базовый случай** останавливает рекурсию. **Рекурсивный случай** вызывает ту же функцию на меньшем входе. **Дерево** — связная структура узлов без цикла. **Корень** — верхний узел. **Лист** не имеет ребёнка.

## Базовый случай и рекурсивный случай

У рекурсивной функции две части.

**Базовый случай** обрабатывает самый маленький вход. Функция возвращается без дальнейшего вызова. Пример: пустой список. Пример: n == 0 для факториала. Пример: нулевой указатель ребёнка.

**Рекурсивный случай** решает меньший вход, затем комбинирует результат. Меньший вход должен двигаться к базовому случаю. Если вход не становится меньше, функция никогда не останавливается.

```text
factorial(n)
  base:      n == 0  →  1
  recursive: n > 0   →  n * factorial(n - 1)
```

```go
func Fact(n int) int {
	if n == 0 {
		return 1
	}
	return n * Fact(n-1)
}
```

```python
def fact(n):
    if n == 0:
        return 1
    return n * fact(n - 1)
```

Обход списка может быть рекурсивным:

```text
sum(node)
  base:      node is null  →  0
  recursive: node.value + sum(node.next)
```

Вы должны сначала написать базовый случай в уме. Затем пишете рекурсивный случай. Тестируйте пустой вход.

Рекурсия использует стек вызовов. У каждого вызова есть кадр. Глубокое n может переполнить стек вызовов. Цикл часто безопаснее для линейного просмотра. Рекурсия естественно подходит дереву: каждый ребёнок — меньшее дерево.

Не используйте рекурсию, когда простого цикла достаточно, если не изучаете рекурсию.

## Дерево вызовов

**Дерево вызовов** — картинка рекурсивных вызовов. Корень — первый вызов. Каждый ребёнок — вызов, который делает родитель. Листовой вызов — базовый случай.

```text
fib(4)
  fib(3)              fib(2)
    fib(2)  fib(1)      fib(1)  fib(0)
      fib(1) fib(0)
```

Наивная функция Фибоначчи делает два рекурсивных вызова. Дерево вызовов имеет много повторных узлов. Число вызовов растёт как Θ(φⁿ). Этот рост экспоненциальный. Цикл или мемоизация избегают повторной работы.

Обход дерева, который вызывает left и right, тоже имеет дерево вызовов. Если каждый узел посещается константное число раз, суммарная работа — Θ(n) для n узлов.

Читайте дерево вызовов сверху. Глубина дерева вызовов — глубина стека вызовов. Тощее глубокое дерево может переполнить стек. Широкое мелкое дерево использует меньше стека и больше соседней работы.

```text
depth of call tree ≈ maximum number of frames at one time
```

Рисуйте дерево вызовов, когда отлаживаете рекурсивную функцию. Считайте листья базового случая. Проверьте, что каждый путь заканчивается базовым случаем.

## Терминология дерева: корень, лист, родитель, ребёнок, глубина, высота

**Дерево** в этом справочнике — набор узлов со ссылками родитель и ребёнок. Есть один **корень**. Каждый другой узел имеет ровно одного родителя. Цикла нет.

**Ребёнок** узла u — узел, у которого родитель u. **Родитель** узла v — единственный узел выше v. У корня нет родителя.

**Лист** — узел без ребёнка.

**Глубина** узла — число рёбер от корня до этого узла. У корня глубина 0.

**Высота** узла — число рёбер на самом длинном пути от этого узла вниз до листа. Высота листа — 0.

**Высота дерева** — высота корня.

```text
        A          depth(A)=0, height(A)=2
       / \
      B   C        depth(B)=1, height(B)=1
     /
    D              depth(D)=2, height(D)=0  (leaf)
```

Некоторые тексты говорят, что высота листа — 1, или считают узлы вместо рёбер. Этот справочник считает **рёбра**. Пишите соглашение, когда читаете другую книгу.

**Брат** делит того же родителя. **Предок** сидит на пути от узла вверх к корню. **Потомок** сидит в поддереве.

**Поддерево** узла u — u плюс все потомки u.

Пустое дерево не имеет узла. Нулевой ребёнок — не узел. Многие функции считают нуль высотой −1, чтобы лист (два нулевых ребёнка) имел высоту 0.

## Двоичное дерево

**Двоичное дерево** — дерево, в котором каждый узел имеет не больше двух детей. Дети — **левый** и **правый**. Левый и правый разные. У узла может быть левый ребёнок и не быть правого ребёнка.

```go
type BinNode struct {
	Value int
	Left  *BinNode
	Right *BinNode
}
```

```python
class BinNode:
    def __init__(self, value, left=None, right=None):
        self.value = value
        self.left = left
        self.right = right
```

Двоичное дерево не всегда двоичное дерево поиска. Двоичное дерево поиска добавляет правило порядка. Это правило — тема 11.

Обход двоичного дерева использует рекурсию естественным образом:

```text
walk(node)
  base: node is null → return
  walk(node.left)
  use node
  walk(node.right)
```

Порядок трёх строк даёт симметричный, прямой или обратный обход. Тема 11 определяет эти имена в постановке BST. Те же имена применимы к любому двоичному дереву.

Двоичное дерево может представлять выражение. Внутренние узлы — операторы. Листья — числа. Эту картинку можно изучить позже.

Максимальное число узлов на глубине d — 2ᵈ, если каждый уровень полон. Максимальное число узлов в двоичном дереве высоты h — 2^{h+1} − 1.

## Полное / совершенное / завершённое / сбалансированное (определения)

Эти слова описывают **форму** двоичного дерева. Выучите определения. Разные книги расходятся по «complete» и «full». Этот справочник использует определения ниже.

**Совершенное (perfect).** Каждый внутренний узел имеет двух детей. Все листья имеют одну глубину. Совершенное дерево высоты h имеет 2^{h+1} − 1 узлов.

**Полное (full, иногда «proper»).** Каждый узел имеет 0 детей или 2 детей. Ни у одного узла нет ровно одного ребёнка.

**Завершённое (complete).** Каждый уровень полон, кроме возможно последнего уровня. Последний уровень заполнен слева. Двоичная куча использует завершённое дерево. Вы увидите это расположение в более поздней теме.

**Сбалансированное (практически).** Высота мала по сравнению с n. Обычная цель — высота Θ(log n). Одно точное правило (AVL): для каждого узла высота левого поддерева и высота правого поддерева различаются не больше чем на 1. Вы не реализуете AVL в этой теме.

```text
perfect, height 1:     3 nodes (root and two leaves)
full, not perfect:     root with two children; one child has two leaves
                       (every node has 0 or 2 children; leaf depths differ)
complete, not perfect: last level filled from the left; one missing node on the right
```

**Вырожденное** дерево — линия. У каждого узла один ребёнок. Высота — n − 1. Вырожденное двоичное дерево ведёт себя как связный список. Тема 11 снова использует это слово.

Не говорите «сбалансированное», когда у вас нет правила высоты. Используйте определение. Для этой темы пишите высоту и n. Если высота около log₂ n, дерево мелкое. Если высота около n, дерево вырожденное.

# 6. Соединения и операции над множествами

## Описание

Эта тема показывает, как объединять строки из более чем одной таблицы. Вы изучаете внутренние соединения, внешние соединения, декартовы соединения и самосоединения. Вы также изучаете операторы множеств и подзапросы.

Используйте один термин для каждого понятия. Соединение сопоставляет строки из двух таблиц по условию. Оператор множества складывает два результата запроса. Подзапрос — запрос внутри другого оператора. Завершите эту тему до группировки строк.

Квалифицируйте имена столбцов, когда две таблицы делят имя. Используйте псевдонимы таблиц.

## Внутреннее соединение

Внутреннее соединение возвращает строки, которые совпадают по условию соединения. Строка без совпадения не появляется.

```sql
SELECT o.order_id, c.name, o.ordered_at
FROM orders AS o
INNER JOIN customers AS c
    ON o.customer_id = c.customer_id;
```

`INNER JOIN` то же самое, что `JOIN` в стандартном SQL. Пишите `INNER JOIN`, пока учитесь. Слово ясно.

Предложение `ON` — правило совпадения. Большинство соединений сопоставляют внешний ключ с первичным ключом. Это обычный и безопасный шаблон.

Если у одного клиента три заказа, в результате три строки. Имя клиента повторяется. Это повторение правильно. Зерно результата — заказ, не клиент.

Если у заказа есть `customer_id`, которого нет, внутреннее соединение отбрасывает этот заказ. Внешний ключ должен предотвращать этот случай. Если видите отброшенные заказы, проверьте данные и условие соединения.

```text
customers          orders
id  name           id  customer_id
1   Ada            10  1
2   Alan           11  1
                   12  2

INNER JOIN on customer_id
→ (10, Ada), (11, Ada), (12, Alan)
```

Не опускайте предложение `ON`. Соединение без условия становится декартовым соединением в некоторых диалектах. Этот результат — взрыв строк.

Не соединяйте по неверному столбцу. `ON o.order_id = c.customer_id` может выполниться и всё равно быть бессмысленным. Проверяйте имена.

## Левое / правое / полное внешнее соединение

Внешнее соединение оставляет несовпавшие строки с одной или обеих сторон. Столбцы стороны без совпадения — `NULL`.

**Левое внешнее соединение.** Оставьте каждую строку левой таблицы. Добавьте совпадающие строки правой таблицы. Когда совпадения нет, правые столбцы — `NULL`.

```sql
SELECT c.customer_id, c.name, o.order_id
FROM customers AS c
LEFT OUTER JOIN orders AS o
    ON o.customer_id = c.customer_id;
```

Клиент без заказов всё равно появляется. `order_id` равен `NULL` для этой строки.

**Правое внешнее соединение.** Оставьте каждую строку правой таблицы. Это соединение — левое со свапнутыми таблицами. Предпочитайте `LEFT OUTER JOIN` и пишите нужную таблицу слева. Команды легче читают левые соединения.

**Полное внешнее соединение.** Оставьте несовпавшие строки с обеих сторон. Клиент без заказов появляется. Заказ без клиента появляется. Многие продукты поддерживают `FULL OUTER JOIN`. Некоторые продукты нет. Проверьте свою СУБД.

```sql
SELECT c.customer_id, o.order_id
FROM customers AS c
FULL OUTER JOIN orders AS o
    ON o.customer_id = c.customer_id;
```

`LEFT JOIN` — обычная короткая форма `LEFT OUTER JOIN`. Пишите `OUTER`, пока учитесь, если это помогает.

Фильтр в `WHERE` по правому столбцу может превратить левое соединение во внутреннее.

```sql
SELECT c.name, o.order_id
FROM customers AS c
LEFT OUTER JOIN orders AS o
    ON o.customer_id = c.customer_id
WHERE o.ordered_at >= DATE '2026-01-01';
```

Строки с `o.ordered_at` `NULL` не проходят этот `WHERE`. Клиенты без заказов исчезают. Ставьте фильтры по необязательной таблице в предложение `ON`, когда нужно сохранить несовпавшие левые строки.

```sql
LEFT OUTER JOIN orders AS o
    ON o.customer_id = c.customer_id
   AND o.ordered_at >= DATE '2026-01-01';
```

## Декартово соединение и когда это ошибка

Декартово соединение спаривает каждую строку одной таблицы с каждой строкой другой. Размер результата — произведение двух размеров.

```sql
SELECT c.name, p.name AS product_name
FROM customers AS c
CROSS JOIN products AS p;
```

Если у вас 100 клиентов и 500 товаров, в результате 50000 строк. Каждая пара — строка.

Декартово соединение правильно, когда нужна полная комбинация. Пример: каждый размер в таблице `sizes` с каждым цветом в таблице `colors`, чтобы построить сетку каталога.

Декартово соединение — ошибка, когда вы имели в виду внутреннее соединение и забыли `ON`. Некоторые старые синтаксисы делают это легко:

```sql
SELECT *
FROM orders, customers;
```

Эта форма — декартово соединение. Поздний `WHERE orders.customer_id = customers.customer_id` превращает его во внутреннее соединение. Если забудете `WHERE`, клиент вернёт огромную сетку. Используйте `INNER JOIN ... ON`, чтобы совпадение было обязательным.

Не используйте декартово соединение, чтобы «посмотреть, совпадёт ли что-то» на больших таблицах. СУБД может построить огромный промежуточный результат.

Тестируйте декартово соединение только на маленьких справочных таблицах. Отмените запрос, если число строк неожиданное.

```text
sizes: S, M
colors: red, blue
CROSS JOIN → (S,red), (S,blue), (M,red), (M,blue)
```

## Самосоединение

Самосоединение — соединение таблицы с собой. Вы используете два псевдонима. Каждый псевдоним — одна роль.

Пример. Сотрудники с руководителем в той же таблице:

```sql
SELECT e.name AS employee_name, m.name AS manager_name
FROM employees AS e
INNER JOIN employees AS m
    ON e.manager_id = m.employee_id;
```

`e` — сотрудник. `m` — руководитель. Соединение сопоставляет внешний ключ `manager_id` с `employee_id`.

Левое самосоединение оставляет сотрудников без руководителя (верхнего человека):

```sql
SELECT e.name AS employee_name, m.name AS manager_name
FROM employees AS e
LEFT OUTER JOIN employees AS m
    ON e.manager_id = m.employee_id;
```

Другие применения самосоединения:

- сравнить строку с более ранней строкой (тот же клиент, предыдущий заказ)
- найти пары в списке (аэропорты, `from_code` и `to_code` в одной таблице городов)

Нужно дать таблице псевдоним дважды. Без псевдонимов СУБД не может различить две роли.

Не создавайте в голове цикл как рекурсивный обход, если не используете рекурсивный запрос. Одно самосоединение делает один шаг (сотрудник к руководителю). Полная цепочка нуждается в большем числе соединений или рекурсивном общем табличном выражении. Эта возможность — более поздний материал.

```text
employees
id  name   manager_id
1   Ada    NULL
2   Alan   1
3   Grace  1

self-join → (Alan, Ada), (Grace, Ada)
left self-join also → (Ada, NULL)
```

## Соединение по ключам и соединение по выражениям

Соединение по ключам сопоставляет внешний ключ с уникальным ключом. Совпадение точное. Оптимизатор может использовать индексы (тема 11). Смысл: «эти строки принадлежат вместе».

```sql
FROM order_lines AS ol
INNER JOIN products AS p
    ON ol.product_id = p.product_id;
```

Соединение по выражению сопоставляет вычисленное условие. Примеры: диапазоны дат, неравенство, преобразованный текст.

```sql
FROM orders AS o
INNER JOIN discounts AS d
    ON o.ordered_at >= d.start_at
   AND o.ordered_at < d.end_at
   AND d.active = TRUE;
```

Это соединение может сопоставить один заказ со многими строками скидок, если диапазоны пересекаются. Зерно может взорваться. Нужно знать правило: одна скидка, много или лучшее совпадение.

```sql
FROM customers AS c
INNER JOIN customers AS x
    ON LOWER(c.email) = LOWER(x.email)
   AND c.customer_id <> x.customer_id;
```

Это соединение находит дубликаты email, которые отличаются только регистром. Выражение `LOWER(email)` может помешать простому использованию индекса на некоторых продуктах.

Предпочитайте соединение по ключу, когда в модели есть ключ. Используйте соединение по выражению, когда правило — диапазон или преобразование. Документируйте ожидаемое число совпадений: один-к-одному, один-ко-многим или многие-ко-многим.

Не соединяйте по округлённым меткам времени или по `LIKE` как первый проект. Такие соединения трудно тестировать и ускорять.

Если два условия принадлежат соединению, ставьте оба в `ON`. Не прячьте правило соединения в `WHERE`, когда пишете внешнее соединение (см. ловушку левого соединения).

## `UNION`, `UNION ALL`, `INTERSECT`, `EXCEPT`

Операторы множеств объединяют два результата запроса. У каждого запроса должно быть одно число столбцов. Типы должны быть совместимы. Имена столбцов берутся из первого запроса.

**`UNION`.** Сложить строки. Убрать дубликаты.

**`UNION ALL`.** Сложить строки. Оставить дубликаты.

```sql
SELECT name FROM staff
UNION
SELECT name FROM contractors;
```

```sql
SELECT name FROM staff
UNION ALL
SELECT name FROM contractors;
```

Если `Ada` появляется в обеих таблицах, `UNION` возвращает одну `Ada`. `UNION ALL` возвращает две.

**`INTERSECT`.** Вернуть строки, которые появляются в обоих результатах.

**`EXCEPT`.** Вернуть строки первого результата, которых нет во втором. Некоторые продукты используют `MINUS` для этой идеи. Предпочитайте `EXCEPT`, когда продукт его имеет.

```sql
SELECT customer_id FROM orders
INTERSECT
SELECT customer_id FROM newsletter;

SELECT customer_id FROM customers
EXCEPT
SELECT customer_id FROM banned_customers;
```

Операторы множеств сравнивают полные строки. `SELECT a, b UNION SELECT a, b` использует оба столбца.

Используйте `UNION ALL`, когда знаете, что множества не пересекаются, или когда нужно сохранить дубликаты. `UNION` сортирует или хеширует, чтобы убрать дубликаты. Эта лишняя работа имеет цену.

Обе стороны должны значить одно зерно. Не объединяйте список клиентов со списком заказов, если не хотите только мешок id и не помечаете источник.

```sql
SELECT customer_id, 'order' AS source
FROM orders
UNION ALL
SELECT customer_id, 'newsletter' AS source
FROM newsletter;
```

Не каждый продукт реализует `INTERSECT` и `EXCEPT`. Проверьте руководство. Некоторые из этих идей можно выразить соединениями и `EXISTS`.

## Подзапросы: скалярный, `IN`, `EXISTS`

Подзапрос — `SELECT` внутри другого оператора. Скобки оборачивают его.

**Скалярный подзапрос.** Подзапрос возвращает один столбец и не более одной строки. Можно использовать его в списке `SELECT` или в сравнении.

```sql
SELECT name,
       (SELECT COUNT(*) FROM orders AS o WHERE o.customer_id = c.customer_id) AS order_count
FROM customers AS c;
```

Если скалярный подзапрос возвращает две строки, оператор падает. Если не возвращает строку, значение — `NULL`.

**Подзапрос `IN`.** Внешняя строка совпадает, когда значение равно одному значению из подзапроса.

```sql
SELECT name
FROM customers
WHERE customer_id IN (
    SELECT customer_id
    FROM orders
    WHERE ordered_at >= DATE '2026-01-01'
);
```

**Подзапрос `EXISTS`.** Внешняя строка совпадает, когда подзапрос возвращает хотя бы одну строку. Обычно коррелируете: внутренний запрос ссылается на внешнюю строку.

```sql
SELECT c.name
FROM customers AS c
WHERE EXISTS (
    SELECT 1
    FROM orders AS o
    WHERE o.customer_id = c.customer_id
);
```

`EXISTS` останавливается, когда находит одну строку. `SELECT 1` — обычный фиктивный список. Столбцы не важны.

`NOT EXISTS` находит внешние строки без совпадающей внутренней строки. Эта форма — ясный способ найти клиентов без заказов.

```sql
SELECT c.name
FROM customers AS c
WHERE NOT EXISTS (
    SELECT 1
    FROM orders AS o
    WHERE o.customer_id = c.customer_id
);
```

Предпочитайте `EXISTS` вместо `IN`, когда внутренний запрос может вернуть `NULL` в ловушке `NOT IN` (тема 4). Предпочитайте соединение, когда нужны столбцы из обеих таблиц в результате. Предпочитайте подзапрос, когда только фильтруете.

Коррелированный подзапрос ссылается на внешний запрос. Некоррелированный подзапрос не ссылается. СУБД может выполнить некоррелированный подзапрос один раз.

# 21. Экосистема

## Описание

Экосистема Kafka — набор продуктов, которые говорят на протоколе Kafka или сидят рядом с кластером Kafka. Apache Kafka — открытый брокер и протокол. Другие продукты добавляют серверы, облака и пользовательские интерфейсы.

Эта тема покрывает Confluent Platform против Apache Kafka, Redpanda и Apache Pulsar как точки сравнения, Schema Registry, REST Proxy, Control Center / AKHQ / Kafdrop и облачные сервисы (MSK, Confluent Cloud, Aiven, WarpStream). Завершите эту тему после тем 1, 11, 12 и 14. Предпочитайте KRaft для Apache Kafka и для управляемой Kafka, которая его предлагает. Не запускайте ZooKeeper для новой работы.

Используйте один термин для каждого понятия. Apache Kafka — проект ASF. Система, совместимая с API Kafka, принимает клиенты Kafka. Управляемый сервис запускает брокеров за вас. UI — браузерный инструмент, который вызывает API admin и консьюмера. Реестр хранит схемы (тема 11). REST Proxy открывает HTTP для produce и consume.

## Confluent Platform против Apache Kafka

**Apache Kafka** — проект на [https://kafka.apache.org/](https://kafka.apache.org/). Вы скачиваете брокеров, клиентские библиотеки, Kafka Streams и Kafka Connect. Вы их эксплуатируете. Новые кластеры используют KRaft.

**Confluent Platform** — дистрибутив от Confluent. Он включает Apache Kafka (или совместимый брокер) плюс дополнительные компоненты, которые поддерживает Confluent: Schema Registry, ksqlDB, Control Center, коннекторы и коммерческие функции. **Confluent Cloud** — размещённая форма.

Протокол Kafka — та же идея. Продюсер, который использует клиент Apache, может говорить с Confluent Cloud, если задать bootstrap, безопасность и иногда пакет клиента, который документирует Confluent.

Отличия, которые важны для новичка:

- Документы Apache Kafka — источник для ключей брокера и KRaft.
- Учебники Confluent часто запускают дополнительные контейнеры (реестр, ksql). Они не обязательны, чтобы выучить темы 1–10.
- Лицензии отличаются. Некоторые коннекторы Confluent и функции UI не Apache 2.0. Читайте лицензию до установки.

Не считайте «Confluent» и «Apache Kafka» двумя протоколами. Считайте их ядром плюс необязательные продукты.

Можно запустить Apache Kafka на KRaft и добавить Karapace (тема 11) вместо Confluent Schema Registry. Это допустимый путь с центром Apache.

## Redpanda, Apache Pulsar (точки сравнения)

**Redpanda** — потоковая система, которая говорит на API Kafka. Многие клиенты Kafka работают. Движок — не брокер Kafka JVM. Эксплуатация, раскладка диска и дополнительные функции отличаются. Этот справочник учит Apache Kafka. Используйте Redpanda, когда команда выбирает этот продукт и принимает отличия.

**Apache Pulsar** — другая система pub/sub и потоков. По умолчанию она использует отдельный протокол. У неё другая модель (брокеры плюс bookies, сегментированное хранилище). Некоторые инструменты связывают Pulsar и Kafka. Pulsar — не «Kafka под другим именем».

Точки сравнения (высокий уровень):

- Протокол: Redpanda ≈ API Kafka. Pulsar ≠ API Kafka (если нет прокси).
- Модель процесса: брокеры Kafka JVM (KRaft). Redpanda — свой двоичный файл. Pulsar — брокеры + слой хранения.
- Потоки: Kafka Streams — для Kafka. У Pulsar есть Functions. У Redpanda свои дополнения.
- Эксплуатация: инструменты (`kafka-topics`) работают на Kafka и часто на Redpanda. Они не управляют Pulsar.

Не запускайте учебник Pulsar и не думайте, что выучили партиции Kafka и KRaft. Не предполагайте, что каждый коннектор Kafka Connect работает на каждом клоне API Kafka.

Если вендор говорит «совместим с Kafka», тестируйте: produce, consume, группы, транзакции (если нужен EOS) и admin.

KRaft — режим метаданных Apache Kafka. У Redpanda и Pulsar свои метаданные. Не ищите `kafka-storage format` на Pulsar.

## Schema Registry, REST Proxy, Control Center / AKHQ / Kafdrop

**Schema Registry** (Confluent или Karapace, тема 11) хранит схемы и правила совместимости. Это HTTP-сервис. Это не брокер.

**REST Proxy** (Confluent REST Proxy и похожие проекты) открывает HTTP для produce, consume и некоторого admin. Используйте его, когда у языка нет хорошего клиента или когда устаревшая система может только вызывать HTTP. Предпочитайте нативный клиент Kafka, когда можете. Прокси — ещё один процесс для защиты (тема 17).

**Control Center** — UI Confluent для топиков, Connect, ksql и метрик. Он не часть Apache Kafka.

**AKHQ** и **Kafdrop** — открытые браузерные UI. Они перечисляют топики, просматривают записи и осматривают группы. Им нужны bootstrap и учётные данные. UI, который потребляет топик, — консьюмер. Он может изменить лаг или использовать группу, если так настроить. Используйте выделенный идентификатор группы. Не присоединяйте UI к продакшен-группе приложения.

UI не заменяют `kafka-topics` и метрики. Они помогают новичкам видеть партиции и офсеты.

Все они говорят с кластером Kafka. Этот кластер должен быть KRaft для новой работы. Ни одному из них не нужно устанавливать ZooKeeper.

Фиксируйте версии UI. Не открывайте UI в публичный интернет без аутентификации.

## Облако: MSK, Confluent Cloud, Aiven, WarpStream

**Amazon MSK** — Kafka как управляемый сервис на AWS. Вы выбираете версию, размер и сеть. Новые кластеры MSK могут использовать KRaft. Вы всё равно используете топики, ACL и клиенты. Вы не делаете SSH на брокера по умолчанию.

**Confluent Cloud** — размещённая Kafka Confluent плюс реестр, ksql и другие облачные продукты. Bootstrap — имя хоста, которое даёт Confluent. Аутентификация часто ключи API или OAUTHBEARER (тема 17).

**Aiven** — управляемая платформа данных, которая включает Kafka (и другие хранилища). Вы получаете bootstrap и проект. Функции следуют предложению Aiven Kafka.

**WarpStream** — сервис протокола Kafka, который хранит данные в объектном хранилище. Модель эксплуатации отличается от классического диска брокера в `log.dirs`. Клиенты всё равно используют протокол Kafka. Тестируйте совместимость ваших функций.

Общие факты облака:

- Вы не запускаете `kafka-server-start` на ноутбуке для продакшена.
- Вам всё равно нужна осведомлённость о KRaft, когда вендор предлагает старые версии на ZooKeeper. Выбирайте KRaft.
- Сеть (private link, VPC) — часть дизайна.
- Цена включает партиции, хранилище и трафик между зонами (тема 16).
- Вендоры добавляют свой UI. Протокол остаётся Kafka.

Не предполагайте транзакции, exactly-once или конкретную модель ACL без страницы вендора. Не предполагайте, что Connect или Streams работают внутри вендора (иногда запускаете их сами).

Этот справочник остаётся на концепциях Apache Kafka. Облако — развёртывание этих концепций.

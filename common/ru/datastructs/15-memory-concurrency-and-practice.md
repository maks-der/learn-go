# 15. Память, конкурентность и практика

## Описание

Эта тема связывает структуры данных с памятью, программами с общей памятью и данными, которые не помещаются в ОЗУ. Вы изучаете персистентные и неизменяемые структуры, конкурентные очереди и отображения на концептуальном уровне (блокировка против lock-free), сортировку во внешней памяти, обязательный список реализаций и как читать одну настоящую реализацию.

Завершите эту тему последней. Используйте темы 1–14, когда реализуете и когда читаете промышленный код.

Используйте один термин для каждого понятия. **Персистентная** структура сохраняет старые версии после обновления. **Неизменяемое** значение не меняется на месте. **Блокировка** — механизм взаимного исключения. **Lock-free** — свойство прогресса некоторых конкурентных алгоритмов. **Внешняя память** — хранилище, которое не является основной ОЗУ (диск или подобное). Эта тема концептуальна для конкурентности. Не считайте её руководством писать lock-free код для промышленной системы.

## Персистентные / неизменяемые структуры

Обновление **на месте** меняет узел или ячейку массива. Старое значение исчезло.

**Неизменяемая** структура никогда не меняет опубликованный объект. «Обновление» строит новый объект. Старый объект остаётся действительным.

**Персистентная** структура позволяет использовать больше одной версии после обновлений. **Частичная персистентность** позволяет читать все старые версии и обновлять только самую новую. **Полная персистентность** позволяет обновлять старые версии (ветвящаяся история). Этот справочник фокусируется на частом случае: неизменяемые деревья, которые делят структуру.

```text
version 0:      4
               / \
              2   6

insert 5 → version 1 copies the path 4–6
              4'
             / \
            2   6'
               /
              5
node 2 is shared
```

**Структурное разделение** копирует O(высоты) узлов при обновлении дерева. Остальное дерево переиспользуется. Время и лишняя память одного обновления есть O(log n) для сбалансированного дерева, не O(n).

Полная копия массива есть O(n). Персистентный массив может использовать дерево блоков, чтобы точечное обновление копировало путь блоков.

Зачем персистентность:

- отмена и путешествие во времени
- несколько потоков могут читать версию без блокировки, если эта версия никогда не меняется
- функциональные программы передают новые отображения и сохраняют старые отображения

Стоимость: больше выделений, больше погони за указателями, больше сборки мусора. Массив на месте всё равно выигрывает для плотного числового цикла.

Не мутируйте узел, который всё ещё делят другие версии. Эта мутация изменила бы историю.

Язык может принуждать неизменяемость. Идея независима от языка: новая версия, общие неизменённые части.

## Конкурентные очереди и отображения (блокировка против lock-free, концептуально)

Больше одного потока могут вызывать операции на одной структуре. Без правила гонки разрушают структуру: потерянные обновления, сломанные ссылки, чтения наполовину записанных полей.

**Блокировка** (мьютекс) позволяет одному потоку выполнить критическую секцию. Другие потоки ждут.

```text
lock
  enqueue or map put
unlock
```

**Грубая блокировка** покрывает всю структуру. Она проста. Она ограничивает параллелизм.

**Тонкие блокировки** покрывают корзины или узлы. Больше одного потока могут работать на разных частях. Взаимная блокировка и порядок блокировок становятся вашей проблемой. Блокировки корзин хеш-отображения — частая картинка.

Алгоритмы **lock-free** используют атомарное чтение-изменение-запись (например, compare-and-swap), чтобы хотя бы один поток делал прогресс, даже если другие останавливаются. Их трудно писать и трудно доказывать. Им всё равно нужна модель памяти. Эта тема не даёт рецепт lock-free.

```text
conceptual contrast
  lock:           "I own the structure for this operation"
  lock-free:      "I retry an atomic step; no thread holds a mutex"
```

**Конкурентная очередь** — частый строительный блок (очередь работ, конвейер). Заблокированное кольцо или список — верный дизайн. Lock-free очередь существует в литературе. Предпочитайте библиотечную реализацию.

**Конкурентное отображение** часто использует блокировку на шард (группу корзин) или lock-free таблицу. Resize — трудный момент: много потоков и растущий массив корзин.

Правила, которые можно использовать сейчас:

- задокументируйте, какой поток владеет структурой
- если больше одного потока пишут, используйте блокировку или известный конкурентный тип
- не обходите отображение, пока другой поток делает resize (инвалидация темы 6 плюс гонки)
- не пишите своё lock-free отображение для первого проекта

Слова прогресса (wait-free, obstruction-free) существуют. Они не нужны, чтобы верно заблокировать очередь.

Этот раздел оборонительный. Используйте его, чтобы избегать гонок данных. Не используйте его, чтобы атаковать систему.

## Сортировка во внешней памяти (данные больше ОЗУ)

**ОЗУ** держит ограниченный массив. **Внешняя память** (диск, флеш) держит остальное. **Страница** или блок диска — единица I/O. Один I/O дорог по сравнению со сравнением в ОЗУ (тема 9).

**Сортировка во внешней памяти** (внешняя сортировка слиянием) сортирует n записей, когда n не помещается в ОЗУ.

Идея:

1. Прочитайте кусок, который помещается в ОЗУ. Отсортируйте кусок. Запишите **отсортированный прогон** на диск. Повторяйте, пока весь вход не в прогонах.
2. **Слейте** k прогонов за раз в больший отсортированный прогон. Используйте k-путевое слияние (куча следующей записи из каждого прогона).
3. Повторяйте проходы слияния, пока не останется один отсортированный файл.

```text
RAM holds 3 pages
input: 12 pages
pass 0: write 4 sorted runs of 3 pages
pass 1: merge to fewer, longer runs
...
output: 1 sorted file
```

Число проходов зависит от n, размера ОЗУ и ширины слияния k. k ограничен тем, сколько голов прогонов вы можете держать в ОЗУ, и дескрипторами файлов.

**Куча** (тема 10) выбирает следующий минимум среди k голов прогонов. Каждая снятая запись читает следующую запись из этого прогона (буферизованную страницами).

Не предполагайте, что можете отобразить весь файл как массив со случайным доступом. Случайный I/O на диске медленный. Последовательные чтения и записи прогонов — обычный шаблон.

B+ дерево (тема 9) — внешний индекс. Внешняя сортировка — одноразовый (или пакетный) алгоритм. Можно построить B+ дерево из отсортированных прогонов.

Считайте **I/O**, не только сравнения, когда судите внешний алгоритм.

Если данные помещаются в ОЗУ, используйте сортировку в памяти. Внешняя сортировка — для случая переполнения.

## Реализуйте: динамический массив, хеш-отображение, BST, куча, BFS/DFS

Реализуйте эти пять частей на языке, который вы знаете. Не копируйте полное решение из этого справочника. В справочнике нет решений. Используйте более ранние темы как контракты.

**1. Динамический массив** (тема 2). Поля: буфер, длина, ёмкость. Операции: get, set, append, вставка в i, удаление в i. Растите постоянным множителем. Отвергайте индексы за границами. Обходите только до длины.

**2. Хеш-отображение** (темы 5–6). Цепочек достаточно. Операции: get, put, delete, size. Делайте resize, когда коэффициент заполнения проходит порог. Ключи должны быть хешируемыми и стабильными. Напишите тесты на коллизию, отсутствующий ключ и перезапись.

**3. BST** (тема 8). Операции: поиск, вставка, удаление (три случая), обход in-order. Проверьте вырожденный порядок вставки и смешанный порядок. Можно пропустить AVL. Укажите, что высота может быть линейной.

**4. Куча** (тема 10). Двоичная мин-куча в массиве. Операции: insert, peek-min, extract-min, build-heap. Используйте формулы индексов с нуля. Проверьте extract пустого как ошибку.

**5. BFS и DFS** (темы 4 и 11). Список смежности. BFS: очередь, dist, parent, невзвешенный кратчайший путь. DFS: рекурсия или явный стек, обнаружение ориентированного цикла или топологическая сортировка на DAG. Проверьте сетку или маленький граф с циклом и без цикла.

Пишите тесты до того, как назовёте структуру готовой. Тесты — не решения. Они — проверки.

Предлагаемый порядок совпадает с путём: массив, затем хеш-отображение, затем BST, затем куча, затем BFS/DFS.

Можно добавить Union-Find, бор или дерево отрезков после пяти. Это лишнее.

Не тратьте первую неделю на lock-free отображение или промышленное B+ дерево. Завершите пять.

## Обзор темы

Эти вопросы не повторяют вопросы в разделах выше. Они покрывают всю тему.

### Вопросы

#### Теоретические вопросы

1. Как неизменяемость и грубая блокировка обе снижают гонки, и чем различаются их стоимости?
2. Почему B+ деревья (тема 9) и внешняя сортировка обе заботятся о страницах?
3. В каком порядке вы реализуете пять частей, и какую тему каждая часть использует?
4. Что настоящий HashMap или skiplist добавляет, чего опускает учебная структура?
5. Когда вы отказываетесь писать lock-free код и используете блокировку или библиотеку вместо этого?

#### Простые практические задания

1. Напишите одностраничную шпаргалку: персистентное, делить путь, блокировка, lock-free, прогон, k-путевое слияние, пять реализаций, одно настоящее чтение.
2. Нарисуйте пару персистентных деревьев, заблокированную очередь и два дисковых прогона.
3. Составьте таблицу: «Задача», «Сделано (да/нет)». Добавьте пять реализаций и одно чтение.
4. Перечислите четыре дефекта: мутировать общий персистентный узел, обходить отображение во время resize на двух потоках, mmap-сортировать огромный файл случайно, пропустить тесты.

#### Средние практические задания

1. Напишите личный лабораторный план на две недели: дни на каждую реализацию, один день на заметку чтения.
2. Спроектируйте крошечный конвейер: потоки-производители, заблокированная очередь, потребитель, который вставляет в ваше хеш-отображение. Напишите область блокировки.
3. Напишите бюджет I/O для внешней сортировки N страниц с M страницами ОЗУ (только символы).

#### Сложные практические задания

1. Завершите пять реализаций и карточку заметок. Сохраните их в своём репозитории. В этом справочнике по-прежнему нет решений.
2. Прочитайте CLRS, Sedgewick, VisuAlgo или CP-Algorithms для одной структуры, которую вы реализовали. Напишите карту терминов из десяти строк.

# 6. Файлы и права

## Описание

Файловая система — абстракция ОС для именованных постоянных данных. Эта тема объясняет файлы, каталоги, пути и inode Unix. Вы изучаете жёсткие ссылки и символические ссылки, биты прав и дескрипторы файлов. Вы также изучаете вызовы `open`, `read`, `write`, `close` и `lseek`.

Завершите эту тему после процессов и виртуальной памяти. Дескриптор файла живёт в процессе. Завершите эту тему до раскладки файловой системы на диске (тема 7).

Используйте один термин для каждого понятия. Файл — именованный inode с данными. Каталог — файл, который отображает имена на номера inode. Путь — строка имён. Дескриптор файла — целое в одном процессе. Жёсткая ссылка — другое имя того же inode. Символическая ссылка — маленький файл, который хранит путь. Не смешивайте путь с inode. Не смешивайте дескриптор файла с номером inode.

## Файл, каталог, путь, inode

Файл — объект, который ОС именует и который программа читает или пишет. В Unix файл — не только документ. Каталог, узел устройства, сокет и именованный канал — файлы в смысле inode. Тип — поле inode.

Каталог — файл, который хранит список имён. Каждое имя указывает на номер inode. Ядро использует каталог, чтобы разрешить путь.

Путь — последовательность имён, которую ядро обходит. Имена разделены `/` в Unix. Путь `/home/ada/notes.txt` значит: начать с корневого каталога, затем `home`, затем `ada`, затем `notes.txt`.

Inode — запись ядра и на диске об одном файле. Inode хранит тип, биты прав, размер, метки времени, счётчик ссылок и указатели на данные. Ядро не хранит полный путь внутри inode. Многие пути могут достичь одного inode (жёсткие ссылки).

Абсолютный путь начинается с `/`. Ядро начинает обход с корня процесса. Относительный путь не начинается с `/`. Ядро начинает обход с текущего рабочего каталога (CWD). `chdir` меняет CWD. Потомок наследует CWD при `fork`. `exec` сохраняет CWD.

`.` — текущий каталог в пути. `..` — родительский каталог. У корня `..` — корень.

`PATH` — не путь файловой системы файла. `PATH` — список каталогов, в которых оболочка ищет имя команды.

Пользовательские программы видят дерево. Дерево начинается с `/`. Монтирование может прикрепить другую файловую систему к каталогу. Тема 7 покрывает монтирования.

Не думайте о файле как о «байтах на одном секторе диска». Файл — inode плюс блоки данных плюс хотя бы одно имя в каталоге (кроме некоторых безымянных объектов).

## Жёсткая ссылка и символическая ссылка

Жёсткая ссылка — запись каталога, которая именует inode. Две жёсткие ссылки на один inode — два имени одного файла. Они делят размер, данные и права. `ln` без `-s` создаёт жёсткую ссылку. `stat` показывает один номер inode. Счётчик ссылок в inode растёт.

Нельзя сделать жёсткую ссылку на каталог в большинстве систем Unix (или только `root` может в особых случаях). Нельзя сделать жёсткую ссылку через файловые системы. Номер inode уникален на файловую систему.

Символическая ссылка (symlink) — маленький файл, который хранит путь. `ln -s` её создаёт. `ls -l` показывает `->`. Когда программа открывает путь по обычным правилам, ядро обходит цель. `readlink` читает сохранённый путь. `lstat` даёт факты о самой symlink. `stat` по умолчанию следует по ссылке.

Symlink может указывать на отсутствующую цель (висячая ссылка). Symlink может пересекать файловые системы. Symlink может образовать цикл. У ядра есть предел обхода (`ELOOP`).

`unlink` или `rm` удаляет имя. Для жёсткой ссылки inode и данные остаются, пока счётчик ссылок не станет 0 и ни один процесс не держит файл открытым. Для symlink `rm` удаляет symlink. Цель остаётся.

Не используйте symlink как блокировку. Не следуйте по ненадёжным symlink в привилегированном каталоге без осторожности (`O_NOFOLLOW`).

## Права и дескрипторы файлов

Биты прав Unix сидят на inode. `ls -l` показывает строку вроде `-rw-r--r--`. Первый символ — тип. Следующие девять символов — владелец, группа и остальные, у каждого чтение, запись и исполнение.

Ядро проверяет эффективный идентификатор пользователя и идентификаторы групп процесса (тема 11) против владельца и группы inode. Исполнение на каталоге значит, что вы можете пройти сквозь него. Чтение на каталоге значит, что вы можете перечислить имена.

`chmod` меняет биты. `chown` меняет владельца. `umask` маскирует биты, когда процесс создаёт файл. Типичный `umask` `022` делает файлы `644` и каталоги `755`, если режим создания просил `666` или `777`.

Есть дополнительные биты: setuid, setgid и sticky-бит. setuid на исполняемом может поднять эффективный UID (тема 11). Sticky-бит на `/tmp` ограничивает unlink файлов других пользователей.

Дескриптор файла (FD) — маленькое целое в одном процессе. `0` — stdin, `1` — stdout, `2` — stderr. `open` возвращает следующий свободный FD. Таблица FD процесса указывает на объект файла ядра. У этого объекта есть смещение и слово флагов состояния. Два FD в двух процессах могут указывать на один объект файла ядра после `fork`. Два вызова `open` создают два смещения.

`ls -l` — не таблица FD. `ls -l` — inode и имя. `lsof` или `/proc/self/fd` показывает FD.

Права проверяются при `open` (и при некоторых поздних операциях). Процесс, у которого уже есть FD, может делать `read` после того, как `chmod` убрал доступ для новых открытий. Это стандартное правило Unix.

Не выполняйте повседневную работу как UID 0. Не ставьте файлам `0777`, чтобы «заработало».

## `open`, `read`, `write`, `close`, `lseek`

Эти пять вызовов — ядро файлового API Unix.

`open` принимает путь и флаги. `O_RDONLY`, `O_WRONLY` и `O_RDWR` задают доступ. `O_CREAT` создаёт. `O_TRUNC` ставит размер в 0. `O_APPEND` заставляет записи идти в конец. `open` возвращает FD или `-1` и `errno`. Всегда проверяйте возврат.

`read` копирует до `n` байт из FD в буфер. Возврат — число байт, `0` на конце файла или `-1` при ошибке. Короткое чтение нормально. Канал и сокет часто возвращают меньше `n`. Файл на диске тоже может вернуть меньше. Циклите, пока не наберёте достаточно байт или пока EOF.

`write` копирует байты из буфера в FD. Короткое письмо тоже возможно. Циклите. `write` в полный канал может блокироваться. `write` не всегда попадает на устройство. Кэш страниц может держать данные (тема 7). Используйте `fsync`, когда нужна долговечность.

`close` отпускает FD. Объект файла ядра живёт, пока не закрыт последний FD, который на него указывает. После `close` это целое могут повторно использовать. Не используйте закрытый FD.

`lseek` ставит смещение файла для FD, которые это поддерживают. `SEEK_SET`, `SEEK_CUR` и `SEEK_END` — откуда. Каналы, сокеты и многие устройства не поддерживают `lseek` (`ESPIPE`). Записи `O_APPEND` всё равно идут в конец, даже если вы делаете seek.

`pread` и `pwrite` читают или пишут по смещению, не меняя смещение FD. Они помогают, когда потоки делят FD.

Не игнорируйте `EINTR`. Сигнал может прервать `read` или `write`. Повторите или обработайте ошибку.

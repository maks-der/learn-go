# 19. Дополнения IPv4 и маршрутизация IPv6

## Описание

Эта тема добавляет поведения IPv4 и IPv6, которые первые темы адресации и маршрутизации только назвали. Она показывает ICMP redirect, обнаружение MTU пути, объявления маршрутизатора IPv6 и обнаружение дубликатов адресов, unique local адреса и инструменты перехода NAT64 и 464XLAT на уровне осведомлённости.

Используйте один термин для каждого понятия. Redirect говорит хосту лучший следующий хоп на том же канале. MTU пути — наименьший MTU на пути. Завершите эту тему после IPv4, IPv6, маршрутизации и превью MTU.

Практикуйтесь в LAN, которой владеете. Захватывайте ICMPv6 RA, если LAN их отправляет. Не затопляйте ping. Не меняйте рабочие sysctl PMTU без отката.

## ICMP redirect

Маршрутизатор может отправить ICMP redirect (IPv4) или ICMPv6 redirect. Сообщение говорит хосту: для этого назначения используйте другой следующий хоп на том же канале. Маршрутизатор первого хопа — не лучший первый хоп.

Пример: два маршрутизатора в одной LAN. Хост использует маршрутизатор A как по умолчанию. Пакет для префикса P должен идти к маршрутизатору B. A отправляет redirect. Хост может добавить маршрут хоста или маршрут префикса к B.

Многие хосты игнорируют redirect или ограничивают их. Злоумышленники в LAN могут отправлять ложные redirect. Значения современных ОС по умолчанию осторожны. Не полагайтесь на redirect как на чистый проект. Используйте верный маршрут по умолчанию или более конкретный маршрут.

Не включайте «accept redirects» на хосте в недоверенной LAN, если не знаете риск. Не используйте redirect как единственный способ направлять центр данных. Используйте протоколы маршрутизации или статические маршруты, которые документируете.

Захват показывает тип 5 на ICMP IPv4 в обычном случае. Wireshark называет сообщение. Вы уже встречали echo и time exceeded в теме 6.

## Обнаружение MTU пути

Обнаружение MTU пути (PMTUD) находит наименьший MTU на пути, чтобы отправитель мог избежать размера, который хоп не может нести.

PMTUD IPv4: отправитель ставит бит Don't Fragment (DF). Хоп, которому нужно фрагментировать, отбрасывает пакет и должен отправить ICMP destination unreachable, fragmentation needed, со следующим MTU. Отправитель уменьшает размер.

IPv6: маршрутизаторы не фрагментируют. Хоп отправляет ICMPv6 Packet Too Big. Источник уменьшает. Тема 3 это превьюировала.

Межсетевой экран, который отбрасывает эти сообщения ICMP, вызывает чёрную дыру PMTU: маленькие пакеты работают, большие сегменты TCP зависают. Тема 6 уже предупреждала. Исправление — разрешить нужный ICMP, или зажать MSS, или поставить безопасный MTU на туннеле. Зажим MSS — обычный трюк middlebox для TCP.

Не выключайте DF на IPv4 как первый рабочий ремонт. У фрагментации свои неисправности. Не ставьте MTU IPv6 1280 на каждой LAN без причины. 1280 — минимум IPv6, который путь должен поддерживать.

Туннели (VPN, GRE) добавляют заголовки. Эффективный MTU падает. Пользователи тогда видят неисправности PMTU после того, как «только добавили VPN».

Ping большого размера с DF (IPv4) — лабораторный тест. Не затопляйте. Не тестируйте в сети, которой не владеете.

## RA / DAD IPv6

Объявление маршрутизатора (RA) — сообщение ICMPv6. Маршрутизатор отправляет его периодически и в ответ на запрос маршрутизатора (RS). RA может нести префиксы, флаги (M, O), MTU и параметры рекурсивного DNS. Тема 5 представила SLAAC. Этот раздел добавляет вид плоскости управления.

Хосты используют RA, чтобы:

- выбрать маршрутизатор по умолчанию (источник RA, link-local адрес)
- формировать адреса через SLAAC, когда префикс это позволяет
- узнать, запускать ли DHCPv6
- узнать серверы DNS, когда есть RDNSS

Обнаружение дубликатов адресов (DAD) идёт, прежде чем хост использует адрес IPv6. Хост отправляет neighbor solicitation для своего предварительного адреса. Если другой хост отвечает, адрес дубликат. Хост не должен его использовать.

Не отключайте RA в LAN и потом ждите глобальный IPv6. Не запускайте два маршрутизатора, которые объявляют конфликтующие префиксы, без проекта. Не пропускайте DAD в реализации, которую пишете.

Враждебный RA в недоверенной LAN может украсть маршрут по умолчанию. RA guard на коммутаторах — идея укрепления. Тема 21 вернётся к недоверенным сетям.

Windows, macOS и Linux все обрабатывают RA по умолчанию. Фильтр захвата `icmpv6` их показывает.

## Unique local адреса

Unique local адреса (ULA) — адреса IPv6 в `fc00::/7`. Обычная практика — `fd00::/8` со случайным 40-битным глобальным ID, затем 16-битная подсеть, затем 64-битный ID интерфейса. ULA — для локальных связей. Это не то же самое, что link-local `fe80::/10`. ULA может маршрутизироваться внутри одной организации через много каналов. Link-local не может.

ULA — двоюродный брат RFC 1918 по духу, не по битам. Не думайте, что ULA немаршрутизируем в Internet по волшебству. Операторы не должны объявлять ULA в публичный Internet. Маршрут IPv6 по умолчанию всё равно может попытаться. Политика должна это остановить.

У хоста могут быть ULA и глобальные адреса одновременно. Happy Eyeballs и выбор адреса по умолчанию выбирают источник и назначение. Назначение только ULA не будет работать из публичного Internet.

Не берите `fd00::1` для каждой лаборатории. Рандомизируйте глобальный ID, чтобы два слитых сайта не столкнулись. Не используйте ULA как единственный адрес на сервере, который должен быть публичным.

Префикс документации `2001:db8::/32` — не ULA. Не смешивайте их.

## Переход: NAT64, 464XLAT (осведомлённость)

Хосты IPv4 и IPv6 всё ещё должны говорить в долгую эру двойного стека. Инструменты перехода переводят или инкапсулируют. Этот раздел — осведомлённость.

NAT64 позволяет клиенту только IPv6 достичь сервера только IPv4. У переводчика есть префикс IPv6 (часто `64:ff9b::/96` для общеизвестного). Адрес IPv4 встраивается в назначение IPv6. DNS64 синтезирует записи AAAA из записей A, чтобы клиент открывал IPv6 к переводчику.

464XLAT использует NAT64 плюс клиентский CLAT. CLAT даёт IPv4 локальным приложениям, которые не умеют IPv6. Мобильные сети используют это, чтобы приложение только IPv4 всё ещё работало на радио только IPv6.

Другие имена, которые можете увидеть: 6to4, Teredo, DS-Lite, MAP. Многие устаревшие или специфичные для провайдера. Не включайте случайные туннели на рабочем ПК.

Не считайте NAT64 причиной пропустить IPv6 на серверах, которые можете сделать двойным стеком. Не забывайте, что перевод ломает некоторые протоколы, которые несут адреса в полезной нагрузке.

SIIT — перевод IP/ICMP без состояния. NAT64 часто с состоянием для портов. Вам нужно только: только IPv6 плюс мир IPv4 нуждается в переводчике или двойном стеке.

# 4. Запросы к документам

## Описание

Эта тема показывает, как формировать результаты find. Вы проецируете поля, сортируете, пропускаете, ограничиваете и используете курсоры. Также запрашиваете вложенные документы и массивы. Сначала завершите тему CRUD.

Используйте один термин для каждого понятия. **Проекция** выбирает поля в результате. **Sort** задаёт порядок. **Skip** и **limit** листают результат. **Курсор** — итератор, который сервер использует для `find`. **Точечная нотация** именует поле внутри вложенного документа или массива.

Не запускайте неограниченный `find` в приложении. Всегда думайте о лимите, фильтре и индексах.

## Проекция (включить / исключить поля)

Проекция — второй аргумент `find` (или помощник `.project()`). Она выбирает, какие поля вернёт сервер.

Режим включения: полям ставят `1`.

```javascript
db.items.find({ qty: { $gt: 0 } }, { name: 1, qty: 1 })
```

`_id` включён, пока его не исключить:

```javascript
db.items.find({}, { name: 1, _id: 0 })
```

Режим исключения: полям ставят `0`.

```javascript
db.items.find({}, { notes: 0 })
```

Нельзя смешивать включение и исключение обычных полей в одной проекции. Можно исключить `_id`, включая другие поля. Это обычное исключение.

Проекция уменьшает сетевую нагрузку. Она не меняет хранимый документ. Меньшая проекция может сделать запрос **покрытым**, если индекс держит все возвращаемые поля. Это следующая тема о производительности.

Не проецируйте хеш пароля в публичный API. Проекция — часть безопасности чтения.

`findOne` принимает проекцию так же.

## Sort, skip, limit

`sort` упорядочивает курсор. Передают поля и направление: `1` — по возрастанию, `-1` — по убыванию.

```javascript
db.items.find().sort({ qty: -1 })
```

`limit` задаёт максимальное число документов, которое вернёт курсор.

```javascript
db.items.find().sort({ qty: -1 }).limit(10)
```

`skip` пропускает столько документов в порядке сортировки, затем возвращает остальные (или лимит).

```javascript
db.items.find().sort({ name: 1 }).skip(20).limit(10)
```

Сортировка использует значения полей и порядок типов BSON. Отсутствующие поля и смешанные типы могут удивить. Держите типы стабильными.

Большой `skip` дорог. Сервер всё равно проходит пропущенные документы. Для глубоких страниц используйте диапазонный фильтр по ключу сортировки (`qty < lastQty`) вместо большого skip.

Сортировка может использовать индекс. Сортировка, которая не совпадает с индексом, может упасть или сильно использовать память. У сервера есть лимит памяти сортировки. Индексы и `allowDiskUse` для агрегации — в следующих темах.

Всегда задавайте `sort`, когда используете `skip` и `limit`. Без сортировки порядок страниц — не стабильный контракт.

## Курсоры

`find` возвращает **курсор**. Курсор — не полный набор результатов в памяти клиента. Сервер отправляет **пакеты**. Когда клиенту нужно больше документов, он отправляет `getMore`.

В `mongosh` печать `find()` показывает первый пакет. Можно итерировать:

```javascript
const c = db.items.find({ qty: { $gt: 0 } })
c.forEach((doc) => { print(doc.name) })
```

Помощники курсора включают `hasNext`, `next`, `toArray`, `limit`, `sort` и `project`. `toArray` загружает все оставшиеся документы в память. Не вызывайте `toArray` на неограниченном результате.

Курсор может **истечь** на сервере, если клиент его не потребляет. Таймаут простоя по умолчанию — 10 минут во многих развёртываниях. Tailable-курсоры — особый случай (capped-коллекции, change streams).

Можно задать размер пакета. Маленький пакет увеличивает число обменов. Огромный пакет увеличивает память.

Закрывайте курсор, когда останавливаетесь рано в драйвере. `mongosh` часто закрывает его за вас в конце скрипта.

`explain` на курсоре показывает план. Используйте его при изучении индексов.

## Вложенные документы и точечная нотация

Вложенный документ — поле, значение которого — документ.

```javascript
{
  name: "Ann",
  addr: { city: "Oslo", zip: "0001" }
}
```

**Точечная нотация** именует путь: `"addr.city"`.

Равенство по целому вложенному документу требует точного совпадения полей и в некоторых случаях порядка. Для одного поля предпочитайте точечную нотацию:

```javascript
db.people.find({ "addr.city": "Oslo" })
```

Запрос `{ addr: { city: "Oslo" } }` может не совпасть, если у `addr` ещё есть `zip`. Фильтр значит «addr равен этому точному документу».

Можно `$set` вложенное поле тем же точечным путём. Можно проецировать вложенное поле тем же путём.

Массивы вложенных документов тоже используют точечную нотацию: `"items.sku"`. Этот запрос совпадает, если **любой** элемент массива имеет `sku` с этим значением. Следующий раздел покрывает `$elemMatch`, когда два поля должны совпасть на **одном** элементе.

Не используйте точку в имени поля приложения. Точка — разделитель пути.

## Запросы к массивам: `$elemMatch`, `$size`, `$all`

Массивам нужны особые операторы, когда совпадение — не одно равенство.

**Равенство полному массиву** использует `{ tags: ["a", "b"] }`. Важны порядок и точное содержимое.

**Равенство одному элементу** использует `{ tags: "a" }`. Документ совпадает, если любой элемент равен `"a"`.

`$all` совпадает, если массив содержит все перечисленные значения (в любом порядке):

```javascript
db.posts.find({ tags: { $all: ["db", "mongo"] } })
```

`$size` совпадает с точной длиной:

```javascript
db.posts.find({ tags: { $size: 3 } })
```

`$size` не принимает диапазон. Для диапазона длин храните `tagCount` или используйте агрегацию.

`$elemMatch` требует, чтобы **один** элемент массива совпал со всеми условиями:

```javascript
db.orders.find({
  lines: { $elemMatch: { sku: "nail", qty: { $gte: 10 } } }
})
```

Без `$elemMatch` запрос `{ "lines.sku": "nail", "lines.qty": { $gte: 10 } }` может совпасть с **двумя разными** элементами.

Можно сочетать `$elemMatch` с проекцией, чтобы вернуть только совпавший элемент (позиционная проекция `$` или `$elemMatch` в проекции). Читайте текущее руководство для формы, которую используете.

## Регулярные выражения (осторожно с индексами)

Строки можно сопоставлять регулярным выражением.

```javascript
db.items.find({ name: /nail/i })
db.items.find({ name: { $regex: "nail", $options: "i" } })
```

`i` делает совпадение без учёта регистра.

Регулярное выражение, которое не является префиксным совпадением, часто **плохо использует индекс**. Ведущий `.*` заставляет сканировать много значений. Префиксное выражение вроде `/^nail/` чаще может использовать индекс по `name`.

Поиск без учёта регистра без collation или нормализованного поля тоже может обойти простой индекс. Atlas Search лучше подходит для богатого текстового поиска. Это следующая тема.

Не передавайте сырой текст пользователя в regex без экранирования спецсимволов. Пользователь может написать шаблон, который медленный (атака сложности) или совпадает слишком широко.

Предпочитайте точное совпадение или `$in`, когда знаете полную строку. Для простого равенства без учёта регистра предпочитайте нормализованное поле в нижнем регистре.

Проверяйте regex-запросы через `explain`. Если на большой коллекции видите `COLLSCAN`, измените запрос или добавьте лучшее поле.

# 4. Маршрутизация, ICMP и NAT

## Описание

Маршрутизация — выбор следующего хопа для пакета. ICMP сообщает о сетевых ошибках и поддерживает `ping` и `traceroute`. NAT переводит адреса на краю. Эта тема показывает таблицу маршрутизации и самое длинное совпадение префикса. Вы узнаете ICMP, `ping` и `traceroute`. Вы получите обзор статической и динамической маршрутизации. Вы узнаете source NAT, перенаправление портов и боль одноранговых связей. Вы узнаете carrier-grade NAT на уровне осведомлённости.

Завершите эту тему после адресов IPv4 и IPv6. Завершите эту тему до глубокого изучения UDP и TCP.

Используйте один термин для каждого понятия. Маршрут — префикс плюс следующий хоп или исходящий интерфейс. Таблица маршрутизации — список маршрутов, которые использует устройство. ICMP — протокол управления рядом с IP. Source NAT меняет исходный адрес пакетов, которые покидают LAN. Перенаправление портов сопоставляет публичный порт с частным хостом. Не смешивайте таблицу маршрутизации с таблицей ARP. Не смешивайте NAT с полным межсетевым экраном.

Вы уже знаете шлюз по умолчанию. Эта тема кладёт этот шлюз в таблицу вместе с другими префиксами.

## Таблица маршрутизации и самое длинное совпадение префикса

Таблица маршрутизации сопоставляет префикс назначения со следующим хопом и интерфейсом. Ядро ищет IP назначения каждого пакета. Ядро выбирает один маршрут. Затем ядро использует ARP или neighbor discovery для следующего хопа, если следующий хоп в LAN.

Таблица хоста часто мала: локальная подсеть, маршрут по умолчанию, loopback и, возможно, VPN. Таблица маршрутизатора может быть большой. Интернет-маршрутизатор может держать сотни тысяч префиксов.

Подключённые маршруты появляются, когда у интерфейса есть адрес и маска. Назначение в этой подсети локально. Следующий хоп — не маршрутизатор. Хост отправляет на MAC назначения.

Когда два маршрута совпадают с одним назначением, устройство выбирает совпадение с самым длинным префиксом (самой конкретной маской). `/32` побеждает `/24`. `/24` побеждает `/0`.

Пример: назначение `192.168.1.50`. Маршруты: `0.0.0.0/0` через G1, `192.168.1.0/24` через интерфейс LAN, `192.168.1.50/32` через G2. Хостовой маршрут `/32` побеждает.

Самое длинное совпадение префикса — не то же самое, что наименьшая метрика. Если у двух маршрутов одна длина префикса, устройство использует метрику, предпочтение или разделение с равной стоимостью. Детали зависят от ОС.

IPv6 использует ту же идею. `::/0` — по умолчанию. `/128` — хостовой маршрут.

В Linux `ip route` показывает IPv4. `ip -6 route` показывает IPv6. В Windows `route print` показывает оба в одном виде.

Не правьте продакшен-таблицу маршрутизации без плана. Не добавляйте маршрут по умолчанию на неверный следующий хоп. Можно обрезать свой путь управления. Не считайте, что меньшая метрика бьёт более длинный префикс. Длина префикса в обычной модели первая.

## ICMP, `ping`, `traceroute`

ICMP — Internet Control Message Protocol. IPv4 использует ICMP. IPv6 использует ICMPv6. Хосты и маршрутизаторы отправляют ICMP, чтобы сообщить об ошибках и поддержать инструменты. ICMP в обычном дизайне не транспорт для данных вашего приложения.

`ping` отправляет echo request. Цель может отправить echo reply. Ответ доказывает, что этот зонд достиг стека, который отвечает на ICMP. Отсутствующий ответ — не всегда «хост выключен». Межсетевой экран может отбрасывать echo. Хост всё равно может обслуживать HTTPS.

`traceroute` (Linux) и `tracert` (Windows) картируют хопы. Инструмент отправляет зонды с растущим TTL (IPv4) или hop limit (IPv6). Каждый хоп, который уменьшает значение до нуля, может отправить Time Exceeded. Источник узнаёт адрес этого хопа. Звёзды значат нет ответа ICMP. Путь всё равно может работать для TCP.

Path MTU discovery использует ICMP Packet Too Big (или IPv4 fragmentation needed). Политика, которая отбрасывает весь ICMP, может сломать большие передачи.

ICMPv6 обязателен для neighbor discovery. Правило «отбросить весь ICMP» на IPv6 — серьёзная неисправность.

Не считайте успешный ping доказательством, что порт TCP открыт. Не считайте звёзды traceroute сломанным Internet. Не заливайте ping на хост, которым не владеете.

## Статическая и динамическая маршрутизация (обзор)

Статический маршрут — маршрут, который пишет администратор. Шлюз по умолчанию на домашнем хосте часто статический или установлен DHCP. Статический маршрут не учит новый путь, когда канал умирает, пока человек или скрипт его не сменит.

Динамический протокол маршрутизации позволяет маршрутизаторам обмениваться сведениями о префиксах. Внутри одной организации OSPF и IS-IS — обычные протоколы состояния канала. Они затопляют топологию и считают пути. RIP — старый протокол вектора расстояния. Его можно увидеть в лабораториях.

Между организациями в Internet обычный протокол — BGP. Тема 14 покрывает BGP на высоком уровне. Этот раздел только называет его.

Динамическая маршрутизация нужна лишний CPU, лишняя настройка и модель доверия. Маленькая лаборатория из двух маршрутизаторов может остаться статической. Большой сети нужна динамическая маршрутизация, чтобы отказ одного канала не ждал человека.

DHCP может установить маршрут по умолчанию на хосте. Этот маршрут — не OSPF. У хоста всё равно таблица, похожая на статическую. Источник маршрута — DHCP.

Не запускайте динамический протокол в домашней LAN без плана. Не анонсируйте частные префиксы в публичный Internet. Не смешивайте «маршрут есть» с «у пути есть ёмкость».

## Source NAT, перенаправление портов, боль одноранговых связей

Source NAT переписывает исходный IP пакета, который покидает внутреннюю сеть. Masquerade — source NAT, который использует текущий адрес исходящего интерфейса. Домашние маршрутизаторы делают эту работу, чтобы много частных хостов делили один публичный адрес IPv4.

Ящик также переписывает исходный порт, когда два внутренних хоста столкнулись бы. Ящик хранит сопоставление: внутренний IP, внутренний порт, внешний IP, внешний порт, протокол и часто удалённый сосед. Обратные пакеты совпадают с сопоставлением. Ящик переписывает назначение обратно на внутренний хост.

Сопоставление stateful. Если сопоставление истекает, поздний ответ не достигает внутреннего хоста. Таймауты простоя различаются для UDP и TCP.

Перенаправление портов (destination NAT) сопоставляет публичный порт с частным хостом и портом. Входящее соединение на публичный адрес и этот порт идёт на внутренний сервер. Без сопоставления или строки исходящего состояния новое входящее соединение не достигает частного хоста.

Одноранговые приложения хотят, чтобы два хоста за NAT говорили. Ни у одного хоста нет стабильного входящего сопоставления. Обход NAT (STUN, TURN, hole punching) пытается создать сопоставления. Часто не удаётся, когда обе стороны сидят за строгим NAT. Тогда реле несут медиа.

NAT — не полный межсетевой экран. Stateful-экран может сидеть в том же ящике. Держите две задачи раздельно в заметках. NAT — не прокси. Прокси понимает приложение.

Не считайте NAT шифрованием. Не ждите входящий SSH на хост LAN без перенаправления или туннеля. Не путайте source NAT с dest NAT.

## Carrier-grade NAT (осведомлённость)

Carrier-grade NAT (CGNAT или CGN) — NAT в сети ISP. Много клиентов делят пул публичных адресов IPv4. Домашний маршрутизатор всё равно может делать NAT. Тогда у вас два слоя NAT: домашний NAT плюс CGNAT.

CGNAT ломает входящее перенаправление портов на домашнем ящике для публичного Internet. Публичный адрес, который показывает веб-страница, может принадлежать общему пулу. Перенаправление порта на WAN IP дома никогда не видит пакет.

ISP используют CGNAT, потому что публичные адреса IPv4 дефицитны. IPv6 избегает этого деления, когда у обоих концов есть IPv6. Dual stack может использовать IPv6 для одноранговых связей, пока IPv4 остаётся за CGNAT.

Факты осведомлённости:

- вы можете не получить выделенный публичный адрес IPv4
- журналы на сервере показывают общий адрес
- отчёты о злоупотреблениях могут назвать много клиентов сразу
- IPv6 или туннель могут вернуть входящую достижимость

Не считайте, что «у меня есть домашний маршрутизатор» значит уникальный публичный адрес IPv4. Не покупайте план перенаправления портов, пока не проверите, публичный ли и выделенный ли адрес WAN.

Этот раздел — осведомлённость. Вы не настраиваете ящик CGNAT у ISP.

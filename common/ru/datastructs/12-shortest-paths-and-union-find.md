# 12. Кратчайшие пути и Union-Find

## Описание

Эта тема объясняет взвешенные кратчайшие пути и структуру непересекающихся множеств. Вы изучаете Дейкстру, Беллмана–Форда, релаксацию DAG, массив parent Union-Find, объединение по рангу, сжатие пути, Краскала как клиента Union-Find и идею Краскала и Прима для минимального остовного дерева.

Завершите эту тему после графов, куч и массивов.

Используйте один термин для каждого понятия. **Релаксация** обновляет предварительное расстояние, когда появляется лучший путь. **Неотрицательный** вес больше или равен 0. **Отрицательный цикл** — ориентированный цикл, сумма весов которого отрицательна. **Union-Find** хранит разбиение n элементов. **Find** возвращает представителя элемента. **Union** сливает два множества. **MST** — минимальное остовное дерево.

## Дейкстра и Беллман–Форд

**Релаксация** ребра u → v с весом w:

```text
if dist[v] > dist[u] + w:
  dist[v] = dist[u] + w
  parent[v] = u
```

Оба алгоритма используют релаксацию. Они различаются порядком рёбер и правилами весов.

**Дейкстра** вычисляет расстояния от s, когда **все веса неотрицательны**.

Идея:

1. Поставьте dist[s] = 0 и dist[v] = ∞ для v ≠ s.
2. Держите множество установленных вершин (точный метод использует мин-очередь с приоритетом неустановленных вершин).
3. Извлеките неустановленную вершину u с наименьшим dist[u]. Установите u.
4. Расслабьте каждое исходящее ребро u.

```text
s=A
A --1--> B --3--> C
A --4--> C

dist: A=0, B=1, C=min(4, 1+3)=4
```

С двоичной кучей время есть O((n + m) log n) на списке. Каждая вершина извлекается один раз, если вы не вставляете снова. Некоторые реализации разрешают больше одной записи очереди на вершину.

Дейкстра неверна, когда отрицательное ребро может улучшить путь после того, как вы установили вершину. Не используйте Дейкстру на графах, в которых могут быть отрицательные веса.

**Беллман–Форд** разрешает отрицательные веса. Он запрещает **отрицательный цикл**, достижимый из s, если нужны конечные расстояния.

Идея:

1. Поставьте dist[s] = 0 и dist[v] = ∞ для v ≠ s.
2. Повторите n − 1 раз: расслабьте каждое ребро.
3. Ещё один проход: если ребро всё ещё релаксирует, достижим отрицательный цикл.

Время есть Θ(n m).

Беллман–Форд медленнее. Это верный выбор по умолчанию, когда веса могут быть отрицательными.

Восстановите путь с parent[], как в BFS. Если dist[t] всё ещё ∞, t недостижима.

## Релаксация DAG

У DAG нет ориентированного цикла (тема 11). Кратчайшие пути на DAG могут использовать **один проход** в топологическом порядке.

Идея:

1. Вычислите топологический порядок.
2. Поставьте dist[s] = 0 и dist[v] = ∞ для v ≠ s.
3. Для каждой вершины u в топологическом порядке расслабьте каждое исходящее ребро u.

```text
A → B → D
A → C → D
weights on each edge

order: A, B, C, D
relax A's edges, then B's, then C's, then D's
```

Время есть Θ(n + m) после того, как есть список смежности. Этот класс совпадает с одним DFS плюс один просмотр рёбер.

Веса могут быть отрицательными. Цикла нет, поэтому отрицательного цикла нет.

Если s — не источник, который может достичь всех, некоторые значения dist остаются ∞. Вершины до s в порядке не могут помочь s. Можно начать цикл релаксации с s, или всё равно просмотреть все вершины; рёбра из недостижимых вершин не улучшают достижимые, если у этих вершин dist ∞.

Самые длинные пути на DAG используют тот же порядок с max-релаксацией или с отрицательными весами. Этому разделу нужны только кратчайшие пути.

Не используйте релаксацию DAG на графе, в котором может быть цикл. Сначала запустите проверку цикла.

Дейкстра не нужна на DAG. Топологический проход проще и обрабатывает отрицательные веса.

## Массив parent, объединение по рангу, сжатие пути

Структура **непересекающихся множеств** (Union-Find) хранит разбиение n элементов. Элементы — целые 0 .. n−1.

Массив **parent** имеет длину n. parent[i] — родитель i. Если parent[i] = i, то i — **корень**. Каждый корень называет одно множество.

В начале каждый элемент — своё множество:

```text
parent:  0  1  2  3  4
index:   0  1  2  3  4
```

**Find** без сжатия идёт parent[i], parent[parent[i]], ... пока не достигнет корня. Этот корень — представитель.

**Union** без ранга прикрепляет один корень к другому:

```text
union(a, b):
  ra = find(a)
  rb = find(b)
  if ra == rb: return
  parent[rb] = ra
```

Плохой порядок прикрепления может сделать линию. Find тогда стоит Θ(n).

**Объединение по рангу** (или по размеру) прикрепляет более короткое дерево под более высокое дерево. Ранг — верхняя оценка высоты. Высота остаётся O(log n) даже без сжатия пути.

**Сжатие пути** во время find ставит каждый пройденный узел указывать на корень. Поздние find почти константного времени.

```text
find(4) on 4 → 3 → 2 → 2 (root 2)
after compression: 4 → 2, 3 → 2
```

Вместе объединение по рангу и сжатие пути дают почти Θ(1) амортизированные find и union. Точная функция — обратная функция Аккермана. Для всех практических n считайте стоимость очень малой.

Структура — лес деревьев. Это не BST. Порядка ключей нет.

Память есть Θ(n) для parent и rank.

Не храните полный список членов в каждом множестве, если не нужно обходить членов.

## Краскал использует Union-Find

**Алгоритм Краскала** строит MST связного неориентированного взвешенного графа.

Идея:

1. Отсортируйте все рёбра по возрастанию веса.
2. Начните с пустого леса (n множеств в Union-Find).
3. Для каждого ребра u–v в отсортированном порядке: если find(u) ≠ find(v), добавьте ребро в MST и сделайте union(u, v).
4. Остановитесь, когда добавили n − 1 рёбер, или после просмотра всех рёбер.

```text
edges sorted: 1, 2, 2, 4, ...
first edge always added
later edge skipped if u and v are already in one set
that skip rejects a cycle
```

Union-Find отвечает «замыкает ли это ребро цикл?» почти за константное время. Без Union-Find вы искали бы растущий лес после каждого кандидата-ребра.

Если граф не связный, Краскал производит **минимальный остовный лес**: MST в каждой компоненте.

Время доминирует сортировка: O(m log m), плюс почти линейная работа Union-Find.

Краскал не вычисляет кратчайшие пути от одного источника. Расстояния на MST — не расстояния кратчайших путей в исходном графе.

Не запускайте Краскала на ориентированном графе как готовый MST. MST — неориентированная идея.

## MST: Краскал и Прим (идея)

**Остовное дерево** связного неориентированного графа — подмножество рёбер, которое связывает все вершины и не имеет цикла. **Минимальное остовное дерево (MST)** имеет минимальный суммарный вес среди остовных деревьев.

**Краскал** растит лес глобально самыми лёгкими рёбрами, которые не образуют цикл (предыдущий раздел).

**Прим** растит одно дерево от стартовой вершины.

Идея Прима:

1. Начните с любой вершины s. Множество дерева S = {s}.
2. Повторяйте, пока S не держит все вершины: добавьте самое лёгкое ребро, у которого один конец в S и один конец вне S. Добавьте новую вершину в S.

```text
S starts {A}
lightest edge out of S: A—B weight 1
S = {A, B}
next lightest cut edge: B—C weight 2
...
```

Двоичная куча кандидатов-рёбер или вершин с ключом (как Дейкстра) реализует Прима за O(m log n).

Прим и Краскал дают один вес MST. Дерево может различаться, когда существует несколько MST (равные веса).

**Свойство разреза** (идея): для разреза, который делит V на S и V−S, самое лёгкое ребро через разрез безопасно для некоторого MST. Прим всегда выбирает такое ребро. Добавленные рёбра Краскала тоже безопасны по похожему доводу.

Не путайте MST с деревом кратчайших путей. Дерево кратчайших путей от s минимизирует расстояния от s. MST минимизирует сумму всех рёбер дерева. Два дерева могут различаться.

```text
A--1--B--1--C
A------3------C

MST can be A—B, B—C (weight 2)
shortest path A to C can be the direct 3 or the path 2, depending on weights
here path A–B–C has length 2 < 3
```

Используйте MST для проектирования сети (связать все площадки минимальным кабелем). Используйте кратчайшие пути для поездки от одного источника.

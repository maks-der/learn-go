# 15. Алгоритмы на графах (ядро)

## Описание

Алгоритм на графе обходит вершины и рёбра, чтобы ответить на вопрос. Эта тема объясняет BFS, невзвешенный кратчайший путь, DFS, метки времени, обнаружение цикла, топологическую сортировку, Дейкстру, Беллмана–Форда, релаксацию DAG и предварительный взгляд на компоненты связности. Завершите эту тему после представления графов, очередей, стеков и куч.

Используйте один термин для каждого понятия. **Посещение** помечает вершину как найденную. **Релаксация** обновляет предварительное расстояние, когда появляется лучший путь. **Метка времени** — счётчик шагов во время DFS.

## BFS и кратчайший невзвешенный путь

**Поиск в ширину (BFS)** посещает вершины в порядке невзвешенного расстояния от старта s. BFS использует **очередь**. У каждого ребра длина 1.

Идея:

1. Поставьте dist[s] = 0. Поставьте dist[v] = ∞ для каждой другой вершины.
2. Положите s в очередь. Пометьте s как посещённую.
3. Пока очередь не пуста, снимите u. Для каждого непосещённого соседа v у u поставьте dist[v] = dist[u] + 1, пометьте v посещённой, положите v в очередь.

```text
s=0
0 — 1 — 2
    |
    3

queue order: 0, 1, 2, 3   (if neighbor order is 1 then 2 from 0, and 3 from 1)
dist: 0:0  1:1  2:1  3:2
```

Посещение при постановке в очередь — обычная невзвешенная форма. Вы помечаете v, когда впервые находите v. Это первое нахождение — кратчайший путь по числу рёбер.

Храните **parent[v] = u**, когда ставите dist[v]. Восстановите путь от s к t, идя по parent от t назад к s, затем разверните список.

BFS на неявной сетке — тот же алгоритм. Вершины — ячейки. Соседи приходят из `neighbors(cell)`.

Время — Θ(n + m) на списке смежности. Каждая вершина входит в очередь не больше одного раза. Каждое ребро просматривается константное число раз.

BFS не вычисляет взвешенные кратчайшие пути. Малый вес на длинном пути может победить. Используйте Дейкстру или Беллмана–Форда для весов.

Не используйте стек для этого порядка. Стек даёт DFS, не кратчайшие невзвешенные пути.

## DFS, метки времени, обнаружение цикла

**Поиск в глубину (DFS)** идёт так глубоко, как возможно, по одному пути, затем возвращается. DFS использует **стек вызовов** (рекурсия) или **явный стек**.

Полезный DFS записывает два времени на вершину:

- время **открытия (discover)**: шаг, когда вы впервые входите в вершину
- время **закрытия (finish)**: шаг, когда вы оставляете вершину после всех потомков

```text
dfs(u):
  time = time + 1
  disc[u] = time
  color[u] = gray
  for each neighbor v:
      if color[v] is white: dfs(v)
      else if color[v] is gray:  // back edge, directed cycle
          report cycle
  color[u] = black
  time = time + 1
  fin[u] = time
```

Цвета:

- **белый**: не открыта
- **серый**: открыта, не закрыта
- **чёрный**: закрыта

В **ориентированном** графе серый сосед — **обратное ребро**. Обратное ребро означает ориентированный цикл.

В **неориентированном** графе сосед, который является родителем, сам по себе не цикл. Серый или посещённый сосед, который не родитель, означает цикл.

```text
directed cycle:  0 → 1 → 2 → 0
dfs(0) discovers 1, then 2, then edge to gray 0
```

Метки времени упорядочивают вершины. Времена закрытия — ключ для топологической сортировки и для некоторых методов сильно связных компонент.

Время DFS — Θ(n + m) на списке смежности, если вы посещаете каждую вершину один раз (лес деревьев DFS).

Не используйте DFS, когда нужны невзвешенные кратчайшие пути. Используйте BFS.

## Топологическая сортировка

**Топологическая сортировка** DAG — список всех вершин. Для каждого ребра u → v, u появляется до v в списке. Список — допустимый порядок работ для предпосылок.

Топологическая сортировка существует тогда и только тогда, когда ориентированный граф не имеет цикла.

**Метод DFS.** Запустите DFS. После поиска перечислите вершины в убывающем времени закрытия. Этот список — топологический порядок, если граф — DAG. Если DFS находит обратное ребро, остановитесь. Топологического порядка нет.

**Метод Кана.**

1. Вычислите входящую степень каждой вершины.
2. Положите в очередь каждую вершину с входящей степенью 0.
3. Пока очередь не пуста, снимите u, добавьте u к порядку и уменьшите входящую степень каждого соседа. Если сосед достигает 0, положите его в очередь.
4. Если длина порядка меньше n, цикл существует.

```text
edges: 0→2, 1→2, 2→3
one order: 0, 1, 2, 3
also valid: 1, 0, 2, 3
```

Может существовать больше одного порядка. Любой допустимый порядок — топологическая сортировка.

Время — Θ(n + m) для обоих методов.

Не запускайте топологическую сортировку на неориентированном графе. Направление обязательно.

Используйте порядок в релаксации DAG: обрабатывайте вершины в топологическом порядке, затем релаксируйте исходящие рёбра.

## Дейкстра

**Дейкстра** вычисляет кратчайшие пути от s в ориентированном или неориентированном графе с **неотрицательными** весами рёбер.

Идея:

1. Поставьте dist[s] = 0 и dist[v] = ∞ для других вершин.
2. Положите вершины в мин-кучу по dist (или вставьте s и вставляйте других, когда находите).
3. Пока куча не пуста, извлеките вершину u с наименьшим dist. Для каждого ребра u → v веса w **релаксируйте**: если dist[u] + w < dist[v], поставьте dist[v] = dist[u] + w и обновите кучу (decrease-key или вставьте новую пару).

```text
relax(u, v, w):
  if dist[v] > dist[u] + w:
      dist[v] = dist[u] + w
      parent[v] = u
```

Когда вы извлекаете u, dist[u] финально, если все веса ≥ 0. Вам не нужно обрабатывать u снова в классической форме. Если вы используете дополнительные вставки вместо decrease-key, вы можете извлечь устаревшие пары. Пропустите пару, если её расстояние в куче хуже текущего dist[u].

```text
s=0
0 -1→ 1 -4→ 3
0 -2→ 2 -1→ 3

dist[3] = 3  (path 0-2-3)
```

Время с двоичной кучей — O((n + m) log n) в форме дополнительных вставок или O(m log n) с аккуратной формой decrease-key. Сначала выучите идею. Затем выберите один API кучи.

Не запускайте Дейкстру с отрицательным весом. Позднее извлечение может быть неверным.

Невзвешенные графы могут использовать BFS. Дейкстра всё ещё работает, если каждый вес 1, но BFS проще.

Храните parent как в BFS, чтобы восстановить пути.

## Беллман–Форд

**Беллман–Форд** вычисляет кратчайшие пути от s, когда веса рёбер могут быть **отрицательными**. Он также обнаруживает **отрицательный цикл**, достижимый из s.

Идея:

1. Поставьте dist[s] = 0 и dist[v] = ∞ для других вершин.
2. Повторите n − 1 раз: релаксируйте каждое ребро (u, v, w) в графе.
3. Сделайте ещё один проход по каждому ребру. Если какая-то релаксация всё ещё успешна, отрицательный цикл достижим из s (или из вершины, которую этот проход может улучшить). Сообщите «отрицательный цикл».

```text
for i = 1 to n - 1:
    for each edge (u, v, w):
        relax(u, v, w)
for each edge (u, v, w):
    if dist[v] > dist[u] + w:  // still improvable
        report negative cycle
```

После n − 1 успешных раундов найден кратчайший простой путь (не больше n − 1 рёбер), если отрицательный цикл не влияет на s.

Время — Θ(n m). Это медленнее Дейкстры. Используйте Беллмана–Форда, когда вес может быть отрицательным или когда нужно обнаружить отрицательный цикл.

Отрицательный цикл, который вы не можете достичь из s, не всегда важен. Определите, заботитесь ли вы обо всём графе или только о вершинах, достижимых из s.

Не используйте Беллмана–Форда как первый код кратчайшего пути. Реализуйте BFS, затем Дейкстру, затем Беллмана–Форда.

Вы можете остановиться рано, если один полный проход рёбер не делает обновления.

## Релаксация DAG

У **DAG** есть топологический порядок. Кратчайшие пути (и самые длинные пути) на DAG используют этот порядок.

**Кратчайшие пути на DAG:**

1. Вычислите топологический порядок. Если граф не DAG, остановитесь.
2. Поставьте dist[s] = 0 и dist[v] = ∞ для других вершин.
3. Для каждой вершины u в топологическом порядке релаксируйте каждое исходящее ребро u → v.

```text
order: 0, 1, 2, 3
for u in order:
    for each edge u → v:
        relax(u, v, w)
```

Каждое ребро релаксируется один раз. Время — Θ(n + m) после того, как у вас есть порядок.

Веса могут быть отрицательными. У DAG нет цикла, поэтому отрицательный цикл не может существовать.

**Самые длинные пути на DAG** используют тот же обход. Вы максимизируете вместо минимизации или отрицаете веса и запускаете кратчайший путь. Самый длинный простой путь на общем графе — другая, трудная задача. Случай DAG линеен.

Используйте релаксацию DAG для длительности задач: самый длинный путь — критический путь в DAG проекта.

Не заменяйте Дейкстру релаксацией DAG на графе, который может иметь цикл.

Если s не первая вершина в порядке, вершины до s остаются ∞, если нет другого источника. Это верно, если вас заботят только пути от s.

## Компоненты связности / предварительный взгляд Union-Find

Неориентированный граф распадается на **компоненты связности**. Две вершины в одном компоненте, если путь соединяет их.

**Метод DFS или BFS.** Повторяйте: выберите непосещённую вершину s, запустите DFS или BFS и назначьте всем достигнутым вершинам один id компонента. Время — Θ(n + m).

```text
0—1    3—4
   \    |
    2   5

components: {0,1,2} and {3,4,5}
```

**Предварительный взгляд Union-Find.** Структура непересекающихся множеств хранит разбиение вершин. `find(u)` называет компонент u. `union(u, v)` сливает два компонента, когда вы обрабатываете ребро {u, v}. После union каждого ребра `find(u) == find(v)` означает, что u и v связны. Следующая тема реализует Union-Find. Этот раздел только формулирует нужду.

Используйте DFS/BFS, когда уже есть списки смежности и нужно посетить вершины. Используйте Union-Find, когда рёбра приходят как список и вы задаёте много запросов связности, или когда запускаете Крускала.

Ориентированные графы используют **сильно связные компоненты** (SCC). Этот алгоритм — продвинутая тема графов. Не считайте дерево DFS ориентированного графа неориентированным компонентом.

Число компонентов — число стартов BFS/DFS (плюс изолированные вершины, каждая из которых начинает один поиск).

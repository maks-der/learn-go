# 4. Функции

## Описание

Функция — именованный блок инструкций. Вы объявляете функцию один раз. Вызываете функцию много раз. Эта тема показывает, как писать функции, как возвращать значения и как использовать значения функций.

Функции Go могут возвращать больше одного значения. Частый шаблон — результат и ошибка. Поздние темы используют этот шаблон в каждой программе.

Функция может захватывать переменные из внешнего блока. Такая функция — замыкание. Функция может вызвать себя. Такой вызов — рекурсия. Функция `init` выполняется до `main`. Panic останавливает обычное управление потоком.

Используйте функции, чтобы разделить работу. Дайте каждой функции одну ясную задачу. Возвращайте ошибки для ожидаемых сбоев. Используйте panic только для неисправностей, которые программа не может обработать.

## Объявление, несколько возвращаемых значений и именованные результаты

Объявление функции начинается с `func`. Далее идёт имя. Далее — параметры в скобках. Далее — тип результата, когда функция возвращает значение. Тело — блок.

```go
func add(a int, b int) int {
	return a + b
}
```

Соседние параметры одного типа могут делить одно имя типа. `func add(a, b int) int` — то же, что `func add(a int, b int) int`.

Нельзя объявить именованную функцию внутри другой функции. Можно объявить анонимную функцию внутри функции. Две функции в одном пакете не могут иметь одно имя. Вызывайте функцию с правильным числом аргументов. Типы аргументов должны совпадать с типами параметров. Go не преобразует типы в вызове.

Функция может вернуть больше одного результата. Пишите типы результатов в скобках. Частый шаблон — `(value, error)`. Последний результат часто `error`. Ошибка `nil` означает успех. Ненулевая ошибка означает сбой. Проверяйте ошибку до использования значения.

```go
func div(a, b int) (int, error) {
	if b == 0 {
		return 0, fmt.Errorf("divide by zero")
	}
	return a / b, nil
}

q, err := div(10, 2)
if err != nil {
	fmt.Println(err)
	return
}
fmt.Println(q)
```

Используйте пустой идентификатор `_`, когда нужно игнорировать один результат. Не игнорируйте результат `error`.

Параметры результата можно именовать. Имена становятся переменными в теле функции. Go задаёт им нулевое значение в начале. `return` без выражений — голый return. Используйте голый return только в короткой функции.

```go
func rect(w, h int) (area int, perim int) {
	area = w * h
	perim = 2 * (w + h)
	return
}
```

Отложенная функция может изменить именованный результат. Предпочитайте явный `return`, когда функция длиннее нескольких строк. Вызывающему коду не нужно использовать те же имена.

## Вариативные функции

Вариативный параметр принимает ноль или больше аргументов одного типа. Пишите `...T` как последний параметр. Внутри функции этот параметр — срез типа `[]T`.

```go
func sum(nums ...int) int {
	total := 0
	for _, n := range nums {
		total += n
	}
	return total
}

func main() {
	fmt.Println(sum())
	fmt.Println(sum(1, 2, 3))
}
```

Только последний параметр может быть вариативным. `func bad(x ...int, y int)` недопустима.

Существующий срез можно передать с `...` после среза. `sum(values...)` передаёт элементы. Функция по-прежнему видит срез.

```go
values := []int{4, 5, 6}
fmt.Println(sum(values...))
```

`append` — встроенная вариативная функция. `fmt.Println` тоже вариативна.

Пустой вызов `sum()` даёт срез длины ноль. Срез может быть `nil`. Range по этому срезу безопасен.

Не смешивайте аргумент-срез и лишние элементы в одном вызове. `sum(values..., 9)` недопустимо.

## Функции как значения и замыкания

Функция — значение. Функцию можно присвоить переменной. Функцию можно передать как аргумент. Функцию можно вернуть.

Тип функции — её сигнатура. `func(int) int` — тип. Две функции имеют один тип, когда совпадают типы параметров и типы результатов. Имена в сигнатуре не входят в тип.

```go
func square(n int) int { return n * n }

func apply(n int, fn func(int) int) int {
	return fn(n)
}

func main() {
	f := square
	fmt.Println(apply(4, f))
}
```

Нулевое значение типа функции — `nil`. Вызов значения функции `nil` вызывает panic. Проверяйте `nil`, когда параметр функции необязателен.

У анонимной функции нет имени. Вы пишете `func(...) ... { ... }`. Её можно вызвать сразу.

Замыкание — значение функции, которое ссылается на переменные из внешнего блока. Функция может читать эти переменные. Функция может присваивать эти переменные.

```go
func counter() func() int {
	n := 0
	return func() int {
		n++
		return n
	}
}
```

Внутренняя функция держит `n` живым после возврата `counter`. Каждый вызов `counter` создаёт новый `n`. Замыкание захватывает переменную, а не копию текущего значения.

Go 1.22 даёт каждой итерации цикла `for` свою переменную цикла. Замыкания, которые захватывают переменную цикла в Go 1.22, видят значение этой итерации.

Используйте значения функций для обратных вызовов и маленьких стратегий. Используйте замыкания для маленького состояния. Предпочитайте структуру, когда у состояния несколько полей.

## Рекурсия

Рекурсия — вызов функции той же функции. Каждый вызов должен двигаться к базовому случаю. Базовый случай возвращает управление без нового рекурсивного вызова.

```go
func fact(n int) int {
	if n <= 1 {
		return 1
	}
	return n * fact(n-1)
}
```

Используйте ясный базовый случай. Отсутствующий базовый случай вызывает бесконечную рекурсию. Бесконечная рекурсия растит стек. Затем программа паникует с переполнением стека.

Go не гарантирует оптимизацию хвостовых вызовов. Глубокий рекурсивный вызов может переполнить стек даже когда последнее действие — вызов. Используйте цикл, когда глубина может быть большой.

Рекурсия подходит деревьям, вложенным структурам и алгоритмам «разделяй и властвуй». Срез или число с небольшой границей можно использовать рекурсию для обучения.

Рекурсивная функция может иметь больше одного рекурсивного вызова. Пример: обход дерева, который посещает левого и правого потомков.

Держите рекурсивную функцию чистой, когда можете. Передавайте нужные данные как параметры. Не скрывайте прогресс в глобальной переменной.

## `init` (когда выполняется; почему не злоупотреблять)

Функция `init` имеет такую форму:

```go
func init() {
	fmt.Println("init runs")
}
```

Вы не вызываете `init`. Среда выполнения вызывает `init` во время инициализации пакета. У `init` нет параметров и результатов. Нельзя ссылаться на `init` по имени.

Инициализация пакета идёт в таком порядке:

1. Среда сначала инициализирует импортированные пакеты.
2. Среда инициализирует переменные уровня пакета в текущем пакете.
3. Среда запускает функции `init` в текущем пакете.
4. После инициализации всех пакетов среда вызывает `main` в пакете `main`.

В одном файле может быть больше одной функции `init`. Эти функции выполняются в порядке исходного кода. Не полагайтесь на порядок файлов в пакете, если можете этого избежать.

Пустой импорт `_ "pkg"` импортирует пакет только ради побочных эффектов `init`. Драйверы баз данных используют этот шаблон. Импорт легко пропустить при ревью.

Избегайте многих функций `init`. Они скрывают работу. Тесты не могут их пропустить. Порядок старта между пакетами трудно увидеть. Предпочитайте экспортируемую функцию `Setup`, которую вызывает `main`.

Используйте `init` только для регистрации, которая должна выполниться при старте. Пример: зарегистрировать драйвер. Держите `init` коротким. Не читайте файлы и не запускайте серверы в `init` без сильной причины.

## Panic и recover

Panic останавливает обычное выполнение текущей горутины. Среда выполняет отложенные функции. Затем программа падает, если отложенная функция не вызовет `recover`.

```go
func mustPositive(n int) {
	if n < 0 {
		panic("n must be >= 0")
	}
}
```

Ошибка — значение. Вы возвращаете ошибку для ожидаемых сбоев. Примеры: отсутствующий файл, плохой ввод пользователя, сетевой таймаут. Вызывающий код проверяет ошибку и выбирает следующий шаг.

Panic — для неисправности, которую программа не может обработать чисто. Примеры: сломанный инвариант, разыменование nil, индекс вне диапазона. Считайте panic ошибкой или последней остановкой.

`recover` останавливает panic. `recover` работает только внутри отложенной функции. `recover` возвращает значение, переданное в `panic`. `recover` возвращает `nil`, когда panic нет.

```go
func safe() (err error) {
	defer func() {
		if v := recover(); v != nil {
			err = fmt.Errorf("panic: %v", v)
		}
	}()
	panic("boom")
}
```

Не используйте `panic` для обычного управления потоком. Не скрывайте panic в библиотеке без задокументированной границы. Некоторые серверы восстанавливаются на границе запроса. Этот recover защищает процесс. Он не исправляет ошибку.

Предпочитайте результаты `error` в своих функциях. Используйте `panic`, когда программа неверна и должна остановиться. Используйте `recover` только на ясной границе.

1. Напишите `mustAtoi`, которая паникует, когда `strconv.Atoi` не удаётся. Затем напишите обёртку, которая восстанавливается и возвращает `error`.
2. Добавьте три печати `defer` вокруг panic. Запишите порядок печати.
3. Покажите, что panic в функции `A` выполняет defer в `A`, затем defer в вызывающем коде, если `recover` его не остановит.

#### Сложные практические задания

1. Напишите небольшую функцию-воркер, которая восстанавливается после panic и возвращает ошибку вызывающему коду. Процесс должен продолжать работу.
2. Прочитайте, как `net/http` документирует восстановление после panic в обработчиках. Напишите пять предложений, почему сервер восстанавливается на этой границе.

## Обзор темы

Эти вопросы не повторяют вопросы в разделах выше. Они покрывают всю тему.

### Вопросы

#### Теоретические вопросы

1. Опишите путь вызова, который возвращает `(T, error)`, от вызываемой функции до правильной проверки в вызывающем коде.
2. Как именованные результаты, `defer` и `recover` работают вместе в одной функции?
3. Когда выбирать вариативный параметр, параметр-срез или параметр-значение функции?
4. Почему среда инициализирует импортированные пакеты до переменных уровня пакета и `init` в импортирующем пакете?
5. Как решать между возвращённой ошибкой, panic и замыканием, которое хранит ошибку?

#### Простые практические задания

1. Напишите `repeat(s string, n int) (string, error)`, которая отклоняет `n < 0`. Используйте именованный результат для ошибки.
2. Напишите вариативную `printAll(...any)`, которая печатает каждый аргумент на своей строке.
3. Напишите `applyTwice(fn func(int) int, x int) int`. Передайте анонимную функцию, которая добавляет один.
4. Нарисуйте таблицу со столбцами «Форма функции», «Когда использовать» и «Один риск». Добавьте строки для именованных результатов, замыканий, `init` и panic.

#### Средние практические задания

1. Напишите рекурсивную функцию и помощник-значение функции, которые решают одну маленькую задачу. Укажите, какую форму оставляете.
2. Постройте крошечную карту плагинов: имя к `func([]int) int`. Добавьте `sum` и `max`. Отклоняйте неизвестные имена ошибкой.
3. Напишите пакет с `init`, который затем удалите. Перенесите ту же настройку в функцию, которую тесты могут пропустить.

#### Сложные практические задания

1. Напишите функцию, которая использует именованный `error`, `defer` с `recover` и помощник, который может паниковать. Верните один `error` в `main`.
2. Спроектируйте пять функций для построчного калькулятора. Перечислите только сигнатуры. Отметьте, какие сигнатуры используют несколько результатов, вариативные параметры или значения функций.

## Описание

Структура данных — способ хранить и организовывать значения в программе. Эта тема объясняет эту идею. Вы узнаете разницу между абстрактным типом данных и реализацией. Вы также узнаете время и память как ресурсы. Завершите эту тему до изучения массивов и списков.

Используйте один термин для каждого понятия. Абстрактный тип данных (ADT) — список операций. Реализация — код, который выполняет эти операции. Операция — именованное действие, например вставка, удаление, поиск или обход.

## Что такое структура данных

Структура данных — организация значений в памяти. Структура решает, как вы храните значения и как вы получаете значения. Структура также решает, как вы добавляете значения и как вы удаляете значения.

Примеры структур данных: массив, связный список, хеш-таблица и дерево. Каждая структура хранит значения. Каждая структура даёт разную стоимость каждой операции.

Вы не выбираете структуру только по имени. Вы выбираете структуру по операциям, которые вам нужны. Если нужен быстрый доступ по индексу, используйте массив. Если нужна быстрая вставка в начало, используйте связный список.

Структура данных — не алгоритм. Алгоритм — последовательность шагов. Структура данных — расположение значений. Алгоритм использует структуру данных.

Значение в структуре — элемент. Некоторые тексты говорят «item». Этот справочник использует **элемент** для хранимого значения. Этот справочник использует **узел** только для связной ячейки, которая держит значение и ссылку.

```text
structure: array of 4 integers
indexes:   0    1    2    3
elements:  10   20   30   40
```

Те же четыре числа могут жить в списке узлов. Значения не меняются. Расположение в памяти меняется. Это изменение расположения и есть структура данных.

## Абстрактный тип данных (ADT) и реализация

Абстрактный тип данных (ADT) — контракт. Контракт называет операции. Контракт не называет расположение в памяти.

Стек — это ADT. Операции стека — push, pop и peek. Контракт не говорит «массив» или «список».

Реализация — код, который выполняет контракт. Один стек может использовать массив. Другой стек может использовать связный список. Обе реализации — стеки, если они выполняют одни и те же операции.

ADT скрывает расположение. Пользователь ADT вызывает операции. Пользователь не читает внутренние поля. Это разделение позволяет позже сменить реализацию.

```text
ADT: Stack
  push(x)  — put x on the top
  pop()    — remove the top and return it
  peek()   — return the top and do not remove it
  empty()  — true when the stack holds no element

Implementation A: array + top index
Implementation B: linked list + head node
```

Тип в языке программирования не всегда является ADT. Тип языка — инструмент. ADT — идея проектирования. Вы можете записать ADT как тип. Вы также можете записать ADT как набор функций.

Используйте один термин для каждой идеи. Говорите **ADT**, когда говорите о контракте. Говорите **реализация**, когда говорите о коде и расположении в памяти.

## Время и память как ресурсы

Программа использует время и память. Время — работа, которую делает процессор. Память — то, что программа держит.

У каждой операции есть стоимость по времени. У каждой структуры есть стоимость по памяти. Вы сравниваете структуры по этим стоимостям.

Стоимость по времени растёт, когда растёт вход. Стоимость по памяти тоже растёт, когда растёт вход. Структура, которая быстрая, может использовать больше памяти. Структура, которая использует мало памяти, может быть медленной.

Вы измеряете время в шагах, а не в секундах. Шаг — одно простое действие: сравнение, присваивание или индекс. Секунды меняются вместе с машиной. Шаги не меняются.

Вы измеряете память в элементах и в дополнительных ячейках. Дополнительные ячейки — указатели, индексы и неиспользуемая ёмкость.

```text
n = number of elements

array find by index:   few steps, does not grow with n
list find by value:    steps grow with n
array of n integers:   space grows with n
list of n integers:    space grows with n, plus one link per node
```

Не оптимизируйте до того, как узнаете, какая операция медленная. Сначала запишите ADT. Затем измерьте. Затем выберите более быструю реализацию, если она нужна.

## Почему у одного ADT может быть больше одной реализации

У одного ADT может быть много реализаций. Операции остаются теми же. Стоимости меняются.

ADT списка может использовать непрерывный массив. ADT списка может использовать связные узлы. Пользователь по-прежнему вызывает insert и find. Время вставки в середину не одно и то же.

Вы выбираете реализацию по операциям, которые делаете часто. Если много поисков по индексу, используйте массив. Если много вставок в начало, используйте связный список.

Вторая причина для нескольких реализаций — язык и машина. Один язык даёт динамический массив. Другой язык даёт связный список в стандартной библиотеке. ADT по-прежнему список.

Третья причина — безопасность и простота. Простую реализацию легко проверить. Сложная реализация может быть быстрее. Начните с простой реализации. Меняйте её, когда измерение покажет нужду.

```text
ADT: List
  get(i), set(i, x), insert(i, x), remove(i), length()

Implementation: fixed array     — get is fast; insert in the middle copies many elements
Implementation: linked nodes    — insert at the front is fast; get(i) walks i nodes
Implementation: dynamic array   — get is fast; append at the end is usually fast
```

Имя ADT не говорит вам стоимость. Реализация говорит вам стоимость. Всегда спрашивайте, какая у вас реализация.

## Как читать «операции» (insert, delete, find, iterate)

Операция — именованное действие над структурой. Частые операции — insert, delete, find и iterate.

**Insert** добавляет элемент. Вы должны знать позицию. Вставка в начало, вставка в конец или вставка по индексу i — разные операции. Стоимости не одинаковые.

**Delete** удаляет элемент. Удаление по позиции и удаление по значению — разные операции. Удаление по значению сначала должно найти элемент.

**Find** возвращает элемент или сообщает, что элемента нет. Поиск по индексу и поиск по значению — разные операции. Поиск по ключу — третья форма. Отображение использует поиск по ключу.

**Iterate** посещает каждый элемент один раз. Обход не обязан давать особый порядок. Некоторые структуры обходят в порядке индексов. Некоторые структуры обходят в отсортированном порядке. Некоторые структуры обходят в неопределённом порядке.

Когда текст говорит «вставка быстрая», текст должен назвать позицию. Когда текст говорит «поиск быстрый», текст должен назвать ключ. Читайте полное имя операции.

```text
insert(x) at end     — append
insert(x) at index i — shift or relink
delete(i)            — remove the element at i
find(x)              — search for value x
find_key(k)          — search for key k
iterate              — visit each element
```

Записывайте операции списком, когда проектируете структуру. Для каждой операции напишите вход, выход и эффект на структуру.

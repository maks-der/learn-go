# 5. Таблицы и ограничения

## Описание

Эта тема показывает, как создавать таблицы в PostgreSQL 16 и PostgreSQL 17. Вы узнаёте `CREATE TABLE`, столбцы identity и ограничения. Также узнаёте внешние ключи, значения по умолчанию и наследование таблиц.

Сначала завершите тему 4. Нужно знать типы и `NULL`. Завершите эту тему до написания соединений.

Используйте один термин для каждого понятия. Таблица — именованный набор строк. Ограничение — правило, которому должна удовлетворять строка. Столбец identity — столбец, который PostgreSQL заполняет из последовательности. Наследование копирует определения столбцов из родительской таблицы. Для новых дизайнов предпочитайте композицию (внешние ключи), а не наследование.

## `CREATE TABLE`

`CREATE TABLE` задаёт имя таблицы, столбцы и ограничения таблицы.

```sql
CREATE TABLE customers (
    id         bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    email      text NOT NULL,
    created_at timestamptz NOT NULL DEFAULT now()
);
```

Порядок столбцов — тот, который использует `SELECT *`. В прикладном SQL называйте столбцы явно.

Полезные предложения:

- `IF NOT EXISTS` — не падать, если таблица есть
- `TEMPORARY` / `TEMP` — таблица сессии; удаляется в конце сессии (или транзакции)
- `UNLOGGED` — без WAL; быстрее; не устойчива к сбою; не реплицируется
- `INHERITS` — см. раздел про наследование
- `PARTITION BY` — тема 15

```sql
CREATE TEMP TABLE scratch (id int);
CREATE UNLOGGED TABLE cache_keys (k text PRIMARY KEY, v text);
```

Используйте `TEMP` для черновых данных сессии. Используйте `UNLOGGED` только когда данные можно потерять.

`CREATE TABLE ... AS SELECT` строит таблицу из запроса:

```sql
CREATE TABLE customer_copy AS
SELECT id, email FROM customers;
```

`CREATE TABLE AS` не копирует ограничения. Добавьте ограничения после или используйте `CREATE TABLE` плюс `INSERT ... SELECT`.

`ALTER TABLE` позже добавляет столбцы и ограничения. Некоторые формы `ALTER TABLE` переписывают таблицу. Тестируйте на копии.

`DROP TABLE name;` удаляет таблицу. `DROP TABLE name CASCADE;` также удаляет зависимые объекты. Используйте `CASCADE` только когда именно этого хотите.

Называйте таблицы в единственном или множественном числе так, как выбрала команда. Используйте одну форму. Используйте `snake_case`.

## `GENERATED ALWAYS AS IDENTITY` (для новой работы лучше `serial`)

Столбец identity использует последовательность. PostgreSQL владеет последовательностью и привязывает её к столбцу.

```sql
CREATE TABLE orders (
    id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    note text
);

INSERT INTO orders (note) VALUES ('first') RETURNING id;
```

Два режима:

- `GENERATED ALWAYS AS IDENTITY` — столбец нельзя писать в `INSERT`, если не использовать `OVERRIDING SYSTEM VALUE`
- `GENERATED BY DEFAULT AS IDENTITY` — значение можно задать; последовательность заполняет остальное

```sql
INSERT INTO orders (id, note) OVERRIDING SYSTEM VALUE
VALUES (1000, 'manual');
```

`serial`, `bigserial` и `smallserial` — старые макросы. Они создают последовательность, задают `DEFAULT nextval(...)` и `NOT NULL`. Они не помечают столбец как identity. Привилегии и поведение дампа различаются. Для новых таблиц используйте identity.

```sql
-- old style; do not use for new work
id serial PRIMARY KEY
```

Identity есть в стандарте SQL. `serial` нет.

Посмотреть identity:

```sql
SELECT column_name, is_identity, identity_generation
FROM information_schema.columns
WHERE table_name = 'orders';
```

`\d orders` показывает `generated always as identity`.

Identity можно добавить к существующему столбцу через `ALTER TABLE ... ADD GENERATED`. Последовательность можно менять через `ALTER TABLE ... ALTER COLUMN ... SET GENERATED` и `RESTART`.

Не используйте `uuid` и identity на одном столбце. Выберите один стиль ключа.

## Первичный ключ, unique, check, exclude (обзор)

**Первичный ключ** идентифицирует одну строку. Он `UNIQUE` и `NOT NULL`. У одной таблицы не больше одного первичного ключа. Первичный ключ может использовать один столбец или много столбцов (составной).

```sql
CREATE TABLE products (
    sku  text PRIMARY KEY,
    name text NOT NULL
);
```

Ограничение **unique** запрещает дубликаты в наборе столбцов. Обработка `NULL`: много значений `NULL` допустимы, если не написать `UNIQUE NULLS NOT DISTINCT` (PostgreSQL 15+).

```sql
CREATE TABLE users (
    id    bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    email text NOT NULL UNIQUE
);
```

Ограничение **check** — булево выражение. Строка допустима, когда выражение `true` или `NULL` (unknown). Пишите `IS NOT NULL` внутри check, когда нужно отклонить `NULL`.

```sql
CREATE TABLE prices (
    id    bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    cents integer CHECK (cents >= 0)
);
```

Ограничение **exclusion** (`EXCLUDE`) запрещает две строки, которые совпадают указанным оператором. Частый случай — пересекающиеся диапазоны с GiST:

```sql
CREATE TABLE reservations (
    id    bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    room  int NOT NULL,
    during tstzrange NOT NULL,
    EXCLUDE USING gist (room WITH =, during WITH &&)
);
```

Этот пример говорит: две строки не должны иметь одну `room` и пересекающийся `during`. Тема 20 глубже разбирает диапазонные типы. Знайте, что `EXCLUDE` существует. Используйте, когда `UNIQUE` не выражает правило.

Ограничения можно именовать:

```sql
CONSTRAINT prices_cents_nonneg CHECK (cents >= 0)
```

Именуйте ограничения. Тогда тексты ошибок показывают стабильное имя.

`PRIMARY KEY` и `UNIQUE` создают индекс. `CHECK` не создаёт. `EXCLUDE` создаёт индекс указанного типа.

## Внешние ключи и действия `ON DELETE`

Внешний ключ говорит, что значение должно совпадать с первичным или уникальным ключом в другой таблице (или в той же).

```sql
CREATE TABLE orders (
    id          bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    customer_id bigint NOT NULL REFERENCES customers (id)
);
```

`REFERENCES customers (id)` — внешний ключ столбца. Ограничение таблицы может перечислить несколько столбцов.

`ON DELETE` задаёт, что происходит при удалении родительской строки:

| Действие | Эффект |
| --- | --- |
| `NO ACTION` | по умолчанию; ошибка, если есть дочерние строки; проверка может подождать конца оператора |
| `RESTRICT` | ошибка, если есть дочерние строки; проверка немедленная |
| `CASCADE` | удалить дочерние строки |
| `SET NULL` | поставить внешний столбец в `NULL` (столбец должен допускать NULL) |
| `SET DEFAULT` | поставить внешний столбец в его значение по умолчанию |

```sql
CREATE TABLE order_lines (
    id         bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    order_id   bigint NOT NULL REFERENCES orders (id) ON DELETE CASCADE,
    product_sku text NOT NULL REFERENCES products (sku) ON DELETE RESTRICT
);
```

У `ON UPDATE` те же имена действий. `ON UPDATE CASCADE` обновляет дочерние ключи, когда меняется родительский ключ. Предпочитайте стабильные ключи, чтобы `ON UPDATE` почти не понадобился.

Внешний ключ требует индекс на родительском ключе (у первичного ключа или ограничения уникальности он уже есть). PostgreSQL не создаёт индекс на дочернем столбце. Добавьте индекс на `order_id`, когда часто удаляете родителей или соединяете.

Обе таблицы должны быть в одной базе. Внешний ключ не может указывать на другую базу.

`NOT VALID` и `VALIDATE CONSTRAINT` позволяют добавить ограничение в два шага на больших таблицах. Изучите этот шаблон до блокировки большой продакшен-таблицы.

## Значения по умолчанию и `now()`

Значение по умолчанию заполняет столбец, когда `INSERT` его опускает.

```sql
CREATE TABLE audit_notes (
    id         bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    body       text NOT NULL,
    created_at timestamptz NOT NULL DEFAULT now(),
    updated_at timestamptz NOT NULL DEFAULT now()
);
```

`DEFAULT now()` использует `now()`. `now()` — метка времени старта текущей транзакции. Все строки, вставленные в одной транзакции, получают одно значение `now()`. Для `created_at` это обычно то, что нужно.

Другие функции времени:

- `CURRENT_TIMESTAMP` — то же, что `now()`
- `CURRENT_DATE` — дата старта транзакции
- `clock_timestamp()` — настенные часы; меняется внутри транзакции
- `statement_timestamp()` — старт текущего оператора

Для значений по умолчанию используйте `now()`. Используйте `clock_timestamp()` только когда нужно разное время на оператор или на вызов внутри одной транзакции.

Значения по умолчанию могут быть выражениями:

```sql
DEFAULT 0
DEFAULT gen_random_uuid()
DEFAULT CURRENT_DATE
```

Значение по умолчанию срабатывает, когда столбца нет в `INSERT`. Явный `NULL` значение по умолчанию не использует. Нужно опустить столбец или использовать `DEFAULT`:

```sql
INSERT INTO audit_notes (body) VALUES ('hi');
INSERT INTO audit_notes (body, created_at) VALUES ('hi', DEFAULT);
```

Значения по умолчанию `updated_at` не меняются при `UPDATE`. Используйте триггер (тема 13) или задайте столбец в операторе `UPDATE`.

`ALTER TABLE ... ALTER COLUMN ... SET DEFAULT` меняет значение по умолчанию для новых строк. Старые строки не переписывает.

## Наследование таблиц (знать, что есть; предпочитать композицию)

Наследование таблиц позволяет дочерней таблице получить столбцы от родительской.

```sql
CREATE TABLE vehicles (
    id    bigint,
    label text NOT NULL
);

CREATE TABLE cars (
    doors int NOT NULL
) INHERITS (vehicles);
```

У `cars` есть `id`, `label` и `doors`. `INSERT` в `cars` также делает строку видимой в `SELECT` из `vehicles`, если не использовать `ONLY`:

```sql
SELECT * FROM vehicles;
SELECT * FROM ONLY vehicles;
```

Проблемы:

- Индексы и ограничения уникальности не покрывают всё дерево наследования так, как ожидает новичок.
- Внешние ключи на родителя не видят дочерние строки как родительский ключ надёжным образом.
- Identity и уникальные ключи на родителе не дают одну последовательность по детям простым способом.
- Декларативное секционирование (тема 15) — поддерживаемый путь для разбиения больших таблиц.

Предпочитайте **композицию**: таблица `vehicles` и таблица `cars` с `vehicle_id` как внешним ключом. Делите столбцы только когда настоящей таблице подтипа нужны дополнительные столбцы, и всё равно предпочитайте одну таблицу плюс допускающие NULL столбцы или JSON, когда модель простая.

Знайте наследование, чтобы читать старые схемы. Не используйте наследование для новых прикладных таблиц. Не используйте наследование вместо секционирования.

`ALTER TABLE parent ADD COLUMN` может каскадироваться на детей. Тестируйте это на копии.

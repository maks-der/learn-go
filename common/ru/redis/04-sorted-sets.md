# 4. Упорядоченные множества

## Описание

Упорядоченное множество хранит уникальных членов. У каждого члена есть счёт. Redis держит членов в порядке счёта. Эта тема показывает модель счёта, основные команды записи и диапазонов, таблицы лидеров и простые скользящие окна.

Завершите эту тему до изучения потоков, битовых карт и других типов.

Используйте один термин для каждого понятия. Член — уникальная строка. Счёт — число двойной точности. Ранг — позиция в упорядоченном множестве (с нуля). Не считайте упорядоченное множество списком. Вы адресуете членов по имени и по счёту, не только через push и pop.

---

## Счёт и член

Упорядоченное множество — множество плюс число на члена. Член уникален. Счёт может повторяться. Два члена могут делить один счёт. Redis тогда упорядочивает этих членов по строке члена (лексикографический порядок).

Счёт — 64-битное число с плавающей точкой. Большие целые могут потерять точность. Для времени многие коллективы хранят время Unix в секундах или миллисекундах как счёт. Для рейтингов хранят очки.

Нельзя хранить две копии одного члена. Новый `ZADD` того же члена обновляет счёт.

У отсутствующего члена нет счёта. `ZSCORE` возвращает null.

Упорядоченное множество — один ключ. Типичные имена:

```text
lb:game:42
z:recent:user:9
z:delay:emails
```

Выберите счёт так, чтобы диапазонные запросы совпадали с задачей. Если нужны «топ 10 по очкам», счёт — очки. Если нужны «события за последние 60 секунд», счёт — метка времени.

Стоимость памяти выше, чем у множества. Redis держит словарь и skip-список (или компактную кодировку для маленьких ключей). Используйте упорядоченное множество, когда нужны порядок или диапазоны. Используйте множество, когда нужна только уникальность.

Не используйте члена как огромный JSON-блоб. Храните id как члена. Храните объект в хеше.

## `ZADD`, `ZRANGE`, `ZRANK`, `ZSCORE`, диапазон по счёту

`ZADD key score member [score member ...]` добавляет или обновляет членов. Ответ — число новых членов (не число обновлений счёта), если не используете опции вроде `CH`.

Опции включают `NX` (добавить только если отсутствует), `XX` (обновить только если есть), `GT` / `LT` (обновить счёт только если больше или меньше) и `INCR` (добавить к счёту, как `ZINCRBY`). Читайте страницу команды для вашей версии.

`ZSCORE key member` возвращает счёт как строку или null.

`ZRANK key member` возвращает ранг от наименьшего счёта к наибольшему. Наименьший счёт имеет ранг `0`. Отсутствующий член возвращает null.

`ZREVRANK` возвращает ранг от наибольшего счёта к наименьшему. Наибольший счёт имеет ранг `0`.

`ZRANGE key start stop` возвращает членов по рангу. `0` — наименьший счёт. `-1` — наибольший. Добавьте `WITHSCORES`, чтобы включить счета.

```text
ZADD lb 100 ada 80 bea 80 cam
ZRANGE lb 0 -1 WITHSCORES
ZRANK lb ada
ZSCORE lb bea
```

`ZREVRANGE` возвращает членов от высокого ранга к низкому. Redis 6.2+ предпочитает `ZRANGE ... REV` вместо `ZREVRANGE`. Обе существуют. Новый код может использовать `ZRANGE` с `REV`.

`ZCARD` возвращает число членов. `ZCOUNT key min max` считает членов в диапазоне счёта.

`ZREM key member` удаляет членов. `ZINCRBY key increment member` добавляет к счёту.

Ранги меняются, когда меняются счета. Не кэшируйте ранг в приложении надолго без обновления.

`ZRANGEBYSCORE key min max` возвращает членов, чьи счета лежат между `min` и `max`. Обе границы включительные по умолчанию. Префикс границы `(` делает её исключительной.

```text
ZRANGEBYSCORE events 1700000000 1700003600
ZRANGEBYSCORE events (10 (20
```

Используйте `-inf` и `+inf` для открытых концов.

`LIMIT offset count` листает диапазон. Всегда используйте `LIMIT` на больших диапазонах.

Redis 6.2+ также позволяет:

```text
ZRANGE key min max BYSCORE
ZRANGE key min max BYSCORE REV
```

Предпочитайте `ZRANGE ... BYSCORE` в новом коде, когда сервер это поддерживает. `ZRANGEBYSCORE` всё ещё работает.

`ZREMRANGEBYSCORE key min max` удаляет членов в этом диапазоне счёта. Ответ — число удалённых членов.

`ZREMRANGEBYRANK key start stop` удаляет по рангу. `ZPOPMIN` и `ZPOPMAX` удаляют одного или нескольких членов с концов.

Эти команды реализуют окна времени: счёт — время Unix, `ZRANGEBYSCORE` читает окно, `ZREMRANGEBYSCORE -inf old-cut` сбрасывает старых членов.

Не запускайте `ZRANGEBYSCORE -inf +inf` на огромном ключе без `LIMIT`. Команда может заблокировать и вернуть большой массив.

`ZCOUNT` дешевле, чем выборка всех членов, когда нужен только размер окна.

## Таблицы лидеров

Таблица лидеров — упорядоченное множество id игроков и счетов. Счёт — очки (или время, если меньшее время лучше).

Типичные операции:

- Отправить счёт: `ZADD lb:season1 2500 user:42` или `ZADD ... GT`, чтобы Redis оставлял только лучший счёт
- Прочитать топ 10: `ZREVRANGE lb:season1 0 9 WITHSCORES` или `ZRANGE ... REV`
- Прочитать ранг одного игрока: `ZREVRANK lb:season1 user:42` (добавьте 1 для места с единицы)
- Прочитать счёт: `ZSCORE lb:season1 user:42`
- Прочитать соседей: получите ранг, затем `ZREVRANGE` вокруг этого ранга

Отображаемые имена и аватары не принадлежат члену, если они меняются. Храните `user:42` как члена. Загружайте профиль из хеша.

Когда два игрока делят счёт, документируйте правило ничьей (лексикографический член). Если нужно «первый, кто достиг счёта, побеждает», закодируйте время в счёте (составное число) или используйте второе упорядоченное множество.

Шардирование огромной таблицы лидеров трудно. Одно упорядоченное множество живёт на одном экземпляре (или одном слоте Cluster). Для очень больших игр коллективы делят доски (по региону, по неделе) или используют прикладной ярус.

Срок целого сезона: задайте TTL на ключе `lb:season1` или удалите ключ в конце сезона. Нельзя задать TTL одному члену в базовом Redis. Удалите игрока через `ZREM`.

Не делайте `ZRANGE 0 -1`, чтобы сортировать в клиенте. Используйте ранги и диапазоны.

## Скользящие окна

Скользящее окно держит членов, которые принадлежат последним N секундам (или последним N событиям). Упорядоченное множество может смоделировать простой случай.

Окно времени (уникальные id событий):

1. `ZADD window:user:9 <now> event-id`
2. `ZREMRANGEBYSCORE window:user:9 -inf <now - 60>`
3. `ZCARD window:user:9` — счётчик за последние 60 секунд

Этот шаблон — лимит частоты или счётчик «действий за последнюю минуту», когда у каждого события уникальный id. Один член не может появиться дважды. Если один id может повторяться, добавьте уникальный суффикс.

Окна только по счёту без id могут использовать члена как случайный nonce или как `timestamp-seq`.

Потолок событий (последние N элементов): используйте удаления по рангу. После `ZADD` выполните `ZREMRANGEBYRANK key 0 -<N+1>`, если используете время как счёт и хотите новейшие N. Проверьте направление ранга. Многие коллективы используют `ZADD` плюс `ZCARD` плюс `ZPOPMIN`, пока размер не станет N.

Эта модель — не RedisTimeSeries. Нет агрегации, даунсэмплинга или компактных выборок. Есть точные члены в окне, пока вы их не удалите.

Ограничения:

- Каждое событие использует память на члена и счёт
- `ZREMRANGEBYSCORE` на каждый запрос имеет стоимость
- Cluster: все команды `ZADD` и удаления должны попадать в один ключ

Для тяжёлых временных рядов используйте RedisTimeSeries (обзор в теме 5) или специализированное хранилище. Для простых лимитов частоты и «недавних id» упорядоченного множества достаточно.

Можно хранить ключ окна с TTL чуть длиннее окна, чтобы простаивающие ключи исчезали.

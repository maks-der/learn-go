# 10. Топики и администрирование

## Описание

Административная работа создаёт и меняет топики, задаёт конфигурацию и осматривает группы. Kafka включает инструменты командной строки в папке `bin`. У клиентов также есть Admin API.

Эта тема покрывает создание, описание и удаление топиков, конфигурацию на топик, внутренние топики, превью ACL и обычные shell-инструменты. Завершите эту тему после тем 2 и 8. Тема 17 подробнее покрывает безопасность.

Используйте один термин для каждого понятия. Административная операция меняет метаданные кластера или конфигурацию топика. Внутренний топик — топик, который Kafka использует для своего состояния. ACL — правило контроля доступа. Используйте кластеры KRaft. Инструменты admin используют `--bootstrap-server`. Не используйте старые флаги ZooKeeper на новых кластерах.

## Создание / описание / удаление топиков

Топик создают с именем, числом партиций и фактором репликации. Пример формы команды:

```text
kafka-topics --bootstrap-server localhost:9092 --create --topic orders.placed --partitions 3 --replication-factor 1
```

В Windows используйте файл `.bat`. На macOS и Linux используйте файл `.sh`. Некоторые установки кладут инструменты в `PATH` без суффикса.

`--describe` показывает партиции, лидеров, реплики, ISR и конфигурацию, когда вы просите конфиги.

`--list` показывает имена топиков.

`--delete` удаляет топик. Кластер должен разрешать удаление (`delete.topic.enable` или текущий эквивалент). Удаление не мгновенно. Данные уходят с диска после процесса удаления. Не удаляйте топик в продакшене без процесса изменения.

Автосоздание может существовать на брокере (`auto.create.topics.enable`). Не полагайтесь на автосоздание в продакшене. Создавайте топики с явным числом партиций и фактором репликации.

У имён топиков есть правила. Используйте буквы, цифры, `.`, `_` и `-`. Избегайте пробелов. Избегайте имён, которые сталкиваются с внутренними префиксами.

Admin API вашего языка делает те же операции из программы или конвейера.

## Переопределения конфига на топик

Значения брокера по умолчанию применяются ко всем топикам. Можно переопределить ключи на одном топике. Примеры: `retention.ms`, `cleanup.policy`, `min.insync.replicas`, `max.message.bytes`.

Задавайте переопределения при создании (`--config` на `kafka-topics`) или позже через `kafka-configs`.

Описывайте с конфигами, чтобы увидеть эффективные значения и является ли значение значением по умолчанию или переопределением топика.

Используйте переопределения для особых топиков. Не создавайте уникальную снежинку для каждого топика без причины. Стандарт команды плюс несколько переопределений проще эксплуатировать.

Некоторые ключи небезопасно менять на живом топике без плана. Прочитайте официальную документацию ключа. Добавление партиций — отдельная операция от изменения конфига.

Также существует динамический конфиг брокера. Это изменение на весь кластер. Этот раздел фокусируется на переопределениях на топик.

## Внутренние топики (`__consumer_offsets`, топики транзакций)

Kafka создаёт внутренние топики для своего состояния.

`__consumer_offsets` хранит зафиксированные офсеты групп консьюмеров. Не пишите прикладные события в этот топик. Не удаляйте его. Его использует координатор группы.

Состояние транзакций использует внутренние топики (имена включают состояние транзакций в официальных документах, например `__transaction_state`). Они нужны EOS-продюсерам. Не удаляйте их.

Могут появиться другие внутренние имена (метаданные кластера в KRaft используют журнал метаданных на контроллерах, который не обычный прикладной топик). Connect и Streams могут добавить больше топиков, когда вы используете эти продукты.

`--list` может показать внутренние топики. Некоторые инструменты скрывают их, пока не попросите. Считайте каждое имя, которое начинается с `__`, зарезервированным, если документация не говорит иное.

Ретеншн и очистка на `__consumer_offsets` особые. Не задавайте случайные переопределения на внутренних топиках.

Если `__consumer_offsets` нездоров, группы не могут фиксировать. Это аварийная ситуация эксплуатации. Тема 15 покрывает эксплуатацию.

## ACL (превью)

ACL — правило: принципал может или не может выполнить операцию над ресурсом. Пример идеи: пользователь `alice` может писать в топик `orders.placed`.

Kafka авторизует, когда включён authorizer. Без authorizer клиент, который достигает listener, может делать все операции admin и данных. Локальный учебный кластер часто без ACL. Продакшен-кластер должен иметь аутентификацию и ACL (тема 17).

Принципалы приходят из метода аутентификации (пользователь SASL, идентичность сертификата). Ресурсы включают топики, группы и операции кластера. Операции включают Read, Write, Create, Delete, Describe и другие.

`kafka-acls` добавляет и перечисляет правила. Суперпользователи обходят ACL. Не запускайте продакшен как суперпользователя для приложений.

Этот раздел — превью. Не проектируйте полную систему безопасности только с этой страницы. Выучите TLS и SASL в теме 17. Затем задайте ACL.

Неверные ACL выглядят как «тайм-аут» или «authorization failed». Читайте лог брокера. Не открывайте listener миру, чтобы «починить».

## `kafka-topics.sh`, `kafka-configs.sh`, `kafka-consumer-groups.sh`

Эти инструменты — ежедневный интерфейс администрирования.

**`kafka-topics`.** Создание, список, описание, удаление и изменение числа партиций. Всегда передавайте `--bootstrap-server`.

**`kafka-configs`.** Изменение и описание конфигурации топика или брокера. Используйте тип сущности, который называет текст справки (`topics`, `brokers`).

**`kafka-consumer-groups`.** Список групп, описание участников и лага, удаление группы, сброс офсетов для остановленной группы. Сброс опасен. Сбрасывайте только когда группа простаивает и есть письменная причина.

Существуют другие полезные инструменты: `kafka-console-producer`, `kafka-console-consumer`, `kafka-get-offsets`, `kafka-reassign-partitions` (эксплуатация), `kafka-acls`. Учите их, когда нужны.

`--help` — источник истины для вашей версии. Имена флагов меняются. Старые блоги показывают `--zookeeper`. Не используйте этот флаг на кластере KRaft.

Положите каталог `bin` в `PATH` или пишите полный путь. В Windows вызывайте файлы `.bat` из `cmd` или PowerShell.

Предпочитайте скрипты в контроле версий для повторного администрирования. Не запускайте разовые удаления из памяти в продакшене.

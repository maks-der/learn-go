# 4. Функции, JSON и массивы

## Описание

Эта тема показывает частые функции, типы JSON и массивы в PostgreSQL 16 и PostgreSQL 17. Вы узнаёте функции строк, дат и математики. Узнаёте `COALESCE`, `NULLIF`, `GREATEST` и `LEAST`. Также узнаёте сопоставление с образцом, короткий обзор полнотекстового поиска, `json` против `jsonb`, GIN-индексы на `jsonb` и `unnest`.

Сначала завершите тему 3. Вы умеете писать соединения и `WITH`. Завершите эту тему до изучения индексов и планов запросов.

Используйте один термин для каждого понятия. Функция возвращает значение из аргументов. Оператор — символ вроде `||` или `@>`. `json` — текстовый тип JSON. `jsonb` — двоичный тип JSON. Массив — типизированный список (`text[]`, `int[]`). `unnest` превращает массив в набор строк. GIN-индекс на `jsonb` поддерживает операторы включения и существования ключа. Для JSON, который ищете, предпочитайте `jsonb`.

## Функции строк, дат и математики

Строковые функции работают с `text` и `varchar`.

```sql
SELECT length('PostgreSQL');
SELECT char_length('PostgreSQL');
SELECT lower('ABC'), upper('abc');
SELECT trim(BOTH ' ' FROM '  nail  ');
SELECT substring('washer' FROM 1 FOR 3);
SELECT left('washer', 3), right('washer', 2);
SELECT replace('red nail', 'red', 'blue');
SELECT split_part('a,b,c', ',', 2);
SELECT position('SQL' IN 'PostgreSQL');
```

`||` склеивает текст. `NULL` в выражении `||` делает результат `NULL`. Используйте `concat` или `concat_ws`, когда нужно пропустить `NULL`:

```sql
SELECT 'a' || NULL;           -- NULL
SELECT concat('a', NULL, 'b'); -- ab
SELECT concat_ws(',', 'a', NULL, 'c');
```

Функции даты и времени:

```sql
SELECT now();
SELECT current_date;
SELECT date_trunc('hour', now());
SELECT extract(year FROM DATE '2026-09-13');
SELECT date_part('month', DATE '2026-09-13');
SELECT age(DATE '2026-01-01');
SELECT DATE '2026-09-13' + INTERVAL '1 month';
SELECT timestamptz '2026-09-13 12:00:00+00' AT TIME ZONE 'Europe/Kyiv';
```

`date_trunc` обрезает метку времени до единицы (час, день, месяц). `extract` возвращает поле как `numeric`. `age` возвращает `interval`.

Математические функции:

```sql
SELECT abs(-3);
SELECT round(12.56, 1);
SELECT ceil(12.1), floor(12.9);
SELECT mod(10, 3);
SELECT power(2, 10);
SELECT sqrt(9);
SELECT random();
```

`round` на `numeric` принимает масштаб. `round` на `float8` использует другую форму. Предпочитайте `numeric`, когда нужен заданный масштаб.

`random()` возвращает `float8` в `[0, 1)`. Не используйте его для секретных токенов. Для секретов используйте `gen_random_uuid()` или `pgcrypto` (тема 9).

Вызывайте функции с именами аргументов, когда документация их показывает. В прикладном SQL предпочитайте задокументированные имена. Предпочитайте операторы, когда это обычная форма (`||` для текста).

## `COALESCE`, `NULLIF`, `GREATEST`, `LEAST`

Эти функции выбирают значение из списка. Они не агрегаты. Они работают с фиксированным списком аргументов.

`COALESCE(a, b, ...)` возвращает первый аргумент, который не `NULL`.

```sql
SELECT COALESCE(NULL, NULL, 'nail');
SELECT COALESCE(nickname, display_name, 'guest') FROM users;
```

`NULLIF(a, b)` возвращает `NULL`, когда `a` равно `b`. Иначе возвращает `a`.

```sql
SELECT NULLIF(qty, 0);
SELECT NULLIF(trim(name), '');
```

Частая пара: превратить пустую строку в `NULL`, затем подставить default:

```sql
SELECT COALESCE(NULLIF(trim(name), ''), 'unknown');
```

`GREATEST(a, b, ...)` возвращает наибольшее ненулевое значение. `LEAST` возвращает наименьшее ненулевое значение. Если каждый аргумент — `NULL`, результат — `NULL`.

```sql
SELECT GREATEST(1, 5, 3);
SELECT LEAST(created_at, updated_at);
SELECT GREATEST(1, NULL, 2);  -- 2
```

`GREATEST` и `LEAST` сравнивают значения общего типа. Смешанные типы следуют обычным правилам типов.

Не используйте `COALESCE`, чтобы прятать ошибки данных в каждом запросе. Исправьте схему через `NOT NULL`, когда значение должно существовать. Не пишите `GREATEST`, когда нужен `MAX` по группе. `MAX` — агрегат (тема 3 `GROUP BY` / позже тема окон).

## Сопоставление с образцом и обзор полнотекстового поиска

В PostgreSQL несколько инструментов шаблонов. Выбирайте один намеренно.

`LIKE` / `ILIKE` — шаблоны SQL (`%`, `_`). Тема 3 их разбирала. Их хватает для префикса и простого «содержит». `LIKE '%foo%'` не может использовать обычное B-дерево (тема 5).

`SIMILAR TO` — регулярные выражения SQL с квотированием `LIKE`. Мало команд его используют. Предпочитайте `LIKE` или POSIX regex.

POSIX-регулярные выражения:

```sql
SELECT name ~ '^[A-Za-z]+$';
SELECT name ~* 'nail';          -- без учёта регистра
SELECT substring(name FROM '[0-9]+');
```

`~` — совпадение с учётом регистра. `~*` — без учёта регистра. `!~` и `!~*` — отрицания.

Полнотекстовый поиск (FTS) — отдельная система. Вы храните или строите `tsvector`. Запрашиваете через `tsquery`. `@@` проверяет совпадение.

```sql
SELECT to_tsvector('english', 'The nails are cheap');
SELECT to_tsvector('english', 'The nails are cheap')
       @@ to_tsquery('english', 'nail');
```

`to_tsvector` сводит слова (стемминг) и отбрасывает стоп-слова. `nail` может совпасть с `nails`. GIN-индекс на `tsvector` поддерживает `@@` (тема 5).

Полезные функции FTS для первого взгляда:

- `to_tsvector(config, text)`
- `to_tsquery(config, text)` — операторы `&`, `|`, `!`
- `plainto_tsquery` — превращает обычный текст в AND-запрос
- `ts_headline` — подсвечивает совпадения
- `ts_rank` — ранжирует совпадения

```sql
SELECT ts_headline('english', body, query), ts_rank(vec, query)
FROM ...;
```

Этот раздел — обзор. У FTS есть словари, веса и ранжирование. Не считайте `ILIKE '%word%'` поиском по большому корпусу текста. Не смешивайте `~` и `@@` без плана. Не пропускайте конфигурацию текстового поиска (`english`, `simple`).

`pg_trgm` (тема 9) добавляет триграммное сходство и может индексировать `ILIKE '%foo%'`. Используйте, когда нужен нечёткий текст без полного FTS.

## `json` против `jsonb` и операторы JSON

`json` хранит входной текст. Сохраняет порядок ключей. Сохраняет дубликаты ключей. Сохраняет незначимые пробелы. Каждая операция должна разбирать текст.

`jsonb` хранит разобранное дерево. Отбрасывает незначимые пробелы. Если ключ повторяется, побеждает последний. Порядок ключей — не контракт данных. Операторы и индексы работают на `jsonb`.

```sql
SELECT '{"b": 1, "a": 2}'::json;
SELECT '{"b": 1, "a": 2}'::jsonb;
SELECT pg_typeof('{"a":1}'::jsonb);
```

Предпочитайте `jsonb` для столбцов, которые фильтруете, индексируете или обновляете на месте. Предпочитайте `json` только когда нужно хранить точный текст, который прислал клиент.

| Оператор | Результат |
| --- | --- |
| `->` | поле или элемент; тип остаётся `json` / `jsonb` |
| `->>` | поле или элемент как `text` |
| `#>` / `#>>` | путь как JSON или как текст |
| `@>` | включение `jsonb` (слева содержит справа) |
| `<@` | слева содержится в справа |
| `?` | ключ верхнего уровня существует |
| `?\|` / `?&` | существует любой / все из этих ключей |
| `\|\|` | склеить `jsonb` |

```sql
CREATE TABLE events (
    id      bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    payload jsonb NOT NULL
);

INSERT INTO events (payload)
VALUES ('{"type": "click", "n": 3, "tags": ["a","b"]}');

SELECT payload ->> 'type' AS type,
       payload -> 'n'     AS n_jsonb,
       payload @> '{"type":"click"}' AS is_click,
       payload ? 'tags' AS has_tags
FROM events;
```

`->>` возвращает `text`. Приводите, когда нужно число: `(payload ->> 'n')::int`.

PostgreSQL 16 добавляет больше предикатов SQL/JSON (`IS JSON` и связанные проверки). PostgreSQL 17 добавляет помощники запросов SQL/JSON вроде `JSON_TABLE` для превращения JSON в строки. Повседневную работу всё ещё можно делать через `->`, `->>`, `@>` и `jsonb_set`.

Обновить ключ:

```sql
UPDATE events
SET payload = jsonb_set(payload, '{n}', '4', true)
WHERE id = 1;
```

`jsonb_set` принимает массив пути, новое значение `jsonb` и флаг создать-если-нет.

Не храните каждый столбец как JSON. Используйте таблицы для полей, которые фильтруете, соединяете и ограничиваете. Используйте `jsonb` для необязательных или меняющихся атрибутов.

## Индексирование `jsonb` через GIN

GIN-индекс на `jsonb` поддерживает операторы включения и существования ключа. Он не заменяет B-дерево на типизированном столбце.

```sql
CREATE INDEX events_payload_gin ON events USING GIN (payload);
```

Класс операторов GIN для `jsonb` по умолчанию — `jsonb_ops`. Он поддерживает `@>`, `?`, `?|`, `?&` и связанные поиски по ключам и значениям.

`jsonb_path_ops` — меньший индекс. Хорошо поддерживает `@>`. Не поддерживает существование ключа `?` так же. Используйте, когда запрашиваете только включение.

```sql
CREATE INDEX events_payload_path
    ON events USING GIN (payload jsonb_path_ops);
```

Индексы выражений извлекают одно поле:

```sql
CREATE INDEX events_type_idx ON events ((payload ->> 'type'));
```

Это B-дерево помогает `WHERE payload ->> 'type' = 'click'`. Оно не помогает `@>`.

Правила:

- GIN большой и медленный в построении и обновлении. Используйте, когда запрашиваете документ.
- Типизированный столбец плюс B-дерево дешевле, когда ключ стабилен.
- После большой загрузки выполните `ANALYZE` таблицы (тема 5).
- `EXPLAIN` должен показать bitmap index scan или похожее, прежде чем доверять индексу.

PostgreSQL 16 и 17 эти классы сохраняют. Частичные GIN-индексы допустимы: `CREATE INDEX ... ON events USING GIN (payload) WHERE payload ? 'type';`

Не создавайте и `jsonb_ops`, и `jsonb_path_ops` на одном столбце без измеренной нужды. Не индексируйте столбец `json` (текст) через GIN для этих операторов. Приведите или храните `jsonb`.

## Массивы и `unnest`

Массив — типизированный список. Тип пишите как `int[]`, `text[]` или `jsonb[]`.

```sql
CREATE TABLE posts (
    id   bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    tags text[] NOT NULL DEFAULT '{}'
);

INSERT INTO posts (tags) VALUES (ARRAY['sql', 'postgres']);
INSERT INTO posts (tags) VALUES ('{gin,json}');
```

`{}` — пустой массив, не `NULL`. `{a,b}` — текстовая форма ввода.

Операторы и функции:

```sql
SELECT tags[1] FROM posts;                 -- индекс с 1
SELECT tags && ARRAY['sql'];               -- пересечение
SELECT tags @> ARRAY['sql'];               -- содержит
SELECT 'sql' = ANY (tags);
SELECT unnest(tags) AS tag FROM posts;
SELECT cardinality(tags);
SELECT array_append(tags, 'btree');
SELECT array_agg(name) FROM items;
```

`unnest` возвращает набор строк. Используйте в `FROM` или в списке select. `WITH ORDINALITY` добавляет позицию:

```sql
SELECT p.id, u.tag, u.ord
FROM posts AS p
CROSS JOIN LATERAL unnest(p.tags) WITH ORDINALITY AS u(tag, ord);
```

`array_agg` строит массив из группы. `string_to_array` и `string_agg` переводят между текстом и массивами.

GIN-индекс на `text[]` поддерживает `@>`, `<@`, `&&` и `=`:

```sql
CREATE INDEX posts_tags_gin ON posts USING GIN (tags);
```

Пределы массивов:

- Все элементы одного типа.
- Массивы могут быть многомерными. Для прикладных данных предпочитайте одно измерение.
- Отдельная таблица `post_tags` проще ограничивать и соединять. Массив — для маленького простого списка.

Не храните большую реляционную модель в массивах. Не используйте `tags[0]`. Первый элемент — `tags[1]`.

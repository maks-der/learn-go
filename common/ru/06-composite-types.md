# 6. Составные типы

## Описание

Составной тип хранит другие значения. Эта тема разбирает массивы, `slice`, `map` и `struct`. Вы используете эти типы почти в каждой программе на Go.

У массива фиксированная длина. `slice` — это вид на массив. `map` хранит ключи и значения. `struct` группирует именованные поля.

Предпочитайте `slice` массивам для большинства последовательностей. Предпочитайте `map` для поиска по ключу. Предпочитайте `struct` для записей с известным набором полей.

Длина входит в тип массива. Заголовок `slice` хранит указатель, длину и ёмкость. Значение `map` ссылается на хеш-таблицу. Значение `struct` хранит свои поля.

Каждый раздел ниже — одна идея. Сначала прочитайте разделы про массивы. Затем прочитайте `slice`. Затем прочитайте `map`. Затем прочитайте `struct`.

## Массивы: фиксированная длина и семантика значения

Тип массива — `[N]T`. `N` — длина. `T` — тип элемента. Длина входит в тип. `[3]int` и `[4]int` — разные типы.

```go
var a [3]int
b := [3]int{1, 2, 3}
c := [...]int{4, 5, 6}
```

`var a [3]int` задаёт каждому элементу нулевое значение. Составной литерал `[3]int{1, 2, 3}` задаёт каждый индекс. Форма `[...]int{4, 5, 6}` позволяет компилятору посчитать элементы. Тип `c` — `[3]int`.

Присваивание копирует массив. Копия имеет свои элементы. Изменение `b` не меняет `a` после `a = b`.

```go
a := [2]int{1, 2}
b := a
b[0] = 9
fmt.Println(a[0], b[0])
```

Это печатает `1` и `9`. Массивы не делят хранилище.

Передача массива в функцию тоже копирует массив. Большой массив как параметр дорог. Используйте `slice`, когда длина может меняться или когда нужно избежать копии.

Массивы сравнимы, когда тип элемента сравним. Можно использовать `==` для двух значений `[3]int`. Можно использовать массив сравнимых элементов как ключ `map`.

Индексируйте массив через `a[i]`. Индекс должен быть от `0` до `N-1`. Индекс вне диапазона вызывает `panic`.

Используйте массивы, когда размер входит в смысл. Примеры: дайджест хеша, точка размера 2, маленькая таблица поиска. Используйте `slice` для списков.

## Многомерные массивы

Многомерный массив — это массив массивов. `[2][3]int` имеет две строки. Каждая строка имеет три значения `int`.

```go
var m [2][3]int
m[0][1] = 7
n := [2][3]int{
	{1, 2, 3},
	{4, 5, 6},
}
```

Внутренний тип — `[3]int`. Внешний тип — `[2][3]int`. Присваивание копирует каждый внутренний массив. Копия глубокая для значений. Общего базового массива нет.

Сначала индексируйте внешний массив. `n[1][2]` равно `6` в примере. Внутренний индекс вне диапазона вызывает `panic`.

`[2][3]int` не совпадает с `[][]int`. `[][]int` — это `slice` из `slice`. Каждый внутренний `slice` может иметь разную длину. `slice` из `slice` может делить базовые массивы. Массив массивов не может менять длину.

Можно обойти внешний массив через `range`. Каждый элемент — внутренний массив. Обойдите этот внутренний массив, чтобы посетить каждое значение.

```go
for i := range n {
	for j := range n[i] {
		fmt.Println(i, j, n[i][j])
	}
}
```

Используйте многомерный массив, когда у каждой строки один и тот же фиксированный размер. Используйте `slice` из `slice`, когда строки растут или когда строки имеют разную длину.

Параметр функции типа `[2][3]int` копирует все шесть целых чисел. Передавайте указатель, когда нужно изменить массив вызывающего кода.

## Длина и ёмкость `slice`

`slice` — это дескриптор сегмента массива. Заголовок `slice` имеет три части: указатель, длину и ёмкость.

Длина — число элементов, которые можно индексировать. `len(s)` возвращает длину. Допустимые индексы — от `0` до `len(s)-1`.

Ёмкость считает элементы в базовом массиве. Счёт начинается от начала `slice`. Счёт заканчивается в конце массива. `cap(s)` возвращает ёмкость. Ёмкость всегда больше или равна длине.

```go
s := make([]int, 3, 5)
fmt.Println(len(s), cap(s))
```

Это печатает `3 5`. Можно индексировать `s[0]`, `s[1]` и `s[2]`. Нельзя индексировать `s[3]`. Этот индекс вызывает `panic`. `append` может использовать запас ёмкости.

Индекс должен использовать длину, не ёмкость. Запас ёмкости не используется, пока `append` или выражение нарезки не увеличит длину.

`len` и `cap` — встроенные функции. Они работают для `slice`, массивов и некоторых других типов. Для `slice` обе быстрые.

Нулевое значение `slice` имеет длину `0` и ёмкость `0`. Следующие разделы разбирают `nil` `slice` и `append`.

Не храните ёмкость в своём поле, если вы не оборачиваете `slice` намеренно. Используйте `len` и `cap` у значения `slice`.

## `make`, `append` и `copy`

`make` создаёт `slice`, `map` или канал (`channel`). Для `slice` используйте `make([]T, len)` или `make([]T, len, cap)`.

```go
a := make([]int, 3)
b := make([]int, 0, 8)
```

У `a` длина `3` и ёмкость `3`. Каждый элемент — нулевое значение. У `b` длина `0` и ёмкость `8`. `b` может расти через `append` без нового массива сначала.

`append` добавляет элементы в конец. `append` возвращает `slice`. Нужно использовать возвращённый `slice`.

```go
s := []int{1, 2}
s = append(s, 3)
s = append(s, 4, 5)
s = append(s, []int{6, 7}...)
```

Когда длина меньше ёмкости, `append` пишет в базовый массив. Когда длина равна ёмкости, `append` выделяет новый массив. Среда выполнения копирует старые элементы. Новая ёмкость больше.

`copy` копирует элементы из исходного `slice` в целевой `slice`. `copy` возвращает число скопированных элементов. Это число — меньшее из `len(dst)` и `len(src)`.

```go
dst := make([]int, 2)
src := []int{9, 8, 7}
n := copy(dst, src)
```

`n` равно `2`. `dst` равен `{9, 8}`. `copy` корректно обрабатывает перекрытие.

`make` только с длиной задаёт ёмкость равной длине. Используйте запас ёмкости, когда знаете итоговый размер. Этот выбор снижает число выделений.

Не игнорируйте результат `append`. Переменная слева должна получить новый заголовок.

## Выражения нарезки и базовый массив

Выражение нарезки создаёт новый заголовок `slice`. Выражение использует существующий массив или `slice`. Новый `slice` может делить тот же базовый массив.

```go
a := [5]int{0, 1, 2, 3, 4}
s := a[1:4]
```

У `s` длина `3`. Элементы — `1`, `2` и `3`. Ёмкость — `4`. Четыре элемента остаются от индекса `1` до конца массива.

Выражение — `x[low:high]`. Новая длина — `high - low`. Новая ёмкость — `cap(x) - low`, когда `x` — `slice`. Индексы следуют полуоткрытому правилу. `low` входит. `high` не входит.

Можно опустить `low` или `high`. `s[:]` сохраняет ту же длину. `s[1:]` отбрасывает первый элемент. `s[:2]` сохраняет первые два элемента.

Форма с тремя индексами — `x[low:high:max]`. Эта форма задаёт ёмкость как `max - low`. Используйте её, когда следующий `append` не должен писать в поздние элементы исходного массива.

```go
s := a[1:3:3]
```

У `s` длина `2` и ёмкость `2`. `append` на `s` выделяет новый массив. Исходный массив не получает новый элемент.

Изменение элемента `s` меняет базовый массив. Другие `slice`, которые делят этот массив, видят изменение.

```go
t := a[0:2]
s[0] = 9
fmt.Println(a, t)
```

Планируйте совместное использование. Когда нужен независимый `slice`, скопируйте элементы в новый `slice` через `copy`.

`slice` от `slice` не копирует элементы. Он только строит новый заголовок.

## `nil` и пустой `slice`

`slice` может быть `nil`. `slice` может быть пустым и не `nil`. У обоих длина `0`. Они не совпадают в каждом API.

```go
var n []int
e := []int{}
m := make([]int, 0)
```

`n` — `nil`. `len(n)` равна `0`. `cap(n)` равна `0`. `e` и `m` пустые. Они не `nil`. `len` равна `0` у обоих.

`append` работает с `slice` равным `nil`. Первый `append` выделяет базовый массив. Обход `nil` `slice` через `range` делает ноль итераций. `copy` в `nil` `slice` или из него копирует ноль элементов.

`n == nil` равно `true` для `var n []int`. `e == nil` равно `false`. Предпочитайте `len(s) == 0`, когда вас интересуют только элементы.

`encoding/json` кодирует `nil` `slice` как `null`. Он кодирует пустой `slice` как `[]`. Эта разница важна в API.

Функция, которая возвращает `slice` без элементов, может вернуть `nil`. Такой возврат допустим. Документируйте выбор JSON, когда кодируете результат.

Не пишите особые случаи для `nil` перед `append` или `range`. Эти операции уже принимают `nil`.

## Типичные ошибки со `slice`

Две частые ошибки — совместное использование при `append` и сюрпризы ёмкости.

`append` может писать в неиспользованную ёмкость. Эта ёмкость может принадлежать массиву, который всё ещё использует другой `slice`. Другой `slice` тогда видит новые значения. Другой `slice` также может потерять старые значения, когда `append` их перезаписывает.

```go
base := []int{1, 2, 3, 4}
a := base[:2]
b := append(a, 9)
fmt.Println(base, a, b)
```

У `a` ёмкость `4`. `append` пишет `9` в `base[2]`. `base` становится `{1, 2, 9, 4}`. Читатель может пропустить этот результат.

Когда `append` нужна большая ёмкость, он выделяет новый массив. Поздние записи не меняют старый массив. Тот же код может делить хранилище или не делить. Результат зависит от `cap`.

```go
a := []int{1, 2}
b := append(a, 3)
```

Если `cap(a)` равна `2`, у `b` новый массив. Если `cap(a)` больше, `b` может делить хранилище с `a`.

Исправьте совместное использование нарезкой с тремя индексами: `a := base[:2:2]`. Тогда `append` не может писать в `base`. Исправьте совместное использование через `copy` в новый `slice` перед `append`.

Другая ошибка — игнорировать результат `append`. Старый заголовок может остаться со старой длиной. Новый заголовок имеет новую длину. Всегда присваивайте `s = append(s, x)`.

Другая ошибка — держать маленький `slice` большого базового массива. Сборщик мусора не может освободить большой массив, пока живёт маленький `slice`. Скопируйте маленькую часть наружу, когда храните её долго.

Не предполагайте, что `append` всегда выделяет память. Проверяйте `cap` или обрезайте ёмкость, когда нужна изоляция.

## Создание `map`, поиск и comma-ok

Тип `map` — `map[K]V`. `K` — тип ключа. `V` — тип элемента. Тип ключа должен быть сравнимым.

`make` создаёт пустой `map`, в который можно писать.

```go
m := make(map[string]int)
m["a"] = 1
```

Составной литерал тоже создаёт `map`.

```go
m := map[string]int{"a": 1, "b": 2}
```

Поиск использует `m[key]`. Результат — значение. Когда ключа нет, результат — нулевое значение `V`. Один поиск не показывает отсутствие ключа, когда ноль — допустимое сохранённое значение.

Форма comma-ok сообщает о наличии.

```go
v, ok := m["a"]
if !ok {
	fmt.Println("missing")
}
```

`ok` равно `true`, когда ключ есть в `map`. `ok` равно `false`, когда ключа нет.

`make(map[K]V, hint)` принимает подсказку размера. Подсказка — не предел длины. `map` может вырасти дальше подсказки. Подсказка может снизить ранний рост.

`len(m)` — число ключей. У `map` нет `cap`.

Не используйте `slice`, `map` или функцию как тип ключа. Эти типы не сравнимы.

## `delete` и порядок обхода

`delete` удаляет ключ. `delete(m, key)` ничего не делает, когда ключа нет. `delete` на `map` равном `nil` тоже ничего не делает.

```go
m := map[string]int{"a": 1, "b": 2}
delete(m, "a")
delete(m, "missing")
```

После первого `delete` ключ `"a"` исчез. Второй `delete` ничего не делает.

Обход `map` через `range` посещает каждый ключ и значение.

```go
for k, v := range m {
	fmt.Println(k, v)
}
```

Порядок обхода случайный. Среда выполнения меняет стартовую позицию. Не пишите тесты, которые требуют фиксированного порядка печати. Не считайте первую пару из `range` минимумом или порядком вставки.

Если нужен стабильный порядок, соберите ключи. Отсортируйте ключи. Затем найдите каждый ключ.

```go
keys := make([]string, 0, len(m))
for k := range m {
	keys = append(keys, k)
}
sort.Strings(keys)
```

Можно обходить только ключи: `for k := range m`. Можно игнорировать ключ: `for _, v := range m`.

`clear(m)` удаляет все ключи. `clear` есть в Go 1.21 и новее. После `clear` `len(m)` равна `0`. `map` всё ещё не `nil`.

Не удаляйте ключи из `map`, если вы предполагаете фиксированный порядок посещения. Можно удалить текущий ключ во время `range`. Не полагайтесь на посещение ключей, которые вы добавляете в том же `range`.

## `nil` `map` и пустой `map`

`map` может быть `nil`. `map` может быть пустым и не `nil`. Чтения отличаются от записей.

```go
var n map[string]int
e := map[string]int{}
m := make(map[string]int)
```

`n` — `nil`. `e` и `m` — пустые `map`. `len` равна `0` у всех трёх. `n == nil` равно `true`. Остальные не `nil`.

Чтение из `map` равного `nil` возвращает нулевое значение. Comma-ok возвращает `ok == false`. Обход `nil` `map` через `range` делает ноль итераций. `delete` на `map` равном `nil` ничего не делает. `len` у `map` равного `nil` равна `0`.

Запись в `map` равный `nil` вызывает `panic`. Сообщение — `assignment to entry in nil map`.

```go
var n map[string]int
n["a"] = 1 // panic
```

Создайте `map` через `make` или литералом до первой записи.

`encoding/json` кодирует `nil` `map` как `null`. Он кодирует пустой `map` как `{}`.

Возвращайте `map` равный `nil`, когда пар нет и вы не пишете новые пары. Возвращайте `make(map[K]V)`, когда вызывающий код будет вставлять ключи.

Не оставляйте поле `struct` как `map` равный `nil`, если поздний код пишет в него. Инициализируйте это поле в конструкторе.

## `map` ведёт себя как ссылка

Значение `map` ссылается на хеш-таблицу. Присваивание копирует заголовок `map`. Копия ссылается на ту же таблицу. Запись через одну переменную видна через другую переменную.

```go
a := map[string]int{"x": 1}
b := a
b["x"] = 2
fmt.Println(a["x"])
```

Это печатает `2`. `a` и `b` делят таблицу.

Функция, которая получает `map`, может вставлять, обновлять и удалять ключи. Вызывающий код видит эти изменения. Функция не может заменить `map` вызывающего кода на `nil` присваиванием параметру. Параметр — копия заголовка.

`map` не безопасен для одновременной записи. Две горутины не должны писать в один `map` в одно время. Запись и чтение в одно время тоже небезопасны. Среда выполнения может остановить программу сообщением `fatal error: concurrent map writes`. `recover` не обрабатывает эту неисправность.

Одновременное чтение без записей безопасно. Многие горутины могут читать `map`, который никакая горутина не меняет.

Защитите общий `map` через `sync.Mutex`. Отдайте `map` одной горутине. Или используйте `sync.Map`, когда этот тип подходит. Поздние темы разбирают горутины и `sync`.

`map` — не указатель в исходном тексте. Для обычного использования пишите `map[K]V`, не `*map[K]V`. Поведение как у ссылки находится в заголовке.

Не передавайте `map` другой горутине и не пишите с обеих сторон без блокировки.

## Объявление `struct`

`struct` — это последовательность именованных полей. У каждого поля есть имя и тип.

```go
type Point struct {
	X int
	Y int
}

type User struct {
	Name string
	Age  int
}
```

`type` связывает имя с типом `struct`. Используйте именованный тип, когда передаёте значения, пишете методы или документируете смысл. Можно также написать анонимный тип `struct`. Именованные типы — обычная форма.

Нулевое значение `struct` имеет нулевое значение в каждом поле. У `var p Point` выполняется `X == 0` и `Y == 0`.

Доступ к полю идёт через точку. `p.X = 3`. Чтение — `p.X`.

Два именованных типа `struct` разные даже когда поля совпадают. `Point` не равен `User`. Можно преобразовать между двумя типами `struct`, когда поля совпадают. Имена, типы, порядок и теги должны быть теми же.

`struct` сравним, когда каждое поле сравнимо. Можно использовать `==` для двух значений `Point`. Нельзя использовать `==`, когда поле — `slice` или `map`.

Поместите одно определение `struct` в пакет, который владеет этим понятием. Держите имена полей ясными. Используйте комментарии к типу, когда смысл неочевиден.

Пустой `struct` `struct{}` не имеет полей. `struct{}{}` — частый маркер. Его размер — ноль.

## Составные литералы

Составной литерал строит значение массива, `slice`, `map` или `struct`. Для `struct` перечислите поля в фигурных скобках.

```go
p := Point{1, 2}
q := Point{X: 1, Y: 2}
r := Point{X: 1}
```

Первая форма — позиционный литерал. Порядок совпадает с порядком полей в типе. Вторая форма использует имена полей. Третья форма задаёт `X` и оставляет `Y` нулевым значением.

Предпочитайте имена полей. Имена остаются верными, когда кто-то добавляет поле. Позиционный литерал ломается или меняет смысл, когда список полей меняется.

Можно взять адрес составного литерала.

```go
p := &Point{X: 3, Y: 4}
```

Тип `p` — `*Point`. Эта форма частая в конструкторах.

Нужно назвать тип. `Point{X: 1}` допустим. `{X: 1}` недопустим как самостоятельное значение.

Вложенные литералы могут опускать внутренний тип в некоторых позициях. `[]Point{{1, 2}, {3, 4}}` допустим. Держите код удобным для чтения. Используйте имена, когда вложенность глубокая.

Не смешивайте позиционные поля и именованные поля в одном литерале `struct`. Компилятор отвергает эту смесь.

Используйте литерал указателя, когда значение нужно делить или когда методу нужен указатель. Следующая тема разбирает методы.

## Экспортируемые поля

Имя поля, которое начинается с заглавной буквы, экспортируемое. Другие пакеты могут читать и писать это поле. Имя поля, которое начинается со строчной буквы, неэкспортируемое. Только тот же пакет может использовать это имя.

```go
type Account struct {
	ID    string
	email string
}
```

`ID` экспортируемое. `email` неэкспортируемое. Код в другом пакете может задать `a.ID`. Этот код не может задать `a.email`.

Экспортируйте поле, когда вызывающий код должен задавать или читать его. Оставляйте поле неэкспортируемым, когда тип должен его защищать. Используйте методы в следующей теме, чтобы дать контролируемый доступ.

`encoding/json` по умолчанию кодирует экспортируемые поля. Он игнорирует неэкспортируемые поля. Тег JSON не экспортирует поле. Правило имени всё равно действует.

Имя типа `struct` тоже следует правилу экспорта. Экспортируемый тип с неэкспортируемыми полями — частый шаблон. Вызывающий код использует конструкторы и методы.

Два `struct` в разных пакетах не делят неэкспортируемые поля для преобразования. Имена полей должны совпадать для преобразования. Неэкспортируемые имена включают личность пакета для этой проверки.

Не экспортируйте поле только чтобы заполнить его в тесте в другом пакете. Поместите тест в тот же пакет или добавьте конструктор.

## Встраивание и именованные поля

У именованного поля есть имя и тип. Встроенное поле перечисляет тип без нового имени. Имя поля становится именем типа.

```go
type Point struct {
	X int
	Y int
}

type Circle struct {
	Point
	Radius int
}

type Disk struct {
	Center Point
	Radius int
}
```

`Circle` встраивает `Point`. Поля `X` и `Y` продвигаются. Можно писать `c.X`. Можно всё равно писать `c.Point.X`. У `Disk` есть именованное поле `Center`. Нужно писать `d.Center.X`. Поля `d.X` нет.

Встраивание — не наследование. Подкласса нет. `Circle` не является `Point`. Функция, которая принимает `Point`, не принимает `Circle`.

Продвинутые поля могут конфликтовать. Если два встроенных типа делят имя поля, нужно использовать более длинный селектор. Компилятор отвергает неоднозначный `c.X`, когда продвинуты два поля `X`.

Встраивание также продвигает методы. Следующая тема разбирает наборы методов. Продвижение методов — причина встраивать тип.

Используйте встраивание, когда внутренний тип — часть внешнего типа и продвижение помогает. Используйте именованное поле, когда внутреннее значение — роль, например `Center` или `Owner`.

Можно встроить тип указателя. `*Point` как встроенное поле может быть `nil`. Использование продвинутого поля тогда вызывает `panic`. Инициализируйте указатель.

## Теги `struct`

Тег `struct` — это строковый литерал после типа поля. Компилятор хранит тег. `reflect` читает тег. Пакеты вроде `encoding/json` используют теги.

```go
type User struct {
	Name string `json:"name"`
	Age  int    `json:"age,omitempty"`
	Pass string `json:"-"`
}
```

Обычная форма — `` `key:"value"` ``. В одном теге может быть больше одного ключа. Разделяйте ключи пробелами.

`json:"name"` сопоставляет поле с именем JSON `name`. `omitempty` опускает поле, когда значение нулевое. `json:"-"` пропускает поле в JSON.

Тег не меняет имя поля в Go. `u.Name` всё равно имя в Go. Тег — метаданные.

Используйте обратные кавычки для строки тега. Сырая строка может держать двойные кавычки вокруг значения.

`encoding/json` видит только экспортируемые поля. Тег на неэкспортируемом поле не кодирует это поле.

Держите теги короткими. Используйте имена, которые нужны формату обмена. Не изобретайте новый ключ тега, если вы не пишете код, который его читает.

Другие пакеты тоже используют теги. Примеры: `xml`, `yaml` во внешних модулях и преобразователи баз данных. Эта тема использует `json` как главный пример.

Неверный синтаксис тега всё равно строка. Пакет json может игнорировать плохое значение. Проверяйте официальные правила тегов json, когда добавляете параметры.
